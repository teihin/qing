# 热更新包生成脚本

先在 Cocos Creator 2.4.13 中完成一次 Native 构建，确认最新运行资源已经进入 `build/jsb-link`，然后双击项目根目录的 `生成热更新包.command`，或在终端运行：

```bash
python3 tools/generate_hot_update.py
```

首次运行会要求填写起始版本号和服务器地址。以后每次运行都会依次显示全部当前配置：

- 本次版本号
- 热更新服务器根地址
- 是否同步更新 `assets/resources` 里的两个 manifest
- 是否加密热更新包中的 PNG

直接回车表示保持显示的当前值不变；输入新版本、地址或 `y/n` 表示本次修改。首次填写的版本会用于第一次生成，以后每次成功生成后自动递增最后一段。

选择同步更新时会覆盖：

- `assets/resources/project.manifest`
- `assets/resources/version.manifest`

选择更新后，这两个文件可供下一次完整 Native 包构建使用；选择不更新则只生成本次服务器更新包。

脚本还会询问是否加密 PNG，默认选择“是”。启用后会在终端实时显示当前张数、总张数、百分比和正在处理的文件；只转换输出包中的 `.png`，不会修改 `build/jsb-link` 和项目 `assets` 源图；`project.manifest` 的文件大小及 MD5 基于加密后的最终文件生成。加密格式已按旧版 `/Volumes/CB/nnnn2/tool.py` 核对，并与当前 2.4.13 `CCImage.cpp` 中已移植的解密兼容逻辑一致：标准 PNG 会移除头尾后转换，缺少标准 IEND 的旧兼容输入会保留其余内容继续转换，非 PNG 文件头会原样跳过。它属于资源混淆，不应当作安全加密。

输出位于 `hot-update-output/`：

- `<版本号>/`：可直接部署到 manifest 中服务器根地址的完整目录。
- `ver_<版本号>.zip`：上述目录的 ZIP 归档，版本号中的点会替换为下划线。

本机配置保存在被 Git 忽略的 `.hot-update-config.json`。也可以显式传参用于无人值守执行：

```bash
python3 tools/generate_hot_update.py --version 1.2.0 --server https://example.com/update --encrypt-images yes
```

脚本不会启动或操作 Cocos Creator，也不会自动上传服务器。当前客户端直接请求服务器根地址下的 `project.manifest`、`version.manifest`、`src/` 和 `assets/`；只上传 ZIP 而不解压，客户端无法直接读取。

## 上传最新热更新

双击项目根目录的 `上传最新热更新.command`，脚本会自动选择 `hot-update-output/` 中版本号最高且结构完整的版本，通过 SFTP 上传到服务器 `/up`。每次都会显示服务器、端口、用户、SSH 密钥和远程目录，直接回车沿用，输入新值修改。

上传时会实时显示当前文件数、总文件数、总体百分比和文件路径。上传顺序是 `src/`、`assets/`、`project.manifest`、`version.manifest`，其中 `version.manifest` 最后上传，避免资源尚未上传完成时客户端提前发现新版本。上传只覆盖同名文件，不删除服务器中的旧文件，也不会上传 ZIP。配置保存在被 Git 忽略的 `.hot-update-upload-config.json`。
