# 业绩核心共享 · 界面原型（用线上真实数据）

文件：`agent-rewards-prototype.html`（双击用浏览器打开，单文件、不联网、不写任何数据）
数据快照：2026-11-07 19:40，对线上库与游戏命令的**只读**查询，没有发放任何金币。

## 一、这份原型用什么数据

| 项 | 真实情况 |
| --- | --- |
| 全库账号 | 64 个 |
| 代理候选（老板/盟主/合伙人/总裁/普通代理） | **16 人**，原型名单就是这 16 人，昵称、ID、身份、上下级关系全部真实 |
| 已开通业绩（`client_prop=True`） | **27 个账号**，比代理还多 11 个（历史批量开通过，含普通玩家） |
| 今日业绩点数 | **全部为 0**（线上还没产生奖池提留，`all_performance=0`） |
| 线输赢/贡献数据 | `club_member_score_info` 只有 32 行（11-04 起）；16 个代理里**只有 4 个**挂在俱乐部下（分属 3 个俱乐部） |

所以默认打开会看到满屏 0 和「无数据」，这是**线上现状**，不是原型坏了。要看分摊效果，点右上角「载入演示点数」（会标明是演示值）。

## 二、对着这 8 个地方提意见

1. **名单从哪来** —— 现在自动同步 16 人。BOSS（648425 匿名）要不要拿一份？「新玩家」身份的 4 个人算不算代理？
2. **业绩点数** —— 现在只有"奖池提留"一种来源，没提留的日子全平台点数都是 0，等于当天业绩奖没人能分。这个口径对不对？还是要把抽水/流水也算进业绩？
3. **上下级扣减** —— 表里"今日业绩（毛）/已下发/实际点数（净）"三列能看懂吗？上级扣完下级还剩多少，是不是你们要的算法？
4. **0 点不保底** —— 现在 0 点就是 0 元、不发钱、不产生工单。确认？
5. **整条线输赢取不到** —— 16 个代理里 12 个「无数据」，因为线输赢是俱乐部口径，没进俱乐部的代理根本没有数。奖池共享按什么发？
6. **主子账号** —— 点「分账号」看交互。现在线上没有任何绑定关系，绑定入口够不够用？
7. **排除** —— 点行尾「排除」，选范围、填原因，人立刻从名单消失；再点顶部「已排除」能恢复。这个流程对吗？「三种奖励全部停发」这个范围要不要？
8. **账单** —— 点右上「发放账单」，空态就是线上现状（从没发过）。表头字段够不够对账？要不要按代理汇总 + 按流水两个视图？

## 三、原型里可以点的东西

- 三个 tab 分别看业绩 / 核心 / 奖池共享的表格列差异
- 「载入演示点数」→「按点数自动分摊」：看分摊与尾差（合计恒等于计划总额）
- 改「计划发放总额」，看差额变红、发放按钮禁用
- 行尾「线数据」：上级 → 当前 → 下级逐层看输赢/贡献（真实层级，真实数值）
- 行尾「分账号」「排除」；顶部「按 ID 添加」「排除选中」「已排除」
- 右上「确认并发放」：二次确认 + 逐笔进度（原型不真发钱）
- 右上「发放账单」：账本与导出入口

## 四、原型没做的事

- 不连后台接口、不写库、不发金币，所有操作只在本页内存里
- 分页、权限、审计、导出文件、CSV 内容都没做（正式版才有）
- 「载入演示点数」的数字是为了演示分摊随手编的，**不是线上数据**
