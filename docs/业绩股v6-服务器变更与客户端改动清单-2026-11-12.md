# 业绩股 v6：服务器变更与客户端改动清单

- 日期：2026-11-12
- 依据：`服务器文档整理/俱乐部业绩-客户端与后台接口文档.md`（2026-11-12 14:30 更新，变更记录 v4 → v6）
- 状态：2026-11-12 已按本清单实施客户端（`panelMyHongli.ts` + `panelMyHongli.prefab`），
  未改服务端；Creator 构建/真机/联调待验。服务端 v6 需部署重启后才有 `scope`/`leaders`。

## 一、结论

1. 之前抓包里的「在 A1（775447）授权 580629，回包落到 267493」**不是普通代理跨俱乐部**，而是
   **总群主给 A3 盟主的联盟层授权**。v6 起这种授权会出现在 A1 的 `leaders` 列表里，
   并计入总群主的「下放」；当前客户端完全没消费 `leaders`，所以看不到人。
2. 客户端必改三处：渲染 `leaders`、按回包 `scope` 处理授权结果、删掉上一轮「已记录在其它俱乐部」的提示。
3. 后台业绩报表 §6 **没有变化**，XuanManager 的 `异步_查询_俱乐部_业绩_报表` 调用无需改。
4. 抓包回包里没有 `scope`，也没有 `leaders` 字段，说明**服务端 v6 可能还没部署/重启到当前联调服**；
   实现前先确认线上回包已带 `scope`（联盟授权）和 `leaders`。

## 二、服务器 v6 的变化

| # | 变化点 | v6 之前 | v6 之后 | 客户端影响 |
| --- | --- | --- | --- | --- |
| 1 | 总群主口径 | 单俱乐部 | **联盟树**：`我`=联盟总次数；`下放`=A1 已授权代理子树 + 已授权盟主的整俱乐部 `M_c`；`剩`=我-下放 | 只影响展示值，字段不变；不要自行重算 |
| 2 | 联盟层授权 | 无独立作用域 | 新增 `club_perf_union_grant_info`；总群主/boss 给本联盟/全服的**盟主节点**授权 | 授权成功不再是「记录在别处」 |
| 3 | 普通代理跨俱乐部 | v5 会全部设置 | **拒绝**，返回「联盟层只支持盟主节点，其他俱乐部代理请由该俱乐部盟主授权」 | 直接展示服务端错误；不要自行兜底 |
| 4 | 授权回包 | `user_id, enabled, club_id, club_ids` | 增加 `scope`：缺省/`club`=俱乐部内授权；`union`=联盟层授权盟主 | 客户端按 `scope` 分支 |
| 5 | 下发列表 | 只有 `list` | 增加 `leaders`（仅总群主查自己俱乐部且 `page=0` 返回，其他情况 `[]`） | **必须新渲染** |
| 6 | 分页 | `count` = frontier 人数 | 不变；`leaders` 不计入 `count` | 分页仍按 `list` 算 |
| 7 | 存量盟主 | — | 默认**未授权**；需总群主逐个授权后才计入「下放」 | 首次打开会看到 `leaders[*][10]=0` |
| 8 | 盟主自己页面 | — | 仍是单俱乐部口径、`leaders=[]`、创建者默认开通，不受联盟授权状态影响 | 不要给盟主自己页面加联盟逻辑 |

`leaders[i]` 字段（11 项）：

```
[0] 盟主 guuid
[1] 昵称
[2] 盟主自己的俱乐部 ID（授权/跳转用）
[3] 身份（盟主）
[4] 联盟名
[5] 俱乐部名
[6] 该盟主俱乐部总次数 M_c（我）
[7] 该盟主俱乐部内已下放 G_c
[8] 该盟主俱乐部剩余 L_c = M_c - G_c
[9] L_c / all_count，两位小数
[10] 联盟授权状态：1=已授权，0=未授权
```

## 三、客户端改动清单

文件：`assets/scripts/UI/panelMyHongli.ts`（Prefab 视交互方案决定是否改）。

### P0-1 渲染 `leaders`

- 位置：`applyPerfList`（[:697](file:///Volumes/SSD/qing/assets/scripts/UI/panelMyHongli.ts#L697)）现在只读 `listData.list`；
  `leaders` 完全被丢弃。
- 建议：把 `leaders` 作为**第 0 页的前置行**放进同一个 `业绩列表` ScrollView，行数 =
  `leaders.length + list.length`；`leaders` 只在回包带值时渲染（服务端只 page=0 返回）。
- 行内容（复用现有 `记录行` 模板，不改 Prefab 也能先上）：
  - 昵称：`【盟主】<昵称>`；
  - 玩家ID：`ID:<guuid> · <俱乐部名>(<club_id>)`；
  - 占比：`leaders[i][9]%`（注意是 `L_c/all_count`，不是 `M_c/all_count`）；
  - 状态：`leaders[i][10]===1 ? 已授权 : 未授权`（可拼进 ID 行或占比行）；
  - `M_c` 可放在 ID 行末尾，便于总群主核对。
- 关联改动：
  - `renderPerfRows`（[:768](file:///Volumes/SSD/qing/assets/scripts/UI/panelMyHongli.ts#L768)）行数与空态判断要算上 `leaders`；
    `list=[]` 但 `leaders` 非空时不能提示「暂无业绩股成员」。
  - `layoutPerfList`（[:795](file:///Volumes/SSD/qing/assets/scripts/UI/panelMyHongli.ts#L795)）高度 = `(leaders+list)` 行数。
  - `refreshPerfPaging`（[:810](file:///Volumes/SSD/qing/assets/scripts/UI/panelMyHongli.ts#L810)）**保持**按 `list` 的 `count` 算，不要把 `leaders` 加进总数。

### P0-2 按 `scope` 处理授权回包

- 位置：`onPerfGranted`（[:734](file:///Volumes/SSD/qing/assets/scripts/UI/panelMyHongli.ts#L734)）。
- 现状：只要回包 `club_id` 与当前俱乐部不同，就提示「该代理的业绩股已记录在俱乐部 X，当前俱乐部列表不显示」。
  **对 v6 的联盟授权是错的**——它对当前页面有效，会体现在 `leaders` 和「下放」里。
- 改为：
  - `scope === "union"`：按成功处理（「已授权盟主/已取消联盟授权」），刷新 info + list；
  - `scope` 缺省或 `"club"`：沿用「已添加业绩股成员」；
  - `enabled=0` 的取消同样走成功提示；
  - 只有 `scope!==union` 且当前俱乐部不在 `club_ids` 时，才保留「记录在其它俱乐部」提示（按新规则基本不会出现）。
- 授权后刷新保留现有 1.0s + 2.4s 两次（写库异步），同时更新 `leaders[*][10]` 与底部三比例。

### P1-1 盟主行的授权 / 取消入口（需产品确认交互）

- 联盟层授权只能给盟主节点，最自然的入口是 `leaders` 行上直接「授权 / 取消授权」；
  这需要 Prefab 新增按钮节点（`记录行` 模板加按钮，或新增 `盟主行` 模板），按项目规则要带 `cc.Widget`
  并直接写进正式 Prefab。
- 若暂不改 Prefab：可先复用现有「代理ID输入 + 确认添加业绩」按钮，输入盟主 guuid 发送
  `enabled=1`；**取消**没有入口（当前只发 `enabled=1`），需要单独加按钮或长按菜单。
- 建议一次做到位：行内「授权/取消」按钮 + 状态色；否则总群主无法回收授权。

### P1-2 文案与错误

- 输入框占位从「请输入下级代理ID」改为「输入下级代理ID / 盟主ID」。
- 服务端新增错误「联盟层只支持盟主节点，其他俱乐部代理请由该俱乐部盟主授权」直接弹原错误，
  不做客户端改写（符合「服务端回包原样展示」）。
- 授权成功提示区分「俱乐部内授权」与「联盟层授权盟主」，避免运营误解授权对象。

### P2 无需改的部分

- `applyPerfTotals`（[:519](file:///Volumes/SSD/qing/assets/scripts/UI/panelMyHongli.ts#L519)）继续用 `*_count / *_percent`，
  总群主的联盟树口径由服务端给。
- 页签按 `enabled` 显隐：非成员只隐藏「业绩股」页签，「我的红利」页签保留并居中；总群主创建者恒 `enabled=true`。
- 列表排序仍以服务端为准，客户端不二次排序。
- `leaders` 只有 page=0；翻到第 2 页时服务端返回 `[]`，客户端按「无 leaders」渲染即可，不必缓存。

## 四、后台 XuanManager

- §6 `异步_查询_俱乐部_业绩_报表` 的请求/返回**未变**，`agent_rewards.go` 不需要改。
- 联盟层授权只影响总群主自己的业绩页口径，不改变报表按俱乐部/联盟返回的已开通代理集合。
- 若运营希望「联盟发放名单」体现盟主的 `M_c` 或联盟授权状态，属于新需求，需另立口径；
  当前文档没有这个要求。

## 六、实施结果与待确认

1. 已实现行内「授权」按钮（`tools/apply_my_hongli_perf_leaders.py` 给业绩股
   `记录行` 模板加 `授权按钮`），点击复用 `设置_俱乐部_业绩_授权`，`enabled` 恒为 1；
   未授权显示金色「授权」，已授权显示不可点的深色「已授权」。
   **按业务要求只授权、不提供取消**；普通成员行只读。入口只对有管理权限的账号显示
   （boss level≥99、俱乐部创建者、总群主）。
2. 盟主行展示：`【盟主】昵称`、`ID · 俱乐部名 · 整线 M_c 次`、`L_c/all_count` 占比、
   授权状态按钮；M_c 是整俱乐部/整条线的昨日贡献次数，不是个人次数或金额。
3. 服务端 v6 是否已部署并重启仍需确认：抓包回包没有 `scope`/`leaders`，
   否则客户端改了也看不到数据。
4. 文档头部仍写「2 张表已建」，v6 实际是 3 张（新增 `club_perf_union_grant_info`）；
   变更记录 v4/v5 的「跨俱乐部全部设置」已被 v6 覆盖，以 v6 为准。
5. `leaders` 仅第一页返回；如果产品希望翻页时仍看到盟主汇总，需要服务端改成每页都返回或客户端缓存。
