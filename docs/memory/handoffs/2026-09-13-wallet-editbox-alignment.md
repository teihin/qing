# 钱包输入框文字错位修复

日期：2026-09-13；目录 `/Volumes/SSD/qing`；分支 `main`。用户要求统一修复钱包 TEXT_LABEL 错位，继续遵守不操作 Creator、由用户验证、不提交的约束。

## 原因与修改

- 本地 2.4.13 引擎 `components/editbox/CCEditBox.js` 的 `_upgradeComp()` 会通过 `_updateTextLabel()` 将带兼容字体字段的输入文字改成左上锚点 `(0,1)`，但不会把现有 `(0,0)` 坐标移到框左上角。之前换肤工具将文字当作普通居中 Label 布置，造成运行后向右下偏移。占位文字也需要遵守相同锚点契约。
- `钱包.prefab` 的全部 20 个 EditBox、40 个输入/占位文字节点统一使用左上锚点、与输入区域匹配的左上坐标、左对齐及垂直居中。Native Widget 绑定本输入框四边，在尺寸变化后同步文字范围；长内容使用 CLAMP，避免越出边框。
- TRC20 地址输入框按其最终缩窄后的宽度设置文字区域。充值资料的 5 个输入保留左侧字段名称预留空间，修正原先半像素垂直偏差。
- 本次只修改 40 个 Label 节点及各自 Label/Widget 组件，共 120 条内部记录；外层输入框、页面、按钮、背景、字体字号、文字内容、密码模式、长度限制、事件和业务脚本均与本轮开始时一致。
- 新增 `tools/repair_wallet_editbox_labels.py`，可单独修复输入框内部，无需重新套用整页换肤。`tools/apply_v8_wallet_pages.py` 在最终保存前调用同一修复，避免将来重新生成时恢复错误坐标。
- 本轮开始时的完整 Prefab 保存于 `art_sources/v8-repairs/wallet-pages/before-editbox-alignment/钱包.prefab`。保留用户在上一阶段之后的手动调整，没有重新运行整页应用器或切图。

- `node tools/tests/wallet_editbox_alignment_regression.js` 通过：执行本机安装版本的真实 EditBox 初始化/兼容升级、字符串显示及密码转换、文字/占位切换、隐藏后重新显示、模式更新，同时使用真实 Widget 对齐函数检查输入区域缩放后的位置；20 个输入、40 个文字节点均保持在框内并垂直居中。没有启动 Creator。
- 同一检查对本轮改前快照失败，确认能识别旧坐标越界。逐条 JSON 差异检查证明仅内部标签记录变化，EditBox 契约与全部外层节点保持原样；修复工具再次运行无变化。Python 语法和限定范围 `git diff --check` 通过。
