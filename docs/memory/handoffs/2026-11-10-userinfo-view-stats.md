# 玩家信息：付费查看输赢统计（未构建、未真机）

日期：2026-11-10
分支：`codex/club-ui`（改动未提交）
目录：`/Volumes/SSD/qing`
关联：[钻石消费价格](2026-10-26-stone-consume-price.md)

## 目标

玩家信息弹窗（`panelUserInfo`）统计框底部空白处新增「查看」按钮：点击提示扣除 N 钻石查看，
确认后显示当前玩家 6 项数据（总手数 / 总胜率 / 失败率 / 胜利 / 平局 / 失败）。
N 复用后台「钻石消费价格」里的 `看数据`，默认 1 钻，运营改价不用发客户端。

## 改动

- `assets/resources/UI/panelUserInfo.prefab`：在 `数据/统计` 下新增 `查看` 按钮
  （`cc.Sprite` 九宫格 `V7/player_info_v8_button.png` + `cc.Button` + 文字 `V8文字`），
  位置 `(0,-80)`、尺寸 `380×60`，落在统计框内「胜利/平局/失败」行下方的空白区。
  未加 `cc.Widget`：该弹窗内容都挂在会随画布拉伸的根节点下、按 750×1334 基准居中排布，
  与同级统计/道具节点一致；新增节点不贴画布边缘，不需要单独锚定。
- `assets/scripts/UI/panelUserInfo.ts`：
  - 新增 `statsUnlocked`，未确认扣费前 6 项保持设计占位（上排 `**`、下排 `-`）；
  - `RefreshViewButton()` 按 `GetConsumeStone(CONSUME_LOOK_DATA)` 刷按钮文案并已查看后隐藏；
  - `OnClickViewStats()`：余额不足提示；价格为 0 直接显示；否则弹 `panelMsgView` 双按钮确认；
  - `UnlockStats()`：显示数据并 `reqHallCommand(BuildConsumeStoneParam("看数据"), "玩家_消费_命令")`；
  - 删除原本未被任何 Prefab 节点绑定的旧 `看一下` 分支（引用已不存在的
    `数据/统计/总局数` 等节点，属死代码）。
- 数据仍取 `player.info.remark` 的逗号字段：`0=胜、1=负、2=平、3=翻牌数、5=翻牌胜、6=入池次数`，
  与改动前 `UpdateInfo` 同一口径。

## 对外约定

- 价格项固定为 `看数据`（客户端常量 `ConfigManager.CONSUME_LOOK_DATA`）。后台
  「系统配置 → 钻石消费价格」改价后，客户端需重进大厅才生效。
- 每次打开面板都要重新付费查看；面板关闭即丢失解锁状态。
- 看自己的资料同样走扣费（沿用原「玩家资料看数据」消费点口径）。

## 风险 / 待确认

1. 其他玩家的统计依赖服务端在房间玩家信息里下发 `remark`；本仓库无服务端源码，
   只能沿用旧面板同一字段，需真机联调确认非本人也有数据。
2. 扣费沿用「先显示、后发命令」的乐观刷新；若服务端拒绝（余额并发变化等），
   本次面板仍会显示数据，与既有消费点行为一致。
3. 价格文案在打开面板时读取；牌桌内不刷新配置。
