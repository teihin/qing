## 脚本

- 新增两个数据通道（各自一套 context/timer，互不干扰）：
  - `QueryAll("players"|"agents", page)` → `查询_俱乐部_所有_玩家` / `查询_俱乐部_所有_代理`；
  - 推送 `AllClubPlayerList` / `AllClubAgentList` → `OnAllList` → `RenderAllList`；
  - 回执 `HandleListReply` 按 context 认领（0x200/0x500 只代表受理），`代理数据加载中` 自动重试 2 次。
- 排序：`RenderSortBar` 克隆 `排序模板` 生成条件按钮，选中项带 ↑/↓，再点切方向（`OnSortChip`）。
  **2026-11-07 用户要求改成 9 项**：输赢 3 + 贡献 3 + 红利 3（`total_bonus_fen` / `today_bonus_fen` / `yesterday_bonus_fen`）。
  `RenderSortBar` 按 `perRow=5` 多行排布：第一行 5 个、第二行 4 个居中，行高 40、行距 4（每行 5 个才够宽放大字号）。
  按钮文字 **24 号**（2026-11-08 用户要求「文字大一点」，原来 20；代码里显式设置，prefab 模板也同步成 24）。
  ⚠️ 服务端文档目前仍写「红利不参与排序、传了回落 `total_score`」，这 3 个条件要等服务端支持后才真正生效，客户端已按可排序发送。
- 分页：`RenderPaging` + `TurnPage`，到边界压暗并关 `interactable`。**每页 10 条**（`PAGE_SIZE`；服务端默认 20/上限 100，2026-11-07 按用户要求调小，卡片高 240 一页 20 条要滚好几屏，同时把每页头像查询压到 10 条）。
- 搜索：列表页签里搜索框是过滤条件（空=全服），走接口 `search`。
- 行渲染：`FillPlayerListRow` / `FillAgentListRow` → 共用 `FillListStats`。
  接口未下发的贡献/红利一律显示「—」；玩家行左栏第二行放「上级 xxx」，代理行放「下线 N 人」。
  行内按钮：`查看`（`panelClubPlayerInfo`）、`代理链`（跳页签查这个人）、`战绩`、`添加到分组`（未分组时）。
- 默认页签：`ReadInput` 按入参判定 —— `playerLogic` 入参（牌桌点头像）→ `info`；JSON 无 `userId`（我的→数据统计）→ `players`。
- 占位文案随页签切换：列表页签「输入玩家ID或昵称筛选（留空看全部）」，玩家信息/代理链「输入玩家ID或昵称」。


### 行内「添加到分组」（2026-11-07 追加，同日改口径）

- **最初做法（已废弃）**：因为文档那版两条列表接口不带分组字段，客户端逐行发 `查询_俱乐部_玩家_分组`（§3.3）补查。
  **实测一页 20 条同时发会把连接打掉（客户端断网一下）**，用户明确要求停掉。
- **现行做法（2026-11-08 文档已正式支持）**：分组**随行下发**，字段 `group_id` / `group_name` / `groups`，和成员列表/代理链同结构——`ParseListRow` 用现成的 `GroupText(raw)` 解析
  （优先 `groups[]`，其次 `group_id` / `group_name`），`hasGroup=是否下发了分组字段`。
  `ApplyRowGroup(row, item)` 直接调 `ApplyGroupCell(row, id, 分组名)`——**和「玩家信息 / 代理链」完全同一套**：
  已分组→「分组:XXX」，未分组→「添加到分组」（2026-11-08 用户明确要求「没分组的显示添加按钮，和另两个页签一样」）。
- 加人/移人后 `RefreshRowGroup` 纯改标签、不发请求；删除分组后整页重查一次（服务端会把新分组字段带回来）。
- 教训：**列表页不要为每行发一条命令**，一页十几二十条并发会触发断线；能由列表接口带回来的字段一律别单独查。
