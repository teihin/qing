## 服务器口径

- `查询_俱乐部_成员` 的 `user_id='ALL'`（含搜索）只返回**被查节点自己 + 直属下级代理 + 直属普通玩家**，`count` 为直属人数，排序由服务端完成。
- 新增 `agent_id`：缺省/空/自己 = 自己的直属列表；传自己子树内任意层级代理 ID = 该代理的直属列表（首行为该代理）；树外/普通玩家 = 空列表。

## 追加：申请列表报「上一入会查询尚未返回」

- 现象：打开「入会申请」直接显示「上一入会查询尚未返回，请稍后重试或重新登录」，列表点刷新也无效。
- 根因：`ClubAgentReqInfo` 的串行车道在请求超时后保留墓碑，等迟到推送排空；若推送是单条对象（服务端 `count=1` 时与 `ClubAgentInfo` 一样把 `result` 包成对象）会被 `receive()` 当成非数组丢弃，推送永远等不到 → 墓碑永久占住车道，之后所有申请/红点请求被立即拒绝。
- 修法（`ClubManagementApi.ts`）：
  1. `receive()` 的 `rows` 解析改为优先找数组，找不到再把单条对象包成数组；兼容 `result` 内再包一层或 JSON 字符串。
  2. 超时墓碑增加 2 秒排空窗口，到期强制释放车道；期间新请求排队而不是直接报错。
  3. 后台红点轮询超时从 12 秒缩到 6 秒，减少占住用户申请列表的时间。
- 验证：`tools/test_club_joiner_protocol.js` 扩充为「墓碑排空 + 到期释放 + 单条对象回包」，通过；`ClubManagementApi.ts` 转译 0 诊断。真实服务器回包待验。
