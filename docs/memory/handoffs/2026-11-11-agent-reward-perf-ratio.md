# 后台业绩核心共享：三类奖励统一按业绩股比例（2026-11-11）

## 目标

「业绩核心共享」三个 tab（业绩奖励 / 核心奖励 / 奖池共享）的**金额分配比例**统一改成
最新《俱乐部业绩》文档（`服务器文档整理/俱乐部业绩-客户端与后台接口文档.md`）的
业绩股口径；同时把默认发放日期改为昨天，因为当天业绩还没结束。

## 规则

1. **统一权重**：三类奖励都用 `异步_查询_俱乐部_业绩_报表` 的 `left_count`（净次数）
   作为权重；只有报表里出现（已开通业绩，含俱乐部创建者）的代理有权重，未开通的记 0、不参与分摊。
   名单内按净次数归一，再按计划总额等比分摊（最大余数法，合计严格等于总额）。
2. **业绩股占比**：顶部占比与表格「业绩占比」= 本人净次数 ÷ 本次名单净次数合计。
   与业绩股页的池占比同比例；名单不含全部已授权代理时会等比放大到 100%。
3. **日期**：页面默认昨天（`beijingDateInput(-1)`），日期选择不能晚于今天；后端 `rewardDate`
   也拒绝未来日期。发给游戏服的 `date` 按批次日期换算偏移：昨天 `-1`、今天 `0`。
   选今天时后端返回警告「当天数据还没结算完，建议发放昨天的批次」。
4. **核心奖励**：计划总额仍由主管填写；不再用「上次金额」当权重，上次金额只作为表格参考列。
   自动分摊按钮统一改为「按业绩比例分摊」。
5. **奖池共享**：计划总额仍 = 奖池 50% × 共享比例（可覆盖）；个人分配改为按业绩股净次数。
   历史日期优先用批次保存时的 `pool_base` 快照，没有快照才退回当前实时奖池并提示；
   `pool_base` 只在发放当天保存时写入，避免把今天的奖池写成历史日期的快照。
6. **表格/导出**：列改为 业绩(毛次) / 净业绩(次) / 业绩占比；移除整条线输赢与贡献列。
   「线数据」弹窗仍保留今日实时数据，并在弹窗内明确说明与统计日无关。

## 接口与解析

- 游戏服命令：`异步_查询_俱乐部_业绩_报表`，参数 `union_id`、`date`（相对今天天数）、`context`。
- 后台 HTTP 通道的 `context` 传 `p@<xuan-...>`；回包兼容：
  - `{"ret_code":512,"ret_result":"{\"ClubPerfReport\":{...}}"}`（文档口径，无 context/result 包裹）
  - `{"context":"...","result":{"ClubPerfReport":{...}}}`（p@ 包裹）
  - `result` 内再套字符串的兼容处理。
- 列表行：`[guuid, name, role, unionName, clubName, my, granted, left, left_percent]`；
  同一 guuid 可能出现在多个俱乐部，按 guuid 累加 my/granted/left。
