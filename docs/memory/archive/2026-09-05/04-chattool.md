## ChatTool 网页客服系统

- 2026-08-11 已在根目录 `ChatTool/` 实现独立的游戏在线客服项目，技术栈为 Go 标准库服务端、React/Vite 双端页面和 MySQL 5.7；默认只监听 `127.0.0.1:8893`，生产数据使用 `webcm` 的 `chat_` 前缀表且不创建外键，图片/视频/文件保存在权限受控的独立媒体目录，数据库只记录元数据和不可预测媒体ID。正式公网入口按IP子路径部署：玩家端为 `http://154.37.155.17/chattool/player`，客服工作台为 `http://154.37.155.17/chattool/agent`，Caddy剥离 `/chattool` 后转发到本机8893，8893和MySQL均不直接开放公网。
- 玩家手机H5已实现无客服在线提示和发送禁用、自动接入状态、文字/相册图片/现场拍摄/视频/PDF/文本/ZIP、输入中、媒体预览、结束咨询和五星评价；客服端已实现独立登录、主管/普通客服、在线/离开/离线、最少接待量与最久未分配优先的自动派单、接待上限、待接入/我的/全部/已结束队列、聊天、快捷回复、内部备注、转接、结束、玩家资料列、客服团队创建/启停/角色/容量及评价查看。客服主动离线、心跳超时或账号停用时，活动会话会重新入队并自动分配。
- 2026-08-11 用户明确取消KB授权和一次性票据链路，要求系统保持简单，只需让普通用户无法直接看懂入口中的玩家资料。当前接入改为：`panelKefu.ts` 直接读取当前Account的玩家ID、昵称、等级、平台、角色和房间，加入客服入口、服务通道和秒级时间戳后复用现有 `Tool.encrypt()` 生成AES-ECB/PKCS7十六进制密文，打开 `http://154.37.155.17/chattool/player?d=<密文>`；网页把密文提交到 `POST /api/player/session`，后端用 `CHAT_PLAYER_LINK_KEY` 兼容解密并校验默认15分钟有效期，成功后立即从地址栏移除密文。`ConfigManager.kefuUrl` 默认值已改为该模板；线上哈希配置 `客服2` 若覆盖默认值，也必须同步更新。游戏内“客服”传 `channel=general`，两个“VIP充值”入口均已改为同一ChatTool地址并传 `channel=vip_recharge`；本轮按用户要求只修改Cocos源码，不生成或发布客户端热更新包。
- 轻量加密只保证玩家ID、昵称等资料不以明文出现在URL中，不是可靠身份认证：口令随客户端发布，技术人员可以逆向后伪造资料。客服资料栏和元数据明确显示“游戏客户端轻量加密、未服务端认证”，不得向运营人员宣称这是权威游戏身份。`Tool.aesKeyBytes()` 和 `Tool.encrypt()` 已移除口令、派生键及密文的调试打印。ChatTool不再需要 `CHAT_INTERNAL_TOKEN`、`CHAT_TICKET_TTL`、`chat_player_ticket` 表或KB接入示例。
- ChatTool 客服密码仍使用bcrypt cost 12，会话仅存随机令牌SHA-256，并实施HttpOnly/SameSite Cookie、独立CSRF、同源校验、限流、CSP、媒体鉴权、文件头白名单、大小限制、审计和范围下载。公网纯HTTP部署时 `CHAT_COOKIE_SECURE=false`，Cookie路径限制为 `/chattool`；Caddy转发的客户端IP只在请求确实来自本机回环代理时才信任。实时通道采用SSE且消息以MySQL为权威；当前为单Go实例且没有内置恶意附件扫描，多实例前需增加Redis/NATS和共享对象存储，开放ZIP/PDF前应接入杀毒隔离或只开放图片和视频。
- 用户已明确确认ChatTool“不需要HTTPS，直接通过IP访问”。前端生产构建统一使用 `/chattool/` 的静态资源、API、SSE和媒体前缀，Caddy兼容无末尾斜杠308跳转。轻量直传版已通过CryptoJS已知密文兼容测试、Go `test -race`/`vet`、Linux amd64无CGO静态构建、React ESLint、TypeScript/Vite生产构建及三个Cocos修改文件的TypeScript语法转译。纯HTTP下客服密码、聊天内容和附件仍可能被链路窃听或篡改，此风险已保留在部署文档中。
- 2026-08-11 ChatTool 已正式部署到服务器私有目录 `/www/html/.chattool`，静态Linux amd64服务只监听 `127.0.0.1:8893`，复用服务器本机 `webcm` 账号并创建14张 `chat_` 表、记录4个迁移；运行配置权限为600，首次主管账号创建及公网登录闭环通过后已从运行环境删除一次性初始化密码。Caddy路由ID为 `qing_chattool_proxy` 和 `qing_chattool_redirect`，用户级crontab包含开机启动及每分钟路由看门狗。服务删除初始化密码后重启成功，本机/公网健康、`/chattool` 308、玩家页和客服页200、主管登录/身份、团队管理、在线/停止接待均已验证。

- 2026-08-11 游戏内真实点击客服首次显示“入口信息无效”的根因已经确认：当前测试客户端的AES密文和口令均正确，但 `JSON.stringify` 把玩家 `level` 发送为数字，服务端 `directPlayerPayload.Level` 原来只接受字符串，解密后的JSON反序列化失败并被统一映射成 `INVALID_PLAYER_DATA`。后端现用 `playerTextValue` 同时兼容字符串、数字和 `null`，入库前统一转为字符串；数字等级回归测试、Go `test -race`/`vet`、Linux amd64静态构建、正式二进制哈希及本机/公网健康均通过。线上真实密文在修复后先正确进入“入口信息已过期”分支；以同一真实资料刷新时间戳重新加密后，玩家页成功创建会话并进入无客服状态，证明游戏入口、解密和玩家会话闭环已通。无客服时能否发送的旧行为已于2026-08-12改为强制禁发。该修复只更新服务端，不需要发布Cocos热更新；文字/图片/视频的玩家与在线客服双端收发仍应在客服上线后完成首单验收。
