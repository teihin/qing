## 2026-11-26 机器人「坐不上 / 不出牌」修复：座位表未到不判无座 + 带入时序

- 现场：19:36 四台**确实出过牌**（休/大/跟/丢）并结算，说明俱乐部模式的出牌链路没问题。
  真正卡住的是抢座：进房 1.5 秒就去抢，座位表还没下发 → `freeSeats` 为空 → 判「本房没空座」→ 离房 →
  下一条找房结果又是同一间 → **1 秒一圈来回进出**，所以看不到出牌、只看倒计时。
  - 修：座位表为空时不算无座，等 1 秒重试（最多 8 次）；确实没座才换房，并给刚离开的房间 **30 秒短避让**。
- 另一个真实障碍：预坐后立刻发带入会被回 **769「请先选择带入分数！」**（官方客户端是
  「预坐锁座 → PlayerList 确认 → 再选带入」）。修：预坐成功后等 600ms 再带入；收到 769 且提示含「选择带入」时
  补发带入而不是换座位。
- **结算后不再一局就走**（用户 2026-11-26 反馈「积分没输完都跑了」）：俱乐部房间不结束，一结算就集体离房会让
  房间直接空掉（日志里 `人数不足，房间关闭剩余 2 分钟`）。改成默认**原地重新带入继续打**，
  只有「俱乐部金币不够下一次带入」或「同房续入次数用满（策略 `stayBuyinTimes`，默认 2）」才换桌。
  这与 10-29 定的「每轮结算离房换桌」相反，以本次为准；轮换节奏由 `stayBuyinTimes` 控制。
- **现场补充（19:40）**：3 台 `seated` 但 `mgr_automation_robot.buyin = 0` —— 座位坐上了、桌面没带入分，
  房间开不了局一直倒计时。旧代码把 769「请先选择带入分数」当抢座失败，座留住了钱没进去；新逻辑（锁座 600ms 后带入 +
  769 补带入）能解，但**必须重启 worker**。
- **房间解散后不出房**（用户 19:43 反馈 worker003 卡在 `playing` / 房 154570）：服务端只推一条
  「人数不足，房间关闭剩余 N 分钟」，客户端原来只记日志不动作。修：提示含「房间关闭/人数不足/已解散」→ 立刻离房，
  1.5 秒后重新找房；另加兜底——在房里 **5 分钟无任何牌局动静**（`state.lastTableAt`）就主动离房重进，防服务端不推事件。
- 需重启 worker 生效；只改 `agent-client/client.js`，后端未动。
