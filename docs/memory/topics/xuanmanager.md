- 根目录 `XuanManager/`，Go 标准库后端、React/Vite 前端，同源提供构建产物。接口依据 `XuanManager/新后台管理系统接口文档.md`，实时房间另读 `大厅所有房间列表Web接口文档.md`。

## 权限和身份：以最终规则为准

- 菜单隐藏不是鉴权，每个接口独立校验。后台用户与游戏玩家分开。
- 2026-08-16 起，**超级管理员功能能力与受保护根账号身份分开**：能力按 super_admin 角色并兼容旧标记；隐私隐藏仅针对代码精确指定的根账号，不能隐藏所有 super_admin。其他超级管理员的业务能力及正常审计可见性保留。具体受保护账号标识查现行后端，专题不复制账号信息。
- 受保护账号归属被隐藏时不可回退更早审计而错误归因；按用户列表、统计、审计、历史、详情与写接口分别核验。玩家 IP/GPS 等敏感信息查看不等同普通超级管理员能力。
- 房间维护及平台收益是超级管理员专属；发牌优化 create/update/delete 则按对应角色权限，不恢复历史超级管理员硬限制。
- 后台密码最终规则为至少 6 个 Unicode 字符，bcrypt 最多 72 字节；不用早期至少 7 位或强制字符组合规则，不把示例密码存进文档。

来源：原记忆第 114–118、171、177–178、195–198 行。

## 统计、金额和时间的权威来源

- 2026-08-16 时间统一北京时间，但按字段来源转换：mgr_ 默认时间/审计等来源为 UTC；游戏业务字符串已是北京时间；Unix 时间按时区渲染。禁止全局加 8 小时或贸然修改数据库连接时区。今日新增用 Go 生成北京时间日界，不依赖曾返回 UTC 的 CURDATE()。
- 金币完整流水为 `usr_cash_water`，不合并同构辅助表。钱包真实变动用 `new_money - old_money`；add_money 在部分业务中不是收支方向。消费前后余额也用 old_money/new_money，“余X分”不是总余额。
- remark 字段按 option_type 解释。结算场景码不是金额/局数/时长；客服加减分原因在 mgr_audit_log，不在游戏流水 remark 中，关联必须匹配玩家、余额、方向和有限时间窗。
- 房间最终输赢优先“结算返还－累计带入”，无结算才回退原始战绩；保留差异标记。历史地九王用 `usr_total_score.remark` 索引 10，不能混用大厅压缩数组索引。牌谱映射与阶段解析查原协议。
- 代理链直属上级优先注册关系 upper_guuid，账号 sm_agentID 冲突要标记；MySQL 5.7 不依赖递归 CTE，遍历有层数/条数上限并声明截断。红利账户汇总以 sm_all_hongli/sm_use_hongli/sm_hongli 除 100；同一正向红利不能把两张来源表重复相加，缺失提取明细要展示差额而非补造记录。
- 工作台仅累计玩家、今日新增、今日登录；`kbe_entitylog` 残留实体和离线也能返回的属性均不是实时在线证据。权威在线接口未提供前不恢复在线数/峰值曲线。
- 平台净收益历史口径：大厅普通抽水＋奖池中奖折扣＋玩家消费＋提现手续费－普通代理红利－奖池代理红利－抽奖池转入，充值手续费暂不计。游戏表只读不加索引，查询最多 31 天、单并发、4 秒超时；缓存自有表。普通抽水按结算键去重，消费排除“延长时间”。

来源：原记忆第 108–110、121–131、153、194、197–199 行。精确字段与枚举按接口文档/当前代码再次核对。

## 有副作用流程的契约

- 长期公告保存纯文本空白，仅统一 CRLF/CR 为 LF，全空白才清空。游戏 `usr_hash_info` 的系统公告继续兼容客户端 `btoa(encodeURIComponent(content))`。历史实测表为 MyISAM，ROLLBACK 不会撤销；使用原行快照、写后全量回读和按原 ID 显式恢复。
- 支付配置按通道维护各自 bank 字段及客户端 Base64 JSON，不新增另套后台银行权威表。防并发修订摘要、MyISAM 快照恢复不可删；RowsAffected=0 不代表不存在，不能据此插入重复键。
- 即时通知与轮播使用普通通知协议，不恢复旧 ####“系统广播”前缀；英文逗号处理须兼容旧客户端分段。轮播只有正式实例启唯一工作器，本地和候选明确关闭，避免重复全服发送。失败重试当前条目，不直接跳过。
- 实时房间只从专用“查询_大厅_所有房间”协议获取，失败清空，不从账号 roomID 或历史战绩拼出幽灵房间。解散 cmd 为纯命令字符串，不是嵌套 JSON；接受码仅代表受理，复查确已消失/终态才 verified=true，未确认返回 202。全部操作分页枚举逐房，不能向 room_id=0 发伪命令。
- 玩家加减分只改变账号金币，不改当前牌桌带入分；在房也可加减，不能恢复 PLAYER_IN_ROOM 拦截。仍有权限、整数、基准余额、原因、显式确认、限额、写后回读和审计；签名仅在受控运行配置。
- 发牌优化只更新 sm_optimize01_man/count/chance 三白名单字段，独立本机连接、InnoDB 事务、FOR UPDATE、页面基准、回读一致后提交；不依赖在线，不调用只改在线实体的通用属性命令。旧“胡牌优化”字段不查不改；原因已非必填，仍保留权限与审计。
- 注册昵称与登录账号的唯一性跨相关表校验，规范化比较；昵称串行锁、账号唯一索引兜底。邀请上级链检测循环/断链，人数按完整关系重算，不做易重复的缓存 +1。头像选择写入有游戏账号创建时序，客户端暂存/服务端补写闭环不能删。历史“20/100 头像”等范围有演进，接续前查当前代码，不按旧上限改回。

来源：原记忆第 132–136、159–162、172、174–186、189–193 行。

先核对本地目标文件、当前接口文档、实际迁移和线上只读状态。常规候选验证包含 Go test/vet、前端 lint/最后源码修改后的生产构建、静态 Linux 产物、上传前后 SHA-256、候选健康与未授权访问、相关登录态只读回读。不能用首页 200 代替权限和业务正确性；通知/加减分/解散/支付等真实写操作不因“验收”而自动执行。
