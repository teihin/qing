- 项目为 Cocos Creator 2.4.13、8 座四川扑克“扯弦/丁二黄”，不是牌九。历史设计分辨率为 960×640、fitHeight=true；最新页面布局要再核对实际场景，不能据此覆盖 V7 竖屏配置。
- 正常启动：`login.fire → StartGameManager → GameDataManager → panelUpdate → panelLogin → panelMain → drh8.fire`。`login - 001.fire` 是测试/备用场景。`settings/project.json` 和 `settings/builder.json` 的目标需在构建前重新确认。
- 脚本入口：`assets/scripts/GameDataManager.ts`（会话、登录、心跳、重连和导航）；`common/UIManager.ts`（动态 UI）；`UI/panelMain.ts`（大厅）；`UI/panelGameView.ts`（牌桌）；`logic/DrhLogicMgr.ts`（全房状态）；`logic/DrhPlayerLogic.ts`（座位）；`logic/DrhNameManager.ts`（牌型）；`kbe_scripts/kbengine.js` 和 `Account.js`（协议）；`mobile/MobileManager.ts`（原生桥）。
- **服务端权威**：客户端展示与发送操作，不能自行决定胜负、下注合法性、金币、VIP、支付或提现。修改字段、事件名、中文命令、动作编码前同步核对协议；本仓库没有完整游戏服务端。
- `PlayerList` 是全量快照，`状态鸡` 是逐座位增量；房间外层状态约为 `init → ready → running → end`。特殊动作编码：跟 -1、敲 -3、休 -5、滚 -6、丢 -7，不擅自重编号。

## 必须保留的状态与异步契约

### 普通重连与踢线（2026-08-12）

普通断网、连接失败、心跳超时继续原重连。明确收到 `onKicked` 后停止重连、作废排队中的异步登录、停止心跳/超时检测，将提示留在常驻管理器并重载 login；用户主动登录才解除停止状态。服务端重启也可能发同一事件，不能统一宣称“其他设备登录”。缓存账号信息的处理沿用既有逻辑，不因换肤改变。

来源：原记忆第 144 行；历史未完成两设备互踢、服务器重启及房内踢线全矩阵。

### 排队、预坐与换房（2026-08-12～15）

- 先读根目录 `排队撮合功能接口文档.md`，定位常驻 `QueueMatchManager`、`panelQueueMatch`、`roomTransition.fire`。管理器统一持有申请/取消/查询、`QueueMatchInfo`、目标房/座位/queue_id 与切换代次；撮合导航回包由协调器独占消费。
- 异房换房必须先成功退房，再经过 `roomTransition` 销毁旧 drh8，进入目标房并加载全新 drh8。**结算后即使 account.roomID 已清空，只要当前仍是 drh8，也必须走过渡场景**，不能复用旧牌桌。
- 结算首次申请排队要完整 `reqStopGame()+reqLeaveRoom()`，成功退房后再用保存的原房号申请；不能拿“起立”替代退房。原房缓存按账号隔离，踢线清理。已经确认退房后的取消/重申请才能复用该事实。
- 预坐可以在收到目标房 `onEnterRoom` 成功后、场景加载完成前发送，这是锁座顺序，不是越过入房。新视图通过 `onRoomViewReady()`重放预约并请求 PlayerList；冷加载超过锁座时限仍需真实测试。
- 2026-08-15 后的规则：目标房 PlayerList 确认本人位于预定座位，即作为预坐成功的权威事实，立即清除本地排队/切房展示，同时保留预约消费迟到回包。它替代“PlayerList 先到只标记、必须再等命令回包”的旧规则。
- 不让迟到成功回包把 selecting/submitting 倒退为 waiting，也不在用户取消带入后重新武装。预坐失败留在新房继续排队，等待服务端再分配，不自重试同一 queue_id/座位。
- 看门狗限定撮合导航，绑定 switchGeneration；超时先查询对账，重连废弃旧命令/场景回调。不能顺带改普通进房与全局重连。
- 已有队列再次打开只展示/查询；“已经排队”等权威回包仅窄范围恢复 queued，普通余额不足等失败不可吞掉。名单查询只展示，不能触发切房。

来源：原记忆第 259、514–522、544–545 行。检索词：`QueueMatchManager`、`playerListConfirmed`、`switchGeneration`、`beginTargetRoomTransition`、`queue_pre_site`。

## 其他易丢业务约束

- 房间邀请（2026-08-14）：V2 协议带权威最低带入，接收和点击前都核验 `gold + gold2/100`。已坐、预坐、正在带入不弹；PlayerList 占座立即关弹窗。观战换房走现有过渡，排队先取消。180 秒冷却按账号/房间保存；“本次登录不再弹出”仅会话有效。详见原记忆第 69–71 行、`RoomInviteManager`。
- 金币赠送沿用 Account RPC `调用_方法_Exchange2`，金额为大于 0 的整数字符串，不乘除 100，不改为 HTTP。2026-09-04 V7 大厅入口已从页内直接读取交易密码并取消二次弹窗；第 322 行“先查名字再确认”的旧说明不能覆盖这一入口的新流程。服务端成功清空输入/刷新记录，失败保留输入。详见第 54、322–323 行及 V7 专题。
- 头像异步（2026-07-23）：PlayerList 缺 photo 时新绑定座位仍刷新服务端；每个 Sprite 保留最新期望序号，缓存、成功与失败回调均检查序号，避免默认头像迟到覆盖。不要用服务端返回的默认值推断 Sprite 串用。详见第 442–444 行。
- 苹果网页 GPS（2026-08-14）：真实坐标合法才提交；坐下检查不等待定位、不自动续做，无合法坐标就保留提示并结束本次操作。不能提交伪造坐标或靠历史缓存放行。Native 和非苹果网页分支保持各自行为。详见第 101–102 行。
- Web 加载（2026-08-14）：`WebLoadingManager`/`WebSceneLoader` 只管浏览器；并发任务合并、过期预加载受代次约束、失败保留旧界面。实时头像/音效等保持静默。第二段登录进度绑定可见 fileLabel，不能误用已隐藏的 byteLabel。详见第 79、86–89 行。
- 历史浏览器 WSS 与 Native WS 分支分开；浏览器端口白名单和未知端口拒绝降级仍需保留。历史某端口握手成功不能等同当前登录、BaseApp 切换和重连通过。详见第 75 行。
