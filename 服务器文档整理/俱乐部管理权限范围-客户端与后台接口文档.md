## 1. 通用说明

### 1.1 通道

| 调用方 | 通道 | 执行身份 |
| --- | --- | --- |
| 游戏客户端 | `reqHallCommand(param, context)` | 当前登录账号 |
| 后台 | `POST /hall/command` | 固定 `Hall.boss` |

### 1.2 授权模型

| 账号 | 判定 | 范围 |
| --- | --- | --- |
| 平台 boss | `level>=99` 或 `d_users` 的 `boss`/`bigboss` | 全平台，不依赖授权字段 |
| 授权账号 | `union_manage` 含联盟号，或 `club_manage` 含俱乐部号 | 对应联盟内全部俱乐部 / 对应独立俱乐部 |

```text
可管理俱乐部 C ⇔ C ∈ club_manage
               或 C.union_id ∈ union_manage
               或 是平台 boss

可管理联盟 U ⇔ U ∈ union_manage
             或 U.owner_guuid == 我
             或 是平台 boss
```

**范围内权利与平台 boss 一致**，不区分查看 / 修改 / 发放。例外：联盟红利提取仅总群主本人；平台级资金命令不下放（§4）。

### 1.3 账号属性

| 属性 | 类型 | 客户端可见 | 说明 |
| --- | --- | --- | --- |
| `club_manage` | `UNICODE` | 是 | 已有。逗号分隔的俱乐部号，表示可管理的独立俱乐部 |
| `union_manage` | `UNICODE` | 是 | **新增**。逗号分隔的联盟号，表示可管理的联盟 |

两个属性都是 `BASE_AND_CLIENT`，自动随账号实体下发，**客户端不需要新增协议**。

格式为字符串，不是数组：

```text
club_manage  = "984470,710701"
union_manage = "310521"
```

未授权时为空串 `""`。

### 1.4 返回码

| 情况 | `ret_code` | `ret_result` |
| --- | --- | --- |
| 成功（同步命令） | `0x200` | `{}` 或命令自定义 JSON |
| 失败 | `0x301` | `{"error":"..."}` |
| 异步命令受理 | `0x500` | 后续走推送 / 后台等待 |

### 1.5 客户端界面判断

| 条件 | 建议显示 |
| --- | --- |
| `union_manage != ""` | "我管理的联盟"入口；联盟列表取这些联盟号 |
| `club_manage != ""` | "我管理的俱乐部"入口；俱乐部列表取这些俱乐部号 |
| 两者都为空且不是平台 boss | 不显示平台管理入口（与现状一致） |

一个账号可以同时有两者，界面取并集。

> 授权联盟时**只下发联盟号**，不展开成员俱乐部。客户端展示联盟下有哪些俱乐部仍走 `查询_我的_联盟`。
> 授权独立俱乐部时下发俱乐部号，客户端"我管理的俱乐部"直接可用。

## 2. 新增后台命令：`异步_设置_俱乐部_管理范围`

### 2.1 用途

平台 boss 给某个账号设置/取消可管理的联盟与俱乐部。按字段更新：不传该字段 = 保持原值，传 `[]` = 清空该类授权，传非空列表 = 覆盖该类授权。两个字段都不传才报参数错误。

### 2.2 请求

下面是"两类都设置"的完整示例；只改一类时**省略另一个字段**，不要补 `[]`。

```json
{
  "header": "异步_设置_俱乐部_管理范围",
  "guuid": "430994",
  "union_ids": ["310521"],
  "club_ids": ["984470"],
  "context": "grant-001"
}
```

| 字段 | 必填 | 类型 | 说明 |
| --- | --- | --- | --- |
| `guuid` | 是 | string | 目标账号 guuid |
| `union_ids` | 否 | array / string | 可管理的联盟号；也接受 `"310521,310522"`；**不传 = 保持原值**，传 `[]` = 清空 |
| `club_ids` | 否 | array / string | 可管理的俱乐部号；格式同上；**不传 = 保持原值**，传 `[]` = 清空 |
| `context` | 否 | string | 原样回传 |

> 两个字段至少传一个（可以传 `[]` 表示清空）；都不传返回参数错误。
>
> **不要为了"格式完整"给不需要改的字段补 `[]`**：那会清空该账号原有的该类授权。

### 2.3 返回

```json
{
  "guuid": "430994",
  "union_manage": "310521",
  "club_manage": "984470",
  "context": "grant-001"
}
```

| 字段 | 说明 |
| --- | --- |
| `guuid` | 目标账号 |
| `union_manage` | 写入后的联盟号字符串（逗号分隔，按请求顺序去重） |
| `club_manage` | 写入后的俱乐部号字符串 |
| `context` | 原样回传 |

### 2.4 错误

| 情况 | `ret_code` | `ret_result` |
| --- | --- | --- |
| 非平台 boss | `0x301` | `{"error":"无权限"}` |
| `guuid` 为空或非数字 | `0x301` | `{"error":"玩家ID非法"}` |
| 账号不存在 | `0x301` | `{"error":"玩家不存在"}` |
| 联盟不存在 | `0x301` | `{"error":"联盟不存在: 310521"}` |
| 俱乐部不存在 | `0x301` | `{"error":"俱乐部不存在: 984470"}` |
| 两个参数都没传 | `0x301` | `{"error":"请传 union_ids 或 club_ids"}` |

校验顺序：权限 → `guuid` → 逐项校验号存在 → 取账号实体 → 写入。**任一号不存在则整笔不写**。

### 2.5 调用示例

只加联盟授权（不动原有俱乐部授权）：

```json
{
  "header": "异步_设置_俱乐部_管理范围",
  "guuid": "430994",
  "union_ids": ["310521"],
  "context": "grant-union-001"
}
```

只加独立俱乐部授权（不动联盟授权）：

```json
{
  "header": "异步_设置_俱乐部_管理范围",
  "guuid": "430994",
  "club_ids": ["984470"],
  "context": "grant-club-001"
}
```

取消全部授权：

```json
{
  "header": "异步_设置_俱乐部_管理范围",
  "guuid": "430994",
  "union_ids": [],
  "club_ids": [],
  "context": "revoke-001"
}
```

### 2.6 审计

本次请求涉及、且值确实发生变化的字段各写一条 `usr_attr_info`（未传的字段不写）：

| 字段 | 值 |
| --- | --- |
| `user_guuid` / `user_name` | 目标账号 |
| `attr_name` | `union_manage` / `club_manage` |
| `old_attr_value` | 修改前字符串 |
| `new_attr_value` | 修改后字符串 |
| `remark` | `授权范围设置` |
| `option_type` | `保存` |

### 3.1 无协议变化

所有现有命令的**请求参数、返回结构、推送 router 全部不变**。变化只在服务端身份判断：授权账号在范围内会被当作"总群主 / 俱乐部创建者"同等对待。

### 3.3 错误文案

| 场景 | 文案 |
| --- | --- |
| 非管理者访问成员/代理/收益 | `无权访问` |
| 非本俱乐部成员操作积分 | `只能操作自己下线的成员` |
| 联盟不存在或无权 | `你还没有联盟` |
| 联盟审批越权 | `只有总群主可以审批` |
| 授权账号提取联盟红利 | `联盟红利需总群主本人提取` |
| 授权账号配置范围外奖池 | `你无权管理该奖池` |
| 授权账号查所有玩家/代理不传 club_id | `请指定俱乐部` |

### 3.4 `查询_我的_联盟` 对授权账号的返回

授权账号调用时，`union_id` 为其 `union_manage` 中的联盟，`members` 为该联盟下所有已加载俱乐部，字段与总群主调用完全一致。

多联盟边界：账号被授权多个联盟时，本命令返回 `union_manage` 中第一个存在的联盟。需要查看其它联盟的命令由客户端显式传 `union_id`。

## 4. 平台级命令（授权账号仍被拒绝）

| 命令 | 说明 |
| --- | --- |
| `增加_联盟_额度` | 平台向联盟池注资 / 扣减 |
| `增加_俱乐部_额度` | 平台调整俱乐部额度 |
| `增加_俱乐部_钻石` | 平台调整群主钻石池 |
| `异步_增加_玩家_钻石` | 平台直接加玩家钻石 |
| `异步_设置_玩家_属性` | 后台专用属性写入 |
| 奖池业绩结算报表等 `_isBackendAccount` 命令 | 后台专用 |

理由：这些是"平台对运营主体的资金/配置操作"，不是联盟或俱乐部内部管理。授信（在联盟池内分配）已下放，注资（池子来源）不下放。

## 5. 后台侧范围控制（后台必读）

### 5.1 服务端无法区分后台管理员

后台 `/hall/command` 固定以 `Hall.boss` 执行，服务端拿不到"当前登录后台的是谁"。因此：

- 后台权限必须由后台自己控制：登录态 → 角色/权限 → 每次调用前校验目标 `club_id` / `union_id` / `user_id` 在范围内；
- 只在前端隐藏按钮不够，后端必须在发起 `/hall/command` 前做校验；
- 服务端对这些后台命令不做额外范围拦截。

### 5.2 建议的校验规则

```text
1. 从后台会话取当前管理员的可管理范围（union_id / club_id 列表）
2. 解析本次请求的目标：
   - 带 club_id：要求 club_id 在范围内
   - 带 union_id：要求 union_id 在范围内
   - 两者都没有（全量列表）：按范围逐个查询，或直接拒绝
3. 不满足返回后台自己的 403，不要发到游戏服
```

### 5.3 授权后如何验证

```sql
select sm_guuid, sm_union_manage, sm_club_manage
from tbl_Account where sm_guuid = '430994';
```

目标账号在线时，设置命令已 `writeToDB` 并更新实体；若在线于另一 baseapp，建议让其重登一次。

### 5.4 审计

- 授权动作：`usr_attr_info`（§2.6）；
- 授权账号的业务操作：沿用 `club_history_info.opter_guuid` / `opter_name`；
- 后台自身的操作审计（谁点的授权）由后台侧记录。

## 6. 客户端联调清单

| # | 步骤 | 预期 |
| --- | --- | --- |
| 1 | 平台 boss 调 `异步_设置_俱乐部_管理范围`，给账号 A 授权联盟 U | 返回 `union_manage="U"` |
| 2 | A 登录 | 账号属性中 `union_manage` 为 `"U"` |
| 3 | A 打开"我管理的联盟" | 显示 U；`查询_我的_联盟` 返回 U 的俱乐部列表 |

| 6 | A 打开"我管理的俱乐部" | 只显示 `club_manage` 中的俱乐部（联盟授权不展开） |
| 7 | A 尝试访问范围外俱乐部 | 按现有文案拒绝 / 空列表 |
| 8 | 平台 boss 取消授权 | A 重新登录后入口消失，属性为空 |
| 9 | 只传 `union_ids`、不传 `club_ids` | 原 `club_manage` 保持不变 |
| 10 | A 调用 `提取_联盟_红利` | 拒绝：`联盟红利需总群主本人提取` |
| 11 | A 调用 `查询_俱乐部_所有_玩家` 且不传 `club_id` | 返回 `请指定俱乐部` |
| 12 | A 查授信记录、联盟红利统计/明细 | 正常返回总群主口径数据，不是"无权限"或空 |
