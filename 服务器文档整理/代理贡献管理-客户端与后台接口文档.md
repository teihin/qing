# 代理贡献管理 — 客户端与后台接口文档

> 更新时间：2026-11-05
> 范围：后台「代理贡献管理」页面、客户端成员列表展示标记、KBE 展示规则接口。
> 原则：客户端和后台调用**同一个成员数据接口**，由 KBE 按调用者身份返回真实值或展示值；后台只下发规则，不在本地重算折扣。

---

## 一、读取成员数据

### 1.1 命令

沿用现有命令：

```text
查询_俱乐部_成员
```

后台通过 `GET /hall/command` 调用（`Hall.boss` 身份），KBE 返回**真实值**；客户端正常登录调用，KBE 返回**展示值**。

### 1.2 请求参数

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `club_id` | string | 是 | 俱乐部 ID |
| `agent_id` | string | 否 | 要展开的代理/玩家 ID；空表示俱乐部创建者 |
| `user_id` | string | 否 | 后台固定传 `ALL` |
| `page` | string/int | 否 | 页码，从 1 开始 |
| `count` | string/int | 否 | 每页数量，后台最大 200 |
| `context` | string | 否 | 后台操作上下文，原样返回 |

### 1.3 响应

沿用 `NumberList` 推送/返回结构。后台读取时建议在 `ret_result.NumberList` 或 `ret_result.result` 中返回行数组；后台会兼容数组、`NumberList`、`result` 等常见包裹。

每行沿用现有字段：

| 字段 | 说明 |
| --- | --- |
| `user_id` / `guuid` | 玩家 ID |
| `name` / `user_name` | 昵称 |
| `role` / `is_agent` / `is_leader` | 身份 |
| `upper_guuid` | 直属上级 ID |
| `team_count` | 整条下线人数 |
| `total_contrib_fen` | 累计贡献（分，真实值给后台） |
| `total_score` | 累计输赢（积分，真实值给后台） |
| `percent` | 代理比例 |

新增规则字段（建议 KBE 在每行下发；后台和客户端都会兼容）：

```json
{
  "contrib_display_rule": {
    "mode": "percent",          // none / percent / fixed
    "percent": 80,              // percent 模式
    "delta": 0,                 // fixed 模式，贡献单位分
    "source": "self",           // self / inherit / global / none
    "source_agent_id": "1001",  // 继承来源代理
    "source_agent_name": "A",
    "sim": true                 // 是否为模拟展示
  },
  "score_display_rule": {
    "mode": "fixed",
    "delta": 20000,             // fixed 模式，输赢单位积分
    "source": "inherit",
    "source_agent_name": "A",
    "sim": true
  }
}
```

也兼容平铺字段：`contrib_display_mode`、`contrib_display_percent`、`contrib_display_delta`、`contrib_display_source`、`contrib_display_source_agent_id`、`contrib_display_source_agent_name`、`contrib_display_sim`；`score_` 同理。

## 二、规则命令

以下命令为后台专用，建议只允许 `level >= 99` 调用。

### 2.1 查询规则

```text
查询_代理_展示规则
```

参数：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `club_id` | 是 | 俱乐部 ID |
| `agent_id` | 是 | 代理/玩家 ID |
| `metric` | 是 | `contrib` 或 `score` |
| `context` | 否 | 后台操作上下文 |

返回示例：

```json
{
  "ret_code": 512,
  "ret_result": {
    "club_id": "710701",
    "agent_id": "1001",
    "metric": "contrib",
    "rule": {
      "mode": "percent",
      "percent": 80,
      "source": "self",
      "sim": true
    }
  }
}
```

### 2.2 设置规则

```text
设置_代理_展示规则
```

参数：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `club_id` | 是 | 俱乐部 ID |
| `agent_id` | 是 | 代理/玩家 ID |
| `metric` | 是 | `contrib` 或 `score` |
| `mode` | 是 | `percent` 或 `fixed` |
| `percent` | 比例模式必填 | 0~100 整数 |
| `delta` | 固定模式必填 | 贡献单位分，输赢单位积分；正数表示调低，负数表示调高 |
| `note` | 是 | 调整原因，2~200 字 |
| `operator` | 否 | 后台操作人 |
| `context` | 否 | 后台操作上下文 |

语义：

- 规则按 `(club_id, agent_id, metric)` 保存。
- 某代理自身有规则时，本人及整条下级线默认使用该规则。
- 下级有单独规则时，以下级自己的规则为准。
- 删除规则即恢复上级规则；上级也没有则回落到全局展示折扣/真实值。
- 比例模式：`展示 = 真实 × percent / 100`；贡献向下取整，输赢按绝对值取整后保留符号。
- 固定模式：`展示 = 真实 - delta`；贡献最小为 0，输赢保留正负。
- 规则只影响展示值，不影响结算、钱包、额度、提取和后台真实报表。

返回：`ret_code = 512` 即成功；建议在 `ret_result.rule` 中回显最终生效规则，便于后台回读。

### 2.3 取消规则

```text
取消_代理_展示规则
```

参数：`club_id`、`agent_id`、`metric`、`context`。

成功后该代理该指标恢复上级规则；没有上级规则时展示真实值。

## 三、后台接口

后台新增以下路由（XuanManager）：

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/game/agent-contributions/clubs/{clubId}/members?agentId=&page=&pageSize=` | `game.agent_contribution.view` | 按俱乐部/代理逐层读取成员与真实数据 |
| GET | `/api/game/agent-contributions/clubs/{clubId}/agents/{agentId}/rule?metric=` | `game.agent_contribution.view` | 查询单个指标规则 |
| PUT | `/api/game/agent-contributions/clubs/{clubId}/agents/{agentId}/rule` | `game.agent_contribution.adjust` | 设置规则 |
| DELETE | `/api/game/agent-contributions/clubs/{clubId}/agents/{agentId}/rule?metric=` | `game.agent_contribution.adjust` | 恢复上级规则 |

后台菜单：`游戏管理 → 代理贡献管理`（模块 `game.agent_contributions`，迁移 `045_agent_contributions.sql`）。左侧按联盟分组，未入盟俱乐部单独一组；右侧按代理逐层展开，表格同时显示真实值和按当前规则估算的展示值。

设置/取消都会写 `mgr_audit_log`，动作 `game.agent_contribution.adjust`，记录俱乐部、代理、指标、模式、参数、原因和结果。

## 四、客户端标记

客户端继续调用原命令，不新增客户端接口。KBE 对客户端返回展示值；客户端识别以下任意一种模拟标记后，在成员列表的「总贡献」「总输赢」值后加 `*`，统计栏显示「含模拟*」，并在首次出现时提示：

> 带 * 的数据为模拟展示，不代表真实账目

客户端兼容的标记字段：

- 通用：`display_adjusted`、`display_sim`、`is_display_adjusted`、`show_adjusted`、`display_type`、`display_flag`、`is_simulated`、`simulated`
- 贡献：`contrib_display_sim`、`contrib_sim`、`total_contrib_sim`、`total_contrib_simulated`、`total_contrib_is_sim`、`contrib_display_percent`、`contrib_display_delta`
- 输赢：`score_display_sim`、`score_sim`、`total_score_sim`、`total_score_simulated`、`total_score_is_sim`、`score_display_percent`、`score_display_delta`
- 规则对象：`display_rule`、`display_rules`、`contrib_display_rule`、`score_display_rule`

如果 KBE 使用其它字段名，只需在 `assets/scripts/UI/ClubManagementApi.ts` 的 `optionalSimFlags` 中补充别名。

## 五、验收

1. 后台选择联盟 → 俱乐部，逐层展开代理与玩家，能看到真实总贡献、真实总输赢。
2. 给 A 设置比例 80%，A 及整条下级线客户端展示为真实的 80%，并带 `*`。
3. 给 B 单独设置固定差额，B 线按 B 的规则；C 仍按 A。
4. 取消 B 的规则，B 线恢复 A 的规则。
5. 真实值从 10 万涨到 12 万：比例 80% 展示从 8 万变 9.6 万；固定差额 2 万展示从 8 万变 10 万。
6. 后台真实值、结算、钱包、额度、提取流水不受影响。
7. 没有规则时客户端不出现 `*`，数值与改动前一致。
