# 代理贡献管理 — 客户端与后台接口文档

> 更新时间：2026-11-05
> 范围：后台「代理贡献管理」页面、客户端成员列表展示标记、KBE 展示规则接口。
> 原则：客户端和后台调用**同一个成员数据接口**，由 KBE 按调用者身份返回真实值或展示值；后台只下发规则，不在本地重算折扣。

---

## 一、读取成员数据

### 1.1 命令

后台使用统一 `异步_` 命名的后台命令：

```text
异步_查询_俱乐部_成员
```

后台通过 `GET /hall/command` 调用（`Hall.boss` 身份），在 `ret_result.NumberList` 返回**真实值 + `*_contrib_display_fen` 展示值**。客户端仍使用 `查询_俱乐部_成员` 的异步推送 `NumberList`，拿到展示值，不受影响；后台不要再调用客户端命令。

### 1.2 请求参数

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `club_id` | string | 是 | 俱乐部 ID |
| `agent_id` | string | 否 | 要展开的代理/玩家 ID；空表示俱乐部创建者 |
| `user_id` | string | 否 | 后台固定传 `ALL` |
| `show_type` | string | 否 | `all` / `union` / `member`；后台联盟级用 `union`，俱乐部级用 `member` |
| `page` | string/int | 否 | 页码，从 1 开始 |
| `count` | string/int | 否 | 每页数量，最大 500 |
| `context` | string | 否 | 后台操作上下文，原样返回 |

### 1.3 响应

沿用 `NumberList` 推送/返回结构。后台读取时建议在 `ret_result.NumberList` 或 `ret_result.result` 中返回行数组；后台会兼容数组、`NumberList`、`result` 等常见包裹。

每行沿用现有字段：

| 字段 | 说明 |
| --- | --- |
| `user_id` / `guuid` | 玩家 ID |
| `name` / `user_name` | 昵称 |
| `role` / `is_agent` / `is_leader` | 身份 |
| `club_id` | 该行所属俱乐部；**盟主虚拟行是盟主自己的俱乐部，不等于父俱乐部** |
| `upper_guuid` | 直属上级 ID |
| `team_count` | 整条下线人数 |
| `today_contrib_fen` / `yesterday_contrib_fen` / `total_contrib_fen` | 今日/昨日/累计贡献（分，真实值给后台） |
| `today_contrib_display_fen` / `yesterday_contrib_display_fen` / `total_contrib_display_fen` | 今日/昨日/累计展示贡献（分，2026-11-05 新增） |
| `today_score` / `yesterday_score` / `total_score` | 今日/昨日/累计输赢（积分，真实值给后台） |
| `today_score_display` / `yesterday_score_display` / `total_score_display` | 今日/昨日/累计展示输赢（积分，2026-11-06 新增） |
| `show_percent` | 该行代理实际生效的展示比例（0~100，未设置默认 100） |

XuanManager 在成员接口回包上额外补两个字段，用于区分“自己设置 / 继承 / 未设置”：

| 字段 | 说明 |
| --- | --- |
| `ownShowPercent` | 该行在 `club_agent_info.show_percent` 里的**自己的值**；null=没有单独设置 |
| `showPercentSource` | `self`=自己设置；`inherit`=自己未设置、按上级继承；`default`=自己及上级都未设置、默认 100；空=游戏服未返回 `show_percent` |
| `club_gold` / `gold` | 俱乐部积分 / 账号积分 |
| `quota` | 俱乐部额度（分，后台按 ÷100 显示元） |
| `percent` | 代理比例 |
| `status` / `note` / `dark_percent` | 在线状态 / 备注 / 暗扣比例（-1 表示无） |

`ret_result` 顶层还会带 `agent_income_show_percent`（该目标代理的展示比例，100 表示真实值）。

新增规则字段（建议 KBE 在每行下发；后台和客户端都会兼容）：

```json
{
  "contrib_display_rule": {
    "mode": "percent",          // none / percent / fixed
    "percent": 80,              // percent 模式
    "delta": 0,                 // fixed 模式，贡献单位分
    "source": "self",           // self / inherit / global / none
    "source_agent_id": "1001",  // 继承来源代理
    "source_agent_name": "A",
    "sim": true                 // 是否为模拟展示
  },
  "score_display_rule": {
    "mode": "fixed",
    "delta": 20000,             // fixed 模式，输赢单位积分
    "source": "inherit",
    "source_agent_name": "A",
    "sim": true
  }
}
```

也兼容平铺字段：`contrib_display_mode`、`contrib_display_percent`、`contrib_display_delta`、`contrib_display_source`、`contrib_display_source_agent_id`、`contrib_display_source_agent_name`、`contrib_display_sim`；`score_` 同理。

## 二、规则命令

以下命令为后台专用，建议只允许 `level >= 99` 调用。

### 2.1 查询规则

```text
查询_代理_展示规则
```

参数：`club_id`、`agent_id`、`metric`（`contrib` 或 `score`）、`context`。

返回示例：

```json
{
  "ret_code": 512,
  "ret_result": {
    "club_id": "775447",
    "agent_id": "718968",
    "metric": "contrib",
    "agent_income_show_percent": 100,
    "effective_show_percent": 50,
    "display_fields": ["today_contrib_fen", "yesterday_contrib_fen", "total_contrib_fen"],
    "context": "admin-get"
  }
}
```

- 规则按代理一份，存 `club_agent_info.show_percent`；
- `agent_income_show_percent` 是该代理**自己**的值（未设置/非代理=100），用于设置表单回显；
- `effective_show_percent` 是**实际生效**值：自己设置优先，未设置时沿直属上级就近继承，到根仍无则 100；
- `metric` 当前固定 `contrib`，原样回显。

### 2.2 查询代理展示数据（2026-11-05 新增）

```text
异步_查询_代理_展示数据
```

参数：`club_id`、`agent_id`、`metric`（`contrib` 或 `score`）、`context`。

返回示例：

```json
{
  "ret_code": 512,
  "ret_result": {
    "club_id": "775447",
    "agent_id": "718968",
    "metric": "contrib",
    "agent_income_show_percent": 80,
    "self_raw":     {"today_score":"0","yesterday_score":"-4","total_score":"-4","today_contrib_fen":"0","yesterday_contrib_fen":"60","total_contrib_fen":"60"},
    "self_display": {"today_score":"0","yesterday_score":"-4","total_score":"-4","today_contrib_fen":"0","yesterday_contrib_fen":"60","total_contrib_fen":"60"},
    "team_raw":     {"today_score":"0","yesterday_score":"355","total_score":"355","today_contrib_fen":"0","yesterday_contrib_fen":"1645","total_contrib_fen":"1645","team_count":"2"},
    "team_display": {"today_score":"0","yesterday_score":"355","total_score":"355","today_contrib_fen":"0","yesterday_contrib_fen":"1645","total_contrib_fen":"1645","team_count":"2"}
  }
}
```

- `self_*` 是该代理本人，`team_*` 是该代理 + 整条下线；后台表格用 `team_*`。
- 2026-11-06 起，`team_display` / `self_display` 的**输赢和贡献都按 `show_percent` 缩放**（示例为 100%，所以 raw/display 相同）；成员列表以外玩家输赢不缩放。
- **`club_id` 必须用该行自己的 `row["club_id"]`**；盟主虚拟行（`is_leader=1`）的 `club_id` 是盟主自己的俱乐部，用父俱乐部会返回「代理不存在」。
- `is_leader` 行可以直接用成员行已有的 `today/yesterday/total_score`、`today/yesterday/total_contrib_fen`、`team_count`。

### 2.3 设置规则

```text
设置_代理_展示规则
```

参数：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `club_id` | 是 | 俱乐部 ID |
| `agent_id` | 是 | 该俱乐部 `status=used` 的代理；创建者始终允许 |
| `mode` | 否 | 仅 `percent`（缺省） |
| `percent` | 是 | 0~100；100=真实值，0=全部显示 0 |
| `metric` | 否 | 原样回显，当前固定 `contrib` |
| `note` / `operator` | 否 | 写入服务端审计 |
| `context` | 否 | 原样返回 |

约束：

- 只支持 percent；实测 `mode=fixed` 返回 `769：mode 仅支持 percent`；
- `percent=101` 返回 `769：展示比例必须在 0~100 之间`；
- 规则按代理一份，**自己设置优先；未设置时沿直属上级就近继承；不支持整线一键覆盖/取消恢复**；
- 下级单独设置后以自己的值为准；要“恢复继承”当前只能继续设置一个与上级相同的值，或联系 KBE 补取消命令；
- 只影响成员列表的贡献和输赢展示；成员列表以外的玩家输赢、积分、人数、比例不缩放；
- 规则只影响展示，不影响结算、钱包、额度、提取和后台真实报表；
- 设置成功返回 `agent_income_show_percent`，后台应回读确认。

### 2.4 恢复真实值

最新方案没有 `取消_代理_展示规则`。恢复真实值直接调用 `设置_代理_展示规则`：

```json
{"club_id":"775447","agent_id":"718968","mode":"percent","percent":100,"note":"恢复真实值","context":"admin-reset"}
```

## 三、后台接口

后台新增以下路由（XuanManager）：

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/game/agent-contributions/clubs/{clubId}/members?agentId=&showType=&page=&pageSize=` | `game.agent_contribution.view` | 按俱乐部/代理逐层读取成员、真实值和 `*_contrib_display_fen`；`showType=union/member` 对应联盟级/俱乐部级 |
| POST | `/api/game/agent-contributions/clubs/{clubId}/display-data` | `game.agent_contribution.view` | 批量查询 1~50 个代理的 `self/team` 原始值和展示值；请求体 `{"items":[{"agentId":"1001","clubId":"267493"}]}`，每个 `clubId` 用该行自己的俱乐部 |
| GET | `/api/game/agent-contributions/clubs/{clubId}/agents/{agentId}/rule?metric=` | `game.agent_contribution.view` | 查询单个指标规则 |
| PUT | `/api/game/agent-contributions/clubs/{clubId}/agents/{agentId}/rule` | `game.agent_contribution.adjust` | 设置规则 |
| DELETE | `/api/game/agent-contributions/clubs/{clubId}/agents/{agentId}/rule?metric=` | `game.agent_contribution.adjust` | 恢复真实值（内部调用设置 100%，不是取消继承） |

后台菜单：`游戏管理 → 代理贡献管理`（模块 `game.agent_contributions`，迁移 `045_agent_contributions.sql`）。左侧按联盟分组，未入盟俱乐部单独一组；右侧按代理逐层展开，表格同时显示真实值和游戏服返回的展示值（贡献取 `*_contrib_display_fen`，输赢取 `异步_查询_代理_展示数据` 的 `team_display`）。展示数据查询和规则设置都使用**当前行自己的 `club_id`**；盟主虚拟行不会再用父俱乐部 ID 去查。

设置/取消都会写 `mgr_audit_log`，动作 `game.agent_contribution.adjust`，记录俱乐部、代理、指标、模式、参数、原因和结果。

## 四、客户端标记

客户端继续调用原命令，不新增客户端接口。KBE 对客户端返回展示值；客户端识别以下任意一种模拟标记后，在成员列表的「总贡献」「总输赢」值后加 `*`，统计栏显示「含模拟*」，并在首次出现时提示：

> 带 * 的数据为模拟展示，不代表真实账目

客户端兼容的标记字段：

- 通用：`display_adjusted`、`display_sim`、`is_display_adjusted`、`show_adjusted`、`display_type`、`display_flag`、`is_simulated`、`simulated`
- 贡献：`contrib_display_sim`、`contrib_sim`、`total_contrib_sim`、`total_contrib_simulated`、`total_contrib_is_sim`、`contrib_display_percent`、`contrib_display_delta`
- 输赢：`score_display_sim`、`score_sim`、`total_score_sim`、`total_score_simulated`、`total_score_is_sim`、`score_display_percent`、`score_display_delta`
- 规则对象：`display_rule`、`display_rules`、`contrib_display_rule`、`score_display_rule`

如果 KBE 使用其它字段名，只需在 `assets/scripts/UI/ClubManagementApi.ts` 的 `optionalSimFlags` 中补充别名。

## 五、验收

1. 后台选择联盟 → 俱乐部，逐层展开代理与玩家，能看到真实总贡献、真实总输赢，以及逐行生效的 `show_percent`；规则列标出「自设 / 继承 / 未设置」。
2. 给代理 A 设置 80%，A 自己的成员行贡献和输赢展示为真实的 80%；A 的下级未单独设置时继承 80%；代理 B 整条线未设置仍为 100%。
3. 真实贡献/输赢从 10 万涨到 12 万：A 的展示从 8 万自动变 9.6 万，不需要重新设置。
4. 设置 100% 后 A 恢复真实值（注意：这是 A 自己的 100%，不会再继承上级）。
5. 后台真实值、结算、钱包、额度、提取流水不受影响；成员列表以外的玩家输赢不缩放。
6. 当前支持“自己设置 + 上级继承”，没有整线一键覆盖、取消继承和固定差额；这些场景不验收。
7. 客户端模拟标识字段尚未由 KBE 下发；若产品仍要求明确标识，需要 KBE 增加标记字段。
