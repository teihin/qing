# 俱乐部成员与代理展示 — 后台接口文档

> 面向新后台/运营工具（HTTP `/hall/command`），用于同步查询俱乐部成员、代理展示规则与代理展示数据。
> 客户端原有 `查询_俱乐部_成员` 仍是“只推送 + 返回 `{}`”，**本文档不会改变客户端行为**。
> 状态：2026-11-05 实现，需重启 baseapp 生效。

---

## 一、背景与通道

`查询_俱乐部_成员` 是客户端推送型命令：服务端发起异步 SQL 后立即返回 `0x500`，数据通过 `NumberList` 推给调用者客户端。HTTP 后台没有对应客户端，所以 `ret_result` 永远是 `{}`。

后台改用以下命令（走 `/hall/command`）：

| 命令 | 类型 | 用途 |
| --- | --- | --- |
| `异步_查询_俱乐部_成员` | 异步（HTTP 会等待结果） | 成员列表，字段与客户端 `NumberList` 对齐 |
| `异步_查询_代理_展示数据` | 异步 | 代理自己/团队的今日、昨日、累计输赢与贡献 |
| `查询_代理_展示规则` | 同步 | 当前展示折扣规则（全局一份） |

> **命令命名**：查库命令统一加 `异步_` 前缀，和项目现有 `异步_查询_奖池业绩_结算报表` 等一致；HTTP/玩家两个入口只按名字里的“异步”判断，不再维护额外白名单。
> `查询_代理_展示规则` 不查库，保持同步，不加前缀。

**权限**：仅 `Hall.boss` 或 `level >= 99` 账号可调用；普通客户端调用返回 `0x301`。
**分页**：`page` **从 1 开始**（与客户端 0 基不同）；`count` 限制 1~500。
**视图**：`agent_id` 是本次要看的代理节点；为空=俱乐部创建者。后台管理员视角**不要求调用者在代理树内**；普通客户端仍按自己的子树校验。

### 1.1 后台需要改的 header

| 后台原调用 | 改为 |
| --- | --- |
| `查询_俱乐部_成员` | `异步_查询_俱乐部_成员` |
| `查询_俱乐部_成员_展示`（若已接入） | `异步_查询_俱乐部_成员` |
| `查询_代理_展示数据` | `异步_查询_代理_展示数据` |
| `查询_代理_展示规则` | 不变 |

> `查询_俱乐部_成员` **不再做 HTTP 转义**：HTTP 调它仍是客户端推送命令的 `0x500/{}`。后台必须使用上表的新 header。
> 客户端 `查询_俱乐部_成员` 不受影响。

## 二、异步_查询_俱乐部_成员

### 2.1 请求

```json
{
  "header": "异步_查询_俱乐部_成员",
  "club_id": "984470",
  "agent_id": "430994",
  "user_id": "ALL",
  "page": 1,
  "count": 200,
  "context": "xuan-agent-contribution-xxx"
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `club_id` | 是 | 俱乐部 ID |
| `agent_id` | 否 | 要查看的代理节点；空=俱乐部创建者 |
| `user_id` | 否 | `ALL`（默认，列表）或具体成员 ID |
| `show_type` | 否 | `all`（默认，联盟+成员）/ `union`（仅联盟盟主虚拟行）/ `member`（仅本俱乐部成员）；兼容 `0/1/2` |
| `page` | 否 | 1 基，默认 1；小于 1 按 1 |
| `count` | 否 | 每页条数，默认 20，最大 500 |
| `context` | 否 | 原样回传 |

### 2.2 返回

`ret_code = 512`，`ret_result` 为 JSON 字符串，结构与客户端 `NumberList` 对齐：

```json
{
  "NumberList": [
    {
      "number": "0",
      "count": "123",
      "guuid": "430994",
      "name": "代理昵称",
      "club_id": "984470",
      "gold": "1000",
      "club_gold": "500",
      "role": "代理",
      "is_agent": "1",
      "is_leader": "0",
      "quota": "0",
      "percent": "10",
      "note": "",
      "team_count": "12",
      "today_score": "100",
      "yesterday_score": "200",
      "total_score": "300",
      "today_score_display": "80",
      "yesterday_score_display": "160",
      "total_score_display": "240",
      "today_contrib_fen": "100",
      "yesterday_contrib_fen": "200",
      "total_contrib_fen": "300",
      "today_contrib_display_fen": "80",
      "yesterday_contrib_display_fen": "160",
      "total_contrib_display_fen": "240",
      "show_percent": "80",
      "status": "在线",
      "dark_percent": "5"
    }
  ],
  "number": "0",
  "count": "123",
  "context": "xuan-agent-contribution-xxx",
  "page": 1,
  "club_id": "984470",
  "agent_id": "430994",
  "agent_income_show_percent": 80
}
```

- `NumberList` 行字段与客户端一致，后台额外返回 `show_percent` 和 `*_display` 字段（客户端 `NumberList` 不含这些）；
- `today_contrib_fen` / `yesterday_contrib_fen` / `total_contrib_fen` 和 `today_score` / `yesterday_score` / `total_score` 是**真实值**；
- 额外下发 `*_contrib_display_fen` / `*_score_display`，为按该行**生效** `show_percent` 缩放后的展示值；
- `number` 是客户端口径的 0 基页号，`page` 是后台口径的 1 基页号；
- `show_percent` 是该行继承后的生效百分比（自己设置优先，未设置沿上级继承，缺省 100）。

> **`show_type` 三态用途**：
> - `all`（默认）：联盟+成员；盟主虚拟行的 `club_id` 是盟主自己的俱乐部，后台按行查代理数据必须用 `row.club_id`，不能用父俱乐部的 `club_id`；
> - `union`：仅联盟盟主虚拟行，不输出本俱乐部成员；盟主行只在第 0 页出现，`count` 为盟主行数；
> - `member`：仅本俱乐部成员，不再返回盟主虚拟行；后台按成员行逐条调用 `异步_查询_代理_展示数据` 时建议传 `member`。

## 三、异步_查询_代理_展示数据

### 3.1 请求

```json
{
  "header": "异步_查询_代理_展示数据",
  "club_id": "984470",
  "agent_id": "430994",
  "metric": "contrib",
  "context": "xuan-probe"
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `club_id` | 是 | 俱乐部 ID |
| `agent_id` | 否 | 代理 ID；空=俱乐部创建者 |
| `metric` | 否 | 原样回传，默认 `contrib`（当前同时返回输赢与贡献） |
| `context` | 否 | 原样回传 |

### 3.2 返回

```json
{
  "club_id": "984470",
  "agent_id": "430994",
  "metric": "contrib",
  "agent_income_show_percent": 80,
  "self_raw": {
    "today_score": "11", "yesterday_score": "22", "total_score": "33",
    "today_contrib_fen": "44", "yesterday_contrib_fen": "55", "total_contrib_fen": "66"
  },
  "self_display": {
    "today_score": "11", "yesterday_score": "22", "total_score": "33",
    "today_contrib_fen": "35", "yesterday_contrib_fen": "44", "total_contrib_fen": "52"
  },
  "team_raw": {
    "today_score": "10", "yesterday_score": "20", "total_score": "30",
    "today_contrib_fen": "100", "yesterday_contrib_fen": "200", "total_contrib_fen": "300",
    "team_count": "5"
  },
  "team_display": {
    "today_score": "10", "yesterday_score": "20", "total_score": "30",
    "today_contrib_fen": "80", "yesterday_contrib_fen": "160", "total_contrib_fen": "240",
    "team_count": "5"
  },
  "context": "xuan-probe"
}
```

- `self_*`：该代理自己的 `club_member_score_info` 数据；
- `team_*`：该代理 + 整条下线的汇总（`team_count` 不含自己）；
- `raw` 为真实值，`display` 为按展示百分比缩放后的贡献值；输赢不缩放；
- 单位：分成/贡献均为**分**，前端展示自行 `/100`。

## 四、查询_代理_展示规则

### 4.1 请求

```json
{
  "header": "查询_代理_展示规则",
  "club_id": "984470",
  "agent_id": "430994",
  "metric": "contrib",
  "context": "xuan-probe"
}
```

### 4.2 返回

```json
{
  "club_id": "984470",
  "agent_id": "430994",
  "metric": "contrib",
  "agent_income_show_percent": 80,
  "display_fields": ["today_contrib_fen", "yesterday_contrib_fen", "total_contrib_fen"],
  "context": "xuan-probe"
}
```

- 规则当前是**全局一份**（`usr_hash_info` 的 `agent_income_show_percent`，缺省 100）；
- 只缩放“贡献/收益”类字段，输赢、积分、人数不缩放；
- 该命令同步执行，不查库（只做参数/俱乐部/代理校验）。

## 五、错误码

| 情况 | ret_code | ret_result |
| --- | --- | --- |
| 成功 | 512 | 上述 JSON |
| 无权访问 | 769 | `{"error":"无权访问"}` |
| 俱乐部不存在 | 769 | `{"error":"俱乐部不存在"}` |
| 代理不存在 | 769 | `{"error":"代理不存在"}`；常见于用父 `club_id` 查盟主虚拟行（`is_leader=1`，该行 `club_id` 是盟主自己的俱乐部）→ 改用 `row.club_id` 或传 `show_type=member` |
| 代理树加载中 | 769 | `{"error":"代理数据加载中，请重试"}` |
| `user_id` 非法 | 769 | `{"error":"user_id 非法"}` |
| 查询失败 | 769 | `{"error":"成员查询失败"/"代理数据查询失败"}` |
| 用旧 header（`查询_俱乐部_成员_展示` / `查询_代理_展示数据`） | 769 | 命令未注册 |

> 代理树加载中是启动/首次查询的瞬时状态，后台重试即可。
> `查询_俱乐部_成员` 仍是客户端推送命令，后台不要再用它取数据。

## 六、实现说明

- 新命令实现于 `scripts/base/Hall.py`：
  - `_actQueryClubMemberDisplay` / `_actQueryAgentDisplayData` / `_actQueryAgentDisplayRule`；
  - 两个查库命令统一用 `异步_` 前缀，`_httpHallCommand` 与 `reqHallCommand` 只按名字里的“异步”判断，不维护额外白名单/别名；
- 成员列表复用现有客户端 `NumberList` 拼包逻辑（假账号捕获，不复制字段），仅新增 `*_display_fen` 和后台元数据；
- 统计口径复用 `club_member_score_info` 和 `Club._calcMemberTeamStats`；
- 无 DDL、无配置键、无客户端协议变更；客户端 `查询_俱乐部_成员` 仍是原推送逻辑；
- **需重启 baseapp 生效**。
