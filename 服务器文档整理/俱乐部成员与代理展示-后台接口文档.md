# 俱乐部成员与代理展示 — 后台接口文档

> 面向新后台/运营工具（HTTP `/hall/command`），用于同步查询俱乐部成员、代理展示规则与代理展示数据。
> 客户端原有 `查询_俱乐部_成员` 仍是“只推送 + 返回 `{}`”，**本文档不会改变客户端行为**。
> 状态：2026-11-06 修订为“就近继承”并已上线验证（build .19）。

---

## 一、背景与通道

`查询_俱乐部_成员` 是客户端推送型命令：服务端发起异步 SQL 后立即返回 `0x500`，数据通过 `NumberList` 推给调用者客户端。HTTP 后台没有对应客户端，所以 `ret_result` 永远是 `{}`。

后台改用以下命令（走 `/hall/command`）：

| 命令 | 类型 | 用途 |
| --- | --- | --- |
| `异步_查询_俱乐部_成员` | 异步（HTTP 会等待结果） | 成员列表，字段与客户端 `NumberList` 对齐 |
| `异步_查询_代理_展示数据` | 异步 | 代理自己/团队的今日、昨日、累计输赢与贡献 |
| `查询_代理_展示规则` | 同步 | 指定代理**自己的值** + **继承后的生效值** |
| `设置_代理_展示规则` | 同步 | 按 `club_id + agent_id` 设置该代理的展示比例 |

> **命令命名**：查库命令统一加 `异步_` 前缀，和项目现有 `异步_查询_奖池业绩_结算报表` 等一致；HTTP/玩家两个入口只按名字里的“异步”判断，不再维护额外白名单。
> `查询_代理_展示规则` 不查库，保持同步，不加前缀。

**权限**：仅 `Hall.boss` 或 `level >= 99` 账号可调用；普通客户端调用返回 `0x301`。`查询_代理_展示规则` / `设置_代理_展示规则` 仅 `game_mode=club` 可用，大厅模式返回 `0x301`。
**分页**：`page` **从 1 开始**（与客户端 0 基不同）；`count` 限制 1~500。
**视图**：`agent_id` 是本次要看的代理节点；为空=俱乐部创建者。后台管理员视角**不要求调用者在代理树内**；普通客户端仍按自己的子树校验。

### 1.1 后台需要改的 header

| 后台原调用 | 改为 |
| --- | --- |
| `查询_俱乐部_成员` | `异步_查询_俱乐部_成员` |
| `查询_俱乐部_成员_展示`（若已接入） | `异步_查询_俱乐部_成员` |
| `查询_代理_展示数据` | `异步_查询_代理_展示数据` |
| `查询_代理_展示规则` | 不变 |

> `查询_俱乐部_成员` **不再做 HTTP 转义**：HTTP 调它仍是客户端推送命令的 `0x500/{}`。后台必须使用上表的新 header。
> 客户端 `查询_俱乐部_成员` 不受影响。

### 1.2 继承规则与显示规则列（后台对接必读）

生效值按成员向上就近继承：

1. 成员自己设置了 `show_percent` → 用自己；
2. 自己没有设置/不是代理 → 沿直属上级找最近的已设置代理；
3. 到根都没有 → `100`。

举例：`abc11` 设 50，下级普通玩家 `a2` 未设置 → `a2` 的输赢/贡献也按 50%；若 `a2` 后来成为代理并设 80，则 `a2` 及其下级按 80。

| 后台场景 | 使用字段 |
| --- | --- |
| 成员列表“显示规则”列 | 行级 `show_percent`（继承后的生效值）或 `查询_代理_展示规则.effective_show_percent`；**不要**用 `agent_income_show_percent` |
| “设置规则”弹窗回显 | `查询_代理_展示规则.agent_income_show_percent`（自己的值） |
| 成员行展示输赢/贡献 | `*_score_display` / `*_contrib_display_fen`（已按生效值缩放）；raw 字段保持真实 |
| “设置规则”按钮 | 只有代理（含创建者）可设置；普通玩家没有自己的值、只能继承，后台应对非代理行隐藏/禁用按钮 |

> 多俱乐部：后台每行都带自己的 `club_id` 查询，规则按该俱乐部节点取，不使用账号级“第一个 used 节点”兜底。
>
> 降级边界：游戏服成员接口不可用、后台回退到俱乐部关系树时，规则只读 `club_agent_info` 里的**自己的值**，不读继承值；此模式下统计/展示值本身为空，不会出现数值与比例矛盾。

### 1.3 客户端已验证行为（build .19）

- 成员列表“显示规则”列读行级 `show_percent`（继承后的生效值），与缩放后的输赢/贡献一致；
- 设置弹窗输入回显 `查询_代理_展示规则.agent_income_show_percent`（自己的值），摘要展示 `effective_show_percent`；
- 普通玩家行不显示“设置规则”按钮；后端仍会校验，手工构造请求返回“该成员还不是代理”，不会写库；
- 后台每行按自己的 `club_id` 查询，不依赖账号级多俱乐部兜底。

## 二、异步_查询_俱乐部_成员

### 2.1 请求

```json
{
  "header": "异步_查询_俱乐部_成员",
  "club_id": "984470",
  "agent_id": "430994",
  "user_id": "ALL",
  "page": 1,
  "count": 200,
  "context": "xuan-agent-contribution-xxx"
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `club_id` | 是 | 俱乐部 ID |
| `agent_id` | 否 | 要查看的代理节点；空=俱乐部创建者 |
| `user_id` | 否 | `ALL`（默认，列表）或具体成员 ID |
| `show_type` | 否 | `all`（默认，联盟+成员）/ `union`（仅联盟盟主行，含总群主自己）/ `member`（仅本俱乐部成员）；兼容 `0/1/2` |
| `page` | 否 | 1 基，默认 1；小于 1 按 1 |
| `count` | 否 | 每页条数，默认 20，最大 500 |
| `context` | 否 | 原样回传 |

### 2.2 返回

`ret_code = 512`，`ret_result` 为 JSON 字符串，结构与客户端 `NumberList` 对齐：

```json
{
  "NumberList": [
    {
      "number": "0",
      "count": "123",
      "guuid": "430994",
      "name": "代理昵称",
      "club_id": "984470",
      "gold": "1000",
      "club_gold": "500",
      "role": "代理",
      "is_agent": "1",
      "is_leader": "0",
      "quota": "0",
      "percent": "10",
      "note": "",
      "team_count": "12",
      "today_score": "100",
      "yesterday_score": "200",
      "total_score": "300",
      "today_score_display": "80",
      "yesterday_score_display": "160",
      "total_score_display": "240",
      "today_contrib_fen": "100",
      "yesterday_contrib_fen": "200",
      "total_contrib_fen": "300",
      "today_contrib_display_fen": "80",
      "yesterday_contrib_display_fen": "160",
      "total_contrib_display_fen": "240",
      "today_bonus_fen": "0",
      "yesterday_bonus_fen": "0",
      "total_bonus_fen": "0",
      "status": "在线",
      "dark_percent": "5",
      "bonus_dark_percent": 10,
      "show_percent": 80
    }
  ],
  "number": "0",
  "count": "123",
  "context": "xuan-agent-contribution-xxx",
  "page": 1,
  "club_id": "984470",
  "agent_id": "430994",
  "agent_income_show_percent": 80
}
```

- 基础字段与客户端 `NumberList` 对齐；后台行另加 `show_percent`、`*_display`、`bonus_dark_percent` 等扩展字段（客户端报文不含）；
- `today_contrib_fen` / `yesterday_contrib_fen` / `total_contrib_fen` 是**真实值**；
- 额外下发 `*_score_display` / `*_contrib_display_fen`，为按**该行成员的生效 `show_percent`** 缩放后的输赢/贡献展示值；raw 字段保持真实；生效规则是“自己优先、未设置沿上级就近继承、根上仍无=100”；
- 每行额外下发 `show_percent`（int，0~100），是该行**实际生效**的展示比例（含继承）：成员自己设置优先，否则取最近上级代理，无则 100；盟主行按盟主自己俱乐部节点；后台可直接展示，客户端 `NumberList` 不含该字段；
- 每行额外下发 `bonus_dark_percent`（int，0~100；未设置=0；按 `row.club_id` 取；`-1`=该俱乐部代理树未加载，web 显示“-”并重试）；仅本后台接口返回，游戏客户端 `NumberList` 不含该字段；
- **2026-11-06 客户端新增 `stat_scope=line|self`（仅单成员 `user_id` 查询生效）**：后台 `异步_查询_俱乐部_成员` 当前不解析该参数，固定按 `line` 返回；因此新增的 `today_bonus_fen` / `yesterday_bonus_fen` / `total_bonus_fen` 在后台行中恒为 `"0"`（客户端单成员 `self` 才会有本人红利）。后台如需本人口径，需后续给异步命令补 `stat_scope` 并复用同一逻辑；
- `number` 是客户端口径的 0 基页号，`page` 是后台口径的 1 基页号；
- 2026-11-07 起凡返回红利（`*_bonus_fen`）的接口均为扣完红利暗抽后的净额；本后台成员行红利仍恒 `"0"`。
- 顶层 `agent_income_show_percent` 是本次被查 `agent_id` 的**生效**展示百分比（自己优先、上级就近继承，默认 100）。

> **`show_type` 三态用途**：
> - `all`（默认）：联盟+成员；盟主虚拟行的 `club_id` 是盟主自己的俱乐部，后台按行查代理数据必须用 `row.club_id`，不能用父俱乐部的 `club_id`；红利暗抽也按该口径取；
> - `union`：仅联盟盟主行，不输出本俱乐部成员；**总群主自己排第一行**（`is_leader=1`、`club_id` 为自己的俱乐部），其后是联盟内其它盟主；盟主行只在第 0 页出现，`count` 为盟主行数；
> - `member`：仅本俱乐部成员，不再返回盟主虚拟行；后台按成员行逐条调用 `异步_查询_代理_展示数据` 时建议传 `member`。

## 三、异步_查询_代理_展示数据

### 3.1 请求

```json
{
  "header": "异步_查询_代理_展示数据",
  "club_id": "984470",
  "agent_id": "430994",
  "metric": "contrib",
  "context": "xuan-probe"
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `club_id` | 是 | 俱乐部 ID |
| `agent_id` | 否 | 代理 ID；空=俱乐部创建者 |
| `metric` | 否 | 原样回传，默认 `contrib`（当前同时返回输赢与贡献） |
| `context` | 否 | 原样回传 |

### 3.2 返回

```json
{
  "club_id": "984470",
  "agent_id": "430994",
  "metric": "contrib",
  "agent_income_show_percent": 80,
  "bonus_dark_percent": 10,
  "self_raw": {
    "today_score": "11", "yesterday_score": "22", "total_score": "33",
    "today_contrib_fen": "44", "yesterday_contrib_fen": "55", "total_contrib_fen": "66"
  },
  "self_display": {
    "today_score": "8", "yesterday_score": "17", "total_score": "26",
    "today_contrib_fen": "35", "yesterday_contrib_fen": "44", "total_contrib_fen": "52"
  },
  "team_raw": {
    "today_score": "10", "yesterday_score": "20", "total_score": "30",
    "today_contrib_fen": "100", "yesterday_contrib_fen": "200", "total_contrib_fen": "300",
    "team_count": "5"
  },
  "team_display": {
    "today_score": "8", "yesterday_score": "16", "total_score": "24",
    "today_contrib_fen": "80", "yesterday_contrib_fen": "160", "total_contrib_fen": "240",
    "team_count": "5"
  },
  "context": "xuan-probe"
}
```

- `self_*`：该代理自己的 `club_member_score_info` 数据；
- `team_*`：该代理 + 整条下线的汇总（`team_count` 不含自己）；
- 顶层 `agent_income_show_percent` 是该 `agent_id` 的**生效值**（自己优先、未设置沿上级就近继承、根上仍无=100）；
- 顶层 `bonus_dark_percent` 是该 `agent_id` 自己的红利暗抽比例（int，0~100；未设置=0），不参与 `show_percent` 缩放；
- `raw` 为真实值，`display` 为按生效百分比缩放后的输赢与贡献值；`team_count` 不缩放；
- 单位：分成/贡献均为**分**，前端展示自行 `/100`。

## 四、查询_代理_展示规则（按代理）

### 4.1 请求

```json
{
  "header": "查询_代理_展示规则",
  "club_id": "984470",
  "agent_id": "430994",
  "metric": "contrib",
  "context": "xuan-probe"
}
```

### 4.2 返回

```json
{
  "club_id": "984470",
  "agent_id": "430994",
  "metric": "contrib",
  "agent_income_show_percent": 100,
  "effective_show_percent": 50,
  "display_fields": ["today_contrib_fen", "yesterday_contrib_fen", "total_contrib_fen"],
  "context": "xuan-probe"
}
```

- `agent_income_show_percent` 是**该 `agent_id` 自己**的 `club_agent_info.show_percent`；未设置（NULL）/非代理返回 `100`，用于“设置规则”表单回显；
- `effective_show_percent` 是该代理实际生效值（自己优先、未设置沿上级就近继承、根上仍无=100），用于展示；成员列表行级 `show_percent` 也是这个值。示例表示该代理自己未设置、但上级设置了 50；
- `mode` 目前固定 `percent`；影响输赢、贡献和收益类展示字段；积分、人数、比例不缩放；
- 该命令同步执行，不查库（只做参数/俱乐部/代理校验，读代理树内存）。

## 五、设置_代理_展示规则

### 5.1 请求

```json
{
  "header": "设置_代理_展示规则",
  "club_id": "984470",
  "agent_id": "430994",
  "metric": "contrib",
  "mode": "percent",
  "percent": 80,
  "note": "运营调整",
  "operator": "admin999",
  "context": "xuan-set-rule"
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `club_id` | 是 | 俱乐部 ID |
| `agent_id` | 是 | 目标代理；必须是本俱乐部 `status=used` 的代理，创建者始终允许 |
| `mode` | 否 | 仅 `percent`（缺省） |
| `percent` | 是 | `0~100` 的整数 |
| `note` / `operator` | 否 | 写入服务端 `usr_attr_info` 审计备注 |
| `context` | 否 | 原样返回 |

### 5.2 返回

```json
{
  "club_id": "984470",
  "agent_id": "430994",
  "metric": "contrib",
  "mode": "percent",
  "percent": 80,
  "agent_income_show_percent": 80,
  "effective_show_percent": 80,
  "context": "xuan-set-rule"
}
```

- 设置立即更新代理树内存，并异步 `UPDATE club_agent_info SET show_percent=...`；
- 设置/回显的是该代理**自己的值**；设置后 `effective_show_percent` 通常等于自己的值（自己的值优先于上级继承）；
- 未设置/设置 `100` 都表示该代理及未单独设置的下级看真实值；
- 审计写 `usr_attr_info`，`attr_name='agent_income_show_percent'`，备注含俱乐部、代理、operator、note；
- 只有 `Hall.boss` / `level>=99` 可调用；普通客户端返回 `0x301`。

## 六、错误码

| 情况 | ret_code | ret_result |
| --- | --- | --- |
| 成功 | 512 | 上述 JSON |
| 无权访问 | 769 | `{"error":"无权访问"}` |
| 俱乐部不存在 | 769 | `{"error":"俱乐部不存在"}` |
| 代理不存在 | 769 | `{"error":"代理不存在"}`；常见于用父 `club_id` 查盟主虚拟行（`is_leader=1`，该行 `club_id` 是盟主自己的俱乐部）→ 改用 `row.club_id` 或传 `show_type=member` |
| 代理树加载中 | 769 | `{"error":"代理数据加载中，请重试"}` |
| `user_id` 非法 | 769 | `{"error":"user_id 非法"}` |
| 设置比例非法 | 769 | `{"error":"展示比例必须在 0~100 之间"/"展示比例必须是整数"}` |
| 目标不是代理 | 769 | `{"error":"该成员还不是代理"}` |
| `mode` 非 percent | 769 | `{"error":"mode 仅支持 percent"}` |
| 查询失败 | 769 | `{"error":"成员查询失败"/"代理数据查询失败"}` |
| 用旧 header（`查询_俱乐部_成员_展示` / `查询_代理_展示数据`） | 769 | 命令未注册 |

> 代理树加载中是启动/首次查询的瞬时状态，后台重试即可。
> `查询_俱乐部_成员` 仍是客户端推送命令，后台不要再用它取数据。

## 六、实现说明

- 新命令实现于 `scripts/base/Hall.py`：
  - `_actQueryClubMemberDisplay` / `_actQueryAgentDisplayData` / `_actQueryAgentDisplayRule`；
  - 两个查库命令统一用 `异步_` 前缀，`_httpHallCommand` 与 `reqHallCommand` 只按名字里的“异步”判断，不维护额外白名单/别名；
- 成员列表复用现有客户端 `NumberList` 拼包逻辑（假账号捕获，不复制字段），额外下发 `*_score_display` / `*_contrib_display_fen` / 行级 `show_percent`；
- 统计口径复用 `club_member_score_info` 和 `Club._calcMemberTeamStats`；
- 展示比例存储在 `club_agent_info.show_percent`（DDL），成员行按“自己优先、上级就近继承”生效；客户端 `查询_俱乐部_成员` 仍走原推送逻辑，但输赢/贡献数值会按生效比例缩放；
- **需重启 baseapp 生效**。
