## 1. 通用说明

### 1.1 通道与响应

- 后台 → 服务器：HTTP `GET http://127.0.0.1:8890/hall/command`，query 带 `header` + `param`（`param` 为 JSON 字符串，需 URL encode）；
- 内部脚本也可以走 `127.0.0.1:8890/hall/command`；**不要**把 `/beifeng/exec` 用于业务调用；
- 返回：`{"ret_code": 512, "ret_result": "<json 字符串>"}`；`ret_result` 是**字符串**，调用方要再 `JSON.parse` 一次；
- 失败体：`{"error":"<文案>"}`，`ret_code=769`；
- `context` 原样回传，建议每次调用带一个唯一值，便于日志对账。

本功能**不面向客户端**：没有客户端命令、没有推送、不改协议。牌桌内不提供入口。

### 1.2 鉴权

所有 8 条命令走同一套前置校验：

1. **模式**：`d_halls.game_mode == 'club'`（`Hall._isClubMode()`）；大厅模式返回 `{"error":"俱乐部功能未启用"}`；
2. **权限**：平台 boss（`opt_target_ctrl.IsBossOnly`，只认 `d_users.config["account"]["boss"]` 名单）；
3. **不开放** `union_manage` / `club_manage`（避免小 BOSS 互列名单），越权返回 `{"error":"无权限"}`；
4. 后台 HTTP 的调用者固定是 `Hall` 的 boss 账号（`self.boss` = `boss[0]`），天然通过。

> 名单 CRUD、导入、执行与查询配置使用同一权限，不做细分。

### 1.3 命令总表

| # | header | 用途 | 类型 |
| --- | --- | --- | --- |
| 1 | `查询_自动平衡_配置` | 读配置、今日计数、最近 Tick | 同步 |
| 2 | `设置_自动平衡_配置` | 改配置（全量或 patch） | 同步 |
| 3 | `查询_自动平衡_候选` | 规则 dry-run 视图 | 同步 |
| 4 | `执行_自动平衡` | 手动跑一次 / advice 落地 / 一键全停 | 同步 |
| 5 | `异步_查询_伙牌名单` | 名单与今日数据 | 异步 |
| 6 | `异步_设置_伙牌成员` | 批量加人/改备注 | 异步 |
| 7 | `异步_移除_伙牌成员` | 软删成员并停其 auto 目标 | 异步 |
| 8 | `异步_导入_伙牌名单` | 从现有玩家分组一次性导入 | 异步 |

实现文件：

- `scripts/server_common/auto_balance.py`：决策、名单、导入、日志；
- `scripts/base/Hall.py`：8 条命令注册与薄方法；
- `res/server/database.sql`：在 `call create_club_invite_code();` 之前新增 `usr_partner_team_member`、`usr_auto_balance_log` 建表。

### 1.4 本期实现边界（调用前必须知道）

| 项 | 说明 |
| --- | --- |
| 默认关闭 | 部署后 `enabled=false`、`mode=observe`，不会下发任何干预；要生效必须先改配置 |
| 压制默认只出建议 | `suppress.mode=advice`；`auto` 本期已实现，切换只改配置，不需要发版或热更 |
| 不推送 | 候选/进度/配置都要轮询；Tick 60 秒一次 |
| 名单缓存 | `team_guuids` 5 分钟刷新；名单 CRUD/导入成功后下一 Tick（≤60 秒）重载 |
| 目标不自动过期 | 沿用 `opt_target_ctrl`：达标结束、离房 600 秒、跨日、人工停；不会按时间过期 |
| 人工目标优先 | 玩家已有非 `auto_balance` 的 active 目标时，本模块跳过，不覆盖 |
| 同房名额 | 每房最多 1 个压制 + 1 个补偿（`max_per_room`），同房多目标按 `chance` 归一抽签 |
| 导入是快照 | 只加不删、不复活已移出成员；分组后续变动需重新导入 |
| 进度不重置 | 目标进行中再次设置会先结束旧目标，新目标进度从 0 开始 |
| 决策日志 | `usr_auto_balance_log` 为 P2；P0/P1 只有 `usr_opt_target_log` + 日志 |

## 2. 查询配置 `查询_自动平衡_配置`

### 2.1 请求

```json
{
  "header": "查询_自动平衡_配置",
  "context": "ab-cfg-001"
}
```

无业务参数。

### 2.2 返回

```json
{
  "cfg": {
    "enabled": false,
    "mode": "observe",
    "protect_exclude_guuids": [],
    "room_play_mode": "传销扯旋",
    "require_club_mode": true,
    "by_dipi": {},
    "protect": {
      "min_loss_score": 1500, "min_rounds": 10, "min_minutes": 15,
      "min_room_players": 3, "max_per_room": 1, "daily_max_times": 1,
      "cooldown_sec": 3600, "target_value": 600, "chance": 35, "min_today_loss": 0
    },
    "suppress": {
      "mode": "advice", "min_win_score": 2000, "min_rounds": 15,
      "min_victims": 2, "daily_max_times": 2, "cooldown_sec": 7200,
      "target_value": 1200, "chance": 40, "min_today_win": 0
    },
    "limits": {
      "max_active_total": 50, "max_set_per_tick": 5,
      "max_set_per_day": 200, "idle_stop_sec": 600
    }
  },
  "today": {"set_count": 12, "active": 3},
  "team": {"teams": 4, "members": 37},
  "last_tick": "2026-11-25 10:00:00"
}
```

| 字段 | 说明 |
| --- | --- |
| `cfg` | **生效值**：读取时已合并默认值、做过 clamp；写坏的值不会让接口报错，会在这里看到回退后的结果 |
| `today.set_count` | 今日已下发的 auto 目标数（含已结束） |
| `today.active` | 当前 active 的 auto 目标数 |
| `team` | 名单团队数与人数 |
| `last_tick` | 最近一次 Tick 完成时间；空串表示还没跑过 |

### 2.3 配置字段

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | `false` | 总开关；关掉时停掉全部 auto 目标 |
| `mode` | `observe` | `observe` 只算不下发 / `advice` 出建议 / `auto` 自动执行；**优先级最高** |
| `protect_exclude_guuids` | `[]` | 保护排除（大客户/测试号/运营号），不占名单表 |
| `room_play_mode` | `传销扯旋` | 只处理该 `play_mode` 的房间 |
| `require_club_mode` | `true` | 非俱乐部模式不工作 |
| `by_dipi` | `{}` | 按底皮覆盖，如 `{"底皮5/10": {"min_loss_score": 2000, "target_value": 800}}`；未知底皮回退全局值 |
| `protect.min_loss_score` | `1500` | 本周期净输达到该分数才扶；`0` 关闭保护 |
| `protect.target_value` | `600` | 固定目标分（正数） |
| `protect.chance` | `35` | 发牌命中概率 |
| `suppress.mode` | `advice` | `advice` 只出建议；`auto` 命中即下发 |
| `suppress.min_win_score` | `2000` | 本周期净赢达到该分数才压；`0` 关闭压制 |
| `suppress.target_value` | `1200` | 固定目标分（落库取负） |
| `suppress.chance` | `40` | 发牌命中概率 |
| `limits.max_active_total` | `50` | 全服 auto 目标并发上限 |
| `limits.max_set_per_tick` | `5` | 单次 Tick 下发上限 |
| `limits.max_set_per_day` | `200` | 全服每日下发上限 |
| `limits.idle_stop_sec` | `600` | 离房/离线多久后停止目标 |

> 数值合法性**在调用时约束**，保存时不做逐字段校验：`chance` 夹到 1~100、负阈值按 0、`target_value=0` 视为该规则不生效、`mode` 不在白名单按 `observe`。

## 3. 设置配置 `设置_自动平衡_配置`

### 3.1 请求

全量：

```json
{
  "header": "设置_自动平衡_配置",
  "cfg": {"enabled": true, "mode": "observe"},
  "context": "ab-cfg-set-001"
}
```

或 patch（只改传入的键，未传的保持原值）：

```json
{
  "header": "设置_自动平衡_配置",
  "patch": {"enabled": true, "suppress": {"mode": "auto"}, "protect": {"min_loss_score": 1800}},
  "context": "ab-cfg-set-002"
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `cfg` | object | 二选一 | 全量替换（未传的键回默认值） |
| `patch` | object | 二选一 | 深合并，只改传入的键 |
| `context` | string | 否 | 原样回传 |

### 3.2 返回

```json
{"ok": true, "cfg": {"enabled": true, "mode": "observe"}}
```

返回的是**写后生效值**（已合并默认值并 clamp）。写库是异步的（`usr_hash_info`），接口返回成功即表示内存已更新，进程重启后从库恢复。

## 4. 查询候选 `查询_自动平衡_候选`

### 4.1 请求

```json
{
  "header": "查询_自动平衡_候选",
  "room_id": 0,
  "limit": 100,
  "context": "ab-cand-001"
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `room_id` | int | 否 | `0`=全部房间；>0 只看该房 |
| `limit` | int | 否 | 默认 100，最大 500 |

### 4.2 返回

```json
{
  "list": [
    {
      "guuid": "718968", "nick": "abc11", "room_id": 564662,
      "init": 1000, "period_net": -1800, "rounds": 14, "seconds": 1260,
      "today_net": -2400, "team_name": "",
      "hit": 1, "action": "protect", "target_value": 600, "chance": 35,
      "has_target": 0, "existing_target_value": 0,
      "existing_target_man": "", "existing_target_time": "",
      "cooldown_left": 0
    },
    {
      "guuid": "496702", "nick": "abc12", "room_id": 564662,
      "init": 1000, "period_net": 2600, "rounds": 22, "seconds": 2400,
      "today_net": 3100, "team_name": "A组",
      "hit": 1, "action": "suppress", "target_value": -1200, "chance": 40,
      "has_target": 1, "existing_target_value": -800,
      "existing_target_man": "boss", "existing_target_time": "2026-11-26 10:00:00",
      "cooldown_left": 0
    }
  ]
}
```

| 字段 | 说明 |
| --- | --- |
| `period_net` | 本周期净输赢（正=赢、负=输），来自房间内存 |
| `rounds` | 本周期参与局数 |
| `seconds` | 本周期在座秒数 |
| `today_net` | 今日累计（`usr_total_score` 聚合）；`min_today_*` 都为 0 时返回 `null`（表示未开启日累计查询，页面显示“未开启”，不要当成 0） |
| `team_name` | 所在团队；空串=不在名单 |
| `hit` | 1=命中规则；0=未命中（仍返回，便于观察） |
| `action` | `protect` / `suppress` / `none` |
| `target_value` | **候选建议**的目标分（保护为正、压制为负）；不是已有目标的值 |
| `has_target` | 1=当前已有 active 目标（人工或 auto） |
| `existing_target_value` | 已有目标的实际值：正=补偿/正向，负=压制/负向；0=无或未知 |
| `existing_target_man` | 已有目标的设置人：`auto_balance`=自动平衡；其他=手工账号 guuid；空=未知 |
| `existing_target_time` | 已有目标的设置时间，如 `2026-11-26 10:00:00`；空=未知 |
| `cooldown_left` | 距冷却结束剩余秒数；0=可下发 |

> 示例里的 `today_net` 假设已开启日累计查询（`min_today_*` 非 0）；默认配置下该字段为 `null`。
>
> 默认排序：`room_id` 升序（`0` 最后）→ 同房内 `hit` 降序 → `action`（protect/suppress/none）→ `period_net`（保护按亏损大在前、压制按盈利大在前）→ `guuid`。只影响展示，不影响判定/名额。列表是**先排序后 `limit` 截断**；房间很多时建议按 `room_id` 过滤，避免后面房间的候选被截掉。

> `observe` 下这里就是"如果开自动会命中谁"；`advice` 下同一份数据就是建议列表。Tick 60 秒一次，两次请求之间数据不变。

### 4.3 XuanManager 展示改造要求（后台开发）

> 本次**只改游戏服返回字段**，不修改 XuanManager 源码；以下要求发给后台开发人员。

游戏服已新增：

```json
"has_target": 1,
"existing_target_value": 800,
"existing_target_man": "boss",
"existing_target_time": "2026-11-26 10:00:00"
```

XuanManager 的 `/api/game/auto-balance/candidates` 应**原样透传**这三个字段；如果后端有固定结构体，补上对应 JSON 字段即可，不需要改游戏服执行逻辑。

前端“状态”列建议：

| 条件 | 展示 |
|---|---|
| `has_target=0` | 按现有逻辑：`冷却 X 分 X 秒` / `可执行` / `—` |
| `has_target=1` 且 `existing_target_value > 0` | `已有目标（补偿 +800）` |
| `has_target=1` 且 `existing_target_value < 0` | `已有目标（压制 -1200）` |
| `has_target=1` 且 `existing_target_man='auto_balance'` | 追加 `· 自动` |
| `has_target=1` 且 `existing_target_man` 为其他非空值 | 追加 `· 手工` |
| `has_target=1` 且值为 0/来源为空 | `已有目标（方向未知）`，不要显示成可执行 |

示例：

```text
已有目标（补偿 +800 · 手工）
已有目标（压制 -1200 · 自动）
```

注意：

- `target_value` 是**候选建议值**，不是已有目标值；不能用它判断已有目标方向；
- `has_target=1` 时仍保持原来的勾选/执行禁用逻辑，不要因为展示改造放开执行；
- `existing_target_time` 可放在悬浮提示里，便于判断目标什么时候设的；
- 不需要新增接口，也不需要数据库字段。

### 4.4 动作下拉增加“未命中”选项（XuanManager 前端）

当前下拉只有“全部 / 补偿 / 压制 / 仅命中”。建议增加“未命中”：

```text
全部
仅命中
未命中
补偿
压制
```

前端筛选逻辑：

```js
// 未命中 = hit=0，不按 action 判断
g === "miss" ? f.filter(e => !e.hit) : ...
```

注意：

- `全部` 仍包含命中和未命中；
- `未命中` 只看 `hit=0`，不要写成 `action === "none"`，避免以后 action 语义变化；
- 这是 XuanManager 纯前端筛选，不需要改游戏服接口，也不需要新增服务端参数；
- 当前候选接口 `limit` 默认100、最大500；“未命中”只筛当前已拉取的列表，不是全服全量；
- 如果 XuanManager 后端有固定枚举，不要把 `miss` 加到服务端 action 枚举，它只是页面筛选值。

## 5. 执行 `执行_自动平衡`

### 5.1 请求

| action | 含义 | 参数 |
| --- | --- | --- |
| `run` | 手动触发一次 Tick（按当前 `mode`） | 无 |
| `run_guuids` | `advice` 落地：对指定玩家执行；**仅 `advice` / `auto` 可用，`observe` 拒绝** | `guuids`（逗号分隔） |
| `stop_all` | 停掉全部 auto 目标 | `remark` |

```json
{"header": "执行_自动平衡", "action": "run", "context": "ab-run-001"}
```

```json
{"header": "执行_自动平衡", "action": "run_guuids", "guuids": "718968,496702", "context": "ab-run-002"}
```

```json
{"header": "执行_自动平衡", "action": "stop_all", "remark": "运营一键停", "context": "ab-run-003"}
```

### 5.2 返回

```json
{
  "ok": [{"guuid": "718968", "action": "protect", "target_value": 600, "chance": 35}],
  "failed": [{"guuid": "496702", "error": "当前已不满足规则（period_net=1200）"}]
}
```

`run_guuids` 会**重新取快照复核**：玩家必须仍在房、当前净输赢仍命中、没有 active 目标；否则进 `failed`，不下发。

`stop_all` 的 `ok` 是已停止的 guuid 列表；没有 active 目标时返回空列表。

## 7. 设置伙牌成员 `异步_设置_伙牌成员`

### 7.1 请求

```json
{
  "header": "异步_设置_伙牌成员",
  "team_name": "A组",
  "guuids": "496702,718968",
  "remark": "运营标记",
  "context": "ab-team-set-001"
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `team_name` | string | 是 | 团队名；不存在则隐式创建；最长 60 字 |
| `guuids` | string | 是 | 逗号/换行分隔，单次最多 200 个 |
| `remark` | string | 否 | 成员备注，最长 250 字 |

行为：

- 已存在 `(team_name, guuid)` 时更新 `user_name / remark / status='used'`；
- 不存在的 guuid 逐条返回失败，不中断整批；
- **只对本次新加入成员、只停其保护目标**（`target_value > 0`）；压制目标保留，结果在 `stopped`；
- 成功后把 `team_loaded_ts` 置 0，下一 Tick（≤60 秒）生效。

### 7.2 返回

```json
{
  "ok": [{"guuid": "496702", "name": "abc12"}],
  "failed": [{"guuid": "123456", "error": "玩家不存在"}],
  "stopped": []
}
```

## 8. 移除伙牌成员 `异步_移除_伙牌成员`

### 8.1 请求

```json
{
  "header": "异步_移除_伙牌成员",
  "team_name": "A组",
  "guuids": "496702",
  "context": "ab-team-del-001"
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `team_name` | string | 是 | 团队名 |
| `guuids` | string | 否 | 逗号分隔；**空=整队移除** |

### 8.2 返回

```json
{
  "ok": ["496702"],
  "failed": [],
  "stopped": ["496702"]
}
```

- 软删（`status='deleted'`），不物理删除；
- 只处理当前确实还在该团队里的成员：`ok` 是实际匹配并删除的 guuid，传入但不在团队里的 guuid 不会误停其 auto 目标；
- 对匹配成员的 `man=auto_balance` 且 `state=active` 的目标执行 `StopTargets`，列入 `stopped`；
- 之后重新导入分组**不会复活**这些成员（导入不改 `status`）。

## 9. 导入伙牌名单 `异步_导入_伙牌名单`

### 9.1 请求

```json
{
  "header": "异步_导入_伙牌名单",
  "group_ids": [12, 15],
  "team_prefix": "导入-",
  "dry_run": 0,
  "context": "ab-team-imp-001"
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `group_ids` | int[] | 是 | `club_player_group_info.id` 列表，显式选择，**不支持全量导入** |
| `team_prefix` | string | 否 | 团队名前缀，默认 `导入-`；同一分组请始终用同一前缀 |
| `dry_run` | int | 否 | `1`=只预估不写库；默认 `0` |

约束：

- 只导 `m.status='used'` 且 `g.status='used'` 的成员；
- `team_name = left(concat(prefix, group_name), 60)`；不同联盟/俱乐部同名分组靠前缀区分；
- 同一玩家在多个分组会出现在多个 `team_name` 下，压制取 guuid 并集；
- 单次最多 2000 行，超了直接拒绝；
- 幂等：重复导入只刷新 `user_name / update_date`，**不改 `status`**；
- **只加不删**：不会移除名单里已存在但分组已没有的人；分组删人要手工移出；
- 已手工移出的成员，重新导入不会复活。

### 9.2 返回

```json
{"ok": true, "teams": 2, "members": 25, "affected": 30, "stopped": []}
```

| 字段 | 说明 |
| --- | --- |
| `teams` | 涉及的分组数 |
| `members` | 去重后的成员数（`dry_run` 时为预估） |
| `affected` | 实际影响行数（MySQL `affected rows`；`dry_run=0` 才有意义） |
| `stopped` | 导入后被停保护目标的 guuid 列表（只停 `man=auto_balance` 且 `target_value>0`） |

> `affected` 不区分插入/更新（`on duplicate key update` 无法可靠拆分），页面展示"导入 25 人（影响 30 行）"即可。

## 10. 错误表

| `error` | 触发 |
| --- | --- |
| `俱乐部功能未启用` | `game_mode != 'club'` |
| `无权限` | 调用者不是平台 boss |
| `action 不合法` | `执行_自动平衡` 的 `action` 不是 `run/run_guuids/stop_all` |
| `总开关未开启` | `enabled=false` 时调 `run_guuids` |
| `observe 模式不下发` | `mode=observe` 时调 `run_guuids` |
| `guuids 不能为空` | `run_guuids` 没传 guuid |
| `team_name 不能为空` | 名单设置/移除未传团队名 |
| `team_name 超过 60 字` | 团队名过长 |
| `单次最多 200 个玩家` | 名单批量加人超限 |
| `玩家不存在` | 名单加人时 guuid 在 `tbl_Account` 查不到，逐条进 `failed` 列表，不是顶层错误 |
| `当前已不满足规则（period_net=...）` | `run_guuids` 复核未通过 |
| `该玩家已有目标` | `run_guuids` 时已有 active 目标 |
| `group_ids 不能为空` | 导入未选分组 |
| `单次最多导入 2000 行` | 导入超限 |
| `分组不存在或已删除` | `group_ids` 里全部无效 |

> 配置类参数**不报错**：非法值会被 clamp 或回退，调用方以返回的 `cfg` 为准。

## 12. 重要口径（对账/验收用）

| 项 | 口径 |
| --- | --- |
| 本周期 | realtime 一次结算一个周期（约 30 分钟），`period_net` 来自房间内存；跨周期累计不做 |
| 今日累计 | `usr_total_score` 的 `date=curdate()` 聚合，最多滞后一个结算周期；`min_today_*` 都为 0 时不查 |
| 阈值 | 固定分数；`by_dipi` 命中时用覆盖值，未知底皮回退全局 |
| 目标值 | 保护 `+protect.target_value`；压制 `-suppress.target_value`；`chance` 35/40 |
| 生效 | 每局 `Start` 写 `optimize01_count=1` + `chance=±目标`，命中后扣减；不打断当前牌局 |
| 停止 | 达标 / 离房 600 秒 / 跨日 / 被人工目标覆盖 / `enabled=false` / `stop_all` |
| 恢复 | 沿用 `opt_target_ctrl` 的 `origin` 快照，恢复设置前的 `optimize01_*` |
| 名额 | 每房最多 1 压制 + 1 补偿；同房多目标按 `chance` 归一抽签 |
| 名单 | `status='used'` 才生效；同人多组只影响展示，压制取并集 |
| 导入 | 一次性快照；只加不删、不复活软删；前缀不稳定会产生重复团队 |
| 日志 | 目标生命周期看 `usr_opt_target_log` / `usr_opt_target_history`（`operator=auto_balance`）；决策快照看 `usr_auto_balance_log`（P2） |
