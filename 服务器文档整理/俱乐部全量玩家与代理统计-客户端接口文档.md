# 俱乐部全量玩家与代理统计 — 客户端接口文档

> 配套：`doc/俱乐部玩家分组管理方案.md`、`doc/俱乐部成员代理链路查询-客户端接口文档.md`
> 状态：2026-11-07 实现并补充贡献/红利字段；2026-11-08 补分组字段与红利排序（玩家红利并入主 SQL）。已上传测试服，待重启 baseapp 后联调。
> 权限：仅平台 boss / 最高 boss（`d_users.config["account"]` 的 `boss` / `bigboss`）；仅俱乐部模式（`game_mode=club`）。
> 数据源：`club_member_score_info`（俱乐部模式每人每天每俱乐部一行，`score`=净输赢、`contrib_fen`=贡献分）。
> 口径：只按**俱乐部代理树**（`club_agent_info`）；不使用大厅模式旧平台代理链（`third_marketing_info.upper_guuid`）。

## 1. 通用说明

- 通道：客户端 `reqHallCommand(param, context)`；服务端推送 `onMessage("AllClubPlayerList"/"AllClubAgentList", json)`，随后 `onHallCommand(0x200, {"context":"..."})`。
- 服务端内部用 `0x500` 标记“不同步返回”，该码不下发；参数/权限错误直接 `0x301` + `{"context","result":{"error"}}`。
- 分页：`page` 0 基，`count` 默认 20、上限 100；返回的 `count` 是**过滤后总条数**。
- 排序值相同的行按 `guuid` 升序，翻页不重不漏。
- 单位：输赢=积分（可负）；贡献=分（客户端展示 ÷100）；红利=分（客户端展示 ÷100）。
- “累计”的起点是 `club_member_score_info` 上线日 **2026-10-24**，不是玩家全部历史。
- 玩家列表一律**本人值**；代理列表一律**本人 + 整条下线**。两处都不套 `score_percent` / `contrib_add` / `show_percent`，返回真实值。
- 输赢/贡献/红利都参与排序：`sort` 只接受下面列出的枚举值，传其它值回落 `total_score`（不报错）。
- 两个列表都返回分组字段 `group_id` / `group_name` / `groups`，形状与 `查询_俱乐部_成员` 完全一致（未分组 = `"0"` / `""` / `[]`）。按行内 `club_id` 所属管理域取一个域，只读已加载缓存；管理域未加载时字段为空并触发一次异步加载，下次请求生效。分组**只展示，不支持按分组筛选**（请求无 `group_id` 参数）。

## 2. 查询_俱乐部_所有_玩家

### 2.1 请求

```json
{
  "header": "查询_俱乐部_所有_玩家",
  "page": 0,
  "count": 20,
  "sort": "total_score",
  "order": "desc",
  "search": "",
  "club_id": "",
  "context": "all-player-001"
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `page` | 否 | 0 基，默认 0；小于 0 按 0 |
| `count` | 否 | 默认 20，限制 1~100 |
| `sort` | 否 | `total_score`（默认）/ `today_score` / `yesterday_score` / `total_contrib_fen` / `today_contrib_fen` / `yesterday_contrib_fen` / `total_bonus_fen` / `today_bonus_fen` / `yesterday_bonus_fen` |
| `order` | 否 | `desc`（默认）/ `asc` |
| `search` | 否 | 玩家 ID 精确匹配或昵称模糊匹配 |
| `club_id` | 否 | 只看该俱乐部成员（`sm_club_join` / `sm_club_join2`）；也决定该行分组取自哪个管理域 |

### 2.2 推送 `AllClubPlayerList`

```json
{
  "number": "0",
  "count": "1234",
  "context": "all-player-001",
  "list": [
    {
      "guuid": "430994",
      "name": "玩家昵称",
      "club_id": "984470",
      "club_name": "A1俱乐部",
      "upper_guuid": "580629",
      "upper_name": "上级代理",
      "today_score": "-120",
      "yesterday_score": "80",
      "total_score": "-3450",
      "today_contrib_fen": "0",
      "yesterday_contrib_fen": "0",
      "total_contrib_fen": "1200",
      "today_bonus_fen": "0",
      "yesterday_bonus_fen": "0",
      "total_bonus_fen": "0",
      "group_id": "12",
      "group_name": "A组",
      "groups": [{"group_id": "12", "group_name": "A组"}]
    }
  ]
}
```

| 字段 | 说明 |
| --- | --- |
| `number` | 当前页（0 基） |
| `count` | 过滤后总人数 |
| `guuid` / `name` | 玩家 ID / 昵称 |
| `club_id` / `club_name` | 展示归属俱乐部：按 `sm_club_join` 再 `sm_club_join2` 的顺序，取第一个当前已加载的俱乐部 |
| `upper_guuid` / `upper_name` | 直属上级代理（俱乐部代理树）；普通玩家取该俱乐部创建者；玩家本人是创建者时为空串 |
| `today_score` / `yesterday_score` / `total_score` | 今日/昨日/累计输赢（同一玩家在多个俱乐部按人合并） |
| `today_contrib_fen` / `yesterday_contrib_fen` / `total_contrib_fen` | 今日/昨日/累计贡献（分），**本人值**，跨俱乐部按人相加 |
| `today_bonus_fen` / `yesterday_bonus_fen` / `total_bonus_fen` | 今日/昨日/累计红利（分），**本人值**，跨俱乐部相加；普通玩家恒为 0 |
| `group_id` / `group_name` / `groups` | 玩家所属分组，形状与 `查询_俱乐部_成员` 完全一致；未分组为 `"0"` / `""` / `[]` |

- 玩家在多个俱乐部时统计合并成一行，`club_id` / `upper_*` 取第一个已加载俱乐部，保证翻页稳定；分组也按这个 `club_id` 的管理域取，多域玩家只显示展示域的分组。
- 没有输赢记录的玩家也会出现（0 分），按排序值排在后面。
- 平台 boss 返回真实值，不套 `score_percent` / `contrib_add` / `show_percent` 展示折扣；与 `查询_俱乐部_成员` 的展示值不能直接对账。
- 红利口径：`累计 = club_agent_info.bonus（未提取） + club_history_info 已提取(元×100)`；`今日/昨日 = usr_income_info 当日分成净额(tax_number - bonus_tax_number)`。与成员列表/分组统计/代理链路同口径。
- 红利随主 SQL 一起返回并参与排序；红利子查询与输赢同一条 SQL，任何一步失败都返回 `查询失败`（不再做「缺红利键显示 `—`」的降级，客户端重试即可）。
- 分组字段对本接口的平台 boss 放行（不再套 `IsManager` 的总群主/创建者口径），与「boss 看真实值」一致；管理域未加载时为空并触发异步加载，不阻塞列表。
- `sort` 支持上表 9 个值（输赢 3 + 贡献 3 + 红利 3）；分组不参与排序，也不支持按分组筛选。

## 3. 查询_俱乐部_所有_代理

### 3.1 请求

```json
{
  "header": "查询_俱乐部_所有_代理",
  "page": 0,
  "count": 20,
  "sort": "total_score",
  "order": "desc",
  "search": "",
  "club_id": "",
  "context": "all-agent-001"
}
```

| 字段 | 说明 |
| --- | --- |
| `sort` | `total_score`（默认）/ `today_score` / `yesterday_score` / `total_contrib_fen` / `today_contrib_fen` / `yesterday_contrib_fen` / `total_bonus_fen` / `today_bonus_fen` / `yesterday_bonus_fen` |
| 其余 | 同玩家列表 |

- 「总赢 / 总输」用 `sort=total_score` + `order=desc` / `asc`（现有数据只有净输赢，不拆赢/输金额）。

### 3.2 推送 `AllClubAgentList`

```json
{
  "number": "0",
  "count": "89",
  "context": "all-agent-001",
  "list": [
    {
      "guuid": "580629",
      "name": "代理昵称",
      "club_id": "984470",
      "club_name": "A1俱乐部",
      "today_score": "500",
      "yesterday_score": "-200",
      "total_score": "12000",
      "today_contrib_fen": "1200",
      "yesterday_contrib_fen": "800",
      "total_contrib_fen": "56000",
      "today_bonus_fen": "1500",
      "yesterday_bonus_fen": "900",
      "total_bonus_fen": "78000",
      "team_count": "35",
      "group_id": "12",
      "group_name": "A组",
      "groups": [{"group_id": "12", "group_name": "A组"}]
    }
  ]
}
```

| 字段 | 说明 |
| --- | --- |
| `today_score` / `yesterday_score` / `total_score` | 该代理**本人 + 整条下线**的今日/昨日/累计输赢 |
| `today_contrib_fen` / `yesterday_contrib_fen` / `total_contrib_fen` | 该代理本人 + 整条下线的今日/昨日/累计贡献（分） |
| `today_bonus_fen` / `yesterday_bonus_fen` / `total_bonus_fen` | 该代理本人 + 整条下线的今日/昨日/累计红利（分），口径同玩家列表 |
| `team_count` | 整条下线人数，**不含自己** |
| `group_id` / `group_name` / `groups` | 该代理所属分组，形状与 `查询_俱乐部_成员` 完全一致；按 `club_id` 所属管理域取，未分组为 `"0"` / `""` / `[]` |

- 只输出 `club_agent_info.status='used'` 的代理；已取消的不出现。
- 所有层级代理统一规则，不区分直属/区域/合伙人等旧层级。
- 同一代理在多个俱乐部有节点时：9 项统计**相加**（各俱乐部独立口径）、`team_count` 取最大值、`club_id` 取第一个俱乐部。
- 整条线复用成员列表同一套树累加：输赢/贡献用 `Club._calcMemberTeamStats`，红利用 `Club._calcMemberLineBonus`（同一份成员集合与兜底规则，无代理行的成员按兜底挂创建者）。
- 结果缓存 60 秒；翻页期间数据不刷新。分组字段在**推送时**按当前已加载缓存计算，不写进 60 秒缓存，管理域加载完成后下一次请求即可看到。
- 红利查询失败时本次不写缓存（避免 60 秒内按红利排序退化成 `guuid` 序且不重试），`*_bonus_fen` 三个键不返回（客户端显示 `—`），其余字段照常。
- 代理树未加载时返回 `代理数据加载中，请重试`，服务端已触发加载，客户端重试即可。

## 4. 错误

| 情况 | ret_code | result |
| --- | --- | --- |
| 非平台 boss | `0x301` | `{"error":"无权访问"}` |
| 非俱乐部模式 | `0x301` | `{"error":"俱乐部功能未启用"}` |
| 查询失败 | `0x301` | `{"error":"查询失败"}` |
| 代理树未加载 | `0x301` | `{"error":"代理数据加载中，请重试"}` |

## 5. 实现落点

- `scripts/base/Hall.py`：命令注册、参数解析、两条 SQL/内存树累加与推送；玩家红利在主 SQL 的派生表 `b` 里（同一条 SQL 排序分页），代理红利走 `_execClubBonusStats`（一次 UNION 查三源，只查在用代理 guuid）；分组统一走 `_allClubPlayerGroups`（按展示 club_id 的管理域读已加载 scope）
- `scripts/server_common/club_biaozhun.py`：复用 `Club._calcMemberTeamStats`（输赢/贡献整条线）、`Club._calcMemberLineBonus`（红利整条线）
- `res/server/database.sql`：`club_member_score_info` 新增 `user_date (user_guuid, date)` 索引（线上需执行 DDL）
