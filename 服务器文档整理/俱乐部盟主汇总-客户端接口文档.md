# 俱乐部盟主汇总 — 客户端接口文档

> 状态：2026-11-18 实现并上传测试服，待重启 baseapp 后联调。
> 关联：`doc/俱乐部与联盟功能-客户端接口文档.md`（§2.14 `查询_俱乐部_成员_总分`）、`doc/俱乐部积分与额度方案-客户端接口文档.md`、`doc/俱乐部成员代理链路查询-客户端接口文档.md`
> 权限：俱乐部创建者 / 联盟总群主 / `club_manage`、`union_manage` 授权账号 / 平台 boss（`boss`、`bigboss`）
> 口径（2026-11-18 产品确认）：**盟主 = 俱乐部创建者**，盟主整条线 = 本俱乐部全体成员（含创建者）；积分总和 = `club_gold` 当前余额合计；未提取红利 = 含所有人（创建者 + 全体代理 + 已取消代理的残留 `bonus`）；返回真实值，不套 `show_percent`。

## 1. 通用说明

- 通道：客户端 `reqHallCommand(param, context)`；服务端推送 `onMessage("ClubSummary", json)`，随后 `onHallCommand(0x200, {"context":"..."})`。
- 仅俱乐部模式（`game_mode=club`）；大厅模式返回 `俱乐部功能未启用`。
- 一次请求返回一个俱乐部的汇总，无分页。
- 单位：积分 = 积分（整数，可负）；红利 = **分**（客户端展示时 ÷100）。
- 数值字段全部为字符串，与 `NumberList` / `AllPlayerGold` 风格一致。

## 2. 查询_俱乐部_汇总

### 2.1 请求

```json
{
  "header": "查询_俱乐部_汇总",
  "club_id": "775447",
  "context": "club-summary-001"
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `club_id` | 是 | 俱乐部 ID（纯数字字符串） |
| `context` | 否 | 原样回传 |

### 2.2 推送 `ClubSummary`

```json
{
  "club_id": "775447",
  "member_count": "128",
  "total_club_gold": "123456",
  "total_unclaimed_bonus_fen": "87654",
  "context": "club-summary-001"
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `club_id` | string | 俱乐部 ID |
| `member_count` | string | 当前成员数（`find_in_set` 精确匹配，含创建者） |
| `total_club_gold` | string | 全体成员在该俱乐部的积分余额合计（每人 `club_gold[club_id]` 求和；JSON 无该 key 按 0） |
| `total_unclaimed_bonus_fen` | string | 全体成员未提取红利合计（分）；`club_agent_info.bonus` 求和，含创建者与已取消代理残留 |
| `context` | string | 原样回传 |

### 2.3 口径说明

1. **积分总和**：`tbl_Account.sm_club_gold`（`club_mode` 2/3 取 `sm_club_gold2`）中 key=`club_id` 的值，按当前成员逐行累加；不套 `show_percent`、`score_percent`、`contrib_add`，也不做展示折扣。
2. **未提取红利**：`club_agent_info.bonus`（分）按 `club_guuid` 求和，**不过滤 `status`**。取消代理/退会只把关系置 `disabled`，`bonus` 仍在账上、仍可提取，过滤会漏掉这部分待付红利。
3. **红利范围**：只含 `club_agent_info.bonus` 这个红利账户的余额——代理抽水分成（`clubroot` / `clubN` / `darkroot`）、独立俱乐部奖池提留（`poolroot`）等入账；**不含联盟上缴 / 总群主 `owner_bonus`**。盟主同时是总群主时，两个数不要相加。
4. **红利是净额**：`bonus` 入账时已扣红利暗抽（`tax_number - bonus_tax_number`），与 `查询_俱乐部_红利_统计` 的 `unclaimed_fen` 同源；不是暗抽前毛额。
5. **成员范围**：只算当前 `sm_club_join`（或 `sm_club_join2`）包含该俱乐部的账号；已退会成员不计入积分总和与成员数，但其残留红利仍会体现在未提取红利总和中（与第 2 条一致）。
6. **残留红利的去向**：已退会 / 已取消代理的残留 `bonus` 仍可提取，但提取后加到该玩家个人 `club_gold[club_id]`，**不会回到本俱乐部成员池**；因此提取后 `total_unclaimed_bonus_fen` 下降、`total_club_gold` 不变。这是对账时的正常现象，不是漏算。
7. **对账口径**：`total_club_gold` 对 `club_gold` JSON 中缺本俱乐部 key 的成员按 **0** 计；成员列表同一情况下发 **`-99`** 哨兵。不要用成员列表各行 `club_gold` 求和来和本接口对账。
8. **实时值与调用频次**：每次请求实时查库，不做缓存；只在进入汇总页时调一次，**不要随成员列表翻页或轮询调用**（接口是 `tbl_Account` 全表扫）。返回 `查询失败` 时提示“稍后重试”，不要自动高频重试。

### 2.4 错误

| 情况 | ret_code | result |
| --- | --- | --- |
| 非客户端调用（HTTP 后台） | `0x301` | `{"error":"仅客户端可用"}` |
| 非俱乐部模式 | `0x301` | `{"error":"俱乐部功能未启用"}` |
| `club_id` 为空 / 俱乐部不存在 | `0x301` | `{"error":"俱乐部不存在"}` |
| 非管理者（普通代理、玩家） | `0x301` | `{"error":"无权访问"}` |
| 积分或红利 SQL 失败 | `0x301` | `{"error":"查询失败"}` |
| 成功 | `0x200` | 先推送 `ClubSummary`，再回 `{"context":"...","result":{}}` |

> 任一条 SQL 失败都整体返回 `查询失败`，不下发 0，避免运营把"查询失败"当成"确实没有积分/红利"。

## 3. 与现有接口的关系

| 现有接口 | 关系 |
| --- | --- |
| `查询_俱乐部_成员_总分`（`AllPlayerGold`） | 只返回 `total_club_gold`，无成员数、无红利；且无权限校验、SQL 用 `like` 子串匹配。本命令是管理者专用的完整汇总，口径更严格 |
| `查询_俱乐部_红利` / `查询_俱乐部_红利_统计` | 单人红利余额/统计（`unclaimed_fen`），仍用于代理查看自己或下线；本命令只给整条线合计 |
| `查询_俱乐部_所有_代理` / `查询_俱乐部_成员_代理链路` | 仅平台 boss / 授权后台；`total_bonus_fen` 是"未提取 + 已提取"的累计，不是未提取余额；本命令口径不同，不要混用 |
| `查询_俱乐部_成员`（`NumberList`） | 盟主虚拟行的 `club_gold` 仍是盟主个人余额、红利字段固定 `"0"`；本命令不改变成员列表报文 |

> 建议客户端统一用本接口取管理者汇总；老接口 `查询_俱乐部_成员_总分` 仍用 `like` 子串匹配，异常数据下不保证与本接口一致。

## 4. 边界与注意事项

| # | 场景 | 表现 |
| --- | --- | --- |
| 1 | 俱乐部无成员 / 全员积分为 0 | `member_count="0"`、`total_club_gold="0"`，成功 |
| 2 | 某成员 `club_gold` JSON 损坏或缺少本俱乐部 key | 该成员按 0 计，不影响其它成员；日志无报错 |
| 3 | 创建者本人也在 `sm_club_join` 里 | 计入成员数与积分总和（整条线含创建者） |
| 4 | 已退会但仍有未提取红利的代理 | 不计入成员数/积分，但红利仍计入 `total_unclaimed_bonus_fen` |
| 5 | 俱乐部 `club_mode` 2/3 | 自动使用 `sm_club_join2` / `sm_club_gold2`，客户端无感知 |
| 6 | 联盟总群主查属下俱乐部 | 允许（`IsClubManager` 覆盖联盟总群主） |
| 7 | 普通代理 / 玩家调用 | `无权访问`，不泄露全俱乐部红利总额 |
| 8 | 代理树未加载 | 不影响：本接口不依赖内存代理树，直接查库 |

## 5. 实现落点
