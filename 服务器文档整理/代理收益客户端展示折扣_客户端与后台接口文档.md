## 一、功能说明

客户端看到的**代理收益类金额**按 `usr_hash_info` 中 `hash_key='agent_income_show_percent'` 的值缩放；**该 hash 不存在时默认 100**；后台调用保持真实值。

| 项 | 口径 |
| --- | --- |
| `100` | 客户端看到真实值，与改动前完全一致（默认） |
| `80` | 客户端看到的收益 = 真实值 × 80%，向下取整 |
| `0` | 客户端看到的收益全部为 0（临时全隐藏开关） |
| 生效对象 | 红利、贡献、抽水、业绩、活动红利、分红等**展示金额** |
| 不生效对象 | 输赢/积分/钱包/额度/钻石/奖池余额、比例/费率、人数/局数、真实提取流水 |
| 后台 | `/hall/command` 走 `Hall.boss`，始终返回真实值 |
| 结算/提取 | 结算、提取校验、提取到账、钱包入账均按真实值，不受折扣影响 |

**本方案不新增客户端接口。** 客户端仍按原命令名、原参数、原报文结构调用；只是部分金额字段的数值变小。完整报文结构以各接口原文档为准，本文只列受影响的字段。

> 本方案是**展示口径**，不是防作弊/防截图的安全边界。折后余额与真实可提金额、真实提取流水可能对不上，属于已确认接受的行为。

## 二、通用协议

### 2.1 客户端通道

| 项 | 说明 |
| --- | --- |
| 调用 | `reqHallCommand(param, context)` |
| 回调 | `onHallCommand(ret_code, result)` |
| 请求 | `param` 为 JSON 字符串，必须含 `header`；`context` 新版本为 `"p@<上下文串>"` |
| 成功 | `ret_code = 0x200`（512），`result` 为 JSON 字符串 |
| 失败 | `ret_code = 0x301`（769）；异常路径可能没有 `result` 键，客户端先判空 |

本功能**没有新增返回码**。各命令原有的参数、分页、权限、推送路由、报文结构均不变。

### 2.2 后台通道

后台通过旧服务 HTTP 入口调用：

```text
GET /hall/command?header=<命令名>&param=<URL 编码的 JSON>
```

服务端 `_httpHallCommand` 固定用 `Hall.boss` 调用命令函数，因此后台返回真实值。完整请求/响应包裹见 `doc/新后台管理系统接口文档.md` §13。

## 三、后台配置接口

配置存储：`usr_hash_info` 的 `hash_key='agent_income_show_percent'`、`hash_content` 为 `0~100` 的整数字符串；**hash 不存在时默认 100**。`d_halls.py` 不保留该键。

### 3.1 读取配置

```bash
curl --get 'http://127.0.0.1:8890/hall/command' \
  --data-urlencode 'header=获取_大厅_配置数据' \
  --data-urlencode 'param={"param_name":"agent_income_show_percent","context":"admin-get"}'
```

返回示例：

```json
{
  "ret_code": 512,
  "ret_result": {
    "param_name": "agent_income_show_percent",
    "param_value": "80"
  }
}
```

### 3.2 设置配置

```bash
curl --get 'http://127.0.0.1:8890/hall/command' \
  --data-urlencode 'header=设置_大厅_配置数据' \
  --data-urlencode 'param={"param_name":"agent_income_show_percent","param_value":"80","context":"admin-set"}'
```

成功返回：

```json
{"ret_code": 512, "ret_result": {}}
```

### 3.3 参数

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `param_name` | string | 是 | 固定 `agent_income_show_percent` |
| `param_value` | string/int | 是 | `0~100` 的整数；`80`=8 折，`100`=真实值，`0`=客户端收益全部显示 0 |
| `context` | string | 否 | 运营操作号，原样返回 |

### 3.4 约束

- 只接受 `0~100` 的整数；`101`、`-1`、`abc`、空值均设置失败（`ret_code = 0x301`），原值不变。
- 权限沿用 `设置_大厅_配置数据` 的既有口径：`account.level >= 99`。本功能没有额外命令。
- 设置后会写一条 `usr_attr_info` 审计（旧值/新值/操作人/备注“设置代理收益展示比例”）。
- 设置会**同时更新 Hall 内存并写入 `usr_hash_info`**；下一次客户端收益查询立即生效，重启后仍保留。
- `d_halls.py` **不保留该键**，编辑 `d_halls.py` 不会再影响本配置，也不会被 `auto_reload` 冲掉。
- `usr_hash_info` 行不存在时默认 100；需要恢复默认时删除该行并重启 Hall（直接设置 100 会写入一行 100，不等于删除）。
- 设置后必须用 `获取_大厅_配置数据` 复核；后台侧仍需写自己的审计表。
- 保存是异步的（现有 `_saveData` 模式）：DB 写失败时当前内存值仍生效，重启回默认 100；后台可复核 `usr_hash_info` 行确认落库。

### 4.4 客户端注意事项

1. **不要按折后值反推真实值**：服务端只保证展示口径，客户端不应自行除以 `percent`。
2. **不要用成对字段互算**：`total_extract_fen` 与 `total_extract` 在 80% 下可能分别是 `720` 和 `7` 元，客户端直接展示原字段即可；`ClubAgentIncomeInfo` 的 `amount_fen` 已扣暗抽，不保证等于 `base_fen × percent`。
3. **不要用展示值做资金判断**：提取按钮、可提提示、钱包余额、提取记录均以真实接口为准；展示折扣不影响实际提取。
4. **`0` 模式**：所有纳入字段显示 0；`is_reward`、`status` 等资格字段仍按真实值计算，客户端不要把“收益 0”当成“没有资格/没有数据”。
5. **字段类型不变**：仍是原文档里的字符串/数字类型；客户端不需要改解析。

## 六、错误与边界

| 场景 | 表现 |
| --- | --- |
| 设置值 `101` / `-1` / `abc` / 空值 | `ret_code = 0x301`，配置不变 |
| 设置账号非 `level >= 99` | `ret_code = 0x301`，配置不变 |
| `usr_hash_info` 行不存在 | 默认 `100`，客户端看到真实值 |
| `usr_hash_info` 行被删除 | 当前运行期仍用内存值；重启 Hall 后回默认 `100` |
| `d_halls.py` 被编辑/服务重启 | 不再影响本配置；DB 行存在时重启后仍按行值 |
| DB 写入失败 | 当前内存值仍生效，重启回默认 `100`；后台应复核 `usr_hash_info` 行 |
| 客户端命令本身 | 无新增错误码；参数/权限/分页/路由与改动前一致 |

## 七、联调与验收示例

1. 后台读取，确认 `param_value = "100"`。
2. 客户端调用 `查询_俱乐部_红利`，`ClubBonus.bonus_fen` 应等于真实余额（如 `12345`）。
3. 后台设置 `80`，再读取确认 `param_value = "80"`。
4. 客户端刷新收益页面，抽查：
   - `ClubBonus.bonus_fen: 12345 → 9876`，`bonus: 123.45 → 98.76`；
   - `ClubBonusStats.unclaimed_fen: 12345 → 9876`，`total_extract: 10 → 8`；
   - `NumberList` 贡献 `8259 → 6607`；
   - `ClubAgentIncomeInfo` `base_fen: 1000 → 800`、`amount_fen: 300 → 240`；
   - `PlayerTaxRecord.tax: 1000 → 800`；
   - `ListJackpotPerformanceInfo` `我的 1000 / 下发 400 / 剩 600 → 800 / 320 / 480`。
5. 后台再查同一数据，确认仍为真实值。
6. 代理执行提取，确认校验/到账仍按真实值。
7. 铜钱宝 4 条抽水命令确认仍按旧 `1/0.8/0.2`，不叠加全局折扣。
8. 恢复 `100`，确认客户端数值与改动前一致。
