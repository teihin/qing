## 一、功能说明

客户端看到的**代理收益类金额、成员列表输赢与贡献**按**该成员生效的** `show_percent` 缩放；**自己优先、未设置沿直属上级就近继承、根上仍无则 100**；后台调用保持真实值。

| 项 | 口径 |
| --- | --- |
| `100` / NULL | 该代理看到真实值（默认） |
| `80` | 该代理看到的收益 = 真实值 × 80%，向下取整 |
| `0` | 该代理看到的收益全部为 0（临时全隐藏开关） |
| 普通玩家 | 自己没有配置；有已设置 `show_percent` 的上级代理则继承，完全没有则 100 |
| 生效对象 | 红利、贡献、抽水、业绩、活动红利、分红等**展示金额**；成员列表的今日/昨日/累计输赢 |
| 不生效对象 | 成员列表以外的其它玩家输赢、积分、钱包/额度/钻石/奖池余额、比例/费率、人数/局数、真实提取流水 |
| 后台 | `/hall/command` 走 `Hall.boss`，始终返回真实值 |
| 结算/提取 | 结算、提取校验、提取到账、钱包入账均按真实值，不受折扣影响 |

**本方案不新增客户端接口。** 客户端仍按原命令名、原参数、原报文结构调用；只是部分金额字段的数值变小。完整报文结构以各接口原文档为准，本文只列受影响的字段。

> 本方案是**展示口径**，不是防作弊/防截图的安全边界。折后余额与真实可提金额、真实提取流水可能对不上，属于已确认接受的行为。

### 1.1 生效规则与字段使用（客户端/后台对接必读）

**生效值**按成员向上就近继承：

1. 成员自己设置了 `show_percent` → 用自己（下级代理可覆盖上级）；
2. 自己没有设置/不是代理 → 沿直属上级找最近的已设置代理；
3. 到根都没有 → `100`。

例如：`abc11` 设 50，其下级普通玩家 `a2` 未设置 → `a2` 的输赢/贡献也按 50%；若 `a2` 后来成为代理并设 80，则 `a2` 及其下级按 80。

| 场景 | 使用字段/行为 |
| --- | --- |
| 客户端 `查询_俱乐部_成员` 的 `NumberList` | 服务端已按生效值缩放 `today_score` / `yesterday_score` / `total_score` 和 3 个 `*_contrib_fen`；单成员 `stat_scope=self` 时的 `today_bonus_fen` / `yesterday_bonus_fen` / `total_bonus_fen` 也按该成员生效值缩放；客户端直接展示，不要再乘一次；不含 `show_percent` |
| 后台 `异步_查询_俱乐部_成员` 行 | `today_score` / `yesterday_score` / `total_score`、`*_contrib_fen` 是 **raw 真实值**；展示用 `*_score_display` / `*_contrib_display_fen`；行级 `show_percent` 是**继承后的生效值**；后台默认 `stat_scope=line`，红利 3 项为 `"0"`；另返回 `bonus_dark_percent`（int，0~100，红利暗抽比例，不参与展示缩放） |
| 后台 `异步_查询_代理_展示数据` | `*_raw` 为真实值；`self_display` / `team_display` 的输赢与贡献已按目标代理生效值缩放；顶层 `agent_income_show_percent` 也是生效值 |
| 后台“显示规则”列 | 用 `查询_代理_展示规则.effective_show_percent`，或成员行 `show_percent`；不要用 `agent_income_show_percent`（那是自己的值） |
| 后台“设置规则”表单回显 | 用 `查询_代理_展示规则.agent_income_show_percent`（自己的值） |
| “设置规则”按钮 | 只有代理（含创建者）可设置；普通玩家没有自己的值，只能继承上级，后台应对非代理行隐藏/禁用设置按钮 |

## 二、通用协议

### 2.1 客户端通道

| 项 | 说明 |
| --- | --- |
| 调用 | `reqHallCommand(param, context)` |
| 回调 | `onHallCommand(ret_code, result)` |
| 请求 | `param` 为 JSON 字符串，必须含 `header`；`context` 新版本为 `"p@<上下文串>"` |
| 成功 | `ret_code = 0x200`（512），`result` 为 JSON 字符串 |
| 失败 | `ret_code = 0x301`（769）；异常路径可能没有 `result` 键，客户端先判空 |

本功能**没有新增返回码**。各命令原有的参数、分页、权限、推送路由、报文结构均不变。

### 2.2 后台通道

后台通过旧服务 HTTP 入口调用：

```text
GET /hall/command?header=<命令名>&param=<URL 编码的 JSON>
```

服务端 `_httpHallCommand` 固定用 `Hall.boss` 调用命令函数，因此后台返回真实值。完整请求/响应包裹见 `doc/新后台管理系统接口文档.md` §13。

## 三、后台配置接口

配置存储：`club_agent_info.show_percent`，按 `club_guuid + user_guuid` 一代理一份；**NULL/未设置默认 100**。生效规则：**自己设置优先；自己没有设置时沿直属上级就近继承；到根都没有才 100**。详细字段、权限和与成员列表的配合见 `doc/俱乐部成员与代理展示-后台接口文档.md`。

### 3.1 查询该代理的展示规则

```bash
curl --get 'http://127.0.0.1:8890/hall/command' \
  --data-urlencode 'header=查询_代理_展示规则' \
  --data-urlencode 'param={"club_id":"775447","agent_id":"718968","metric":"contrib","context":"admin-get"}'
```

返回示例：

```json
{
  "ret_code": 512,
  "ret_result": {
    "club_id": "775447",
    "agent_id": "718968",
    "metric": "contrib",
    "agent_income_show_percent": 100,
    "effective_show_percent": 50,
    "display_fields": ["today_contrib_fen", "yesterday_contrib_fen", "total_contrib_fen"],
    "context": "admin-get"
  }
}
```

- `agent_income_show_percent`：该代理**自己**的值（未设置/非代理=100），用于设置表单回显；
- `effective_show_percent`：该代理**实际生效**的值（含上级继承）；示例表示自己未设置、上级为 50；
- `display_fields` 是历史提示字段，当前输赢也会缩放；不要仅按该列表判断缩放范围。

### 3.2 设置该代理的展示规则

```bash
curl --get 'http://127.0.0.1:8890/hall/command' \
  --data-urlencode 'header=设置_代理_展示规则' \
  --data-urlencode 'param={"club_id":"775447","agent_id":"718968","metric":"contrib","mode":"percent","percent":80,"note":"","operator":"admin999","context":"admin-set"}'
```

成功返回：

```json
{
  "ret_code": 512,
  "ret_result": {
    "club_id": "775447",
    "agent_id": "718968",
    "mode": "percent",
    "percent": 80,
    "agent_income_show_percent": 80,
    "effective_show_percent": 80,
    "context": "admin-set"
  }
}
```

### 3.3 参数

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `club_id` | string | 是 | 俱乐部 ID |
| `agent_id` | string | 是 | 要设置/查询的代理 ID；必须是该俱乐部 `status=used` 的代理，创建者始终允许 |
| `mode` | string | 否 | 仅 `percent`（缺省） |
| `percent` | int | 是 | `0~100`；`80`=8 折，`100`=真实值，`0`=该代理收益全部显示 0；这是代理自己的值，未单独设置的下级会自动继承 |
| `metric` | string | 否 | 原样回显，当前固定 `contrib` |
| `note` / `operator` | string | 否 | 仅写入服务端审计备注，原样回显不返回 |
| `context` | string | 否 | 原样返回 |

### 3.4 约束

- 只接受 `0~100` 的整数；`101`、`-1`、`abc`、空值均设置失败（`ret_code = 0x301`），原值不变。
- 权限沿用后台命令口径：`Hall.boss` 或 `account.level >= 99`；仅 `game_mode=club` 可用，大厅模式返回 `0x301`。
- 设置成功后写一条 `usr_attr_info` 审计（`attr_name='agent_income_show_percent'`，备注含俱乐部、代理、operator、note）。
- 设置会**同时更新代理树内存并异步 `UPDATE club_agent_info.show_percent`**；下一次客户端收益查询立即生效，重启后随代理树重新加载。
- 设置写入的是该代理**自己的值**，优先于上级继承；未单独设置的下级按“最近上级”继承该值。
- 未设置（NULL）与 100 展示效果相同；需要恢复默认可直接设置 100。
- 保存是异步的：DB 写失败时当前内存值仍生效，重启回未设置/100；后台可复核 `club_agent_info.show_percent`。

### 4.4 客户端注意事项

1. **不要按折后值反推真实值**：服务端只保证展示口径，客户端不应自行除以 `percent`。
2. **不要用成对字段互算**：`total_extract_fen` 与 `total_extract` 在 80% 下可能分别是 `720` 和 `7` 元，客户端直接展示原字段即可；`ClubAgentIncomeInfo` 的 `amount_fen` 已扣暗抽，不保证等于 `base_fen × percent`。
3. **不要用展示值做资金判断**：提取按钮、可提提示、钱包余额、提取记录均以真实接口为准；展示折扣不影响实际提取。
4. **`0` 模式**：所有纳入字段显示 0；`is_reward`、`status` 等资格字段仍按真实值计算，客户端不要把“收益 0”当成“没有资格/没有数据”。
5. **字段类型不变**：仍是原文档里的字符串/数字类型；客户端不需要改解析。

## 七、联调与验收示例

1. 后台 `查询_代理_展示规则`，确认 `agent_income_show_percent = 100`（未设置）。

3. 后台 `设置_代理_展示规则` 给该代理设 `80`，再查确认 `agent_income_show_percent = 80`。
4. 客户端刷新收益页面，抽查：
   - `ClubBonus.bonus_fen: 12345 → 9876`，`bonus: 123.45 → 98.76`；
   - `ClubBonusStats.unclaimed_fen: 12345 → 9876`，`total_extract: 10 → 8`；
   - `NumberList` 贡献 `8259 → 6607`；
   - `ClubAgentIncomeInfo` `base_fen: 1000 → 800`、`amount_fen: 300 → 240`；
   - `PlayerTaxRecord.tax: 1000 → 800`；
   - `ListJackpotPerformanceInfo` `我的 1000 / 下发 400 / 剩 600 → 800 / 320 / 480`。
5. 后台再查同一数据，确认仍为真实值。
6. 代理执行提取，确认校验/到账仍按真实值。
7. 铜钱宝 4 条抽水命令确认仍按旧 `1/0.8/0.2`，不叠加代理展示比例。
8. 恢复 `100`，确认客户端数值与改动前一致。
9. 给上级代理 A 设 80：A 的输赢/贡献按 80%；A 的下级未单独设置时继承 80%；下级代理自己设置时用自己的值；无已设置上级的普通玩家仍为真实值。后台 `show_percent` / `effective_show_percent` 应分别反映生效值/自有值。
