## 一、功能说明

### 1.1 一句话

俱乐部业绩 = 代理"自己 + 整条下线"的玩家**给奖池贡献金额的次数**；按 `我 / 下放 / 剩` 展示，支持按联盟/俱乐部授权与后台报表。

### 1.2 指标与单位（最容易错，先看）

| 项 | 定义 | 单位 |
| --- | --- | --- |
| 贡献次数 | 玩家每触发一次奖池贡献（`_EndRoundRewardToClubPool` 扣 `reward_money`）计 1 次 | **次（整数）** |
| 我（毛业绩） | 自己 + 整条下线的次数之和 | 次 |
| 下放 | 离自己最近的已授权后代的毛业绩之和（frontier） | 次 |
| 剩（净业绩） | `我 − 下放` | 次 |
| 占比 | `次数 / 该奖池当日总次数 × 100`，两位小数 | **%** |
| 分母 | 入盟 = 联盟池当日总次数；独立 = 该俱乐部池当日总次数 | 次 |

> ⚠️ **业绩不是金额、不是点数**。后台页面上的「实际点数 / 本次金额」不由本模块提供，见 §六。

### 1.3 支持与不支持

**支持**

- 客户端查自己的 `我 / 下放 / 剩` 与三个占比；
- 客户端查自己的 **frontier（已授权下级）** 列表与各自占比；
- boss / 联盟总群主 / 盟主 / 独立俱乐部创建者按各自下级范围开通/取消；
- 后台按 `club_id` 或 `union_id` 拉**已开通代理（含创建者）**的净次数；未开通不出现，已开通但 0 贡献保留；
- 与现有俱乐部代理树、奖池贡献、红利暗抽完全解耦（只读统计，不参与分账）。

**不支持**

- 不提供「实际点数」换算、不提供「本次金额 / 发放 / 分账号」（沿用后台现有逻辑）；
- 不提供返款、分红、自动打款；
- 不做跨俱乐部合并的"全平台"分母（分母只到联盟/独立俱乐部）；
- 不提供历史回填（上线前的贡献不计入）；
- 不套用 `show_percent` 展示折扣（见 §八）。

### 1.4 与大厅业绩的差异（对接方必看）

| 维度 | 大厅业绩 | 俱乐部业绩 |
| --- | --- | --- |
| 基数 | 输赢 / 奖池提留（金额） | **贡献次数** |
| 分母 | 全平台 ×2 | 本池总次数，**不 ×2** |
| 授权 | `client_prop` 全局标记，平台开通 | 按 `club_guuid + user_guuid`，四类角色按范围开通 |
| 扣减 | 望远镜（最近已授权后代） | 同一 frontier 算法 |
| 展示折扣 | 套 `show_percent` | **不套用** |
| 金额/返款 | 有（线下） | 无 |

## 二、通用协议（所有接口共用）

### 2.1 命令通道

| 通道 | 客户端→服务器 | 服务器→客户端 | 本文档命令 |
| --- | --- | --- | --- |
| 大厅命令通道 | `reqHallCommand(param, context)` | `onHallCommand(ret_code, result)` | 全部 4 个 |
| 后台 HTTP | `POST /hall/command` | JSON | 全部 4 个（报表/授权主要给后台） |

> 本功能**不新增账号命令**，也不新增房间推送字段。

### 2.2 请求格式

- `param`：**JSON 字符串**，必须含 `"header"`（命令名），其余字段为参数；
- `context`：字符串。**必须使用新格式** `"p@<任意上下文串>"`；`@` 后的内容原样回传，用于请求-响应配对。

```json
{"header":"异步_查询_俱乐部_业绩_信息","club_id":"710701","date":-1,"context":"p@perf-1"}
```

> ⚠️ 若 `context` 不带 `p@`，`reqHallCommand` 走老版本兼容分支，`result` 只回传 context 字符串，**拿不到 `{"result":...}` 包裹**。客户端/后台请统一用 `p@`。

### 2.3 响应格式

成功（`ret_code = GC_OK`）：

```json
{
  "context": "perf-1",
  "result": {
    "ClubPerfInfo": { }
  }
}
```

失败（`ret_code = GC_FAILED`）：

```json
{
  "context": "perf-1",
  "result": {
    "error": "你不在该俱乐部"
  }
}
```

`ret_code`（`scripts/common/GlobalConst.py`）：

| 常量 | 值 | 含义 |
| --- | --- | --- |
| `GC_OK` | `0x200`（512） | 成功 |
| `GC_FAILED` | `0x301`（769） | 失败（参数、权限、俱乐部不存在等） |
| `GC_UNKOWN` | `0x500`（1280） | 服务端本次不返回，等后续消息（本功能不用） |

> 异常路径（命令名写错 / param 非法 JSON / 服务端内部异常）：`ret_code = 0x301`，`result` 可能为空或只有 `{"context":"..."}`。客户端请先判空再解析。

**后台 HTTP 的返回差异**：`POST /hall/command` 的响应是

```json
{"ret_code": 512, "ret_result": "{\"ClubPerfInfo\":{...}}"}
```

`ret_result` 是**命令返回的 JSON 字符串**，需要二次 `JSON.parse`；不套 `{"context","result"}`。失败时 `ret_result` 为 `"{\"error\":\"...\"}"`。后台不要按客户端的包裹格式解析。

### 2.4 日期参数

`date` 为**相对今天的天数偏移**：

| 值 | 含义 |
| --- | --- |
| 不传 / `-1` | 昨日（客户端"昨日占比"默认） |
| `0` | 今日 |
| `-2` | 前日 |

服务端按 `today + date` 转成 `YYYY-MM-DD`；非法值按 -1 处理。返回体会带实际 `date`，客户端以返回值为准。

### 2.5 公共错误

| 场景 | `ret_code` | `result.error` |
| --- | --- | --- |
| 俱乐部不存在 | `GC_FAILED` | `俱乐部不存在` |
| 代理树加载中 | `GC_FAILED` | `代理数据加载中，请稍后重试` |
| 调用者不属于该俱乐部（查询） | `GC_FAILED` | `你不在该俱乐部` |
| 无授权/报表权限 | `GC_FAILED` | `无权限` |
| 目标不是代理 | `GC_FAILED` | `目标不是代理` |
| 参数非法 | `GC_FAILED` | `参数错误` |

## 三、接口 1：查询我的业绩（客户端）

- **命令名**：`异步_查询_俱乐部_业绩_信息`
- **通道**：大厅命令通道（`reqHallCommand` / `onHallCommand`）
- **实现**：`scripts/server_common/club_performance.py` `act_query_info`
- **权限**：本俱乐部成员（含创建者/盟主/总群主/boss）；未开通业绩的调用者返回 `enabled=false` + 全 0

### 3.1 请求参数

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `header` | string | 是 | `异步_查询_俱乐部_业绩_信息` |
| `club_id` | string | 是 | 俱乐部号；决定池键（入盟=联盟池，未入盟=俱乐部池） |
| `date` | int | 否 | 天数偏移，缺省 -1（昨日） |
| `context` | string | 否 | 操作号，`p@` 前缀 |

### 3.2 请求示例

```json
{"header":"异步_查询_俱乐部_业绩_信息","club_id":"710701","date":-1,"context":"p@perf-1"}
```

### 3.3 返回

```json
{
  "context": "perf-1",
  "result": {
    "ClubPerfInfo": {
      "date": "2026-11-10",
      "club_id": "710701",
      "pool_key": "535696",
      "pool_type": "union",
      "enabled": true,
      "all_count": 10000,
      "my_count": 16,
      "granted_count": 14,
      "left_count": 2,
      "my_percent": "0.16",
      "granted_percent": "0.14",
      "left_percent": "0.02"
    }
  }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `date` | string | 实际统计日期 `YYYY-MM-DD` |
| `club_id` | string | 请求的俱乐部号 |
| `pool_key` | string | 入盟 = `union_id`；独立 = `club-<club_id>` |
| `pool_type` | string | `union` / `club` |
| `enabled` | bool | 调用者是否被授权开通（创建者恒 true）。false 时其余数值全 0，客户端隐藏入口 |
| `all_count` | int | 分母：该池当日总次数；`enabled=false` 时为 0 |
| `my_count` | int | 我（自己 + 整条下线） |
| `granted_count` | int | 下放（frontier 之和） |
| `left_count` | int | 剩 = `my_count − granted_count` |
| `my_percent` | string | `my_count / all_count`，两位小数；分母 0 时为 `"0.00"` |
| `granted_percent` | string | `granted_count / all_count` |
| `left_percent` | string | `left_count / all_count` |

### 3.4 口径与注意

- `我的 = 下放 + 剩` **恒成立**（整数），客户端可直接校验，不要自行四舍五入后再相加；
- 百分比是**字符串**，保留两位小数；客户端不要再用浮点重算，避免末位不一致；
- `left_count` 是**净次数**，不是金额、不是点数；后台把它填到「今日业绩」列时，列头/单位请按"次"展示（见 §6.5）；
- 未开通：`enabled=false`、`all_count=0`、三个次数全 0、三个占比 `"0.00"`；命令本身成功；
- 创建者默认开通，无需授权记录；
- 查询只返回调用者自己，不能查别人的业绩（后台要看已开通代理列表请用 §六）。

## 四、接口 2：查询我的已授权下级列表（客户端）

- **命令名**：`异步_查询_俱乐部_业绩_下发_列表`
- **通道**：大厅命令通道
- **实现**：`club_performance.act_query_list`
- **权限**：同 §三；未开通返回空列表

### 4.1 请求参数

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `header` | string | 是 | `异步_查询_俱乐部_业绩_下发_列表` |
| `club_id` | string | 是 | 俱乐部号 |
| `date` | int | 否 | 天数偏移，缺省 -1 |
| `count` | int | 否 | 每页数量，默认 20 |
| `page` | int | 否 | 页码，从 0 开始，默认 0 |
| `context` | string | 否 | `p@` 前缀 |

### 4.2 请求示例

```json
{"header":"异步_查询_俱乐部_业绩_下发_列表","club_id":"710701","date":-1,"count":20,"page":0,"context":"p@perf-2"}
```

### 4.3 返回

```json
{
  "context": "perf-2",
  "result": {
    "ClubPerfGrantList": {
      "date": "2026-11-10",
      "club_id": "710701",
      "all_count": 10000,
      "my_count": 16,
      "granted_count": 14,
      "left_count": 2,
      "list": [
        ["844985", "发给我看看", 14, "0.14"]
      ]
    },
    "number": "0",
    "count": "1"
  }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `date` / `club_id` / `all_count` / `my_count` / `granted_count` / `left_count` | — | 同 §3 |
| `list` | array | 当前页的 **frontier**（离我最近的已授权后代），与"下放"完全同集合 |
| `list[i][0]` | string | 代理 guuid |
| `list[i][1]` | string | 昵称 |
| `list[i][2]` | int | 该代理整条线次数（毛业绩） |
| `list[i][3]` | string | 该代理占比（两位小数） |
| `number` | string | 当前页码 |
| `count` | string | 总数（frontier 人数），用于分页 |

### 4.4 注意

- **只列已授权**：未开通的下级不出现（与大厅一致）；「确认添加」由有资格的角色走 §五；
- 列表是 frontier，不是全部下级：如果 A→B→C 且 B、C 都授权，A 的列表里只有 B，没有 C；
- 排序：`次数` 倒序 → `guuid` 升序，客户端不要二次排序；
- 完全无下级/未开通：`list=[]`，`count="0"`。

## 五、接口 3：开通/取消业绩（客户端/后台）

- **命令名**：`设置_俱乐部_业绩_授权`
- **通道**：大厅命令通道（同步命令，`reqHallCommand` / `onHallCommand`）
- **实现**：`club_performance.act_set_grant`
- **权限**：仅以下四类角色，且只能在自己的下级范围内操作

| 角色 | 判定 | 可操作范围 |
| --- | --- | --- |
| 平台 boss | `level >= 99` 或 `_isPlatformBossGuuid` | 任意俱乐部任意代理 |
| 联盟总群主 | `club_unions[union_id].owner_guuid == 自己` | 本联盟内所有俱乐部的代理 |
| 盟主（联盟内俱乐部创建者） | `club.proxy.guuid == 自己` | 本俱乐部代理（任意深度） |
| 独立俱乐部创建者 | `club.proxy.guuid == 自己` | 本俱乐部代理（任意深度） |

> 不做"直属"限制：可以给任意深度的下级开通（跳级也可以）；扣减用 frontier，不会重复归属。

### 5.1 请求参数

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `header` | string | 是 | `设置_俱乐部_业绩_授权` |
| `club_id` | string | 是 | 俱乐部号（决定授权范围） |
| `user_id` | string | 是 | 目标代理 guuid；必须是本俱乐部 `status='used'` 且 `IsClubAgent` |
| `enabled` | int | 是 | `1` = 开通；`0` = 取消（置 `disabled`，保留记录） |
| `context` | string | 否 | `p@` 前缀 |

### 5.2 请求示例

```json
{"header":"设置_俱乐部_业绩_授权","club_id":"710701","user_id":"844985","enabled":1,"context":"p@perf-3"}
```

取消：

```json
{"header":"设置_俱乐部_业绩_授权","club_id":"710701","user_id":"844985","enabled":0,"context":"p@perf-3"}
```

### 5.3 返回

成功：

```json
{
  "context": "perf-3",
  "result": {
    "user_id": "844985",
    "enabled": 1
  }
}
```

失败：

```json
{
  "context": "perf-3",
  "result": {
    "error": "无权限"
  }
}
```

### 5.4 服务端校验顺序（失败即返回，不落库）

| # | 校验 | 错误文案 |
| --- | --- | --- |
| 1 | `game_mode == 'club'` | `俱乐部功能未启用` |
| 2 | `club_id` 存在 | `俱乐部不存在` |
| 3 | 调用者属于四类授权角色之一，且目标在范围内 | `无权限` |
| 4 | 代理树已加载 | `代理数据加载中，请稍后重试` |
| 5 | `enabled ∈ {0,1}` | `参数错误` |
| 6 | 目标在本俱乐部、`status='used'`、`IsClubAgent` | `目标不是代理` |

> 以上为服务端**实际执行顺序**（2026-11-11 评审后按代码修正文档）。

### 5.5 注意

- **写库是异步的**：命令返回时 INSERT 可能尚未落盘，客户端设置后**稍等再刷新**（不要立刻重查）；后台如需强一致，可改为 `异步_设置_俱乐部_业绩_授权` + `yield`，当前不这样设计；
- 重复开通只改状态，不产生多行；
- 取消 = `status='disabled'`，不物理删除；重新开通 = 改回 `used`；
- 创建者默认开通，**不写授权记录**；对创建者设置时直接返回 `enabled=1`，即使传 `enabled=0` 也不会落库（避免"取消成功但实际仍开通"）；
- 授权**跟随代理本人，不跟随树位置**：代理被挪到新上级、退会再回来，授权仍有效；需要回收时手动取消；
- 不做审批流、二次校验、独立审计表；开通人记录在 `club_perf_grant_info.opter_*`。

## 六、接口 4：后台业绩报表（后台只读）

- **命令名**：`异步_查询_俱乐部_业绩_报表`
- **通道**：大厅命令通道 / 后台 `POST /hall/command`
- **实现**：`club_performance.act_query_report`
- **权限**：与 §五 相同的四类角色与范围；越权返回 `无权限`

### 6.1 用途

支撑后台「业绩核心共享」页面，按盟主/独立俱乐部/联盟拉**已开通代理（含创建者）**的业绩；未开通代理不出现：

- 「今日业绩」列 = 本接口的 `left_count`（**整数净次数**）；
- 「实际点数」「本次金额」「发放」「分账号」**不由本接口提供**，继续走后台现有逻辑；
- 分配比例由后台按参与名单自己算，**不要用本接口的 `left_percent`**（见 §6.5）。

### 6.2 请求参数

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `header` | string | 是 | `异步_查询_俱乐部_业绩_报表` |
| `club_id` | string | 二选一 | 按俱乐部拉（该俱乐部已开通代理） |
| `union_id` | string | 二选一 | 按联盟拉（联盟内所有俱乐部的已开通代理）；与 `club_id` 同时传时 `club_id` 优先 |
| `date` | int | 否 | 天数偏移，缺省 -1 |
| `context` | string | 否 | `p@` 前缀 |

### 6.3 请求示例

按独立俱乐部/盟主：

```json
{"header":"异步_查询_俱乐部_业绩_报表","club_id":"710701","date":-1,"context":"p@perf-4"}
```

按联盟：

```json
{"header":"异步_查询_俱乐部_业绩_报表","union_id":"535696","date":-1,"context":"p@perf-4"}
```

### 6.4 返回

```json
{
  "context": "perf-4",
  "result": {
    "ClubPerfReport": {
      "date": "2026-11-10",
      "pool_key": "535696",
      "all_count": 10000,
      "list": [
        ["844985", "a3", "盟主", "复仇者", "A3俱乐部", 16, 14, 2, "0.02"],
        ["430094", "伍", "盟主", "测试测试1", "测试测试2", 0, 0, 0, "0.00"]
      ]
    }
  }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `date` | string | 实际统计日期 |
| `pool_key` | string | 入盟 = `union_id`；独立 = `club-<club_id>` |
| `all_count` | int | 该池当日总次数（分母） |
| `list` | array | **已开通代理（含创建者）**；已开通但 0 贡献保留；未开通不出现；按 `left_count` 倒序 → `guuid` 升序 |
| `list[i][0]` | string | guuid |
| `list[i][1]` | string | 昵称 |
| `list[i][2]` | string | 身份：`大盟主` / `盟主` / `合伙人`（创建者=盟主，总群主=大盟主，其余代理=合伙人） |
| `list[i][3]` | string | 联盟名；独立俱乐部为空串 |
| `list[i][4]` | string | 俱乐部名 |
| `list[i][5]` | int | 我（毛次数） |
| `list[i][6]` | int | 下放（frontier 之和） |
| `list[i][7]` | int | 剩（净次数） |
| `list[i][8]` | string | 剩占比（`left_count / all_count`，两位小数） |

> 示例两行均为已开通代理；第二行是"已开通但当天 0 贡献"。**未开通代理不会出现在 `list` 中**。

### 6.5 后台字段映射（已确认）

| 后台列 | 取值 | 说明 |
| --- | --- | --- |
| **今日业绩** | **`list[i][7]`（`left_count`，整数）** | 对应"扣掉下级后的剩余" |
| **实际点数** | **不由本接口返回** | 沿用后台现有点数来源（含业绩外加点/补贴） |
| **本次金额** | **不由本接口返回** | 后台现有分配/发放逻辑 |
| 分配比例 | `left_count / Σ(名单内 left_count)` | **后台自算**；参与名单 = 后台页面勾选的代理 |
| 业绩比例（展示） | `list[i][8]`（`left_percent`） | 分母是**整个池**，不能当分配比例 |

> 一句话：本接口只提供"净次数"，后台用它填「今日业绩」；「实际点数」「本次金额」继续走后台原有逻辑，**不改变单位、不参与分配**。

- `参与人数` = 名单内 `left_count > 0` 的代理数，后台自行统计；
- 「今日业绩」列头建议改为「今日业绩(次)」，避免运营按金额/点数理解；
- 后台分配时用 `left_count` 求和，不要用 `left_percent` 求和（后者分母是整个池）。

### 6.6 注意

- **只返回已开通（含创建者）**：`_IsEnabled(club, guuid, granted)` 为 true 才出现；未开通代理不出现，避免其"假设剩余"被后台求和后超过分母；
- **后台对接**：`list` 只含已开通代理；页面如需展示全部代理，请用俱乐部代理名单**左关联**、未命中补 0；分配比例只用 `left_count` 求和，不要用 `left_percent`（同 §6.5）；
- **已开通但 0 贡献保留**：以 `Club.agent_tree`（`status='used'`）为范围，当天没有贡献的已开通代理补 0，保证后台名单不缩水；
- 不分页：一个俱乐部/联盟的代理数量有限；如后续需要再补 `count/page`；
- `union_id` 视角返回联盟内所有俱乐部的已开通代理，`list[i][3]/[4]` 区分归属；
- 如果某个俱乐部在联盟内但没有代理行，其创建者仍会出现（`IsClubAgent` 为 true）；
- **不支持不带 `club_id`/`union_id` 的全平台一次性拉取**：后台的"全部联盟/全部俱乐部"视图请按俱乐部循环调用（每俱乐部一次，代理数量有限），或二期再加 `all=1`（仅 boss）；不要在服务端把多个池的分母混在一起。

## 七、数据源与对账（后台/运维）

### 7.1 表结构

| 表 | 用途 | 关键列 |
| --- | --- | --- |
| `club_perf_contrib_info` | 按日、按池、按俱乐部、按玩家的贡献次数 | `date, pool_key, club_guuid, user_guuid, cnt`；唯一键 `(date,pool_key,club_guuid,user_guuid)` |
| `club_perf_grant_info` | 按俱乐部的业绩授权 | `club_guuid, user_guuid, status, date, opter_name, opter_guuid`；唯一键 `(club_guuid,user_guuid)` |

### 7.2 常用 SQL

```sql
-- 本池当日总次数（分母）
select ifnull(sum(cnt),0) from club_perf_contrib_info
where date='2026-11-10' and pool_key='535696';

-- 本俱乐部各玩家次数
select user_guuid, sum(cnt) from club_perf_contrib_info
where date='2026-11-10' and pool_key='535696' and club_guuid='710701'
group by user_guuid;

-- 授权名单
select user_guuid, status, opter_name, date from club_perf_grant_info
where club_guuid='710701';
```

### 7.3 对账

```sql
-- 分母应与当日该池的奖池贡献流水条数一致
select (select ifnull(sum(cnt),0) from club_perf_contrib_info
        where date='2026-11-10' and pool_key='535696') as perf_cnt,
       (select count(*) from usr_cash_water_sub_zhongjiangzhekou
        where date='2026-11-10' and remark4='535696' and option_type='中奖折扣') as flow_cnt;
```

> `usr_cash_water_sub_zhongjiangzhekou` 的大厅 fixed 行 `remark4` 写的是数字，不会命中 `pool_key`（union_id 或 `club-<id>`）过滤，可安全对账。

### 7.4 `pool_key` 规则

| 俱乐部 | `pool_key` | 示例 |
| --- | --- | --- |
| 已入盟（`club_guuid_info.union_id` 非空） | `union_id` | `535696` |
| 未入盟的独立俱乐部 | `club-<club_guuid>` | `club-710701` |

## 八、已知限制（对接方需知）

| # | 限制 | 影响 | 对接处理 |
| --- | --- | --- | --- |
| 1 | 历史不可回填 | 上线前无数据 | 从上线当日起展示；不要拿历史日期对比 |
| 2 | 只在 realtime 俱乐部房计数 | fixed 俱乐部房不计 | 当前线上 `settle_mode=realtime` |
| 3 | 入盟/退盟后池键漂移 | 变更前的日期查不到旧池 | 历史日期按当前池口径；需要对比时变更前导出 |
| 4 | 授权跟人不跟位置 | 调树/退会再回来仍有效 | 回收需手动取消 |
| 5 | 不套 `show_percent` | 与红利/抽水的展示折扣不一致 | 业绩是次数/占比，不是收益金额 |
| 6 | 重复结算双记 | 同一局结算两次，次数 +2 | 与现有流水同源；靠结算流程约束 |
| 7 | 授权写库异步 | 设置后立刻查可能读到旧值 | 稍等刷新；不要加缓存 |
| 8 | 授权无审计流水 | 只保留最后一次 `opter_*` | 重要操作后台自行记录 |
| 9 | 总群主无自己的业绩页 | 总群主只作为授权人/报表视角 | 本期不做联盟维度页面 |
| 10 | 报表不含「实际点数/金额」 | 后台需沿用原逻辑 | 见 §6.5 |

## 九、客户端/后台自测清单

| # | 场景 | 预期 |
| --- | --- | --- |
| 1 | 俱乐部房打一局，最大赢家超触发线 | `club_perf_contrib_info` 新增/累加 1 行；`club_guuid` = 玩家入口俱乐部 |
| 2 | 同一玩家一天贡献 3 次 | 同一行 `cnt=3` |
| 3 | 未超触发线 / 底皮 0.1 | 不计数 |
| 4 | 创建者查 §3 | `enabled=true`，`我` = 本俱乐部全部次数，`我=下放+剩` |
| 5 | 未开通代理查 §3 | `enabled=false`，全 0，命令成功 |
| 6 | 创建者给 A 开通（§5） | A 的 `enabled=true`；创建者 `下放` 增加 A 的整条线 |
| 7 | 跳级：A 已开通、B 未开通、C（B 下级）已开通 | A 的 frontier 命中 C；A 扣 C；B 为 0；C 保留；Σ 不重复 |
| 8 | 取消 C | A 的 `下放` 减少；C 页面变 0 |
| 9 | 盟主给盟友俱乐部代理开通 | `无权限` |
| 10 | 总群主给非本联盟俱乐部代理开通 | `无权限` |
| 11 | 非本俱乐部成员查 §3/§4 | `你不在该俱乐部` |
| 12 | 后台 §6 按盟主筛选 | 返回本俱乐部**已开通代理（含创建者）**；已开通 0 贡献保留；未开通不出现；`今日业绩=left_count` |
| 13 | 后台 §6 按联盟筛选 | 返回联盟内各俱乐部**已开通代理**，带身份/联盟/俱乐部名 |
| 14 | 后台 §6 越权 | `无权限` |
| 15 | 分配比例 | 后台按名单 `Σ left_count` 自算，**不等于** `left_percent` |
| 16 | 对账 | §7.3 的 `perf_cnt == flow_cnt` |
| 17 | 创建者设置 `enabled=0`（§5） | 返回 `enabled=1`；`club_perf_grant_info` 无新行/状态不变 |
