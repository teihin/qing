# 玩家扩展信息查询 — 客户端接口文档

状态：2026-11-08 服务端已实现并上传测试服，待重启 baseapp 后联调
权限：仅平台 boss / 最高 boss（`d_users.config["account"]` 的 `boss` / `bigboss` 名单）
数据源：`tbl_Account.sm_ip`（玩家 IP）+ `kbe_accountinfos.lasttime`（最后登录认证时间）

## 1. 用途

「玩家信息」弹窗按玩家 ID 补查登录/IP 类信息。做成独立命令而不是并进成员列表：

- 成员列表一页 N 人，逐个查库会放大开销；
- 独立按需查询，避免把整个俱乐部成员的 IP 一次性推给客户端。

## 2. 请求

通道：客户端 `reqHallCommand(param, context)`；服务端 `onHallCommand` 回包。

```json
{
  "header": "查询_玩家_扩展_信息",
  "user_id": "376729",
  "club_id": "911912",
  "context": "clubmg:xxxx"
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `user_id` | 是 | 玩家 ID，纯数字字符串（boss 创世号有前导 0，按字符串传） |
| `club_id` | 否 | 仅写入服务端审计日志，不参与查询 |
| `context` | 否 | 原样带回 |

## 3. 成功回包

`onHallCommand(0x200, ...)`：

```json
{
  "context": "clubmg:xxxx",
  "result": {
    "guuid": "376729",
    "name": "a5",
    "ip": "221.236.103.129",
    "last_login_time": "2026-11-07 01:28:00",
    "last_login_ts": 1762440480,
    "is_online": "0"
  }
}
```

| 字段 | 说明 |
| --- | --- |
| `guuid` / `name` | 目标玩家 ID / 昵称，用于客户端确认查的是同一人 |
| `ip` | 玩家 IP 明文；在线优先取内存最新值，离线取数据库 |
| `last_login_time` | 最后登录认证时间，**服务端已按北京时间格式化**，客户端直接展示 |
| `last_login_ts` | 同上，Unix 秒（整数）；无记录时为 `0` |
| `is_online` | `"1"` 在线 / `"0"` 离线（服务端按客户端连接状态判定） |

约定：

- 字段**恒定存在**，无数据时给 `""` 或 `0`，客户端不需要判空。
- 数值型状态用字符串（`"1"/"0"`），时间戳用整数。

## 4. 失败回包

`onHallCommand(0x301, ...)`：

```json
{"context": "clubmg:xxxx", "result": {"error": "无权访问"}}
```

| 场景 | error |
| --- | --- |
| 调用者不是平台 boss | `无权访问` |
| `user_id` 为空或非纯数字 | `玩家ID非法` |
| 玩家不存在 | `玩家不存在` |
| 数据库查询失败 | `查询失败，请稍后重试` |

## 5. 口径与已知限制（联调前必读）

1. **`last_login_time` 是登录认证时间，不是最后在线/离线时间**。玩家在线挂机不会刷新；底层重连（恢复会话）也不会刷新。若要"最后在线时间"，需要另加字段或登录流水表，本接口不提供。
2. **Web 端 IP 会是 `127.0.0.1`**。web 客户端经网关连接 KBE，`clientAddr` 拿到的是网关地址（测试服实测 `a000001/a000002/a000003` 均为 `127.0.0.1`）。原生客户端正常。如需修正，属于网关透传 X-Forwarded-For 的独立改造。
3. **在线的 IP 更准**：`Account.ip` 只在 `onClientEnabled` 赋值，落库依赖 KBEngine 定期 backup，离线读库可能滞后数分钟。服务端已按"在线读内存、离线读库"处理。
4. 服务端不返回 `device_id`、GPS、注册时间等其它字段；后续扩展按 §6 追加。

## 6. 扩展规则

本命令定位为"扩展信息"，后续加字段（设备、最后在线时间、注册时间等）遵循：

- 只**新增** `result` 的 key，不删除、不改已有 key 的名字和含义；
- 客户端按 key 解析，不按字段位置；
- 新增字段同样保持"恒定存在"。

## 7. 实现落点

- `scripts/base/Hall.py`：`_actQueryPlayerExtInfo` / `_closeQueryPlayerExtInfo` / `_playerExtInfoFail`，命令注册名 `查询_玩家_扩展_信息`。
- 权限复用 `Hall._isPlatformBoss`（`boss` + `bigboss` 名单，与俱乐部全量统计、代理链路查询同一口径；**不按 `level>=99` 判定**）。
- 审计：`[Hall]._actQueryPlayerExtInfo: boss_guuid=… target_guuid=… club_id=… context=…` 走 `DEBUG_MSG`，线上 `mylog.level` 已含 `DEBUG`，落在 `logger_baseapp.*.log`。
- 无表结构变更。注意 `tbl_Account.sm_guuid` 目前**无索引**，测试服数据量小无影响；正式服玩家量大时建议补 `idx_sm_guuid`。

## 8. 客户端 IP 短码展示（2026-11-14，6 位 Base62）

本次**未改服务端**：回包 `ip` 仍是明文，客户端 `panelClubPlayerInfo` 上屏前转成可逆短码，弹窗内不再出现明文 IP。后续后台/运维需要还原时按本节规则实现。

- 字母表（区分大小写）：`0123456789abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ`。
- 编码：IPv4 四段按网络字节序拼成 uint32；uint32 转 Base62，固定输出 6 位，左侧补 `0`。
  `62^6 = 568 亿 > 2^32`，所以是无损可逆，不需要映射表。
- 解码：6 位字符按字母表反查，`v = v*62 + index` 拼回 uint32，再按 `(v>>>24).(v>>>16&255).(v>>>8&255).(v&255)` 拆回 IPv4。
- 非 IPv4（如 IPv6）客户端返回空串，界面显示「—」。
- 示例：`221.236.103.129` → `43Ypq1`；`127.0.0.1` → `2kce4N`；`0.0.0.0` → `000000`。
- 弹窗 IP 行右侧有「复制」按钮，复制的是短码本身（`MobileManager.CopyToPhone`）。

注意：短码区分大小写，复制/转述时不要改成全大写；这是展示层遮挡，明文 IP 仍会下发到客户端内存与网络；若后续要求客户端完全拿不到明文，需服务端新增 `ip_code` 字段并停止下发 `ip`，另行决策。

后台「玩家管理」列表复用同一规则：每名玩家返回最近上报 IP 的 `ipCode`（不返回原始 IP），并可用 `ipCode` 精确检索；详情里的明文 IP/GPS 仍仅 `admin999` 可见、口径不变。后台实现见 `XuanManager/server/internal/api/ipcode.go`。
