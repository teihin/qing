## 1. 概览

### 1.1 组织层级

```
平台(boss)
  └─ 联盟(总群主)            club_union_info
       └─ 俱乐部(盟主)        club_guuid_info.union_id / union_quota
            └─ 代理           club_agent_info（只有 percent，没有额度）
                 └─ 玩家
```

- **额度只在「总群主 ↔ 盟主俱乐部」之间存在**：`club_guuid_info.union_quota`（单位分）；**独立俱乐部（未入盟）没有额度概念**，带入只看玩家自己的俱乐部积分 `club_gold`；
- 俱乐部内的代理和玩家全部走**积分**（`club_gold`），代理不再有独立额度账户；
- 抽水按 `percent` 逐层累加到代理的 **红利**（`club_agent_info.bonus`，单位分），可提取成积分。

### 1.4 俱乐部信息里的联盟字段

`查询_俱乐部_信息`（`Hall._actListClubBaseInfo`）的返回**新增三个字段**，客户端据此决定显示「创建联盟 / 加入联盟 / 我的联盟」哪个入口：

| 字段 | 说明 |
| --- | --- |
| `union_id` | 空串 = 未加入联盟；非空 = 已加入（6 位联盟码） |
| `union_apply` | 空串 = 无申请；非空 = 正在申请的联盟码（审核中） |
| `union_quota` | 俱乐部当前可用额度，**分**（未加入时恒为 0） |

| `union_id` | `union_apply` | 状态 | 建议入口 |
| --- | --- | --- | --- |
| `""` | `""` | 从未申请 | 显示「创建联盟」「加入联盟」 |
| `""` | `"123456"` | 申请中 | 显示「加入联盟」，置灰并提示审核中 |
| `"123456"` | `""` | 已加入（盟主） | 显示「我的联盟」 |

> 本期没有「退出联盟」，`union_id` 一旦有值就不会变回空，不需要区分「加入过」和「当前在」。

### 1.5 成员列表里的盟主行

总群主查「我的成员」第一层时，列表最前面会多出 **N 行盟主**（联盟内其它俱乐部的创建者），`role = 盟主`、`is_leader = 1`。

**触发条件**（三个同时满足）：

1. 调用者是联盟总群主（`club_union_info.owner_guuid`）；
2. 查的是**自己第一层**（`user_id` 留空或等于自己）；
3. **第一页**（`page = 0`）。

**虚拟行字段**

| 字段 | 值 |
| --- | --- |
| `role` | **`盟主`** |
| `is_leader` | **`1`** |
| `is_agent` | `0` |
| `percent` | 该盟主的 `union_percent`（本身提留比例，100=不上缴） |
| `quota` | 该盟主俱乐部的额度，**分** |
| `club_id` | 该盟主的俱乐部 ID |
| `team_count` | 该盟主俱乐部的成员数（**不含他自己**，2026-11-03 起与创建者行口径一致） |
| `status` | 在线 / 离线 / 游戏中 |
| `gold` | `0`（平台金币，跨俱乐部不取） |
| `club_gold` | 该盟主**在自己俱乐部**的积分余额（2026-11-03 起为真实值） |
| `today_score` / `yesterday_score` / `total_score` | 该盟主俱乐部的今日/昨日/累计输赢（积分，可负；2026-11-03 起为真实值） |
| `today_contrib_fen` / `yesterday_contrib_fen` / `total_contrib_fen` | 该盟主俱乐部的今日/昨日/累计贡献（**分**，客户端 ÷100 显示；2026-11-03 起为真实值） |
| `today_bonus_fen` / `yesterday_bonus_fen` / `total_bonus_fen` | 固定 `"0"`：盟主虚拟行不是本俱乐部代理，没有本人红利字段 |

**分页**：盟主行**占用** `per_items` 名额。第 0 页先显示盟主行，再显示 `per_items − 盟主数` 个成员；第 1 页起成员偏移扣除盟主数。顶层 `count` = 当前直属视图成员数 + 盟主行数；`number_count` 仍为本俱乐部成员数（不含盟主）。盟主行只出现在第一页，翻页不会重复。

> 成员行内的 `count` 字段仍是原 SQL 成员总数，未改；客户端分页请以顶层 `count` 为准。

> **2026-11-03 起数值为真实值**：这些盟主行以前 `club_gold` / `*_score` / `*_contrib_fen` 全部写死 `0`，现在按「该盟主自己的俱乐部」取：
> 积分取盟主本人在该俱乐部的余额；输赢按该俱乐部的 `club_member_score_info` 聚合（钱包口径），贡献同理（入口口径，单位分）。
> 服务端取不到时仍下发 `"0"`，**字段恒定存在**，客户端不需要判空、也不需要显示 `-`。
> 方案见 `doc/联盟盟主行统计字段方案.md`。

**普通成员行**：`is_leader` 恒为 `0`（盟主不在本俱乐部成员表里），`quota` 只有**创建者那一行**有值（自己俱乐部的额度），其余为 `0`；每行都带 `club_id`（本俱乐部 ID），位置与盟主行一致，**紧跟 `name` 之后**，且每行只出现一次。

**联盟创建者查询属下俱乐部（2026-11-03）**：总群主用 `查询_俱乐部_成员` 传联盟内其它俱乐部的 `club_id` 时，服务端按**该俱乐部盟主视角**返回直属列表，不再返回空列表；`agent_id` 以该俱乐部盟主为根下钻。盟主虚拟行只在总群主查**自己俱乐部**时追加，查属下俱乐部时不追加。详见 `doc/俱乐部与联盟功能-客户端接口文档.md` §2.10。

**搜索盟主（2026-11-05）**：总群主在自己俱乐部的成员列表用 `search_name_id` 搜盟主 ID 或昵称时，虚拟盟主行也会参与匹配并返回；未命中的盟主行不再被夹带；搜索无结果推空 `NumberList`（`count=0`），不再报“玩家不存在”。详见 `doc/俱乐部与联盟功能-客户端接口文档.md` §2.10。

**成员统计范围（2026-11-06）**：`查询_俱乐部_成员` 新增 `stat_scope=line|self`（缺省 `line`）：
① `line` 保持原口径，六项输赢/贡献是“本人 + 整条下线”，盟主行仍按俱乐部汇总；
② `self` **只对单成员 `user_id` 查询生效**，六项切为本人；`team_count` 仍为整条下线人数；`ALL` 列表忽略；
③ 新增 `today_bonus_fen` / `yesterday_bonus_fen` / `total_bonus_fen`，**仅单成员 `stat_scope=self`** 返回本人代理红利（今日/昨日为 `usr_income_info` 新增，总为未提取 `bonus` + 已提取），普通玩家/`line`/`ALL`/搜索固定 `"0"`；
④ 完整字段与折扣规则见 `doc/俱乐部与联盟功能-客户端接口文档.md` §2.10、`doc/代理收益客户端展示折扣-客户端与后台接口文档.md`。

**联盟内单成员详情（2026-11-06）**：`club_id` 所属俱乐部已加入联盟、且 `user_id` 指定具体玩家时，满足权限的调用者会拿到该玩家在**本联盟内所有已加入俱乐部**的数据，每个俱乐部一行，仍走 `NumberList`：
① 权限：平台 boss/bigboss、该联盟总群主、请求俱乐部创建者/管理者、目标玩家本人；其余调用者仍按原单俱乐部逻辑（查不到仍回“玩家不存在！”）；
② `NumberList` 可能多行（同一 `guuid`、不同 `club_id`），每行 `club_id` 是玩家**实际所属俱乐部**，`club_gold` / `role` / `is_agent` / `percent` / `note` / 统计字段 / 分组字段 / `dark_percent` 均按该行俱乐部口径；
③ 排序：**请求俱乐部优先**（命中时首行为它），其余按 `club_id` 升序；
④ 顶层 `number` 固定 `"0"`，`count` = 实际返回行数；
⑤ 玩家在本联盟内没有俱乐部时推**空 `NumberList`**（`count="0"`），不再回“玩家不存在！”；
⑥ 未入盟俱乐部、`user_id=ALL`、模糊搜索行为不变；只返回 `union_id` 相同的俱乐部，玩家在其它联盟的俱乐部不返回。

### 1.6 联盟共享房间（2026-11-03 新增）

- **未加入联盟**：每个俱乐部自己一套自动房；
- **加入联盟后**：联盟内所有俱乐部统一使用**总群主俱乐部**的一套房间；成员俱乐部自己的旧房不再展示、不再允许进入，正在进行的牌局可自然结束；
- `查询_所有_俱乐部_房间` / `查询_俱乐部_房间_信息` 对联盟成员返回同一套房间，不按成员俱乐部重复；
- 房间 `club_guuid` / `roomClubName` 仍是总群主俱乐部；新增 **`union_name`** 字段（未入盟为空串，字段恒定存在）；
- `is_zip_result='1'` 的 9 元数组末尾追加第 10 个元素 `union_name`，老客户端忽略即可；
- 进房成功后 `Account.roomSetting` 新增 **`union_id`**（6 位联盟码；非联盟房/成员旧房为空串）；客户端仅在 `union_id` 非空时按联盟房处理，不再用 `club_id` 限制玩家所属俱乐部；
- 进房建议客户端传**玩家自己的俱乐部 ID**；服务端对传 owner 俱乐部或空值会兜底映射到玩家自己的俱乐部，保证入口俱乐部/钱包/额度归属正确；
- `查询_玩家_加入房间的所属俱乐部_信息` 在联盟房返回玩家自己的俱乐部；
- 自动房只为总群主俱乐部补齐，成员俱乐部不再建房；房间容量沿用总群主俱乐部的自动房配置（当前线上 7 间）。

> 成员俱乐部旧房按“隐藏 + 拒绝新进入 + 不补建”处理，不主动关闭正在进行的牌局；服务重启后旧自动房自然消失。

## 2. 建联盟：`创建_联盟`

一个俱乐部创建者只能建一个联盟，创建后自动成为**总群主**并生成 6 位**联盟码**。

**请求**

```json
{"header":"创建_联盟", "club_id":"567671", "union_name":"XX联盟", "context":"ctx1"}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `club_id` | 是 | 自己的俱乐部（必须是创建者本人） |
| `union_name` | 是 | 联盟名字，不能为空 |

**返回**：`GC_OK`

**推送 `ClubUnionCreate`**

```json
{"union_id": "123456"}
```

**校验顺序与失败文案**

| 顺序 | 校验 | 文案 |
| --- | --- | --- |
| 1 | 名字非空 | `联盟名字不能为空` |
| 2 | 俱乐部存在 | `俱乐部不存在` |
| 3 | 自己是创建者 | `只有俱乐部创建者可以创建联盟` |
| 4 | 自己的俱乐部还没联盟 | `你已经有联盟了，不能重复创建` |
| 5 | 自己账号还没建过联盟 | `你已经有联盟了，不能重复创建` |
| 6 | 联盟码生成成功 | `联盟号生成失败，请重试` |

**副作用**

- `club_union_info` 落一行，`union_quota = 0`；
- 自己的俱乐部自动绑定该联盟（`union_id` 写入），**额度从 0 开始**——必须先由平台注资、再由自己给自己授信，才能带入。

## 3. 我的联盟：`查询_我的_联盟`

总群主查看联盟信息、池余额、盟主列表。

**请求**

```json
{"header":"查询_我的_联盟", "context":"ctx2"}
```

**推送 `ClubMyUnion`**

```json
{"ClubMyUnion": {
  "union_id": "123456",
  "union_name": "XX联盟",
  "union_quota": "0",
  "members": [
    {"club_id": "567671", "club_name": "a", "owner_guuid": "718968", "owner_name": "abc", "union_quota": "0", "union_percent": "100"},
    {"club_id": "535696", "club_name": "b", "owner_guuid": "580629", "owner_name": "def", "union_quota": "1000000", "union_percent": "90"}
  ]
}}
```

| 字段 | 说明 |
| --- | --- |
| `union_quota` | 联盟池余额，**分** |
| `members` | 联盟内所有俱乐部（含总群主自己那家） |
| `members[].union_quota` | 该俱乐部当前可用额度，**分** |
| `members[].union_percent` | 该盟主当前上缴比例，**0~100 整数**；100=不抽，90=上缴 10% |

**失败**：`你还没有联盟`

## 4. 申请加入：`申请_加入_联盟`

盟主用联盟码申请加入总群主的联盟。

**请求**

```json
{"header":"申请_加入_联盟", "club_id":"535696", "union_id":"123456", "context":"ctx3"}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `club_id` | 是 | 自己的俱乐部 |
| `union_id` | 是 | 对方的 6 位联盟码 |

**返回**：`GC_OK`；同时向总群主推送 `ClubUnionApply`（待审列表，与 `查询_联盟_加入申请` 同结构）。总群主离线则不推，登录后查询。

**失败文案**

| 场景 | 文案 |
| --- | --- |
| 俱乐部不存在 | `俱乐部不存在` |
| 不是创建者 | `只有俱乐部创建者可以申请加入联盟` |
| 已有联盟 | `你的俱乐部已经有联盟了，不能重复加入` |
| 已有在审申请 | `已有申请在审核中，请等待总群主处理` |
| 联盟码不存在 | `联盟号不存在` |
| 申请自己的联盟 | `不能申请加入自己的联盟` |

> 申请只写 `union_apply`，**不会**立刻绑定；审批通过才写 `union_id`。

## 5. 审批

### 5.1 待审列表：`查询_联盟_加入申请`

**请求**

```json
{"header":"查询_联盟_加入申请", "context":"ctx4"}
```

（`union_id` 可不传，服务端按“自己是不是总群主”自动取）

**推送 `ClubUnionApply`**

```json
{"ClubUnionApply": [
  {"club_id":"535696","club_name":"b","owner_guuid":"580629","owner_name":"def"}
]}
```

**失败**：`你还没有联盟` / `只有总群主可以查看申请`

### 5.2 同意 / 拒绝

```json
{"header":"同意_加入_联盟", "club_id":"535696", "context":"ctx5"}
{"header":"拒绝_加入_联盟", "club_id":"535696", "context":"ctx6"}
```

| 项 | 说明 |
| --- | --- |
| 方向 | **由命令名决定**，不需要传 `agree`（老客户端传了也兼容） |
| 同意 | 对方俱乐部 `union_id` 写入、`union_apply` 清空 → 成为盟主 |
| 拒绝 | 只清 `union_apply`，对方可以再申请 |

**事件推送（2026-11-03 新增）**

- **同意**：
  - 申请俱乐部创建者收到 `ClubUnionApplyResult`：
    ```json
    {"union_id":"916139","union_name":"大大联盟","club_id":"875111","agree":1}
    ```
  - 申请俱乐部创建者同时收到 `ClubUnionQuota`（`is_owner=0`，新加入俱乐部额度默认 0、比例默认 100）：
    ```json
    {"union_id":"916139","union_quota":"0","is_owner":0,"union_percent":"100"}
    ```
  - 总群主收到 `ClubUnionApply` 最新待审列表（可能为空，空列表也是合法 JSON：`{"ClubUnionApply": []}`）
- **拒绝**：
  - 申请俱乐部创建者收到 `ClubUnionApplyResult`（`agree=0`）
  - 总群主收到 `ClubUnionApply` 最新待审列表

**失败文案**

| 场景 | 文案 |
| --- | --- |
| 俱乐部不存在 | `俱乐部不存在` |
| 没有待审申请 | `该俱乐部没有待处理申请` |
| 不是总群主 | `只有总群主可以审批` |
| 对方已加入其它联盟 | `该俱乐部已加入其它联盟` |

## 6. 授信：`授信_联盟_额度`

总群主把自己的联盟额度分给盟主俱乐部。

**请求**

```json
{"header":"授信_联盟_额度", "club_id":"535696", "quota_fen":1000000, "context":"ctx7"}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `club_id` | 是 | 目标俱乐部（**可以是自己**） |
| `quota_fen` | 是 | **分**，正数授出、负数收回；1 万元 = 1000000 |

**效果**

```
联盟池 −quota_fen
目标俱乐部 union_quota +quota_fen
```

两条流水都记 `opt_type='额度联盟授信'`：
- 联盟池那条：`user_guuid` = 总群主，`club_guuid` = 总群主自己的俱乐部；
- 俱乐部那条：`user_guuid` = 盟主，`club_guuid` = 目标俱乐部。

**事件推送（2026-11-03 新增）**

- 目标俱乐部创建者收到 `ClubUnionQuota`（`is_owner=0`，带新的 `union_quota` 和 `union_percent`）；
- 总群主收到 `ClubUnionQuota`（`is_owner=1`，带新的联盟池余额）；
- 目标是总群主自己的俱乐部时只推 `is_owner=1`；
- 授信失败/回滚不推送。

**失败文案**

| 场景 | 文案 |
| --- | --- |
| 自己没联盟 | `你还没有联盟` |
| 俱乐部不存在 | `俱乐部不存在` |
| 金额为 0 | `授信金额不能为 0` |
| 目标不在自己联盟 | `该俱乐部不在你的联盟里` |
| 联盟池不够 | `你的联盟额度不足` |
| 收回时对方余额不够 | `目标俱乐部额度不足，收回失败`（联盟池会自动回滚） |

> 收回时如果目标俱乐部额度不足，会整笔失败并回滚联盟池，不会出现“池扣了但俱乐部没退”。

## 9. 代理红利

> **2026-11-05 起**：本文红利、联盟红利、成员贡献等收益金额受该收益归属代理的 `club_agent_info.show_percent` 控制（未设置=100），客户端看到的是折扣值（`100`=真实值，`80`=80%）；后台 `/hall/command` 返回真实值。详见 `doc/代理收益客户端展示折扣方案.md`。

**推送 `ClubBonus`**

```json

```

`bonus_fen` 单位分，`bonus` 已换算成元。

### 9.2 明细：`查询_俱乐部_红利_明细`

**请求**


## 10. 联盟抽成与联盟红利

总群主能看到、并控制每个盟主俱乐部抽水的上缴比例。

### 10.1 分配模型

```
原来：  盟主俱乐部创建者(100%) → 代理A(50%) → 代理B(30%) → 玩家
现在：  总群主(100%) → 盟主(90%) → 代理A(50%) → 代理B(30%) → 玩家
```

盟主的 `union_percent` 由总群主设置，含义与其他层完全一致：**本层截留、剩余往上传**。

抽水 100 元、`union_percent=90`、俱乐部链 代理A 50% / 代理B 30%：

| 层 | 拿到 |
| --- | --- |
| 总群主 | 10 |
| 代理A | 45 |
| 代理B | 13.5 |
| 盟主（链顶拿剩余） | 13.5 |

全部进各自红利，**不碰额度**。

### 10.2 设置比例：`设置_联盟_盟主_比例`

```json
{"header":"设置_联盟_盟主_比例", "club_id":"535696", "percent":90, "context":"ctx10"}
```

| 项 | 说明 |
| --- | --- |
| 权限 | 只有总群主；其它返回 `只有总群主可以设置` |
| 目标 | 必须在本联盟，否则 `该俱乐部不在你的联盟里` |
| 取值 | `0~100`，默认 **100 = 不抽** |
| 流水 | `opt_type='联盟比例'`，`remark` 记 `100→90` |

**事件推送（2026-11-03 新增）**：设置成功后向目标盟主推送 `ClubUnionQuota`（`is_owner=0`，带新的 `union_percent`）；目标是总群主自己的俱乐部不推。

### 10.3 查余额：`查询_联盟_红利`

```json
{"header":"查询_联盟_红利", "context":"ctx11"}
```

推送 **`ClubUnionBonus`**：

```json
{"owner_bonus_fen": "12345", "owner_bonus": "123.45"}
```

### 10.4 查明细：`查询_联盟_红利_明细`

```json
{"header":"查询_联盟_红利_明细", "count":20, "page":0, "context":"ctx12"}
```

推送 **`ClubUnionBonusList`**：

```json
{"ClubUnionBonusList":[
  {"number":"0","count":"12","date":"2026-11-03 20:15:02",
   "club_id":"535696","bonus":"10","room_id":"772975","player":"a3"}
]}
```

| 字段 | 说明 |
| --- | --- |
| `club_id` | 来源盟主俱乐部 |
| `bonus` | 本局上缴金额，**分** |
| `player` | 这一局贡献抽水的玩家昵称 |

### 10.5 提取：`提取_联盟_红利`

```json
{"header":"提取_联盟_红利", "extract_gold":10, "context":"ctx13"}
```

- `extract_gold` **单位元、≥1 整数**；
- `owner_bonus − N*100`，总群主自己俱乐部的 `club_gold += N`，余数留在 `owner_bonus`；
- 流水 `opt_type='联盟红利提取'`（与俱乐部代理红利的 `代理红利提取` 区分）。

> 与 `提取_俱乐部_红利` 的区别：前者提取**联盟抽成**（`club_union_info.owner_bonus`），后者提取**代理分成**（`club_agent_info.bonus`），两个池互不影响。

| 字段 | 说明 | 单位 |

| `today_income_fen` / `today_income` | 今日**新增联盟红利**（`usr_income_info` 中 `remark5='unionroot'`） | 分 / 元 |

## 11. 创建俱乐部收费（2026-11-03 改为客户端扣费）

`创建_俱乐部` **服务端不再校验余额、不扣钻、不退款**；请求与返回不变：

```json
{"header":"创建_俱乐部", "club_name":"xx", "club_mode":"1", "club_prop":""}
```

**客户端扣费流程**

```json
// 1) 先创建；同步失败（重名 / 超过 10 个）会直接返回 GC_FAILED，此时不产生扣费
{"header":"创建_俱乐部", "club_name":"xx", "club_mode":"1", "club_prop":""}

// 2) 收到成功响应后，用消费名扣钻
{"header":"玩家_消费_命令", "consume_type":"创建俱乐部", "money":10000, "money_type":"stone"}
```

| 项 | 说明 |
| --- | --- |
| `money` | **钻石个数**，不是分 |
| 余额不足 | `玩家_消费_命令` **仍返回成功并扣到 0**，客户端必须调用前判断 `stone >= 费用` |
| boss 账号 | 消费命令不扣、不写流水（`decStoneNumber` 对 boss 空转） |
| 流水 | `usr_consume_info`：`消费-创建俱乐部`；`usr_cash_water`：`option_type='消费'`、`remark4='创建俱乐部'`、`money_type='stone'` |
| 服务端校验 | **不校验是否已扣费**；直接调 `创建_俱乐部` 可以绕过收费 |

> `创建_俱乐部` 的 `GC_OK` 只代表受理成功，最终落库在异步回调完成；极小概率异步失败时已扣费，按运营补钻处理。

## 12. 带入规则变化（重要）

带入不再扣「最近已授信代理」的额度，改扣**俱乐部额度**。

| 场景 | 结果 |
| --- | --- |
| 俱乐部未加入联盟（独立俱乐部） | **不参与联盟额度**：不校验、不占用、不回补 `union_quota`；只要玩家自己的俱乐部积分 `club_gold` 足够即可带入 |
| 已加入联盟，俱乐部额度 < 本次带入 | 拒绝，玩家积分不动 |
| 已加入联盟，结算 | 回补到**同一个**俱乐部额度池 |
| 审批带入的“管理员追加”部分（已入盟） | 从俱乐部额度扣，结算时不回补（与改动前一致） |
| 审批带入的“管理员追加”部分（未入盟） | 不占额度、不扣积分，直接计入本局带入（无联盟池可占用/回补） |
| 抽水 | **不再回补额度**，全部进代理红利 |

> **切换联盟的限制**：局中不允许加入/退出联盟。俱乐部在加入或退出联盟前，必须先关闭本俱乐部所有房间；**服务端在同意加入时会检查，若该俱乐部仍有未结束的房间/玩家，返回 `{"error": "该俱乐部还有未结束的房间，请先关闭所有房间"}`，不写入 `union_id`**。否则带入时按当时 `union_id` 判定额度口径，结算可能落到另一套口径，导致额度占用/回补对不上。

**代理上分**：仍不扣代理自己的积分（钱在玩家带入时从俱乐部额度出）；**非代理上分**：扣自己积分，流水记 `积分赠送` / `积分受赠` 两条。

**玩家间赠送**：俱乐部内不再限制授信代理一致（额度统一后同俱乐部即同账户），`CanGiveClubGold` 恒放行，只校验双方都在俱乐部。

## 15. 错误文案总表

| 文案 | 场景 |
| --- | --- |
| `联盟名字不能为空` | `创建_联盟` 名字空 |
| `只有俱乐部创建者可以创建联盟` | 非创建者建联盟 |
| `你已经有联盟了，不能重复创建` | 重复建 / 俱乐部已有联盟 |
| `联盟号生成失败，请重试` | 6 位码连续冲突 |
| `只有俱乐部创建者可以申请加入联盟` | 非创建者申请 |
| `你的俱乐部已经有联盟了，不能重复加入` | 已入盟还申请 |
| `已有申请在审核中，请等待总群主处理` | 重复申请 |
| `联盟号不存在` | 联盟码错误 |
| `不能申请加入自己的联盟` | 申请自己的联盟 |
| `你还没有联盟` | 总群主/盟主查询类命令 |
| `只有总群主可以查看申请` | 非总群主看待审 |
| `该俱乐部没有待处理申请` | 审批一个没申请过的俱乐部 |
| `只有总群主可以审批` | 非总群主审批 |
| `该俱乐部已加入其它联盟` | 审批时对方已入盟 |
| `该俱乐部还有未结束的房间，请先关闭所有房间` | 同意加入联盟时，该俱乐部仍有未结束房间/玩家 |
| `该俱乐部不在你的联盟里` | 授信给别的联盟的俱乐部 |
| `授信金额不能为 0` | `quota_fen = 0` |
| `你的联盟额度不足` | 联盟池不够 |
| `目标俱乐部额度不足，收回失败` | 负数授信但对方余额不够 |
| `无权限` | 非 boss 调 `增加_联盟_额度` |
| `注资金额必须大于 0` | 注资传 0 或负数 |
| `你不在该俱乐部` | 提取红利但不在代理树 |
| `提取金额必须是整数元` | `extract_gold` 传小数 |
| `每次至少提取 1 元` | `extract_gold < 1` |
| `红利不足，当前可提 X 元` | `bonus` 不够 |
