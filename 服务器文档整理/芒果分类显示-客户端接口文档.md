## 1. 消息与字段

现有 `当前_玩家_消息` 字段保持不变；本次新增/调整 7 个芒果展示字段：

| 字段 | 类型 | 含义 | 示例（2/5、2 人） |
| --- | --- | --- | --- |
| `mang_show_state` | string | 0=圈芒(默认)，1=休芒，2=揍芒 | `"1"` |
| `mang_show_pool_amount` | string | 当前真实芒果池 `mang_pi_times + xiu_mang_times`，休/揍共用 | `"30"` |
| `mang_show_xiu_count` | string | 休芒**倍率等级**：圈 x1，首休 x2，次休 x3 | `"2"` |
| `mang_show_xiu_amount` | string | 休芒**实际累计扣款**（内部/对账用） | `"10"` |
| `mang_show_quan_count` | string | 固定 `"1"`（圈芒默认倍数） | `"1"` |
| `mang_show_zou_count` | string | 揍芒**倍率等级**：圈 x1，首揍 x2 | `"2"` |
| `mang_show_zou_amount` | string | 揍芒**实际累计扣款** | `"10"` |

皮池字段：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `mang_pi_hand_amount` | string | **每手皮池展示值** = `di_times × 在座人数`（2/5 房 2 人 = 4） |
| `mang_pi_times` | string | 实际累计皮池，供服务端下注/兼容使用，**不要拿它显示每手皮池** |

说明：

- 所有字段沿用当前消息的字符串数值格式，客户端按字符串转数字；
- `mang_show_state` 决定显示哪一行，**不要**再用三个 count 判断；
- 圈芒手算一级：圈 `x1`，首休/首揍 `x2`，后续 `x3/x4`；`mang_show_xiu_count/zou_count` 已经是倍率等级；
- 休芒/揍芒**展示金额统一用 `mang_show_pool_amount`**；`mang_show_xiu_amount` / `mang_show_zou_amount` 是实际累计，不要直接显示；
- `mang_show_pool_amount` = 当前真实芒果池（皮池 + 休/揍池）；最低下注仍以 `min_score` 为准，两者在桌上分地板生效时可能不同；
- `mang_show_quan_count` 固定为 1，客户端显示 `x1` 即可；
- 皮池行用 `mang_pi_hand_amount`，不要用 `mang_pi_times`；
- 老客户端忽略 `mang_show_state` 和新字段即可。

## 3. 客户端显示规则

### 3.1 按状态只显示一行

```text
state == 0：圈芒 x1 10     皮池 4
state == 1：休芒 x2 30     皮池 4
state == 2：揍芒 x2 30     皮池 4
```

- `state == 0`：显示圈芒，隐藏休芒、揍芒；
- `state == 1`：显示休芒，隐藏圈芒、揍芒；
- `state == 2`：显示揍芒，隐藏圈芒、休芒；
- 皮池 `mang_pi_hand_amount` 始终显示；`mang_pi_times` 是实际累计池，不作为每手皮池显示。

### 3.2 关键约束

- **不要**用三个 `if` 判断哪个 count 非 0；
- **不要**同时显示两行或三行；隐藏类型的计数/金额可能仍 >0，但当前状态不显示它，这是预期；
- 圈芒行固定 `x1`，金额直接用 `mang_show_pool_amount`（state=0 时等于皮池 `mang_pi_times`），不要客户端按人数/底注反推；
- 休芒/揍芒行分别用 `mang_show_xiu_count` + `mang_show_pool_amount`、`mang_show_zou_count` + `mang_show_pool_amount`；
- x 是显示等级：圈 x1、首休/首揍 x2、后续 x3/x4；实际休/揍扣费从 1 倍起（首休实际 5/人），不要用 x×基数反推金额；
- 金额总额已经包含累计皮池和本类型实际扣款，客户端不要再加；
- `mang_show_xiu_amount` / `mang_show_zou_amount` 是实际累计扣款，只用于对账，不要直接显示；
- 不能用旧字段 `xiu_mang_count`/`xiu_mang_times` 充当休芒行（它们是休+揍合并值，会把揍芒误显示成休芒）；
- state 对应的行即使金额为 0 也显示 0（例如全员没钱/部分扣款），不要按金额隐藏；
- 皮池行用 `mang_pi_hand_amount`（每手皮池 = `di_times` × 在座人数），不要用 `mang_pi_times`（实际累计池，会逐手增长）；
- state=1 时名称/美术必须是休芒；state=2 是揍芒；圈芒只在 state=0 显示且固定 x1。出现“圈芒 x2”属客户端 state→名称映射错误，不是服务端状态。

### 3.3 旧客户端

- 旧客户端仍读取 `xiu_mang_times`、`xiu_mang_count`、`mang_pi_times`，显示原来的合并芒果/皮池；
- 新字段是追加字段，旧客户端忽略即可；
- 新客户端不要同时显示旧的合并芒果行；
- 新客户端皮池行必须用 `mang_pi_hand_amount`；`mang_pi_times` 仅为兼容/实际池，不再作为每手皮池展示；
- 按早先 6 字段（无 `mang_show_state`）实现的测试客户端必须同步升级；新服务端 `mang_show_quan_count` 固定为 `"1"`，旧逻辑会把它当非 0，导致多行显示。

### 3.4 结算结束消息

`结算_结束_消息` **不携带芒果字段**；客户端只读 `当前_玩家_消息`：

- 状态跟链走：荒/揍后下一手 `当前_玩家_消息` 带 1（休芒）/2（揍芒），客户端直接显示；
- 普通非荒、非揍手链重置后，下一手 `当前_玩家_消息` 带 0（圈芒）；
- 普通手本身（前面是荒/揍）仍显示上一状态；普通手结算后的下一手回圈芒；
- 如果 `is_exit=True` 或房间结束，该玩家可能没有下一局 `当前_玩家_消息`，结算消息里也没有 `state`，不能拿结算消息当下一局状态；
- 如果房间继续，下一局 `当前_玩家_消息` 会带结算后的 `state`（1/2/0）及对应字段，客户端以它为准。

## 4. 状态与生命周期

| 状态 | 进入 | 显示 | 退出 |
| --- | --- | --- | --- |
| 0 圈芒 | 初始 / 普通手链重置后的下一手 | 圈芒 x1 + 基础金额 | 荒→1；揍芒→2 |
| 1 休芒 | 荒局 `_EndRound` 结算后，保持到普通手链重置 | 休芒 xN + 本类型累计 | 普通手结算后下一手→0；揍芒→2 |
| 2 揍芒 | 揍芒 `_EndRound` 结算后，保持到普通手链重置 | 揍芒 xN + 本类型累计 | 普通手结算后下一手→0；荒→1 |

- 状态不在每手 `_init` 清零，跟链走：荒/揍后的 1/2 保持到下一手，`当前_玩家_消息` 继续带；
- 普通手本身仍显示上一状态；普通手 `_EndRound` 链重置后，下一手 `当前_玩家_消息` 回 0（圈芒）；
- 最近一次事件覆盖状态；切换时隐藏类型的本类型计数/金额保留，切回来继续用；
- 普通非荒、非揍手结束当前链时，休/揍计数金额清零；
- 圈芒基础金额按消息时在座人数计算，不累计；
- `结算_结束_消息` 不携带芒果字段；客户端只读 `当前_玩家_消息` 即可；
- baseapp 重启后从 0 状态开始，不恢复。

## 5. 兼容性

1. 不新增消息、不新增命令、不新增路由；
2. 字段追加在现有 `当前_玩家_消息`，老客户端忽略；
3. 现有字段 `xiu_mang_times`、`xiu_mang_count`、`mang_pi_times` 语义不变；
4. 字段缺失时客户端按 0 处理；如果 `mang_show_state` 不存在，回退旧合并芒果行，不要只显示空白；
5. 不改结算、补芒账本、皮池分配和数据库；
6. 客户端不需要本地计算金额，直接展示服务端字段。
