## 1. 消息与字段

现有 `当前_玩家_消息` 字段保持不变；本次新增 6 个**展示字段**：

| 字段 | 类型 | 含义 | 示例 |
| --- | --- | --- | --- |
| `mang_show_xiu_count` | string | 当前链休芒发生次数 | `"3"` |
| `mang_show_xiu_amount` | string | 当前链休芒实际扣款合计 | `"1360"` |
| `mang_show_quan_count` | string | 当前链圈芒发生次数 | `"1"` |
| `mang_show_quan_amount` | string | 当前链圈芒标记金额合计（理论口径） | `"280"` |
| `mang_show_zou_count` | string | 当前链揍芒发生次数 | `"2"` |
| `mang_show_zou_amount` | string | 当前链揍芒实际扣款合计 | `"520"` |

皮池继续使用现有字段：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `mang_pi_times` | string | 当前皮池金额（`GetAllMangPiTimes() + table_mang_times`） |

说明：

- 所有字段沿用当前消息的字符串数值格式，客户端按字符串转数字，不要按 int 直接解析；
- 金额单位与牌桌筹码一致，2 皮房为 2 皮单位，10 皮房为 10 皮单位；
- 休芒/揍芒金额为实际扣款；圈芒金额是 `quan_mang_show` 标记口径（每个在座玩家按底注标记），不是实际扣款；
- 新字段只用于显示，服务端不要求客户端回传；
- 老客户端不解析这些字段即可；
- **字段缺失（服务端未更新）时按 0 处理；6 个字段都不存在时回退显示旧"芒果"行，不要报错。**
- 圈芒字段当前由服务端按"事件次数 + 链累计"计算；若产品确认竞品是"倍数/单次荒"，服务端会调整字段值，客户端只展示，不要按人数/倍数反推。

## 3. 客户端显示规则

### 3.1 四行显示

```text
休芒 x3 1360
圈芒 x1 280
揍芒 x2 520
皮池 4100
```

### 3.2 隐藏规则

- `mang_show_*_count <= 0`：该行不显示；
- `count > 0` 但 `amount == 0`：仍显示该行，金额显示 0；
- `mang_pi_times` 继续按现有"皮池"显示，不参与隐藏判断；
- 新客户端不要同时显示旧的合并"芒果"行，避免和三类重复；
- 休芒+圈芒+揍芒三行合计与旧 `xiu_mang_times` 不一致属正常：圈芒是标记值不进旧值，补芒/站起也会改变旧值，口径不同，可能大也可能小；皮池另算，不参与比较；
- 新老客户端并存时显示口径不同：老端显示当前池，新端显示链上累计；
- 荒局结算过程中的 `当前_玩家_消息` 可能还是累加前的旧值，桌面到下一手开局才刷新，属预期；
- 圈芒行不要用 `count × 人数 × 底注` 自行推算，直接展示服务端字段；口径确认前以服务端值为准。

### 3.3 旧客户端

- 旧客户端仍读取：
  - `xiu_mang_times`：合并后的休/揍金额；
  - `xiu_mang_count`：合并后的次数；
  - `mang_pi_times`：皮池；
- 新字段是追加字段，旧客户端忽略即可，不影响旧布局。

## 4. 含义与边界

| 行 | 次数 | 金额 |
| --- | --- | --- |
| 休芒 | 荒局事件次数 | 本次荒局未 exit 玩家实际增加的 `xiu_mang_score` 之和 |
| 圈芒 | 荒局中产生圈芒的事件次数（x 含义待确认） | 本次荒局在座玩家 `quan_mang_show` 之和（标记值，理论口径；是否链累计待确认） |
| 揍芒 | 揍芒事件次数 | 本次揍芒 `is_pass` 玩家实际增加的 `xiu_mang_score` 之和 |
| 皮池 | 不显示次数 | 现有 `mang_pi_times` |

注意：

- 金额是**实际扣款**的只有休芒、揍芒；圈芒是标记口径，不产生真实扣款；
- 补芒补款不计入这三类金额；
- 次数当前按事件次数下发，不是玩家人数；圈芒的 x 含义待确认（见方案 §10.8）；
- 皮池 `mang_pi_times` 和三类统计相互独立；
- 休芒+圈芒+揍芒三行合计和旧合并芒果的差异符合设计（口径不同，可能大也可能小），客户端不要做对账或反推；皮池另算；
- 圈芒的 x 与金额口径待确认（事件次数/倍数/当前手；链累计/单次荒），客户端不要硬编码；
- 休芒/揍芒金额当前按链累计，若竞品是当前池，服务端会调整，客户端仍只展示。

## 5. 生命周期

- 第一次开局全部为 0；
- 每个荒/揍事件累加一次；
- 普通非荒、非揍手结束当前链时，6 个显示字段同时清零；
- **不按手清零**，跟 `xiu_mang_count` 的链清零点一致；
- 三类清零时，`mang_pi_times` 皮池不清；
- 玩家离座/观战/结算不单独清，跟当前链一致；
- 荒局被三花敲牌打断时不累加、不残留；
- baseapp 重启后从 0 开始，不恢复。

## 6. 兼容性

1. 不新增消息、不新增命令、不新增路由；
2. 字段追加在现有 `当前_玩家_消息` 里，老客户端忽略；
3. 现有字段 `xiu_mang_times`、`xiu_mang_count`、`mang_pi_times` 语义不变；
4. 字段缺失时客户端按 0 处理并回退旧"芒果"行，服务端不加版本位或能力开关；
5. 不改结算、补芒账本、皮池分配和数据库；
6. 客户端不需要本地计算金额，直接展示服务端字段。
