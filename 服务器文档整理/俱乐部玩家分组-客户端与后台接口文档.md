## 1. 通用说明

### 1.1 通道与响应

- 客户端→服务器：`reqHallCommand(param, context)`；`param` 为 JSON 字符串，必须含 `"header"`；
- 服务器→客户端：先 `onMessage("<路由>", json)` 推送业务数据，再 `onHallCommand(0x200, {"context":"..."})` 回执；
- 后台→服务器：HTTP `GET /hall/command`，返回 `{"ret_code":512,"ret_result":"<json 字符串>"}`；
- `context` 原样回传（推送与回执都带）；
- 通用返回码、JSON 包裹、异常路径与 `doc/俱乐部代理与邀请码-客户端接口文档.md` §1 一致，本文不重复；
- 服务端内部用 `0x500` 标记“不同步返回”（该码不下发），最终经 `onHallCommand` 送达：`0x200` 成功 / `0x301` 失败；
- 本组分命令是“先算后推”：成功时**数据在推送里**，`onHallCommand` 只带 `context`；校验失败立即回 `0x301`；
- 失败体：`{"context":"<ctx>","result":{"error":"<文案>"}}`，下文错误表只列 `result.error`。

### 1.2 管理域与权限（先看这段）

分组不是“每个俱乐部各一套”，而是按**管理域**：

| 请求 `club_id` 的状态 | 管理域 | 谁能管理/查看 |
| --- | --- | --- |
| 已入盟（`club.union_id != ''`） | `scope_type="union"`、`scope_id=union_id` | **仅联盟总群主**；联盟内所有成员俱乐部共用一套分组 |
| 未入盟 | `scope_type="club"`、`scope_id=club_guuid` | **仅俱乐部创建者** |

- 请求只需带 `club_id`；服务端按该俱乐部的 `union_id` 解析管理域，不要求客户端传 `union_id`。
- 总群主可以带**任一成员俱乐部**的 `club_id` 调用，都解析到同一个联盟域。
- 成员俱乐部创建者（盟主）、俱乐部管理员 `club_manage`、代理、普通玩家：调用分组命令返回 `无权访问`；成员列表里的分组字段恒为 `"0"`/`""`。
- 大厅模式（`game_mode != 'club'`）：所有命令返回 `俱乐部功能未启用`。
- `group_id` 必须属于解析出的管理域；跨域的 `group_id` 查不到数据（成员列表筛选返回 0 人，其余命令报 `分组不存在`）。

### 1.3 统计口径

分组的 9 项统计都是**当前分组成员本人**的快照（扁平求和，**不递归下线/团队**），不是“入组后新增”：

| 字段 | 单位 | 口径 |
| --- | --- | --- |
| `today_score` / `yesterday_score` / `total_score` | 积分（可负） | 分组成员**本人**在管理域内的今日/昨日/累计输赢；联盟域=成员在各成员俱乐部之和 |
| `today_contrib_fen` / `yesterday_contrib_fen` / `total_contrib_fen` | 分 | 分组成员**本人**在管理域内创造的今日/昨日/累计抽水 |
| `today_bonus_fen` / `yesterday_bonus_fen` | 分 | 分组成员**本人**当日/昨日新增代理红利（`usr_income_info` 分成流水，排除基线行与联盟上缴） |
| `total_bonus_fen` | 分 | 分组成员**本人**累计代理红利：未提取 `club_agent_info.bonus` + 已提取 `代理红利提取`（元×100）；**不含**总群主的 `owner_bonus/unionroot/uniondark/联盟红利提取` |

- **与成员列表的口径差异**：成员列表的输赢/贡献是“该成员 + 整条下线”（团队口径）；分组统计是**成员本人**，两者不相等，不要互相对账。
- 换组后历史数据整体归到新组；移出后不再计入任何组。
- 只统计已结算数据（`OverRoom`/`SettleRealtime` 写入），牌局进行中不实时变化。
- **真实值**：分组统计与预警都不套 `show_percent` 展示折扣；成员列表原有的 `today_score` 等仍按行内成员生效折扣展示。
- 分红单位是**分**，客户端展示 ÷100；积分可负。
- 今日/昨日红利是“当日新增”，与 `total_bonus_fen`（余额 + 已提取）不是同一维度，今日+昨日+历史 ≠ 总。

### 1.4 预警口径

- 分组的预警是**组级三态**：`NULL`=未设置（回退代理线）、`0`=明确关闭（阻断回退）、`1`=开启（用组区间）。
- 判断对象是**容器聚合的今日输赢**：分组规则看该分组的 `today_score`；代理线规则看 home 俱乐部该代理整条线的今日输赢。
- `warn_status`：`"-1"` 不判断（未设置/关闭/统计失败）、`"0"` 正常、`"1"` 越界（预警）。
- 规则来源 `warn_source`：`group`（分组规则）、`agent`（home 俱乐部代理线回退）、`none`（无规则）。
- 代理线规则只在 home 俱乐部的代理树内生效，不跨俱乐部、不跨联盟。

## 2. 分组管理

### 2.1 创建_俱乐部_分组

#### 请求

```json
{
  "header": "创建_俱乐部_分组",
  "club_id": "984470",
  "group_name": "伙牌专项分组",
  "remark": "运营重点观察",
  "context": "pg-create-001"
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `header` | string | 是 | `创建_俱乐部_分组` |
| `club_id` | string | 是 | 当前俱乐部 ID；决定管理域（已入盟→联盟域） |
| `group_name` | string | 是 | 1~20 字（最多 60 字节）；禁止单引号、反斜杠；控制字符会被剔除；同管理域内不可重名（区分大小写） |
| `remark` | string | 否 | 备注，超过 250 字符按字符截断 |
| `context` | string | 否 | 原样回传 |

#### 推送 `ClubPlayerGroupResult`

```json
{
  "club_id": "984470",
  "scope_type": "union",
  "scope_id": "196102",
  "union_id": "196102",
  "union_name": "复仇者",
  "group_id": "1",
  "group_name": "伙牌专项分组",
  "action": "create",
  "context": "pg-create-001"
}
```

- 独立俱乐部：`scope_type="club"`、`scope_id=club_id`、`union_id=""`、`union_name=""`。
- `group_id` 为新建分组的数据库 ID（字符串）；创建成功不自动推送分组列表，客户端自行刷新 `查询_俱乐部_分组列表`。
- 每个管理域最多 50 个 `used` 分组；入盟迁移可能临时超过 50，此时禁止新建（`分组数量已达上限`）。

#### 错误

`俱乐部功能未启用`、`俱乐部不存在`、`无权访问`、`分组名称不能为空`、`分组名称包含非法字符`、`分组名称最多20个字`、`分组名称已存在`、`分组数量已达上限`、`创建分组失败`、`分组数据加载失败`、迁移失败文案（见 §8）。

### 2.2 修改_俱乐部_分组

#### 请求

```json
{
  "header": "修改_俱乐部_分组",
  "club_id": "984470",
  "group_id": "1",
  "group_name": "伙牌专项分组（新）",
  "remark": "调整观察范围",
  "warn_enabled": 1,
  "warn_min": -1000,
  "warn_max": 500,
  "context": "pg-update-001"
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `club_id` | string | 是 | 当前俱乐部 ID |
| `group_id` | string/int | 是 | 分组 ID，必须属于当前管理域 |
| `group_name` | string | 否 | 改名；规则同创建，不能与同域其它分组重名 |
| `remark` | string | 否 | 备注；超过 250 字符截断 |
| `warn_enabled` | int/string | 否 | `1`=开启、`0`=明确关闭、`-1`/`""`/`null`=置空（回退代理线） |
| `warn_min` / `warn_max` | int | 否 | 预警区间（积分）；不传=保留原值，`""`/`null`=置空 |
| `context` | string | 否 | 原样回传 |

#### 推送 `ClubPlayerGroupResult`

```json
{
  "club_id": "984470",
  "scope_type": "union",
  "scope_id": "196102",
  "union_id": "196102",
  "union_name": "复仇者",
  "group_id": "1",
  "group_name": "伙牌专项分组（新）",
  "action": "update",
  "context": "pg-update-001"
}
```

- 所有字段可选，传什么改什么；返回的 `group_name` 是改后的名称。
- `warn_enabled=1` 时区间必须齐全且 `min <= max`（含沿用原值的情况）；`0` 与 `-1` 保留区间值，便于下次开启。
- 修改不改变成员归属与统计。

#### 错误

`无权访问`、`分组不存在`、`分组ID错误`、`分组名称不能为空`、`分组名称包含非法字符`、`分组名称最多20个字`、`分组名称已存在`、`预警开关必须是整数`、`预警开关参数错误`、`预警区间必须是整数`、`开启预警必须设置区间`、`预警下限不能大于上限`、`预警区间超出范围`。

### 2.3 删除_俱乐部_分组

#### 请求

```json
{
  "header": "删除_俱乐部_分组",
  "club_id": "984470",
  "group_id": "1",
  "context": "pg-del-001"
}
```

#### 推送 `ClubPlayerGroupResult`

```json
{
  "club_id": "984470",
  "scope_type": "union",
  "scope_id": "196102",
  "union_id": "196102",
  "union_name": "复仇者",
  "group_id": "1",
  "group_name": "伙牌专项分组",
  "action": "delete",
  "context": "pg-del-001"
}
```

- 分组定义软删（`status='deleted'`），该组全部成员归属物理删除；成员变回“该管理域未分组”。
- 不可恢复；同名可重建（新 `group_id`，旧成员不会自动回来）。

#### 错误

`无权访问`、`分组不存在`、`分组ID错误`。

## 3. 分组查询

### 3.1 查询_俱乐部_分组列表

#### 请求

```json
{
  "header": "查询_俱乐部_分组列表",
  "club_id": "984470",
  "context": "pg-list-001"
}
```

无分页，一次返回该管理域全部 `used` 分组（≤50）。

#### 推送 `ClubPlayerGroupList`

```json
{
  "club_id": "984470",
  "scope_type": "union",
  "scope_id": "196102",
  "union_id": "196102",
  "union_name": "复仇者",
  "count": "2",
  "stats_ok": "1",
  "groups": [
    {
      "group_id": "1",
      "group_name": "伙牌专项分组",
      "member_count": "12",
      "today_score": "-120",
      "yesterday_score": "80",
      "total_score": "-3450",
      "today_contrib_fen": "1200",
      "yesterday_contrib_fen": "2400",
      "total_contrib_fen": "45600",
      "today_bonus_fen": "300",
      "yesterday_bonus_fen": "600",
      "total_bonus_fen": "12000",
      "warn_enabled": "1",
      "warn_min": "-1000",
      "warn_max": "500",
      "warn_value": "-120",
      "warn_status": "0",
      "remark": "运营重点观察",
      "update_date": "2026-11-06 12:00:00"
    }

```

| 字段 | 说明 |
| --- | --- |
| `count` | 分组数量（字符串） |
| `stats_ok` | `"1"` 统计正常；`"0"` 统计查询失败（数字按 0 返回，运营可重试） |
| `member_count` | 该组当前成员数（管理域内按 `user_guuid` 去重，一人只算一次） |
| `today_score` / `yesterday_score` / `total_score` | 分组今日/昨日/累计输赢（积分，成员本人之和） |
| `today_contrib_fen` / `yesterday_contrib_fen` / `total_contrib_fen` | 分组今日/昨日/累计贡献（分，成员本人之和） |
| `today_bonus_fen` / `yesterday_bonus_fen` | 分组今日/昨日新增红利（分，成员本人之和） |
| `total_bonus_fen` | 分组累计红利（分，含已提取，不含联盟红利） |
| `warn_enabled` | `"-1"` 未设置 / `"0"` 关闭 / `"1"` 开启 |
| `warn_min` / `warn_max` | 区间（积分）；未设置为 `""` |
| `warn_value` | 判断值（分组今日总输赢）；未开启/未设置/统计失败为 `""` |
| `warn_status` | `"-1"` 不判断 / `"0"` 正常 / `"1"` 预警 |
| `remark` / `update_date` | 备注、最后更新时间 |

- 所有数值为字符串；积分可负，贡献/红利为分（展示 ÷100）。
- 统计失败时 `stats_ok="0"`，9 项统计为 `"0"`，`warn_status="-1"`，列表仍正常返回。

#### 错误

`无权访问`、`俱乐部不存在`、`俱乐部功能未启用`、`分组数据加载失败`、`分组成员加载失败`、迁移失败文案。

### 3.2 查询_俱乐部_分组_成员

#### 请求

```json
{
  "header": "查询_俱乐部_分组_成员",
  "club_id": "984470",
  "group_id": "1",
  "page": 0,
  "count": 20,
  "context": "pg-members-001"

```

| 字段 | 必填 | 说明 |

| `page` | 否 | 0 基页号，默认 0；小于 0 按 0 |
| `count` | 否 | 每页条数，默认 20，限制 1~100 |

#### 推送 `ClubPlayerGroupMembers`

```json
{
  "club_id": "984470",
  "scope_type": "union",
  "scope_id": "196102",
  "union_id": "196102",

    {
      "guuid": "430994",
      "name": "玩家昵称",
      "role": "玩家",
      "is_agent": "0",
      "status": "在线",
      "club_ids": "775447,267493",
      "home_club_id": "775447",
      "self_today_score": "-50",
      "self_yesterday_score": "20",
      "self_total_score": "-300",
      "self_today_contrib_fen": "100",
      "self_yesterday_contrib_fen": "200",
      "self_total_contrib_fen": "1200",
      "self_today_bonus_fen": "30",
      "self_yesterday_bonus_fen": "60",
      "self_total_bonus_fen": "0",
      "warn_enabled": "1",
      "warn_min": "-1000",
      "warn_max": "500",
      "warn_source": "group",
      "warn_source_id": "1",
      "warn_club_id": "",
      "warn_value": "-120",
      "warn_status": "0"
    }
  ],
  "context": "pg-members-001"
}
```

| 字段 | 说明 |
| --- | --- |
| `number` | 页号（0 基，字符串） |
| `count` | 该分组成员总数（不是本页条数） |
| `stats_ok` | 同分组列表；`"0"` 时 `self_*` 为 `"0"`、`warn_status="-1"` |
| `role` | `老板`（home 俱乐部创建者）/ `管理员`（`club_manage`）/ `玩家`；代理用 `is_agent="1"` 表示，不体现在 `role` |
| `is_agent` | 在 home 俱乐部是否持有效邀请码 |
| `status` | `游戏中` / `在线` / `离线` |
| `club_ids` | 玩家当前在管理域内的成员俱乐部（逗号分隔，联盟域可能多个） |
| `home_club_id` | 玩家在该管理域的归属俱乐部；代理线预警回退用它 |
| `self_*` | 该成员**本人**在管理域内的 9 项统计（输赢/贡献/红利各 3 项）；各行相加 = 分组总计，**不含其下线** |
| `warn_source` | `group` / `agent` / `none` |
| `warn_source_id` | `group_id` 或代理节点 guuid；`none` 为 `""` |
| `warn_club_id` | 代理线回退时的 home 俱乐部；分组规则为 `""` |
| `warn_value` | 判断对象的今日输赢（分组规则=分组今日总输赢；代理线=该代理整条线今日输赢） |
| `warn_status` | `"-1"` / `"0"` / `"1"` |

- 排序：老板 → 代理 → 管理员 → 玩家；同角色内 游戏中 > 在线 > 离线；同状态按 `guuid` 升序。
- 分组规则开启/关闭时，组内所有人共用同一个 `warn_*`；分组未设置时才逐个按 home 俱乐部代理线回退。

## 5. 代理线预警

### 5.1 设置_俱乐部_代理线_预警

用于“分组未设置预警时回退”的俱乐部代理线规则。本命令**只改一个俱乐部的代理树**，不跨俱乐部、不跨联盟。

#### 请求

```json
{
  "header": "设置_俱乐部_代理线_预警",
  "club_id": "984470",
  "user_id": "718968",
  "warn_enabled": 1,
  "warn_min": -2000,
  "warn_max": 1000,
  "context": "pg-warn-001"
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `club_id` | 是 | 俱乐部 ID（不解析联盟域，直接作用于该俱乐部代理树） |
| `user_id` | 是 | 该俱乐部的代理节点（`club_agent_info.status='used'`） |
| `warn_enabled` | 是 | `1`=开启、`0`=明确关闭、`-1`=未设置（清空，沿上级继承） |
| `warn_min` / `warn_max` | 否 | 区间（积分，可负）；不传=保留原值 |
| `context` | 否 | 原样回传 |

#### 返回（同步，无推送）

`ret_code=0x200`，`result`：

```json
{
  "club_id": "984470",
  "user_id": "718968",
  "warn_enabled": "1",
  "warn_min": "-2000",
  "warn_max": "1000",
  "context": "pg-warn-001"
}
```

- `warn_enabled` 返回 `"-1"`/`"0"`/`"1"`；区间未设置为 `""`。
- 规则作用于该节点及其**未单独设置**的下级（沿 `upper` 就近继承）；下级自己设置非空值时优先。
- 开启必须带合法区间（或沿用已存在的合法区间）：缺区间、非整数、`min > max`、绝对值超 1 亿都拒绝，不静默修正。
- 关闭（`0`）保留区间值；`-1` 清空为未设置。
- 权限：本俱乐部 `IsClubManager`（创建者，或本俱乐部所属联盟总群主）；**不是**分组管理权限，成员俱乐部创建者可设置自己俱乐部的代理线。
- 只影响预警判断，不影响结算、抽水、红利、额度。

#### 错误

`无权访问`、`俱乐部不存在`、`俱乐部功能未启用`、`玩家ID非法`、`代理不存在`、`代理数据加载中，请稍后重试`、`预警开关必须是整数`、`预警开关参数错误`、`预警区间必须是整数`、`开启预警必须设置区间`、`预警下限不能大于上限`、`预警区间超出范围`。

## 6. 成员列表 `NumberList` 增量

成员列表仍是**按俱乐部**的直属视图，分组字段来自该俱乐部解析出的管理域。

### 6.1 请求参数 `group_id`

| 字段 | 说明 |
| --- | --- |
| `group_id` | 可选。不传/空=全部；`"0"`=未分组；具体数字=该管理域分组 |

- 仅**管理域管理者**生效：联盟域=总群主，独立域=创建者。其他身份传了按“不筛选”处理（不报错、不泄露分组存在性）。
- 非数字的 `group_id` 按“不筛选”处理；属于其它管理域的有效 ID 命中 0 人。
- 带 `group_id` 且管理域尚未加载完成时，本次成员列表**返回失败** `分组数据加载中，请稍后重试`（不会返回未筛选列表），客户端重试即可。
- 首次不带筛选打开列表时，分组字段可能先为空（服务端同时触发加载），下次刷新即有值。

### 6.2 与 `show_type` 的交互

| `show_type` | `group_id` | 行为 |
| --- | --- | --- |
| 不传 / `all` / `0` | 不传 | 成员行 + 盟主虚拟行（总群主查自己第一层第一页时） |
| 不传 / `all` / `0` | 传了 | 只返回该分组成员；**不追加**盟主虚拟行；`count`=筛选后成员数 |
| `union` / `1` | 不传 | 只返回盟主虚拟行 |
| `union` / `1` | 传了 | 返回空 `NumberList`（`count="0"`） |
| `member` / `2` | 不传/传了 | 只在本俱乐部成员内过滤；盟主行本来就不追加 |

- 筛选后的 `count` 是**直属范围内命中的成员数**；`number_count` 仍是俱乐部总人数（`with_total` 语义不变）。
- `search_name_id` 搜索同样支持 `group_id` 过滤；搜索路径的统计字段仍恒为 `"0"`。

### 6.3 行字段

成员行在 `status` 之前新增两个字段（`dark_percent` 仍是 club 模式最后字段）：

```json
{
  "group_id": "1",
  "group_name": "伙牌专项分组"
}
```

- 仅管理域管理者看到真实值；成员俱乐部创建者、`club_manage`、代理、玩家恒为 `"0"` / `""`。
- 无分组：`"0"` / `""`。
- 盟主虚拟行：恒为 `"0"` / `""`（盟主不属于本管理域分组）。
- 字段恒定存在（大厅模式也下发，值恒为 `"0"` / `""`），老客户端忽略即可。

### 6.4 单成员查询

`user_id` 传具体玩家时（玩家详情/单人刷新）同样返回 `group_id` / `group_name`，可见性规则同上，不需要额外调用分组接口。

### 6.5 与展示折扣的关系

- 成员列表的 `today_score` / `yesterday_score` / `total_score` 和 3 个 `*_contrib_fen` 仍按**行内成员生效的 `show_percent`** 缩放（原行为不变）。
- 分组统计与预警用真实值；**不要**拿成员列表的折后行去和分组统计逐行对账。

## 9. 客户端对接要点

1. **入口**：联盟总群主在联盟/成员管理页显示“分组管理”；独立俱乐部创建者在本俱乐部分组页显示。成员俱乐部创建者/管理员/代理/玩家不显示入口。
2. **管理域展示**：响应里的 `scope_type` / `scope_id` / `union_id` / `union_name` 用于显示“当前管理域”；总群主切换成员俱乐部时分组列表一致（同一联盟）。
3. **写后刷新**：创建/改名/删除后刷新分组列表；加人/移人后刷新分组成员列表与玩家详情；删除后成员变未分组。
4. **数字格式**：所有数值都是字符串；积分可负；贡献/红利为分，展示 ÷100。
5. **预警展示**：分组列表用 `warn_enabled` + `warn_status` 区分“开启-正常/预警、关闭、未设置”；成员/详情页用 `warn_source` 说明规则来自分组还是 home 俱乐部代理线。
6. **分页**：`查询_俱乐部_分组_成员` 的 `page` 从 0 开始，`count` 是分组总人数；成员列表 `NumberList` 的分页语义不变。
7. **重试**：`分组数据加载中，请稍后重试` 自动重试 1~2 次，不要当成员查询失败。
8. **老客户端**：`NumberList` 新增字段是纯增量，严格模式需放开未知字段。
9. **口径提示**：分组统计是“分组成员本人”，成员列表是“本人 + 整条下线”；两者不要互相对账。

## 11. 边界与注意事项

| # | 场景 | 说明 |
| --- | --- | --- |
| 1 | 一个玩家多个成员俱乐部 | 联盟域只有一行分组归属，`member_count` 只算一次；统计按 `user_guuid` 汇总各成员俱乐部数据，不重复计人 |
| 2 | 玩家退出/被踢出成员俱乐部 | 仍在同联盟其它成员俱乐部则保留分组，`home_club_id` 更新；都不在则自动移出分组 |
| 3 | 俱乐部解散 | 分组定义保留（联盟域仍属联盟），成员归属按上一条清理 |
| 4 | 独立俱乐部加入联盟 | 旧独立分组在首次访问联盟域时**惰性同名合并**（联盟配置优先），旧组软删、`group_id` 会变，客户端需重新拉取 |
| 5 | 分组统计范围 | 当前分组成员的历史快照；换组/移出会整体转移或移除，不是“入组后新增” |
| 6 | 红利用 DB 聚合 | `club_agent_info.bonus` 异步落库，可能有秒级延迟；对账以明细/内存为准 |
| 7 | 删除分组 | 软删定义 + 物理删归属，不可恢复；同名重建是新 ID |
| 8 | 分组不是代理关系 | 不改变代理树、团队人数、结算、抽水、红利、额度、房间逻辑 |
| 9 | 成员俱乐部创建者不可见 | 本期不开放“给自己成员加/移组”，后续如需另立需求 |
| 10 | 服务重启 | 管理域缓存惰性重建；首次查询/创建会等待加载（命令排队），不报错 |
| 11 | 统计口径 | 分组 9 项都是**成员本人**（扁平）；成员列表的输赢/贡献是“本人 + 整条下线”，数值天然不同 |
