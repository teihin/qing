## 1. 通用说明

### 1.1 通道

```http
GET http://127.0.0.1:8890/hall/command
```

Query 参数：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `header` | string | 是 | 命令名（中文，需 URL encode） |
| `param` | string | 是 | 命令参数 JSON 字符串（需 URL encode） |

返回：

```json
{"ret_code": 512, "ret_result": "{\"total\":1,\"list\":[…]}"}
```

- `ret_result` 是**字符串**，调用方要再 `JSON.parse` 一次。
- 只允许新后台后端从本机访问，不对公网开放。

### 1.2 ret_code

| 值 | 含义 | 处理 |
| ---: | --- | --- |
| `512`（`0x200`） | 成功 | 解析 `ret_result` |
| `769`（`0x301`） | 失败 | `ret_result` 里是 `{"error":"<文案>"}`，直接展示给操作人并写审计 |
| `1280`（`0x500`） | 服务端内部标记"本次不同步返回" | **本组命令不会出现**；不处理 |

### 1.3 鉴权

- 后台 HTTP 的调用者固定是服务端的 boss 账号（`Hall.boss`），天然通过 `_isBackendAccount` 校验。
- 命令内部仍会再判一次：非后台账号（既不是 boss 也不是 `level>=99`）返回 `{"error":"无权访问"}`。
- **没有单独的 token**，靠"只允许本机访问 8890 端口"隔离（与现有后台接口一致）。

### 1.4 字段与约定

| 项 | 说明 |
| --- | --- |
| `kind` | `uid` = 个人ID 靓号；`invite` = 俱乐部邀请码靓号 |
| `status` | `init` 可分配 / `used` 已绑定 / `disabled` 已停用（号码不回收） |
| 靓号格式 | **6 位纯数字**，与 guuid、邀请码同形；不是 6 位数字的号入不了池 |
| 号码唯一性 | 一个号码在整个系统里只能用一次，**不能既做个人ID 又做邀请码** |
| `page` | 从 `0` 开始（`/hall/command` 其它列表命令的既有口径）。注意后台自己的 `/api/admin/*` 分页是从 1 开始，对接时要做一次换算 |
| `count` | 每页条数，默认 20，最大 100 |
| 返回 `total` | **总条数**，不是本页条数 |
| `context` | 操作号，原样回传；建议形如 `pretty-20261114-0001` |
| 时间格式 | `YYYY-MM-DD HH:MM:SS` 字符串 |

### 1.5 命令总表

| # | header | 用途 | 幂等 |
| --- | --- | --- | --- |
| 1 | `异步_添加_靓号` | 运营挑好号码后调它**入池**（服务端校验 + 从原号池锁定 + 登记） | 否（重复调返回"已在靓号池"） |
| 2 | `异步_查询_靓号_池` | 分页查号池（可筛 kind/status/关键字），带绑定账号名、俱乐部名 | 是 |
| 3 | `异步_绑定_靓号` | 绑定个人ID 或 邀请码 | 否（重复调返回"已被绑定"） |
| 4 | `异步_解绑_靓号` | 解绑，号码转 `disabled` | 否（重复调返回"未绑定"） |

> **入池没有 SQL 脚本**：号码由后台调 `异步_添加_靓号` 加进池子，运营不接触数据库。号池规模建议 200~500 个，扩容时再调一次即可。

> **没有"查询映射"命令**：后台列表要显示 `id(靓号)`，直接 LEFT JOIN `usr_pretty_no_info`（见 §6），不需要接口。

> 命令名里的"异步"是**框架约定**：`_httpHallCommand` 只对含"异步"的 header 走 `yield` 等待分支。调用方无需特殊处理，仍是一次普通 HTTP 请求。

## 2. `异步_添加_靓号`

### 2.1 请求

```json
{
  "header": "异步_添加_靓号",
  "kind": "uid",
  "pretty_no": "888888",
  "op_name": "ops-zhang",
  "remark": "2026-11-14 入池",
  "context": "pretty-20261114-0000"
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `kind` | string | 是 | `uid` 个人ID 靓号 / `invite` 邀请码靓号 |
| `pretty_no` | string | 是 | 要入池的 6 位数字，由运营挑选 |
| `op_name` | string | 否 | 操作人 |
| `remark` | string | 否 | 备注，建议写清来源（如"客户购买"） |
| `context` | string | 否 | 操作号，原样回传 |

### 2.2 返回（成功）

```json
{
  "result": 1,
  "kind": "uid",
  "pretty_no": "888888",
  "status": "init",
  "context": "pretty-20261114-0000"
}
```

| 字段 | 说明 |
| --- | --- |
| `result` | 固定 `1` |
| `status` | 固定 `init`（刚入池，可绑定） |

### 2.3 行为说明

服务端做三件事，后台一次调用即可：

1. **校验**：号码没在靓号池里（跨类型也不允许复用）、不是真实账号 ID、还在原号池里、邀请码必须未被发出；
2. **锁定原号池**：个人ID 把该行从 `usr_guuid_info` 删掉（与真实发号后一致，以后新注册再也抽不到它）；邀请码把 `club_invite_code_info.status` 置 `reserved`（发码只取 `init`，永远不会随机发出）；
3. **登记**：写入 `usr_pretty_no_info`（`status=init`），随后就能在 `异步_查询_靓号_池` 里看到、用 `异步_绑定_靓号` 绑定。

失败会自动回滚：个人ID 把号码插回待分配池、邀请码把码恢复成 `init`，不会出现"号码凭空消失"。

> 入池是不可逆操作（个人ID 侧删行、邀请码侧预留），**号码一旦入池就不能再作为普通号发出**。挑号前请确认。
>
> 号码从哪来：候选查询见 §6.1（后台直连只读库自查），查到后调本接口入池；本接口会再校验一次，并发下也安全。

## 3. `异步_查询_靓号_池`

### 3.1 请求

```json
{
  "header": "异步_查询_靓号_池",
  "kind": "uid",
  "status": "init",
  "keyword": "888",
  "page": 0,
  "count": 20,
  "context": "pretty-20261114-0001"
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `header` | string | 是 | `异步_查询_靓号_池` |
| `kind` | string | 否 | `uid` / `invite` / 空=全部 |
| `status` | string | 否 | `init` / `used` / `disabled` / 空=全部 |

| `count` | int | 否 | 每页条数，默认 20，上限 100 |

```json
      "club_name": "",
      "bind_date": "2026-11-14 10:00:00",
      "op_name": "ops-zhang",
      "remark": "客户购买"
    },
    {
      "id": 13,
      "pretty_no": "666666",
      "kind": "invite",
      "status": "init",
      "user_guuid": "",
      "user_name": "",
      "club_id": "",
      "club_name": "",
      "bind_date": "",
      "op_name": "ops",
      "remark": "2026-11-14 入池"
    }
  ]
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `total` | int | 满足条件的总条数 |
| `page` | int | 当前页码 |
| `list[].pretty_no` | string | 靓号码（6 位数字），也是解绑等操作的唯一入参 |
| `list[].kind` | string | `uid` / `invite` |
| `list[].status` | string | 只有 `init` / `used` / `disabled` 三种。`kind=invite` 时**取自码表**（`club_invite_code_info.status`）：码表的 `reserved`（已预留未绑定）对外归一为 `init`，所以"取消代理"后会立刻显示 `disabled`、而待绑定的靓号仍能用 `status=init` 筛出来 |

| `list[].bind_date` | string | 绑定时间；未绑定为空串 |
| `list[].op_name` | string | 最后一次操作人 |
| `list[].remark` | string | 备注 |

> 列表按 `status`（`init` 在前）+ `pretty_no` 升序返回，方便运营先挑号再绑。

## 4. `异步_绑定_靓号`

### 4.1 请求

个人ID 靓号：

```json
{
  "header": "异步_绑定_靓号",
  "kind": "uid",
  "pretty_no": "888888",
  "user_guuid": "580629",
  "op_name": "ops-zhang",
  "remark": "客户购买",
  "context": "pretty-20261114-0002"
}
```

邀请码靓号：

```json
{
  "header": "异步_绑定_靓号",
  "kind": "invite",
  "pretty_no": "666666",
  "user_guuid": "580629",
  "club_id": "820084",
  "op_name": "ops-zhang",
  "remark": "代理换好码",
  "context": "pretty-20261114-0003"
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `kind` | string | 是 | `uid` / `invite` |
| `pretty_no` | string | 是 | 6 位数字，必须是号池里 `status=init` 的号码 |
| `user_guuid` | string | 是 | 目标账号的真实 ID（**不是靓号**，后台下拉选出来的原始 ID）。个人ID 靓号不限身份；**邀请码靓号必须是该俱乐部的在职代理**（`club_agent_info.status='used'` 或该俱乐部创建者），否则返回错误 |
| `invite_code` | string | `kind=invite` 传它即可 | **服务端已支持**：直接给代理当前使用的 6 位邀请码，由服务端自己解析出代理与俱乐部。传了它就不需要 `user_guuid` / `club_id`（2026-11-15 用户确认） |
| `club_id` | string | `kind=invite` 选填 | 仅在没传 `invite_code` 时才需要：邀请码归属俱乐部 |
| `op_name` | string | 否 | 操作人，写进号池与审计；建议传后台登录账号 |
| `remark` | string | 否 | 备注 |
| `context` | string | 否 | 操作号，原样回传 |

### 4.2 返回（成功）

```json
{
  "result": 1,
  "kind": "uid",
  "pretty_no": "888888",
  "user_guuid": "580629",
  "user_name": "a3",
  "club_id": "",
  "old_invite_code": "",
  "context": "pretty-20261114-0002"
}
```

| 字段 | 说明 |
| --- | --- |
| `result` | 固定 `1`，表示绑定成功 |
| `user_guuid` / `user_name` | 被绑定的账号（真实 ID + 当前昵称） |
| `club_id` | 邀请码绑定时的归属俱乐部；个人ID 为空串 |
| `old_invite_code` | `kind=invite` 时，该账号在本俱乐部**被替换掉的旧码**（原来没有码则为空串）。后台可提示"旧码 482913 已作废" |

### 4.3 行为说明

个人ID：

1. 校验账号存在、靓号在池且 `status=init`；
2. 把号池行改成 `used` 并写入 `user_guuid`；
3. 若玩家在线，服务端主动推一次 `ClubAgentInfo`，**手机端立即显示新号**，无需重登；
4. `tbl_Account` 不做任何修改，历史数据、上下级关系、战绩流水全部不变；
5. **不支持直接换号**：该账号已有个人ID 靓号时返回 `该账号已有个人ID靓号，请先解绑`。个人ID 是"一号一人一辈子"的口径，换号必须先解绑旧号（旧号随后 `disabled` 不再可用）。

邀请码：

1. 校验 `kind=invite` 时 `club_id` 必填且俱乐部存在；
2. **校验该账号是该俱乐部的在职代理**（`club_agent_info.status='used'`，或该俱乐部创建者）；不是代理直接返回 `该账号不是本俱乐部代理，请先设置代理`，号池与码池都不动。判定以库为准，不看内存代理树，避免后台调用时树未加载误拒；
3. 把 `club_invite_code_info` 里该靓号行改成 `used`，归属到 `club_id + user_guuid`。**只要该码当前不是 `used` 就能绑**（`reserved` 预留态、`disabled` 取消代理留下的态都可以），所以"取消代理后想绑回原靓号"能直接成功；
   但**号池行已被运营解绑过（`disabled`）的号码永久停用**，返回 `该靓号已停用，不可再绑定`，与个人ID 口径一致；
4. 该账号在本俱乐部原有的 `used` 码改为 `disabled`（旧码作废，**不回收**）；若原来绑过别的邀请码靓号，那行 `usr_pretty_no_info` 同步置 `disabled`；
5. 该俱乐部下"还没审批、用的是旧码"的入会申请，`invite_code` 批量改成新靓号，避免审批时找不到归属代理。

> **取消代理会让靓号失效**：现有"取消代理"会把该代理在本俱乐部的 `used` 码置 `disabled`（包括靓号）。重新设为代理时系统会分一个新的随机码，靓号不会自己回来——需要后台再调一次 `异步_绑定_靓号` 把号码绑回去。

> **运营顺序**：先在后台把人设为该俱乐部代理（现有 `设置_俱乐部_代理`），再给他绑邀请码靓号。个人ID 靓号没有这个限制，玩家号可以直接绑。

### 4.4 失败

`ret_code=769`，`ret_result` 为：

```json
{"error": "该靓号已被绑定"}
```

错误文案见 §7。

## 5. `异步_解绑_靓号`

### 5.1 请求

```json
{
  "header": "异步_解绑_靓号",
  "kind": "uid",
  "pretty_no": "888888",
  "op_name": "ops-zhang",
  "remark": "客户退号",
  "context": "pretty-20261114-0004"
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `kind` | string | 是 | `uid` / `invite` |
| `pretty_no` | string | 是 | 要解绑的靓号码（`status=used`） |
| `op_name` | string | 否 | 操作人 |
| `remark` | string | 否 | 备注 |
| `context` | string | 否 | 操作号 |

### 5.2 返回

```json
{
  "result": 1,
  "kind": "invite",
  "pretty_no": "666666",
  "old_user_guuid": "580629",
  "status": "disabled",
  "new_invite_code": "482913",
  "context": "pretty-20261114-0004"
}
```

| 字段 | 说明 |
| --- | --- |
| `result` | 固定 `1` |
| `old_user_guuid` | 解绑前绑定的账号 |
| `status` | 号码新状态，固定 `disabled` |
| `new_invite_code` | **仅 `kind=invite`**：解绑后系统给该账号在本俱乐部补的随机码；该账号本来就不是代理时为空串 |

### 5.3 行为说明

- **号码不回收**：解绑后 `status=disabled`，永远不会再被分配给其他人（避免旧截图、旧宣传物料对不上）。运营要回池须线下改库，不在接口范围。
- 解绑后该账号可以**再绑一个新号**（旧行的 `user_guuid` 会被清空，不占"一个账号一个号"的名额）；旧号归属靠 SQL 日志追溯（解绑时也可把原 `user_guuid` 写进 `remark`）。
- 解绑立即生效：服务端刷新缓存并推一次 `ClubAgentInfo`，手机端马上变回真实 ID。
- 邀请码解绑：**如果该码已经被"取消代理"置成 `disabled`，解绑仍然成功**（不报错），只把号池行停用；仅当该账号在本俱乐部仍是有效代理时才补一个随机码，否则不补。
- 请求里的 `pretty_no` 必须是号池里 `status=used` 的号码；已经解绑过的号码返回"该号码未绑定"。

## 6. 后台列表显示口径（`原ID(靓号)`）

后台直连 `kbedm` 只读，一个 LEFT JOIN 即可，**服务端既有回包字段一个都不改**：

```sql
SELECT a.sm_guuid AS user_id,
       a.sm_name  AS user_name,
       CONCAT(a.sm_guuid, IFNULL(CONCAT('(', p.pretty_no, ')'), '')) AS user_id_display
FROM tbl_Account a
LEFT JOIN usr_pretty_no_info p
       ON p.user_guuid = a.sm_guuid
      AND p.kind = 'uid'
      AND p.status = 'used'
WHERE a.sm_guuid = '580629'
```

返回：

| user_id | user_name | user_id_display |
| --- | --- | --- |
| 580629 | a3 | 580629(888888) |

注意事项：

1. **不要改 `user_id` 本身**，只新增 `user_id_display` 给前端渲染；否则后台其它以 `user_id` 为键的逻辑（查详情、调接口）会全部失配。
2. 邀请码侧**不需要 join**：`club_invite_code_info.invite_code` 存的就是靓号码。
3. **调 `/hall/command` 时传 `user_id`（真实 ID），不要传 `user_id_display`**。服务端的入站反解只针对客户端通道；后台传 `580629(888888)` 会得到"玩家不存在"，这是刻意的调用约束（避免服务端猜格式、也避免误伤昵称）。
4. 俱乐部成员/代理列表若要显示，join 键同样是 `user_guuid = sm_guuid AND kind='uid' AND status='used'`；一个账号只会有一行（`kind_club_user` 唯一索引保证）。

### 6.1 候选号码从哪来（入池前挑号）

`异步_查询_靓号_池` 只列**已经在池里**的号码。"还没入池、可以挑"的候选由后台直连只读库自查，不需要新接口：

```sql
-- 个人ID 候选：还在待分配池、没发给真人的号
select user_guuid from usr_guuid_info
 where account_id = 0 and user_guuid like '%888%'
 order by user_guuid limit 50;

-- 邀请码候选：码池里还没发出去的号
select invite_code from club_invite_code_info
 where status = 'init' and invite_code like '%888%'
 order by invite_code limit 50;
```

- `like` 条件按运营的选号规则自己拼（豹子 `%888888`、顺子、包含某串数字等）；前缀匹配（`like '888%'`）能走 `account_id_user_guuid` 索引，`%888%` 是全表扫但 89 万行也就几百毫秒，两种都可用；
- 查出来的号直接调 `异步_添加_靓号` 入池，**服务端会再校验一次**（是否已入池、是否已被真实账号占用、是否刚被发出去），并发下也安全；
- **不要自己往 `usr_pretty_no_info` 插数据**：入池必须由服务端同时把号码从原号池摘掉，只写登记表会出现"靓号仍会被系统随机发给新玩家"。

## 7. 错误文案表

| 文案 | 触发条件 | 后台处理建议 |
| --- | --- | --- |
| `无权访问` | 调用者不是后台账号 | 检查调用来源 |
| `参数错误` | 参数不是合法 JSON / 缺必填 | 检查请求体 |
| `kind 必须是 uid 或 invite` | `kind` 非法 | 修正枚举 |
| `靓号必须是 6 位数字` | `pretty_no` 不是 6 位数字 | 从号池列表里选，不要手输 |
| `缺少目标账号` | 未传 `user_guuid` | 补上目标账号 |
| `该号码已在靓号池` | 入池时号码已存在（含另一 kind） | 换一个号码；号码不允许跨类型复用 |
| `该号码已是真实账号ID，不能作为个人ID靓号` | 入池时该号码已被真实玩家占用 | 换一个号码 |
| `该号码不在待分配号池（可能已发出）` | 入池时 `usr_guuid_info` 里已没有可分配行 | 换一个号码 |
| `该号码不在待分配号池（可能刚被占用）` | 并发：该号恰好在两步之间被另一个添加/注册抢走 | 换一个号码 |
| `该邀请码已被使用，不能作为靓号` | 入池时码表状态不是 `init` | 换一个号码 |
| `该邀请码刚被占用，请重试` | 并发：码在两步之间被改成 `used` | 重试，或换一个号 |
| `号码池里没有该邀请码` | 入池时码表没有这个 6 位数 | 检查号码是否 6 位、是否笔误 |
| `添加失败，请重试` | 入池时数据库错误（已自动回滚） | 重试或找服务端 |
| `靓号不存在` | `pretty_no` 不在号池表 | 先查号池列表 |
| `该靓号已被绑定` | 个人ID：号池行不是 `init`；邀请码：该码当前是 `used` | 刷新列表重新挑号（邀请码若确认要换人，先解绑原代理） |
| `该靓号已停用，不可再绑定` | 号池行是 `disabled`（被运营解绑过） | 换一个号码；号码按规则不回收 |
| `该账号已有个人ID靓号，请先解绑` | 个人ID 已绑（唯一索引命中） | 先调解绑，再绑新号 |
| `账号不存在` | `tbl_Account` 无该 `user_guuid` | 检查目标账号 |
| `俱乐部不存在` | `club_id` 不在 `Hall.clubs` | 刷新俱乐部列表 |
| `该账号不是本俱乐部代理，请先设置代理` | `kind=invite` 且该账号在该俱乐部不是在职代理 | 先调 `设置_俱乐部_代理`，再来绑码 |
| `绑定邀请码必须指定 club_id` | `kind=invite` 未传 `club_id` | 让运营选俱乐部 |
| `邀请码靓号仅支持俱乐部模式` | `game_mode != 'club'` | 该环境不支持邀请码靓号 |
| `该号码未绑定` | 解绑时号码不是 `used` | 刷新列表 |
| `绑定失败，请重试` | 数据库错误（`errstr`） | 记录日志，重试或找服务端 |

## 8. 典型流程

### 8.1 给一个玩家配个人ID 靓号

```
① 异步_添加_靓号    {kind:"uid", pretty_no:"888888"}
   → result=1、status=init，号码离开待分配池
② 异步_查询_靓号_池  {kind:"uid", status:"init", keyword:"888"}
   → 确认 888888 在可绑列表里
③ 异步_绑定_靓号    {kind:"uid", pretty_no:"888888", user_guuid:"580629"}
   → result=1，玩家手机端立即显示 888888
④ 列表渲染用 §6 的 JOIN 显示 580629(888888)，调接口仍用 user_id=580629
```

### 8.2 给某个俱乐部的代理换邀请码

```
① 异步_添加_靓号    {kind:"invite", pretty_no:"666666"}
   → result=1，码表该行变 reserved
② 异步_绑定_靓号    {kind:"invite", pretty_no:"666666", user_guuid:"580629", club_id:"820084"}
   → result=1，old_invite_code=旧码（已作废），玩家手机端邀请码变 666666
③ 玩家把 666666 发给新会员，会员入会申请能正常归属到该代理
```

### 8.3 客户退号

```
① 异步_解绑_靓号    {kind:"uid", pretty_no:"888888"}
   → 号码 disabled，玩家恢复真实 ID
```

## 9. 联调自检清单

| # | 检查项 | 期望 |
| --- | --- | --- |
| 0.1 | 调 `异步_添加_靓号` 入池一个可用号码 | 返回 `result=1`、`status=init`；`异步_查询_靓号_池` 能查到 |
| 0.2 | 重复添加同一个号码 | 返回 `该号码已在靓号池` |
| 0.3 | 添加已被真实玩家占用的号码 | 返回 `该号码已是真实账号ID…` |
| 0.4 | 添加已被代理使用的邀请码 | 返回 `该邀请码已被使用，不能作为靓号` |
| 1 | 号池列表能按 kind/status 过滤 | 字段齐全，`total` 是总数 |
| 2 | 绑一个号池里没有的号码 | 返回 `靓号不存在` |
| 3 | 绑一个 `used` 的号码 | 返回 `该靓号已被绑定` |
| 4 | 同账号重复绑个人ID靓号 | 返回 `该账号已有个人ID靓号，请先解绑` |
| 5 | 绑定后客户端代理页 | 个人ID 变成靓号，上下级显示同步变化 |
| 6 | 绑定邀请码不传 `club_id` | 返回 `绑定邀请码必须指定 club_id` |
| 6.1 | 把邀请码靓号绑给该俱乐部的普通玩家 | 返回 `该账号不是本俱乐部代理，请先设置代理` |
| 6.2 | 把邀请码靓号绑给该俱乐部创建者 | 成功 |
| 6.3 | 把个人ID 靓号绑给任意普通玩家 | 成功 |
| 7 | 后台用真实 `user_id` 调其它命令（如查询成员） | 正常命中该账号；传 `user_id_display` 会报"玩家不存在"（预期） |
| 8 | 解绑后客户端 | 立即恢复真实 ID |
| 9 | 解绑再绑同一号码 | 返回 `该靓号已被绑定`（不回收） |
| 10 | 取消代理后，把同一靓号码再绑回该账号 | 成功（码 `disabled` → `used`） |
| 11 | 解绑一个已被取消代理的邀请码靓号 | 成功，不报错 |
| 12 | 解绑之后，把同一邀请码靓号再绑给任何人 | 返回 `该靓号已停用，不可再绑定` |
