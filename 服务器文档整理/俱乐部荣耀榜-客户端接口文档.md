# 俱乐部荣耀榜 — 客户端接口文档

> 版本：v2.10（2026-11-15，已实施，待部署）
> 对应服务端：已新增 `scripts/server_common/club_honor_rank.py`、`club_honor_rank_reward` 表、`Hall.py` 7 条路由（本地完成，未部署）
> 设计说明见 `doc/俱乐部荣耀榜方案.md`
> 适用模式：**仅俱乐部模式**（`game_mode == 'club'`）。大厅模式请继续使用 `查询_活动_*` 全平台榜，行为完全不变。

## 1. 概览

### 1.1 命令与推送路由

| 命令 | 端 | 用途 | 推送路由 |
| --- | --- | --- | --- |
| `查询_俱乐部_活动_玩家手数` | 客户端 | 玩家手数榜 | `ClubActivityPlayedcount` |
| `查询_俱乐部_活动_玩家输赢` | 客户端 | 玩家赢分榜（俱乐部积分） | `ClubActivityUserScore` |
| `查询_俱乐部_活动_代理红利` | 客户端 | 代理红利榜 | `ClubActivityProxyHongli` |
| `查询_俱乐部_活动_自己排名` | 客户端 | 我的排名 / 当前奖励 | `ClubActivitySelfRank` |
| `查询_俱乐部_活动_状态` | 客户端 | 三个榜的活动开关/起止时间/状态 | `ClubActivityStatus` |
| `异步_查询_俱乐部_活动_奖励` | 后台 | 查询某联盟/俱乐部的奖励配置 | 无（`ret_result` 返回） |
| `异步_设置_俱乐部_活动_奖励` | 后台 | 设置某联盟/俱乐部的奖励配置 | 无（`ret_result` 返回） |

> 榜单推送字段与现有全平台榜（`ListActivityPlayedcount` / `ListActivityUserScore` / `ListActivityProxyHongli`）**完全同构**，客户端可复用现有解析逻辑。

### 1.2 统计范围（scope）由 `club_id` 自动决定

| 俱乐部状态 | 排行范围 | 奖励配置读取 |
| --- | --- | --- |
| 已加入联盟（`union_id != ''`） | 该联盟下全部俱乐部合并 | `scope_type='union'`, `scope_id=union_id` |
| 独立俱乐部（`union_id == ''`） | 仅本俱乐部 | `scope_type='club'`, `scope_id=club_id` |

客户端不需要传 scope。榜标题由客户端按 `club_id` 对应的俱乐部名/联盟名展示。

### 1.3 权限

| 身份 | 可查榜单 / 我的排名 | 可查/设置后台奖励 |
| --- | --- | --- |
| 平台 boss | 任意俱乐部 | 是 |
| 俱乐部创建者 / `club_manage` 授权 | 对应范围 | 对应范围 |
| 联盟总群主 / `union_manage` 授权 | 对应联盟 | 对应联盟 |
| 俱乐部成员 | 本俱乐部（入盟则返回本联盟榜） | 否 |
| 联盟成员（自己任一俱乐部与目标同联盟） | 该联盟榜（可从联盟任一成员俱乐部进入） | 否 |

非成员查任意俱乐部返回 `无权查看`。

## 2. 客户端请求

### 2.1 通用参数

| 参数 | 类型 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `club_id` | string | 否 | 自己第一个已加入的俱乐部 | 当前查看的俱乐部 ID；必须存在且调用者有权限 |
| `count` | string/int | 否 | `10` | 每页条数，服务端限定 **1~50** |
| `page` | string/int | 否 | `0` | 页码，0 起；上限沿用现有活动配置（手数 `activity3_max_page`、红利 `activity_max_count`、赢分 20） |
| `is_zip` | string/int | 否 | `0` | `1` 时列表用压缩数组格式（与现有榜一致） |
| `context` | string | 否 | `""` | 原样回传 |
| `play_type` | string | 手数榜必填 | `1皮` | `1皮` / `2皮` / `5皮` / `10皮` / `20皮`；非法值按 `1皮`。赢分/红利榜忽略 |
| `rank_type` | string | 否 | `play` | `play`（手数）/ `score`（赢分）/ `bonus`（红利）；非法值拒绝 |

> `查询_俱乐部_活动_自己排名` 只使用 `club_id` / `rank_type` / `play_type` / `context`；`count`、`page`、`is_zip` 传了也不生效。

### 2.2 请求示例

手数榜（1皮）：

```json
{"header":"查询_俱乐部_活动_玩家手数","club_id":"222697","play_type":"1皮","count":"10","page":"0","is_zip":"0","context":"club_rank_play_1p"}
```

赢分榜：

```json
{"header":"查询_俱乐部_活动_玩家输赢","club_id":"222697","count":"10","page":"0","is_zip":"0","context":"club_rank_score"}
```

红利榜：

```json
{"header":"查询_俱乐部_活动_代理红利","club_id":"222697","count":"10","page":"0","is_zip":"0","context":"club_rank_bonus"}
```

我的排名（手数 1皮）：

```json
{"header":"查询_俱乐部_活动_自己排名","club_id":"222697","rank_type":"play","play_type":"1皮","context":"club_rank_self"}
```

活动状态：

```json
{"header":"查询_俱乐部_活动_状态","club_id":"222697","context":"club_rank_status"}
```

## 3. 客户端回包

### 3.1 交互顺序

与现有榜一致，客户端收到 **两个消息**：

1. 推送路由（数据包）；
2. `onHallCommand(GC_OK, {"context":"..."})`（完成信号）。

异常时只有第 2 条（`GC_FAILED` + `result.error`）。

### 3.2 榜单数据包（`is_zip=0`）

```json
{
  "ClubActivityPlayedcount": [
    {
      "user_no": "1",
      "user_name": "玩家A",
      "user_guuid": "100001",
      "activity_num": "36",
      "user_reward": "100",
      "proxy_guuid": "***",
      "proxy_reward": "",
      "remark": "小"
    },
    {
      "user_no": "2",
      "user_name": "玩家B",
      "user_guuid": "100002",
      "activity_num": "28",
      "user_reward": "50",
      "proxy_guuid": "***",
      "proxy_reward": "",
      "remark": "小"
    }
  ],
  "number": "0",
  "count": "2",
  "start_date": "2026-11-15 00:00:00",
  "end_date": "2026-11-30 23:59:59",
  "context": "club_rank_play_1p"
}
```

赢分榜路由名 `ClubActivityUserScore`，`activity_num` 为积分；红利榜路由名 `ClubActivityProxyHongli`，`activity_num` 为元。

### 3.3 榜单数据包（`is_zip=1`）

```json
{
  "ClubActivityPlayedcount": [
    [1, "玩家A", "100001", 36, "100"],
    [2, "玩家B", "100002", 28, "50"]
  ],
  "number": "0",
  "count": "2",
  "start_date": "2026-11-15 00:00:00",
  "end_date": "2026-11-30 23:59:59",
  "context": "club_rank_play_1p"
}
```

数组元素顺序：`[名次, 玩家名, 玩家ID, 数值, 奖励]`。未配置奖励或名次超出配置时，第 5 位为 `""`。

### 3.4 榜单字段说明

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `user_no` | string | 名次，从 1 连续递增（页内全局序号；同分按 `user_guuid` 降序稳定排序，不并列） |
| `user_name` | string | 玩家名（账号不存在时为空串） |
| `user_guuid` | string | 玩家 ID |
| `activity_num` | string | 手数=**局**；赢分=**积分**；红利=**元**（已由分换算）。代理查看按 `show_percent` 折扣展示，名次不受影响 |
| `user_reward` | string | 该名次的奖励（**元**），读后台配置；未配置/超出名次为空串 |
| `proxy_guuid` | string | 固定 `"***"` |
| `proxy_reward` | string | 固定空串 |
| `remark` | string | 手数榜：`微/小/中/大`；赢分/红利榜：空串 |
| `number` | string | 当前页码（0 起） |
| `count` | string | 榜内总人数（受 `max_item_count` 截断，与现有榜一致） |
| `start_date` / `end_date` | string | 活动起止，`YYYY-MM-DD HH:MM:SS` |
| `context` | string | 原样回传 |

> 三个榜的 `activity_num` 单位不同，客户端不要混用格式化。

### 3.5 我的排名数据包

```json
{
  "ClubActivitySelfRank": [
    {
      "user_no": "17",
      "user_name": "玩家A",
      "user_guuid": "100001",
      "lingqu_on": "False",
      "is_reward": "True",
      "user_reward": "50",
      "lingqu_count": "0",
      "activity_num": "28",
      "remark": "小"
    }
  ],
  "context": "club_rank_self"
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `user_no` | string | 名次；无数据时为 `"无排位"`；0 分/负分有榜时正常显示名次 |
| `user_name` / `user_guuid` | string | 玩家信息 |
| `lingqu_on` | string | **恒 `"False"`**：俱乐部榜不提供领取（与现有 self 包一致） |
| `is_reward` | string | `"True"` 表示名次在奖励配置内，否则 `"False"`（奖励 0 也算配置内，与现有 self 包一致） |
| `user_reward` | string | 当前名次奖励（元，红利榜按展示折扣缩放） |
| `lingqu_count` | string | 恒 `"0"` |
| `activity_num` | string | 与榜单同单位（局 / 积分 / 元） |
| `remark` | string | 手数榜为 `微/小/中/大`（与榜单同义）；赢分/红利为空串 |
| `context` | string | 原样回传 |

无数据时推 `{"ClubActivitySelfRank": [], "context": "..."}`，客户端显示"无排位"。

### 3.6 活动状态数据包

```json
{
  "ClubActivityStatus": {
    "club_id": "222697",
    "scope_type": "union",
    "scope_id": "196102",
    "list": [
      {"rank_type": "play", "dipi": "1皮", "status": "2", "activity_on": "1",
       "start_date": "2026-11-15", "start_time": "17:55:00",
       "end_date": "2026-11-15", "end_time": "18:00:00"},
      {"rank_type": "play", "dipi": "2皮", "status": "0", "activity_on": "0",
       "start_date": "", "start_time": "", "end_date": "", "end_time": ""},
      {"rank_type": "score", "dipi": "", "status": "1", "activity_on": "1",
       "start_date": "2026-11-20", "start_time": "00:00:00",
       "end_date": "2026-11-30", "end_time": "23:59:59"},
      {"rank_type": "bonus", "dipi": "", "status": "3", "activity_on": "1",
       "start_date": "2026-11-01", "start_time": "00:00:00",
       "end_date": "2026-11-10", "end_time": "23:59:59"}
    ]
  },
  "context": "club_rank_status"
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `status` | string | `0` 未开启/未配置；`1` 未开始；`2` 进行中；`3` 已结束（榜单仍可查最终数据） |
| `activity_on` | string | 该行活动开关 `"0"/"1"` |
| `start_date` / `start_time` | string | 活动开始日期/时间；未配置为空串 |
| `end_date` / `end_time` | string | 活动结束日期/时间；未配置为空串 |
| `rank_type` / `dipi` | string | 固定 7 行：`play`×5 档 + `score` + `bonus` |
| `club_id` / `scope_type` / `scope_id` | string | 本次查询命中的俱乐部与 scope |

- 手数 5 个档位逐行返回；客户端 tab 状态自行聚合：任一档 `2` → 进行中；否则任一档 `1` → 未开始；否则任一档 `3` → 已结束；全 `0` → 未开启。
- 只返回开关/时间/状态，**不返回 `reward_list`**，避免普通成员看到发奖金额。
- 状态 `3` 仍可调三个榜单查询最终数据；运营用后台 `activity_on=0` 彻底关闭。
- `count` / `page` / `is_zip` 传了不生效，固定返回 7 行。

### 3.7 异常回包

```json
{
  "context": "club_rank_play_1p",
  "result": { "error": "无权查看" }
}
```

| 错误文案 | 触发条件 |
| --- | --- |
| `俱乐部功能未启用` | 当前不是俱乐部模式 |
| `俱乐部不存在` | `club_id` 为空/不存在，或账号没有可用俱乐部 |
| `无权查看` | 不在俱乐部/联盟管理或成员范围内 |
| `活动没有开启` | 该 scope 未配置、`activity_on=0` 或起止时间为空（先推空数据包） |
| `活动未开始` | 当前时间早于该 scope 的 `start`（先推空数据包） |
| `rank_type 非法` | 我的排名传了非 `play/score/bonus` |
| `查询失败` | 榜单/名次 SQL 执行失败（已带回 context） |

## 4. 三个榜的口径

### 4.1 玩家手数榜

| 项 | 说明 |
| --- | --- |
| 参与者 | 该联盟/俱乐部**当前成员**（`sm_club_join` / `sm_club_join2`），排除 `sm_level>=99` |
| 数值 | 活动期内 `activity_type='手数'`（有效手数，有投奖的局）按档位 `remark2` 求和 |
| 单位 | 局 |
| 档位 | 1皮 / 2皮 / 5皮 / 10皮 / 20皮，单选 |
| 活动时间 | 由后台按 `(scope, play, 档位)` 配置，1皮~20皮 可分别配置 |

> 手数数据源没有俱乐部字段，只能按"当前成员"归属：退会成员历史手数不再出现；新成员入会前历史手数会补入。

### 4.2 玩家赢分榜（俱乐部积分）

| 项 | 说明 |
| --- | --- |
| 参与者 | 活动期内在本俱乐部（钱包口径）有正输赢的成员 |
| 数值 | `club_member_score_info.score` 求和，显示所有有结算的玩家（含负分/0 分），按数值降序 |
| 单位 | 积分 |
| 归属 | 玩家自己的俱乐部（联盟房跨俱乐部按钱包俱乐部），与成员列表“总输赢”同源 |
| 日期 | 按自然日（首尾日整天计入） |
| 活动时间 | 由后台按 `(scope, score, '')` 配置 |

> 与全平台赢分榜（入口俱乐部、逐局）口径不同，数值不可互相校验。

### 4.3 代理红利榜

| 项 | 说明 |
| --- | --- |
| 参与者 | 活动期内在该俱乐部/联盟房间产生分成的代理/盟主/总群主 |
| 数值 | `usr_income_info` 的 `tax_number - bonus_tax_number` 求和（红利暗抽后净额） |
| 单位 | 元（服务端由分换算） |
| 归属 | 产生分成的入口俱乐部（`proxy_guuid='club-<id>'`），与代理本人所属俱乐部无关 |
| 排除 | 对账基线 `remark5='clubtotal'`；包含 `clubroot/club1/club2/unionroot/uniondark/darkroot` |
| 折扣 | 代理查看按 `show_percent` 缩放展示（名次不受影响） |
| 可见范围 | 联盟/俱乐部成员可见（与现有全平台红利榜一致，本期不做代理/管理者分级） |
| 活动时间 | 由后台按 `(scope, bonus, '')` 配置 |

## 5. 后台奖励与活动配置

### 5.1 配置规则

- 每个 **联盟** 一份（`scope_type='union'`），每个 **独立俱乐部** 各一份（`scope_type='club'`）。
- 每个榜、每个手数档位单独配：`rank_type`（`play/score/bonus`）+ `dipi`（手数 `1皮~20皮`，其它榜空）。
- 查询接口固定返回 7 个组合（play×5 档 + score + bonus），未配置的 `reward_list` 为空数组。
- `reward_list` 为逗号分隔的金额，单位**元**，第 1 名起；最多 100 项，每项非负整数，单值 ≤ 1000000。
- 名次超出配置长度 → 奖励空串。
- **每行同时控制该榜/档位的活动开关与起止时间**：`activity_on`（0/1）+ `start_date/start_time` + `end_date/end_time`。
- 手数 5 个档位可分别配置开关和时间；后台可做“一键应用到全部档位”。
- 配置**实时生效**（榜单查询时读取，无缓存）。
- 只做展示，不提供领取；发放由运营按榜单走后台发放命令。

活动判定（服务端）：

| 条件 | 榜单 | 我的排名 |
| --- | --- | --- |
| 无配置行 / `activity_on != 1` | 推空包 + `活动没有开启` | `活动没有开启` |
| 四个时间任一为空 | 同上 | 同上 |
| `now < start` | 推空包 + `活动未开始` | 同上 |
| `now >= start` | 正常出榜 | 正常返回 |
| `now > end` | 仍返回最终榜（用 `activity_on=0` 关榜） | 同上 |

```json
  "end_time": "23:59:59"
}
```

说明：

- `rank_type=play` 时 `play_type` 必填且必须在白名单；`score/bonus` 忽略 `play_type`，`dipi` 存空串。
- `reward_list` 传空串 = 清空该榜奖励。
- `activity_on` 仅 `0/1`；开启时四个时间必填、日期固定 10 位 `YYYY-MM-DD`、时间接受 `HH:MM` 或 `HH:MM:SS`（5 位自动补 `:00` 存 8 位）、`start <= end`；非零填充日期（如 `2026-1-1`）拒绝。
- 整行覆盖：关闭活动时若需保留时间，后台需回传原时间；不传则时间被清空。
- 非法（奖励负数/非数字/超 100 项/超长、开关非 0/1、时间格式错、`start > end`）整单拒绝，返回 `GC_FAILED` + error。
- 权限：平台 boss / 联盟总群主或授权 / 俱乐部创建者或 `CanManageClub`；非后台账号拒绝。

| 错误文案 | 触发条件 |
| --- | --- |
| `无权访问` | 非后台账号 / 不在管理范围 |
| `俱乐部功能未启用` | 当前不是俱乐部模式 |
| `俱乐部不存在` | `club_id` 无效 |
| `联盟不存在` | `union_id` 不在 `hall.club_unions` |
| `rank_type 非法` | 非 `play/score/bonus` |
| `play_type 非法` | 手数榜档位非法 |
| `奖励配置非法` | 奖励格式/长度/数值校验失败 |
| `活动配置非法` | 开关非 0/1、时间缺失/格式错、`start > end` |
| `保存失败` | 写库回调报错 |

## 7. 客户端联调注意

1. **按模式切命令**：`game_mode == 'club'` 时用本组命令；大厅模式继续用 `查询_活动_*`，服务端大厅逻辑完全未改。
2. **推送路由名不同**：`ClubActivityPlayedcount` / `ClubActivityUserScore` / `ClubActivityProxyHongli` / `ClubActivitySelfRank`，字段与旧榜同构，解析可复用。
3. **无缓存**：每次请求实时查库；后台改奖励后下一次请求即生效。
4. **`count` 上限 50**；`page` 上限沿用现有活动配置，超出直接失败。
5. **联盟/独立由服务端判断**：同一个 `club_id`，入盟返回联盟榜、独立返回本俱乐部榜；标题按俱乐部信息展示。
6. **空榜**：`count=0` + 空数组显示"暂无排行数据"；我的排名空数组显示"无排位"。
7. **单位**：手数=局、赢分=积分、红利=元；红利 `activity_num` 已换算，不要再除 100。
8. **奖励为展示值**：不要与全平台榜的 `user_reward` 互校（配置来源不同）。
9. **不要与全平台榜互校**：赢分口径（钱包 vs 入口）、红利数据源（`usr_income_info` vs 已停写旧表）均不同。
