## 1. 通用说明

### 1.1 通道与形态

- 本功能**没有新的查询命令**：客户端进入俱乐部房间列表时，仍调 `查询_俱乐部_房间_信息`（`club_id` = 当前展示俱乐部，`is_zip_result='1'`）取**全量**；
- 之后由服务端**主动推送**单房间增量，路由 **`ClubRoomInfo`**；
- 推送报文：`{"result": [[...12 位数组...]]}`，数组里**永远只有一个房间**；
- 推送是"这个房间的最新完整行"，客户端按 `room_id`（下标 0）整行替换/插入即可。

### 1.2 订阅与推送范围

| 项 | 规则 |
| --- | --- |
| 订阅 | 客户端每次调 `查询_俱乐部_房间_信息` 时，服务端记住"账号 → 最近一次 `club_id`" |
| 推送范围 | 该 `club_id` 的完整可见集：**本俱乐部 + 联盟共享房**（V2 联盟 owner / 旧联盟，与 `查询_俱乐部_房间_信息` 同口径） |
| 不随筛选收窄 | `fillter_01` / `is_have_site` 只影响查询回包，不影响推送范围 |
| 更新时机 | 每次查询覆盖旧值，后到生效；切俱乐部会重新查询，自动重新订阅 |
| 订阅者 | 在线、不在房间内（`roomID == 0`）、最近查询过列表的账号 |
| 重置 | 重连/重新登录时服务端清空订阅，客户端重新查询后恢复 |
| 房间内玩家 | **不推**；回大厅由客户端重查全量 |
| 未查询过 | **不推** |
| 频率 | **1 秒合并**：同一房间 1 秒内多次变化只推最后一次 |
| 开关 | `d_halls.datas[1].enable_push_room_info`，关闭时完全不推 |

## 3. 初始全量：`查询_俱乐部_房间_信息`

客户端进入列表时调用（现有用法不变）：

```json
{"header": "查询_俱乐部_房间_信息", "club_id": "775447", "count": 10, "page": 0, "is_zip_result": "1", "context": "clubroom:1"}
```

- 推送路由 `AllRoomInfo`，`result` 是数组的数组：

```json
{
  "number": 0,
  "count": 7,
  "result": [
    [448003, "准备", "45分钟", 3, 8, "底皮1/3", "45分钟", "1-448003", 0, "复仇者", "775447", -1],
    [448004, "游戏中", "38分钟", 5, 8, "底皮1/3", "45分钟", "1-448004", 0, "复仇者", "775447", -1]
  ]
}
```

| 下标 | 字段 | 说明 |
| --- | --- | --- |
| 0 | `room_id` | 房间 ID |
| 1 | 状态 | `参与过` / `准备` / `游戏中`（关闭房查询不返回） |
| 2 | 备注 | `"45分钟"`（剩余时间，分钟）；服务端不随时间推，客户端本地倒计时，收到新值校准（§4.4 第 10 条） |
| 3 | 人数 | 在座 + 持座旁观 |
| 4 | 上限 | `max_number` |
| 5 | 底皮 | `special_rule` 的 `底皮...` |
| 6 | 时长 | `special_rule` 的 `...分钟`；realtime 为单人结算周期 |
| 7 | 房间名 | `special_rule` 的 `房间名称:...` |
| 8 | 地九王 | `0/1` |
| 9 | `union_name` | 联盟名；未入盟空串 |
| 10 | `club_guuid` | 房间所属俱乐部（联盟房为总群主俱乐部） |
| 11 | `index` | 全量查询恒 `-1`，客户端忽略 |

## 4. 增量推送：`ClubRoomInfo`

### 4.1 触发时机

以下房间变化会在 **1 秒内**推送该房间的最新行：

- 新建房间；
- 玩家进入 / 离开房间；
- 坐下 / 起立 / 观战转座 / 准备；
- 牌局开始 / 结算；
- 房间解散 / 关闭；
- 超时无人回收（关闭前推 `[1]="关闭"`）。

> **去重（2026-11-07）**：服务端会比较"上次推送时的 `[1]` 状态 + `[3]` 人数"，**两者都没变就不推**。
> 玩家准备/换座/结算等只改其它字段时不会触发刷新；`[2]` 不随时间推送，客户端收到新值时校准并本地按分钟递减（§4.4 第 10 条）。

### 4.2 报文

```json
{"result": [[448003, "游戏中", "38分钟", 5, 8, "底皮1/3", "45分钟", "1-448003", 0, "复仇者", "775447", 3]]}
```

### 4.3 数组下标（固定 12 位）

| 下标 | 字段 | 说明 |
| --- | --- | --- |
| 0 | `room_id` | 房间 ID；客户端按它替换/删除/锚定滚动 |
| 1 | 状态 | `关闭` / `参与过` / `准备` / `游戏中`；**关闭优先**，其次参与过（按接收者算） |
| 2 | 备注 | `"45分钟"`，与查询**完全一致** |
| 3 | 人数 | 与查询同一口径：`GetAllWatcherInHold() + GetAllPlayerInSite()` |
| 4 | 上限 | `max_number` |
| 5 | 底皮 | 与查询一致 |
| 6 | 时长 | 与查询一致；realtime 为单人结算周期 |
| 7 | 房间名 | 与查询一致 |
| 8 | 地九王 | `0/1` |
| 9 | `union_name` | 未入盟空串，**占位不能省** |
| 10 | `club_guuid` | 字符串；只用于客户端兜底过滤，不展示 |
| 11 | `index` | **仅新增房间有效**：该房间在"无客户端筛选"完整列表中的下标（0 基，与 `查询_俱乐部_房间_信息` 排序一致）；状态/人数变化、关闭房间为 `-1` |

### 4.4 客户端处理约定

1. **长度校验**：按 `len(row) >= 12` 解析；不足 12 位忽略并打日志（服务端保证推送与查询前 10 位同值）；
2. 已有房间：按 `room_id` **整行替换**；
3. `row[1] == "关闭"`：**删除**该行（本地没有该 `room_id` 时忽略）；
4. **新增房间**：`row[11] >= 0` 时按该下标插入；无筛选时直接插入，有筛选（小/中/大、有空位）时合并触发一次约 1 秒防抖全量查询，并保留当前滚动位置；
5. 状态/人数变化：`row[11] == -1`，只原地替换，不移动顺序（准备 ↔ 游戏中允许少量顺序差异，下次全量归位）；
6. `row[10]`（`club_guuid`）只用于切换俱乐部/重连期间的残留推送兜底过滤，不展示；
7. 保留全量兜底：进大厅、切页、下拉、重连、房型筛选下新房间；
8. 滚动位置按 `room_id` 锚定，不要按数组下标；
9. 同一秒多个新增：按 `row[11]` 升序批量插入，后面的插入位置按已插入数量顺延；
10. **只有 `[1]` 状态或 `[3]` 人数变化才会收到推送**；`[2]` 不随时间推。客户端**本地倒计时**（本期确认）：
    - 收到 `AllRoomInfo` 全量或 `ClubRoomInfo` 时，以服务端 `[2]` 值校准；
    - 之后按分钟递减，减到 `0` 保持 `0`，等下次全量查询/推送再校准；
    - realtime 下房间常驻不按时长关房，`0分钟` **不代表房间结束**，不要据此删除卡片。

## 5. 边界与已知限制

| # | 场景 | 说明 |
| --- | --- | --- |
| 1 | 房间被 GC 回收后 | 不再补推关闭行；客户端重新进入列表时用全量查询兜底 |
| 2 | 切换俱乐部 | 客户端会重新调 `查询_俱乐部_房间_信息`，服务端订阅随之更新；切换瞬间的残留推送用 `[10]` 兜底过滤 |
| 3 | 重连 / 重新登录 | 服务端清空订阅；客户端重查后恢复；重查前不推 |
| 4 | `play_deleted` 房间（玩法已删除、等待关房） | 不推（与 `查询_俱乐部_房间_信息` 一致） |
| 5 | 比赛场房（`roomGroupID != '0'`） | 不推（与查询一致） |
| 6 | 房型筛选（小/中/大） | 推送不带筛选分类；新房间在筛选下可能触发一次客户端防抖全量查询 |
| 7 | 关闭开关 | 完全不推送，行为与改动前一致 |
| 8 | 旧 `ClubRoomInfo` 报文 | 已改为 12 位数组；旧对象行不再下发 |
| 9 | `[2]` 减到 `0` | 客户端保持 `0分钟`，不删卡片；realtime 房间仍常驻，等下次全量/推送校准 |

## 6. 联调验证清单

| # | 操作 | 预期 |
| --- | --- | --- |
| 1 | 俱乐部玩家进列表 | 先收到 `AllRoomInfo` 全量（12 位数组，`[11]=-1`） |
| 2 | 新建房间 | 1 秒内收到该房间的 `ClubRoomInfo`（12 位数组），`[11]` 为应插入下标 |
| 3 | 玩家进/离房、坐下/起立 | 该房间 `[3]` 人数、`[1]` 状态更新 |
| 4 | 开局 / 结算 | `[1]`（准备/游戏中）更新；`[2]` 只作为该次推送的**校准值**一并带回，服务端不会单独推备注变化（见 §4.4 第 10 条） |
| 5 | 解散 / 关闭 | 收到 `[1]="关闭"`，客户端删除该行 |
| 6 | 切到另一个俱乐部列表 | 服务端订阅更新，旧俱乐部房间不再推；残留行用 `[10]` 过滤 |
| 7 | 房间内玩家 | 不收到推送；回大厅后重查全量 |
| 8 | 重连 | 重连后清空订阅，客户端重查后恢复 |
| 9 | 同一秒内多次变化 | 只收到最后一次 |
| 10 | 关闭 `enable_push_room_info` | 完全不推送 |
| 11 | 卡片剩余时间 | 无推送时本地按分钟递减；收到全量/推送时跳回服务端值；减到 0 保持 0 |
