## 1. 通用说明

### 1.1 通道与形态

- 本功能**没有新的查询命令**：客户端进入俱乐部房间列表时，仍调 `查询_所有_俱乐部_房间` 取**全量**（现有 `AllClubRoomInfo`，行为不变）；
- 之后由服务端**主动推送**单房间增量，路由 **`ClubRoomInfo`**（复用旧路由，客户端已接受）；
- 推送报文：`{"result": [one_room]}`，数组里**永远只有一个房间**；
- 推送是"这个房间的最新完整行"，不是列表、不是差量字段，客户端按 `room_id` 整体替换该行即可。

### 1.2 推送范围

| 项 | 规则 |
| --- | --- |
| 订阅者 | 所有**在线**、**不在房间内**（`roomID == 0`）、**至少加入一个俱乐部**的玩家 |
| 可见范围 | 与 `查询_所有_俱乐部_房间` 完全一致：我加入的俱乐部 + 这些俱乐部的联盟（V2 联盟映射到总群主俱乐部） |
| 房间内玩家 | **不推**（玩家看不到列表，等回到大厅再重查全量） |
| 未加入俱乐部 | **不推** |
| 频率 | **1 秒合并**：同一房间 1 秒内多次变化只推最后一次 |
| 开关 | `d_halls.datas[1].enable_push_room_info`，关闭时完全不推（行为与改动前一致） |

## 3. 初始全量：`查询_所有_俱乐部_房间`

客户端进入列表时调用，保持现有用法：

```json
{"header": "查询_所有_俱乐部_房间", "count": 10, "page": 0, "context": "clubroom:1"}
```

- 参数 `count`/`page` 仅为兼容保留，服务端**一次返回全部可见房间**（不分页）；
- 推送路由 `AllClubRoomInfo`：

```json
{
  "number": 0,
  "count": 7,
  "result": [
    {
      "room_id": 448003,
      "union_name": "复仇者",
      "room_status": "准备",
      "play_mode": "扯旋",
      "special_rule": ["100底分", "房间名称:1-448003"],
      "round_count": 0,
      "game_round": 10,
      "remark": "00:45",
      "player_and_watcher_count": 3,
      "max_number": 8,
      "create_datetime": "2026-11-07 00:00:00",
      "creater_name": "abc11",
      "creater_guuid": "718968",
      "club_guuid": "775447",
      "player_list": ["a5", "a4"],
      "is_sitedowned": "False",
      "room_count": 7
    }
  ]
}
```

> 全量查询的字段与 §4 推送行**完全一致**，客户端可复用同一套解析/渲染。

## 4. 增量推送：`ClubRoomInfo`

### 4.1 触发时机

以下房间变化会在 **1 秒内**推送该房间的最新行：

- 新建房间；
- 玩家进入 / 离开房间；
- 坐下 / 起立 / 观战转座 / 准备；
- 牌局开始 / 结算；
- 房间解散 / 关闭；
- 超时无人回收（关闭前推 `room_status="关闭"`）。

### 4.2 报文

```json
{
  "result": [
    {
      "room_id": 448003,
      "union_name": "复仇者",
      "room_status": "游戏中",
      "play_mode": "扯旋",
      "special_rule": ["100底分", "房间名称:1-448003"],
      "round_count": 3,
      "game_round": 10,
      "remark": "12:30",
      "player_and_watcher_count": 5,
      "max_number": 8,
      "create_datetime": "2026-11-07 00:00:00",
      "creater_name": "abc11",
      "creater_guuid": "718968",
      "club_guuid": "775447",
      "player_list": ["a5", "a4", "a3"],
      "is_sitedowned": "False",
      "room_count": 7
    }
  ]
}
```

### 4.3 字段说明

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `result` | array | 固定只有一个元素（单房间） |
| `room_id` | int | 房间 ID；客户端按它定位并替换/插入本地行 |
| `union_name` | string | 联盟名称；未入盟为空串 |
| `room_status` | string | `准备` / `游戏中` / `关闭` |
| `play_mode` | string | 玩法 |
| `special_rule` | array | 特殊规则/房间名等（与查询一致） |
| `round_count` | int | 已进行局数 |
| `game_round` | int | 总局数 |
| `remark` | string | 剩余/时长，`MM:SS`（与查询一致） |
| `player_and_watcher_count` | int | 在座 + 持座观战人数 |
| `max_number` | int | 人数上限 |
| `create_datetime` | string | 建房时间；用于列表稳定排序 |
| `creater_name` / `creater_guuid` | string | 开房人昵称 / ID |
| `club_guuid` | string | 房间所属俱乐部（联盟共享房为总群主俱乐部） |
| `player_list` | array | 在座玩家昵称数组；**2026-11-07 起为 `name`**（旧 `name#nick` 已废弃，客户端改一处解析，服务端不做兼容） |
| `is_sitedowned` | string | 恒为 `"False"`；客户端用自己 `guuid` 判断是否已坐下，不要用该字段 |
| `room_count` | int | 该房间所属俱乐部的可见房间数（含 `play_deleted` 房间，与查询的房间数口径一致；玩家同时加入多个不同联盟俱乐部时，以全量查询的总数为准） |

### 4.4 客户端处理约定

1. 收到后按 `room_id` 在本地列表中**替换/插入**该行，**不要整体替换列表**；
2. `room_status == "关闭"` → **删除**该行（本地没有该 `room_id` 时忽略即可）；
3. 列表排序保持服务端口径（`create_datetime` 升序，`room_id` 稳定），替换时按 `room_id` 锚定滚动位置；
4. 玩家在房间内不会收到推送；从房间回到大厅后，建议主动重查一次 `查询_所有_俱乐部_房间`（服务端不补推）；
5. 未加入俱乐部的玩家收不到该路由；
6. 同一秒内同一房间的多次变化只收到最后一次，属正常合并，不是丢包。

## 5. 边界与已知限制

| # | 场景 | 说明 |
| --- | --- | --- |
| 1 | 房间被 GC 回收后 | 不再补推关闭行；客户端重新进入列表时用全量查询兜底，行随全量结果消失 |
| 2 | 同一玩家加入多个俱乐部/联盟 | 可见范围取并集，与查询一致；推送按"该房间所属俱乐部是否在我可见集合"过滤 |
| 3 | `play_deleted` 房间（玩法已删除、等待关房） | 查询列表仍会显示，推送同样会推，二者一致 |
| 4 | 比赛场房（`roomGroupID != '0'`） | 不推（与查询一致） |
| 5 | 关闭开关 | 完全不推 `ClubRoomInfo`，行为与改动前一致 |
| 6 | 旧 `ClubRoomInfo` 报文 | 路由名不变；`player_list` 格式由 `name#nick` 改为 `name`，其余字段与查询行对齐 |

## 6. 联调验证清单

| # | 操作 | 预期 |
| --- | --- | --- |
| 1 | 俱乐部玩家进列表 | 先收到 `AllClubRoomInfo` 全量 |
| 2 | 新建房间 | 1 秒内收到该房间的 `ClubRoomInfo` |
| 3 | 玩家进/离房、坐下/起立 | 该房间 `player_and_watcher_count` / `player_list` 更新 |
| 4 | 开局 / 结算 | `room_status`（准备/游戏中）、`round_count` 更新 |
| 5 | 解散 / 关闭 | 收到 `room_status="关闭"`，客户端删除该行 |
| 6 | 房间内玩家 | 不收到推送；回大厅后重查全量 |
| 7 | 两个不同联盟的玩家 | 各自只收到本联盟可见房间的推送 |
| 8 | 同一秒内多次变化 | 只收到最后一次 |
| 9 | 关闭 `enable_push_room_info` | 完全不推送 |
