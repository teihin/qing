# 俱乐部房间玩法配置 — 客户端接口文档

> 配套方案文档：`doc/俱乐部房间玩法配置方案.md`
> 关联文档：`doc/俱乐部暗抽-客户端接口文档.md`（房间 `dark_percent` 的结算口径与可见性）
> 本文档面向客户端，只描述**怎么调、传什么、收什么**。
> 状态：**服务端本地已实施，未部署**；服务端 `game_mode != 'club'` 时，本组命令统一返回 `0x301` + `{"error":"俱乐部功能未启用"}`。
> 最后更新：2026-11-04

---

## 1. 通用说明

### 1.1 通道与响应

- 客户端→服务器：`reqHallCommand(param, context)`；
- 服务器→客户端：同步 `onHallCommand(ret_code, result)`，列表/异步操作另走 `onMessage(router, json)`；
- `param` 为 JSON 字符串，必须含 `"header"`；`context` 原样回传（推送 `ClubPlayList` 也带 `context`）；
- 通用返回码、JSON 包裹、异常路径与 `doc/俱乐部代理与邀请码-客户端接口文档.md` §1 完全一致，本文不重复。

### 1.2 权限

| 操作者 | 查询列表 | 创建/删除 |
| --- | --- | --- |
| 俱乐部创建者（群主） | 允许 | 允许 |
| 平台老板（boss 名单） | 允许 | 允许 |
| V2 联盟成员俱乐部创建者 | **拒绝**：`联盟房间由总群主俱乐部配置` | **拒绝** |
| 普通成员/代理 | 拒绝 | 拒绝 |
| 大厅模式 | `俱乐部功能未启用` | `俱乐部功能未启用` |

> V2 联盟只有“联盟房间 owner 俱乐部”能配置玩法；成员俱乐部只使用总群主俱乐部的一套房。
> 平台老板仍受 V2 owner 限制：成员俱乐部即使老板操作，也返回 `联盟房间由总群主俱乐部配置`。

### 1.3 比例与金额

- `water_rate`：整数百分点，`0~20`；`0` = 不抽水。
- `dark_percent`：整数百分点，`0~water_rate`；`0` = 房间默认不暗抽。
- `dark_percent` 是**按玩家输赢的百分点**，不是“占分账池的百分比”；客户端只负责采集/展示配置值，不要自己换算层层分成。
- 本组接口的 `min_money`/`water_rate`/`dark_percent` 都是**整数**；没有“分/元”换算。
- `dark_percent` 只对群主可见；**不要**下发给普通成员或代理。

## 2. 数据结构 `ClubPlayList`

查询、创建、删除成功后统一推送：

```json
{
  "ClubPlayList": [
    {
      "play_id": "12",
      "dipi_key": "1",
      "dipi_name": "底皮1/3",
      "dijiuwang": 1,
      "water_rate": 5,
      "dark_percent": 1,
      "min_money": 50,
      "max_number": 8,
      "room_ids": ["101", "102"]
    }
  ],
  "context": "ctx_play_01"
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `play_id` | string | 玩法配置 ID；删除时回传 |
| `dipi_key` | string | 底皮短名：`0.1/0.2/1/2/5/10/20/50` |
| `dipi_name` | string | 完整底皮名，展示用，如 `底皮1/3` |
| `dijiuwang` | int | 0/1，是否地九王 |
| `water_rate` | int | 房间总水率，0~20 |
| `dark_percent` | int | 房间默认暗抽，0~water_rate；**仅群主界面展示** |
| `min_money` | int | 准入，服务端按底皮推导 |
| `max_number` | int | 固定 8 |
| `room_ids` | string[] | 当前该玩法下未删除的房间 ID（可多个：1 个可加入 + 若干进行中） |

> 列表只返回 `status='used'` 的玩法；已删除玩法不会再出现。`room_ids` 不含已标记删除的房间；不返回房间状态，客户端如需展示“准备/游戏中”，沿用现有房间列表字段。

## 3. 接口总表

| # | 命令 | 作用 | 成功返回方式 |
| --- | --- | --- | --- |
| 3.1 | `查询_俱乐部_玩法列表` | 拉取本俱乐部全部玩法 | 推 `ClubPlayList` |
| 3.2 | `创建_俱乐部_玩法` | 新建一个玩法并启动对应房间 | 推 `ClubPlayList`；DB 失败推 `ClubPlayResult` |
| 3.3 | `删除_俱乐部_玩法` | 删除玩法；当前房结算后关闭，不再补房 | 推 `ClubPlayList`；失败推 `ClubPlayResult` |

## 4. 接口详述

### 4.1 查询_俱乐部_玩法列表

- **命令名**：`查询_俱乐部_玩法列表`
- **权限**：群主 / 平台老板 / 联盟房间 owner
- **参数**：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `header` | string | 是 | `查询_俱乐部_玩法列表` |
| `club_id` | string | 是 | 俱乐部 ID |
| `context` | string | 否 | 原样回传 |

```json
{"header": "查询_俱乐部_玩法列表", "club_id": "820084", "context": "ctx_play_01"}
```

- **响应**：同步 `0x200`，`result` 为空 `{}`；数据由 `ClubPlayList` 推送。
- **错误**：同步 `0x301`，见 §6。
- 若配置尚未加载完成（服务端刚启动），第一次调用可能返回 `玩法配置加载中，请稍后重试`；服务端已触发加载，客户端短延迟后重试即可。

### 4.2 创建_俱乐部_玩法

- **命令名**：`创建_俱乐部_玩法`
- **权限**：群主 / 平台老板 / 联盟房间 owner
- **参数**：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `header` | string | 是 | `创建_俱乐部_玩法` |
| `club_id` | string | 是 | 俱乐部 ID |
| `dipi_key` | string | 是 | 底皮短名或完整名，如 `1` 或 `底皮1/3` |
| `dijiuwang` | int | 是 | 0/1 |
| `water_rate` | int | 是 | 0~20 |
| `dark_percent` | int | 是 | 0~water_rate；0=房间默认不暗抽 |
| `context` | string | 否 | 原样回传 |

```json
{"header": "创建_俱乐部_玩法", "club_id": "820084", "dipi_key": "1",
 "dijiuwang": 1, "water_rate": 5, "dark_percent": 1, "context": "ctx_play_02"}
```

- **成功**：同步 `0x200`，`result` 为空 `{}`；服务端异步落库并补房后推 `ClubPlayList`。
- **异步失败**：推 `ClubPlayResult`：

```json
{"error": "创建玩法失败"}
```

- **同步错误**：`0x301`，见 §6（参数/权限/重复等在落库前直接返回）。
- 客户端以收到 `ClubPlayList` 作为“创建完成”；不要仅凭同步 `0x200` 就认为房间已建好。

### 4.3 删除_俱乐部_玩法

- **命令名**：`删除_俱乐部_玩法`
- **权限**：群主 / 平台老板 / 联盟房间 owner
- **参数**：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `header` | string | 是 | `删除_俱乐部_玩法` |
| `club_id` | string | 是 | 俱乐部 ID |
| `play_id` | string | 是 | 玩法 ID（`ClubPlayList.play_id`） |
| `context` | string | 否 | 原样回传 |

```json
{"header": "删除_俱乐部_玩法", "club_id": "820084", "play_id": "12", "context": "ctx_play_03"}
```

- **成功**：同步 `0x200`，`result` 为空 `{}`；服务端标记删除后推 `ClubPlayList`（该玩法消失）。
- **异步失败**：推 `ClubPlayResult` `{"error":"玩法不存在"}`。
- **删除后的房间行为**：
  - 该玩法下所有房间立即标记 `play_deleted`，不再接受新玩家，房间列表不再展示；
  - 未开局的房立即关闭；有牌局的房当前这一局正常打完，结算后关闭；
  - 不再补该玩法的新房；其他玩法不受影响。

## 5. 建房规则（客户端展示口径）

- **一个玩法配置保留 1 个“未开局可加入房”**；该房满员或开局后，下一次房间列表刷新/补房周期（服务端 60 秒节流）自动再开一个同配置新房；同配置可同时有多个进行中的房间。
- 没有玩法配置的类型不建房；大厅自动房不受本方案影响。
- 时长固定 **30 分钟**；人数固定 **8**；
- 准入按底皮推导：

| `dipi_key` | 完整底皮 | 准入 |
| --- | --- | --- |
| `0.1` | 底皮0.1/0.3 | 5 |
| `0.2` | 底皮0.2/0.5 | 10 |
| `1` | 底皮1/3 | 50 |
| `2` | 底皮2/5 | 100 |
| `5` | 底皮5/10 | 250 |
| `10` | 底皮10/20 | 500 |
| `20` | 底皮20/40 | 1000 |
| `50` | 底皮50/100 | 2500 |

- 房间公开 `roomSetting` 会带：
  - `water_rate`（int）
  - `play_config_id`（int）
  - **不会带 `dark_percent`**；客户端不要向玩家展示暗抽。
- 房间列表/进房沿用现有俱乐部房间接口；房间特殊规则会带地九王、底皮、准入、30 分钟等现有模板字段。

## 6. 错误文案汇总

| 文案 | 出现接口 | 说明 |
| --- | --- | --- |
| `俱乐部不存在` | 4.1~4.3 | `club_id` 无效/已删除 |
| `俱乐部功能未启用` | 4.1~4.3 | 服务端不是 `game_mode=club` |
| `只有群主可以操作玩法` | 4.1~4.3 | 不是创建者/老板 |
| `联盟房间由总群主俱乐部配置` | 4.1~4.3 | V2 成员俱乐部不能配置玩法 |
| `玩法配置加载中，请稍后重试` | 4.1~4.3 | 启动后配置未加载完，稍后重试 |
| `读取玩法配置失败` | 4.1 | 组装列表异常 |
| `底皮参数错误` | 4.2 | `dipi_key` 不在支持列表 |
| `地九王参数错误` | 4.2 | `dijiuwang` 不是 0/1 |
| `水率/暗抽比例必须是整数` | 4.2 | 参数不是整数 |
| `水率必须在 0~20 之间` | 4.2 | `water_rate` 越界 |
| `暗抽比例必须在 0~水率 之间` | 4.2 | `dark_percent` > `water_rate` 或 <0 |
| `该底皮+地九王玩法已存在` | 4.2 | 同 `(club_id,dipi_key,dijiuwang)` 已有 used 配置 |
| `玩法ID错误` | 4.3 | `play_id` 不是整数 |
| `玩法不存在` | 4.3 | 配置已删/不属于本俱乐部 |
| `创建玩法失败` | 4.2 异步 | DB 插入失败，推 `ClubPlayResult` |

## 7. 典型时序

```text
群主进入“创建玩法”页面
  → 查询_俱乐部_玩法列表
  → 收到 ClubPlayList
  → 创建_俱乐部_玩法 {dipi_key:"1", dij9iuwang:1, water_rate:5, dark_percent:1}
  → 同步 0x200
  → 收到 ClubPlayList（新玩法出现，room_ids 含新房间）
  → 玩家在现有俱乐部房间列表看到该房，进入（roomSetting 带 water_rate/play_config_id）

群主删除某个玩法
  → 删除_俱乐部_玩法 {play_id:"12"}
  → 同步 0x200
  → 收到 ClubPlayList（play_id 12 消失）
  → 该玩法房间从房间列表消失；有牌局的当前局结束后关闭，不再补房
```

## 8. 客户端注意事项

1. **玩法列表只给群主/联盟房间 owner**；普通成员/代理不要请求，也不要展示 `dark_percent`。
2. **`dark_percent` 不是“分账池比例”**，是按玩家输赢的百分点；具体分成由服务端处理，客户端不要重算。
3. 房间 `roomSetting` 只带 `water_rate`/`play_config_id`，**永远不带 `dark_percent`**。
4. 创建/删除都是“先同步成功、后异步 `ClubPlayList`”；以 `ClubPlayList` 为最终刷新依据。
5. 创建玩法不传水率/暗抽时默认 0（不抽水/不暗抽）；建议 UI 明确显示 0 的含义。
6. 同配置满员/开局后由服务端自动补新房，受现有 60 秒补房节流；客户端房间列表短时间只看到 1 个可加入房是正常。
7. V2 联盟成员俱乐部不能配置玩法；成员只看到总群主俱乐部的共享房。
8. 删除玩法不会立即踢出正在打牌的玩家：当前局结算后关房；期间该房不可新进，房间列表已隐藏。
9. 没有玩法配置就没有对应房间；上线前由群主自己创建，不由运营批量 seed。
