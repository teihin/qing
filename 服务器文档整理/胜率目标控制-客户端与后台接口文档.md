## 1. 通用说明

### 1.1 通道与响应

- 客户端→服务器：`reqHallCommand(param, context)`；`param` 为 JSON 字符串，必须含 `"header"`；
- 后台→服务器：HTTP `GET http://127.0.0.1:8890/hall/command`，query 带 `header` + `param`（`param` 为 JSON 字符串，需 URL encode）；
- 返回：`{"ret_code": 512, "ret_result": "<json 字符串>"}`；`ret_result` 是**字符串**，调用方要再 `JSON.parse` 一次；
- `context` 原样回传（后台在 `ret_result` 里，客户端在 `onHallCommand` 里）；
- 失败体：`{"error":"<文案>"}`（`ret_code=769`），成功体见各命令的 `ok/failed` 或 `list/total`。

### 1.2 鉴权（先看这段）

所有 4 条命令都走同一套前置校验：

1. **模式**：`d_halls.game_mode == 'club'`（`Hall._isClubMode()`）；大厅模式返回 `{"error":"俱乐部功能未启用"}`；
2. **权限**：只认 `d_users.config["account"]["boss"]` 名单（`opt_target_ctrl.IsBossOnly`），**不含 `bigboss`、不含 `level>=99`**；非名单返回 `{"error":"无权限"}`。

> 线上 `boss` 名单当前是 `['648425','718968','237737']`，这 3 个账号都能调；后台 HTTP 的调用者固定是 `Hall` 的 boss 账号（`self.boss` = `boss[0]`），天然通过。
> 牌桌内客户端必须用 boss 名单账号登录才能调；普通玩家/代理/俱乐部管理员一律拒绝。

### 1.3 命令总表

| # | header | 用途 | 通道 |
| --- | --- | --- | --- |
| 2 | `异步_设置_胜率目标` | 设置/覆盖目标（单个/多 guuid，或按俱乐部分组批量） | 客户端 + 后台 |
| 3 | `异步_查询_胜率目标_列表` | 查目标与进度（可按 guuid/scope/分组/状态过滤） | 客户端 + 后台 |
| 4 | `异步_停止_胜率目标` | 停止（单个/批量/按分组） | 客户端 + 后台 |
| 5 | `异步_查询_胜率目标_日志` | 操作日志分页 | 后台 |

**不新增分组命令**：分组的选择与维护继续用现有 `查询_俱乐部_分组列表` / `查询_俱乐部_分组_成员` / `设置_俱乐部_分组_成员` / `移除_俱乐部_分组_成员`。本模块只"选分组 → 批量生成目标"。

实现文件：

- `scripts/server_common/opt_target_ctrl.py`：目标 CRUD、`OnBeforeDeal` / `OnRoundEnd`、`FinishTarget`、`LoadAll`、分组展开、日志写入；
- `scripts/server_common/pm_bipai_chuanxiaoxuan_game.py`：`Start` 与 `_EndRound` 两个钩子；
- `scripts/base/Hall.py`：4 条命令注册与接口方法；
- `res/server/database.sql`：`usr_opt_target_log` 建表（在 `call create_club_invite_code();` 之前）。

### 1.4 本期实现边界（调用前必须知道）

| 项 | 说明 |
| --- | --- |
| 不校验账号存在 | `guuids` 里写错的 guuid 不会报错，会生成一条目标记录，但该玩家不入房就永远不会生效；需要严格校验时由调用方先查玩家信息 |
| 列表不返回房间字段 | 列表只返回目标数据与在线状态；牌桌内弹窗请先用当前房在座玩家的 `guuids` 过滤（可传 `guuids` 参数） |
| 分组需已加载 | 按 `club_id + group_id` 设置/停止时，要求该管理域的分组缓存已加载；未加载返回「分组数据加载中，请先查询一次分组列表后重试」。调用方先调一次 `查询_俱乐部_分组列表` 即可 |
| 不做过期 | 目标不会自动失效，只能达标自动结束或人工停止 |
| 不做客户端提示 | 达标/停止都不推送；要看进度就轮询列表 |
| 同局只一个目标生效 | 发牌侧 `_pick_vip` 是单值；同房多个 active 目标时，按 `order` 第一个命中者生效，其余只累加进度 |
| 有 check/must 的局不生效 | 同局有人申请配牌时 `_pick_vip` 直接跳过，目标玩家该局只累计进度、不受控 |
| 离线 origin 不精确 | 离线玩家设置目标时 `origin` 为默认空值，停止/达标清 0，不恢复离线前的手工 `optimize01_*`；需要保留原设置时，先让玩家在线再设目标 |
| 历史查历史表 | 目标记录单条覆盖；每次设置的历史在 `usr_opt_target_history`（一条目标一行），列表传 `history=1` 查 |

## 2. 设置目标 `异步_设置_胜率目标`

### 2.1 请求

```json
{
  "header": "异步_设置_胜率目标",
  "guuids": "718968,496702",
  "club_id": "",
  "group_id": 0,
  "target_value": 500,
  "chance": 100,
  "remark": "牌桌内临时调整",
  "context": "opt-set-001"
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `header` | string | 是 | `异步_设置_胜率目标` |
| `guuids` | string | 二选一 | 逗号分隔的玩家 guuid；**与 `group_id` 二选一，`guuids` 优先**。两者同时传时按 `guuids` 设置，`group_id` 只写入记录作来源标记，**不展开分组** |
| `club_id` | string | 按分组时必填 | 任取该管理域内一个俱乐部 id，用于解析联盟域/独立俱乐部域 |
| `group_id` | int | 按分组时必填 | 俱乐部分组 id（`club_player_group_info.id`） |
| `target_value` | int | 是 | 正=让玩家赢 N 分；负=让玩家输 N 分；**不能为 0** |
| `chance` | int | 是 | 1~100（允许 100），模块按目标方向自动加符号（负目标内部转 `-chance`） |
| `remark` | string | 否 | 备注，写进 `usr_opt_target_log.remark` |
| `context` | string | 否 | 操作号，原样回传 |

> 没有 `expire_hours`：目标不会自动过期。
> 按分组设置时，服务端把分组展开成逐个 guuid，**每人一条独立目标、独立进度**；`scope_type/scope_id/group_id/group_name` 作为来源快照写入每条目标。

### 2.2 返回

```json
{
  "ok": [
    {"guuid": "718968", "name": "abc11", "warning": "已接管原设置（2 次 / 50%）"}
  ],
  "failed": [
    {"guuid": "all", "error": "chance 必须在 1~100"}
  ]
}
```

| 字段 | 说明 |
| --- | --- |
| `ok` | 已成功生成/覆盖的目标列表；`warning` 仅在玩家原有 `optimize01_count/chance` 非 0 时出现 |
| `failed` | 失败列表；本期只在**整体参数错误**时返回（`target_value=0`、`chance` 越界），见 §8 |

### 2.3 行为说明

- **覆盖**：同一 guuid 已有 `active` 目标时，先按 `replace` 结束旧目标（恢复旧 `origin`、写日志），再建新目标、**进度从 0 开始**；
- **立即接管**：设置成功时立刻写一次 `optimize01_man/count/chance`（在线改内存 + `writeToDB`，离线直接 `update tbl_Account`），不等下一局；
- **原设置快照**：设置时取在线玩家的 `optimize01_man/count/chance` 存入 `origin`，停止/达标时恢复；
- **白名单**：`d_halls.white_num_on=False`（默认）时正优化不需要白名单；开关为 `True` 时模块自动把 guuid 注入 `d_users.datas[1]["white_num"]`（只注入、不写文件），停止/达标时移除（只移除自己注入的）；
- **负目标**：`chance` 内部写负数，`white_num_on` 为 `True` 时也免白名单。

## 3. 查询列表 `异步_查询_胜率目标_列表`

### 3.1 请求

```json
{
  "header": "异步_查询_胜率目标_列表",
  "guuids": "",
  "scope_type": "",
  "scope_id": "",
  "group_id": 0,
  "state": "active",
  "context": "opt-list-001"
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `guuids` | string | 否 | 逗号分隔；空=不过滤 |
| `scope_type` | string | 否 | `union` / `club`；空=不过滤 |
| `scope_id` | string | 否 | 联盟 id / 俱乐部 id；空=不过滤 |
| `group_id` | int | 否 | 0=不过滤；>0 按来源分组过滤 |
| `state` | string | 否 | `active`（默认）/ `done` / `stopped` / 空字符串=全部 |
| `history` | int | 否 | `1`=查历史表 `usr_opt_target_history`（每次设置一条）；默认查当前目标 |

### 3.2 返回

```json
{
  "total": 1,
  "list": [
    {
      "guuid": "718968", "name": "abc11",
      "state": "active",
      "target_value": 500, "chance": 100,
      "progress": 320, "remain": 180,
      "round_count": 12, "peer_count": 13,
      "origin": {"man": "", "count": 0, "chance": 0},
      "injected_white": false,
      "man": "648425", "man_name": "老板",
      "scope_type": "club", "scope_id": "775447",
      "group_id": 12, "group_name": "测试组",
      "set_ts": 1762732800, "set_time": "2026-11-10 10:00:00",
      "finish_ts": 0, "finish_time": "", "finish_reason": "",
      "start_user_score": 0, "mode": "deal",
      "online": 1, "cur_chance": 100, "cur_count": 1
    }
  ]
}
```

| 字段 | 说明 |
| --- | --- |
| `id` | 历史记录 ID（仅 `history=1` 返回） |
| `progress` | 目标期间累计输赢（可负） |
| `remain` | `abs(target_value) - abs(progress)`，可为负（已超目标但未结算前） |
| `round_count` | 参与并累加过的局数（0 分荒庄不算） |
| `peer_count` | 参与局数（含 0 分） |
| `origin` | 设置前的 `optimize01_*` 快照（离线账号为默认空值） |
| `injected_white` | 是否由本模块注入过白名单 |
| `online` | 1=当前在线；0=离线 |
| `cur_chance` / `cur_count` | **在线**玩家的实时属性（确认"是否真的挂上了"）；离线为 0 |

> `cur_count=1` 表示本局已挂上次数；`cur_chance` 正/负分别对应正/负目标。

## 5. 查询日志 `异步_查询_胜率目标_日志`

### 5.1 请求

```json
{
  "header": "异步_查询_胜率目标_日志",
  "guuid": "",
  "operator": "",
  "action": "",
  "date0": "2026-11-01",
  "date1": "2026-11-10",
  "count": 50,
  "page": 0,
  "context": "opt-log-001"
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `guuid` | string | 否 | 目标玩家 guuid |
| `operator` | string | 否 | 操作人 guuid |
| `action` | string | 否 | `set` / `update` / `stop` / `done` / `replace` |
| `date0` / `date1` | string | 否 | `YYYY-MM-DD` 闭区间 |
| `count` | int | 否 | 每页条数，默认 50，最大 200 |
| `page` | int | 否 | 从 0 开始 |

### 5.2 返回

```json
{
  "total": 2,
  "list": [
    {
      "id": 12, "date": "2026-11-10", "time": "10:00:00",
      "operator": "648425", "operator_name": "老板",
      "action": "set", "target_guuid": "718968", "target_name": "abc11",
      "group_id": 0, "target_value": 500, "chance": 100,
      "progress": 0, "remark": "牌桌内临时调整"
    }
  ]
}
```

按 `id desc` 排序。`action` 含义：

| action | 触发 |
| --- | --- |
| `set` | 首次设置 |
| `update` | 覆盖已有目标（旧目标先按 replace 结束） |
| `replace` | 旧目标被新目标顶掉时写一条旧目标的结束记录 |
| `stop` | 手工停止 |
| `done` | 达标自动结束 |

> 日志只增不改，无删除接口。

## 6. 按俱乐部分组批量

### 6.1 前置：先加载分组

按分组设置/停止时，服务端要求该管理域的分组缓存已加载（`EnsureScope` 完成）。调用方先调一次现有接口：

```json
{
  "header": "查询_俱乐部_分组列表",
  "club_id": "775447",
  "context": "pg-list-001"
}
```

拿到 `group_id` 后，再调设置：

```json
{
  "header": "异步_设置_胜率目标",
  "club_id": "775447",
  "group_id": 12,
  "target_value": 500,
  "chance": 100,
  "remark": "分组批量",
  "context": "opt-set-002"
}
```

### 6.2 语义

- 分组只是**批量容器**：设置瞬间按 `scope["members"][group_id]` 展开成 N 条独立目标；
- 之后分组成员增减、分组改名/删除，都**不会**自动同步到已生成的目标；要停就显式调停止；
- 每条目标带 `scope_type/scope_id/group_id/group_name` 快照，只用于追溯与筛选，不做归属校验。

## 7. 客户端（牌桌内）对接

1. **入口**：牌桌内 boss 点击「胜率调整」→ 弹窗；
2. **拉数据**：调 `异步_查询_胜率目标_列表`，传当前房在座玩家的 `guuids`（逗号分隔），`state` 传空字符串（含历史）或 `active`；用返回的 `progress/target_value` 画进度条，`online/cur_count` 显示"已生效"；
3. **设置**：弹窗提交 `guuids + target_value + chance + remark`；`target_value` 用"赢/输 + 数值"两个控件拼，避免手输负号；
4. **停止**：单个/批量传 `guuids`；
5. **刷新**：服务端不推送，客户端定时（建议 10 秒级）刷列表，不要逐局轮询。

> 牌桌内只能操作**本房在座玩家**：服务端不校验房间归属，客户端自己用当前房 `guuids` 限定，避免误设其他玩家。

## 8. 错误表

| `result.error` | 触发 |
| --- | --- |
| `俱乐部功能未启用` | `game_mode != 'club'` |
| `无权限` | 调用者不在 `boss` 名单 |
| `target_value/chance/group_id 必须是整数` | 参数不是整数 |
| `target_value 不能为 0` | 目标值为 0 |
| `chance 必须在 1~100` | `chance` 越界 |
| `按分组设置必须传 club_id` | 传了 `group_id` 但没传 `club_id` |
| `按分组停止必须传 club_id` | 同上（停止接口） |
| `没有目标玩家` | `guuids` 与分组展开结果都为空 |
| `俱乐部不存在` | `club_id` 不在 `Hall.clubs` |
| `分组数据加载中，请先查询一次分组列表后重试` | 管理域分组缓存未加载 |
| `分组不存在` | `group_id` 不属于该管理域 |

> 注意：本期**不校验 guuid 是否存在**；写错的 guuid 会返回 `ok` 并生成目标记录，但该玩家不入房就不会生效。

## 10. 重要口径（对账/验收用）

| 项 | 口径 |
| --- | --- |
| 进度 | `round_score + win_mang_score + xi_score` 累计，**奖池提留前**；最大赢家可能比实际到手多算一档 `reward_money` |
| 生效 | 每局 `Start` 写 `optimize01_count=1` + `chance=±目标`，命中后 `decOptimizeNumber` 扣到 0 |
| 停止恢复 | 恢复设置时的 `origin`（`man/count/chance`），不是清零 |
| 达标 | 正目标 `progress >= target_value`；负目标 `progress <= target_value` |
| 离座/离线 | 期间不产生进度，属性保持目标值；重新进任何主力房继续生效、继续累加 |
| 白名单 | 默认 `white_num_on=False`，正优化不需要名单；开关为 `True` 时模块注入，停止移除 |
| 手工冲突 | 目标期间不要对同一玩家用 `异步_设置_玩家_属性` 改 `optimize01_*`，下一局会被覆盖 |

## 11. 变更记录
