## 1. 通用说明

### 1.1 通道与响应

- 客户端→服务器：`reqHallCommand(param, context)`；
- 服务器→客户端：`onMessage("ClubMemberAgentChain", json)` + `onHallCommand(ret_code, result)`；
- `param` 为 JSON 字符串，必须含 `"header"`；`context` 原样回传（推送也带 `context`）；
- 通用返回码、JSON 包裹、异常路径与 `doc/俱乐部代理与邀请码-客户端接口文档.md` §1 一致，本文不重复；
- 服务端内部用 `0x500` 标记“不同步返回”（该码不下发），最终经 `onHallCommand` 回调送达：`0x200` 成功 / `0x301` 失败；
- 本命令无分页；数据通过 `onMessage("ClubMemberAgentChain", json)` 推送，推送后回 `0x200`；参数/权限错误立即回 `0x301`。

### 1.2 权限与模式

| 操作者 | 结果 |
| --- | --- |
| 平台 boss / 最高 boss（`d_users.config["account"]` 的 `boss` / `bigboss` 名单） | 允许 |
| 俱乐部创建者 / 联盟总群主 / 代理 / 普通玩家 | `无权访问` |
| 大厅模式（`game_mode != 'club'`） | `俱乐部功能未启用` |

> 本命令只给平台 boss 用；俱乐部内角色即使能看到成员列表，也不能调本命令。不单独为 `Hall.boss` / `level>=99` 开后门。

### 1.3 统计口径（先看这段）

- **链路**：被点玩家 → 直属上级 → … → 俱乐部创建者 → 总群主（如有）；不含被点玩家自己；已取消代理跳过，自动接到其上级。
- **整条线**：该级本人 + 其全部下级（代理 + 普通玩家），不是只看被点玩家所在的那一条路径。
- **代理行 / 盟主（当前俱乐部创建者）行**：按**当前俱乐部**当前成员口径，与 `查询_俱乐部_成员` 的 `total_score` / `total_contrib_fen` 同源：
  - `total_score`：该级整条线累计输赢（积分，可负）；
  - `total_contrib_fen`：该级整条线在本俱乐部创造的累计抽水（分）；
  - `total_bonus_fen`：当前成员在该级子树内的 `club_agent_info.bonus`（未提取）+ `代理红利提取` 流水（已提取，元×100）。
- **总群主行**：按**本联盟全部俱乐部**汇总：
  - `total_score` / `total_contrib_fen`：联盟内所有俱乐部、当前成员的合计；
  - `total_bonus_fen`：联盟内所有俱乐部、当前成员的代理累计红利 + 总群主自己的联盟上缴（`owner_bonus` + 联盟红利提取）。
- `total_bonus_fen` 中俱乐部代理红利包含 `clubroot/clubN/darkroot`，不含 `unionroot/uniondark`；总群主行再单独加回联盟上缴，二者不重叠。
- 俱乐部代理红利只算当前成员；总群主的联盟上缴按历史累计（总群主自己的收益）。
- **同一人兼任多角色**：按层级/角色分行，允许同一 guuid 出现两行；用 `is_creator` / `is_union_owner` 区分，客户端**不要按 guuid 去重**。
- 联盟内其他盟主不是该玩家的祖先，不单独成行；他们的俱乐部数据计入总群主行。
- 平台 boss 看到**真实值**，不套 `show_percent` 展示折扣。
- 积分单位是积分（可负）；贡献/红利单位是**分**，客户端展示时 ÷100。

## 3. 查询_俱乐部_成员_代理链路

### 3.1 请求

```json
{
  "header": "查询_俱乐部_成员_代理链路",
  "club_id": "984470",
  "user_id": "430994",
  "context": "boss-player-chain-001"
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `header` | string | 是 | `查询_俱乐部_成员_代理链路` |
| `club_id` | string | 是 | 当前俱乐部 ID；决定链路所属代理树和统计范围 |
| `user_id` | string | 是 | 被点玩家 ID，纯数字 |
| `context` | string | 否 | 原样回传 |

无分页、无 `show_type`、无 `agent_id`、无 `search_name_id`。

### 3.2 推送 `ClubMemberAgentChain`

推送 router：`ClubMemberAgentChain`（点对点，只发给请求者；带 `context`）。

```json
{
  "count": "3",
  "club_id": "984470",
  "user_id": "430994",
  "union_id": "123456",
  "union_name": "测试联盟",
  "chain": [
    {
      "guuid": "430995",
      "name": "直属上级",
      "is_creator": "0",
      "is_union_owner": "0",
      "total_score": "-1200",
      "total_contrib_fen": "34500",
      "total_bonus_fen": "12000"
    },
    {
      "guuid": "567671",
      "name": "俱乐部老板",
      "is_creator": "1",
      "is_union_owner": "0",
      "total_score": "-3800",
      "total_contrib_fen": "98000",
      "total_bonus_fen": "42000"
    },
    {
      "guuid": "820084",
      "name": "总群主",
      "is_creator": "0",
      "is_union_owner": "1",
      "total_score": "-15200",
      "total_contrib_fen": "450000",
      "total_bonus_fen": "448000"
    }
  ],
  "context": "boss-player-chain-001"
}
```

字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `count` | string | 链路行数；空链为 `"0"` |
| `club_id` | string | 请求的当前俱乐部；代理/盟主行按该俱乐部统计，总群主行按全联盟统计 |
| `user_id` | string | 被点玩家 ID |
| `union_id` / `union_name` | string | 当前俱乐部所属联盟；未入盟为空串 |
| `chain` | array | 自下而上的祖先链路，不含被点玩家自己；第 0 项是直属上级 |
| `chain[].guuid` / `name` | string | 节点 ID / 昵称 |
| `chain[].is_creator` | string | `"1"` 俱乐部创建者 |
| `chain[].is_union_owner` | string | `"1"` 联盟总群主 |
| `chain[].total_score` | string | 该级整条线累计输赢（积分，可负） |
| `chain[].total_contrib_fen` | string | 该级整条线累计贡献（分） |
| `chain[].total_bonus_fen` | string | 该级整条线累计红利（分） |
| `context` | string | 原样回传 |

约定：

- 所有数值字段都是字符串（与 `NumberList` 风格一致），客户端自行转数字/÷100。
- `chain` 每行字段恒定存在；`count="0"` 时 `chain=[]`。
- 不逐行下发 `club_id`；代理/盟主行按请求的 `club_id` 统计，总群主行按全联盟统计。
- `chain` 第 0 项是直属上级；客户端可直接按数组展示，或反转成“总群主→…→直属上级”。
- 平台 boss 返回真实值，不做展示折扣。
- 总群主行固定 `is_creator="0"`、`is_union_owner="1"`，即使 guuid 与创建者相同。
- 同一人兼任多角色时会出现两行相同 guuid：创建者/代理行按当前俱乐部口径，总群主行按全联盟口径；客户端按 flag 区分层级，**不要按 guuid 去重**。
- 总群主行的数值不等于创建者行；它是整个联盟的汇总。
- 俱乐部有 `union_id` 但联盟数据取不到时不追加总群主行。

### 3.3 空链路

- 玩家是俱乐部创建者/总群主且没有上级（独立俱乐部老板也是创建者）：返回 `count="0"`、`chain=[]`，仍为成功 `0x200`。
- 客户端展示“无上级代理”即可，不要当错误。

### 3.4 错误

| 情况 | ret_code | result |
| --- | --- | --- |
| 非平台 boss | `0x301` | `{"error":"无权访问"}` |
| 非客户端调用（HTTP 后台） | `0x301` | `{"error":"仅客户端可用"}` |
| `club_id` 非法/俱乐部不存在 | `0x301` | `{"error":"俱乐部不存在"}` |
| 非俱乐部模式 | `0x301` | `{"error":"俱乐部功能未启用"}` |
| `user_id` 非法 | `0x301` | `{"error":"玩家ID非法"}` |
| 玩家不在本俱乐部 | `0x301` | `{"error":"玩家不在该俱乐部"}` |
| 代理树加载中 | `0x301` | `{"error":"代理数据加载中，请重试"}` |
| 统计查询失败 | `0x301` | `{"error":"链路统计查询失败"}` |
| 成功 | `0x200` | 先推送 `ClubMemberAgentChain`，再回 `{"context":"..."}` |

> 失败均通过 `onHallCommand(0x301, {"context":"<ctx>","result":{"error":"..."}})` 回调；上表只列 `result.error` 文案。参数/权限等同步校验失败由 `reqHallCommand` 统一包裹，格式相同。

### 3.5 时序

1. 客户端发送 `查询_俱乐部_成员_代理链路`。
2. 服务端校验平台 boss 权限、俱乐部存在、`game_mode=club`、`user_id` 格式。
3. 服务端校验目标玩家是否属于本俱乐部；代理树未加载则触发加载并回“代理数据加载中，请重试”。
4. 服务端查询当前俱乐部成员统计/红利；如需要总群主行，再查本联盟全部俱乐部汇总（当前成员 + 联盟上缴）。
5. 推送 `ClubMemberAgentChain`，随后回 `0x200`。
6. 客户端按数组顺序渲染；同一 guuid 出现两行时按 `is_creator` / `is_union_owner` 区分层级。

## 4. 与现有接口的关系

| 现有接口 | 关系 |
| --- | --- |
| `查询_俱乐部_成员`（`NumberList`） | **不变**，仍是分页 + 直属口径的成员列表；本命令只负责单人链路，不替代成员列表 |
| `查询_俱乐部_代理_信息`（`ClubAgentInfo`） | 只返回“我”的直属上级/直接下级；本命令可查任意被点玩家的完整上行链 |
| `查询_俱乐部_红利` / `查询_俱乐部_红利_统计` | 仍用于代理本人的红利余额、今日/昨日、累计提取；本命令只给“整条线累计红利” |
| `查询_联盟_红利` / `查询_联盟_红利_统计` | 仍用于总群主自己的联盟红利余额、明细、统计；本接口总群主行已包含联盟上缴总量，但不提供明细 |
| `异步_查询_俱乐部_成员`（后台 HTTP） | **不变**；本命令是客户端推送命令，不提供 HTTP 后台入口 |

## 5. 客户端渲染建议

- 平台 boss 打开“玩家信息”详情卡时调用一次，不需要逐级点击。
- `chain` 数组是“直属上级→总群主”的顺序；`is_creator` / `is_union_owner` 渲染“老板/总群主”角标。
- 同一 guuid 可能出现两行（兼任多角色）：创建者/代理行看当前俱乐部，总群主行看全联盟；按 flag 区分，不要按 guuid 去重。
- 不展示今日/昨日，不展示被点玩家自己一行；只展示三个总量。
- 积分可负；贡献/红利单位分，展示时 ÷100。
- `count="0"` 显示“无上级代理”。
- 错误处理：
  - `无权访问`：入口本就不应对非平台 boss 展示；
  - `代理数据加载中，请重试`：自动重试 1~2 次或提示稍后重试；
  - `玩家不在该俱乐部`：关闭详情或提示数据已变化。

## 6. 边界与注意事项

| # | 场景 | 说明 |
| --- | --- | --- |
| 1 | 玩家无代理行/历史成员 | 链路为 `[老板]`；有联盟再追加总群主 |
| 2 | 链路中间有已取消代理 | 跳过该节点，上级接上；统计/红利按成员列表兜底口径 |
| 3 | 总群主 = 俱乐部创建者 | 创建者行 + 总群主行，两行同 guuid；`is_creator` / `is_union_owner` 分别标记 |
| 4 | 总群主已在链路中 | 代理行保持代理口径 + 总群主行，两行同 guuid |
| 5 | 俱乐部有 `union_id` 但联盟数据取不到 | 不追加总群主行，不报错 |
| 6 | 同一玩家属于多个俱乐部 | 按请求 `club_id` 分别返回，互不影响 |
| 7 | 无分页 | 链路深度很小，一次返回全部 |
| 8 | 不提供 HTTP 后台入口 | 后台如需要，后续加 `异步_查询_俱乐部_成员_代理链路` |
| 9 | 无 DDL / 无配置 | 复用 `club_agent_info.bonus`、`club_history_info`、`club_member_score_info`；需重启 baseapp 生效 |

补充解释：

- **为什么 `total_bonus_fen` 和 `total_contrib_fen` 通常不相等**：贡献是该级整条线创造的全部抽水；红利是该线实际留下的累计分成，上级层分走的、联盟上缴的部分不在里面。总群主行例外：它的红利已加回自己的联盟上缴。
- **为什么本接口的红利和红利明细可能对不上**：代理/盟主行只算当前俱乐部成员；总群主行的俱乐部代理红利也只算当前成员，但联盟上缴按历史累计。历史全量以 `查询_俱乐部_红利_明细` / `查询_联盟_红利_明细` 为准。
