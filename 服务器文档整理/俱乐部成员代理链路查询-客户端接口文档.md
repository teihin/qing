## 1. 通用说明

### 1.1 通道与响应

- 客户端→服务器：`reqHallCommand(param, context)`；
- 服务器→客户端：`onMessage("ClubMemberAgentChain", json)` + `onHallCommand(ret_code, result)`；
- `param` 为 JSON 字符串，必须含 `"header"`；`context` 原样回传（推送也带 `context`）；
- 通用返回码、JSON 包裹、异常路径与 `doc/俱乐部代理与邀请码-客户端接口文档.md` §1 一致，本文不重复；
- 服务端内部用 `0x500` 标记“不同步返回”（该码不下发），最终经 `onHallCommand` 回调送达：`0x200` 成功 / `0x301` 失败；
- 本命令无分页；数据通过 `onMessage("ClubMemberAgentChain", json)` 推送，推送后回 `0x200`；参数/权限错误立即回 `0x301`。
- 联盟内请求一次可能返回多条链（`chains[]`）；非联盟俱乐部最多一条；零命中返回空数组，仍为 `0x200`。

### 1.2 权限与模式

| 操作者 | 结果 |
| --- | --- |
| 平台 boss / 最高 boss（`d_users.config["account"]` 的 `boss` / `bigboss` 名单） | 允许 |
| 俱乐部创建者 / 联盟总群主 / 代理 / 普通玩家 | `无权访问` |
| 大厅模式（`game_mode != 'club'`） | `俱乐部功能未启用` |

> 本命令只给平台 boss 用；俱乐部内角色即使能看到成员列表，也不能调本命令。不单独为 `Hall.boss` / `level>=99` 开后门。

### 1.3 统计口径（先看这段）

- **查询范围**：请求 `club_id` 已入盟时，返回该联盟内所有包含被点玩家的俱乐部链路（一个俱乐部一条，按各自俱乐部的成员/代理树独立统计）；未入盟时只按该俱乐部返回一条；零命中返回空数组。
- **链路**：被点玩家 → 直属上级 → … → 俱乐部创建者 → 总群主（如有）；不含被点玩家自己；已取消代理跳过，自动接到其上级。
- **整条线**：该级本人 + 其全部下级（代理 + 普通玩家），不是只看被点玩家所在的那一条路径。
- **每行统一 9 个统计字段**：
  - `today_score` / `yesterday_score` / `total_score`：该级整条线今日/昨日/累计输赢（积分，可负）；
  - `today_contrib_fen` / `yesterday_contrib_fen` / `total_contrib_fen`：该级整条线今日/昨日/累计贡献（分）；
  - `today_bonus_fen` / `yesterday_bonus_fen` / `total_bonus_fen`：该级整条线今日/昨日新增红利、累计红利（分）。
- **代理行 / 盟主（当前俱乐部创建者）行**：按**当前俱乐部**当前成员口径，与 `查询_俱乐部_成员` 的今日/昨日/总输赢、贡献同源。
- **总群主行**：按**本联盟全部俱乐部**汇总：
  - 输赢/贡献：联盟内所有俱乐部、当前成员的今日/昨日/总合计；
  - 红利：联盟内所有俱乐部、当前成员的今日/昨日/累计代理红利 + 总群主自己的联盟上缴。
  - 多链时每条链末尾都会带一条相同的总群主行（全联盟汇总）；客户端按 `is_union_owner` 只渲染一次，不要相加。
- **红利口径**：
  - `total_bonus_fen` = `club_agent_info.bonus`（未提取）+ `代理红利提取`（已提取，元×100）；总群主行再加 `owner_bonus` + 联盟红利提取。
  - `today_bonus_fen` / `yesterday_bonus_fen` = `usr_income_info` 当日/昨日新增红利（当前成员，排除 `clubtotal/unionroot/uniondark`）；总群主行再加自己的 `unionroot/uniondark` 日收益。
  - 今日/昨日是“当日新增”，不要求“今日+昨日+历史 = `total_bonus_fen`”；总红利是累计获得值。
- `total_bonus_fen` 中俱乐部代理红利包含 `clubroot/clubN/darkroot`，不含 `unionroot/uniondark`；总群主行再单独加回联盟上缴，二者不重叠。
- 俱乐部代理红利只算当前成员；总群主的联盟上缴按历史累计（总群主自己的收益）。
- **同一人兼任多角色**：按层级/角色分行，允许同一 guuid 出现两行；用 `is_creator` / `is_union_owner` 区分，客户端**不要按 guuid 去重**。
- 联盟内其他盟主不是该玩家的祖先，不单独成行；他们的俱乐部数据计入总群主行。
- 平台 boss 看到**真实值**，不套 `show_percent` 展示折扣。
- **2026-11-07**：`today/yesterday_bonus_fen` 为扣红利暗抽后的净额；`*_contrib_fen` 为真实贡献 + 该行生效 `contrib_add`；暗抽金额不下发。
- 积分单位是积分（可负）；贡献/红利单位是**分**，客户端展示时 ÷100。

## 3. 查询_俱乐部_成员_代理链路

### 3.1 请求

```json
{
  "header": "查询_俱乐部_成员_代理链路",
  "club_id": "984470",
  "user_id": "430994",
  "context": "boss-player-chain-001"
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `header` | string | 是 | `查询_俱乐部_成员_代理链路` |
| `club_id` | string | 是 | 当前俱乐部 ID；已入盟时服务端扩展到整个联盟，未入盟时只查该俱乐部 |
| `user_id` | string | 是 | 被点玩家 ID，纯数字 |
| `context` | string | 否 | 原样回传 |

无分页、无 `show_type`、无 `agent_id`、无 `search_name_id`。

### 3.2 推送 `ClubMemberAgentChain`

推送 router：`ClubMemberAgentChain`（点对点，只发给请求者；带 `context`）。

| `chain[].groups` | array | **2026-11-07 新增**：该节点所属分组，如 `[{"group_id":"1","group_name":"VIP"}]`；按节点所在俱乐部的管理域取，无分组/管理域未加载/节点无俱乐部时为 `[]`；字段恒定存在 |
| `context` | string | 原样回传 |

约定：

- 所有数值字段都是字符串（与 `NumberList` 风格一致），客户端自行转数字/÷100。
- 请求俱乐部已入盟：`chains` 只包含“玩家当前所属”的联盟俱乐部，可能 0 条或多条；请求俱乐部若包含玩家则排第一，其余按俱乐部 ID 升序。
- 请求俱乐部未入盟：`chains` 最多 1 条，只按该俱乐部统计；玩家不是成员时返回空数组。
- 零命中：`count="0"`、`chains=[]`，仍为成功 `0x200`。
- 每条链各自带总群主行（全联盟汇总）；多链时该行重复且数值相同，客户端按 `is_union_owner` 只渲染一次，**不要把多条链的总群主行相加**。
- 今日/昨日字段是该链/该联盟的当日统计；今日/昨日红利是“当日新增”，不是余额日变化。今日+昨日+历史不要求等于 `total_bonus_fen`。
- 平台 boss 返回真实值，不做展示折扣。
- 总群主行固定 `is_creator="0"`、`is_union_owner="1"`，即使 guuid 与创建者相同。
- **每个节点的俱乐部（2026-11-06）**：`chain[].club_id` / `club_name` 字段恒定存在。代理/创建者行是**当前链所属俱乐部**；总群主虚拟行是**总群主自己的俱乐部**（`club_guuid`），多链时每条链末尾那条总群主行的俱乐部相同。客户端可直接按节点渲染，不必从父级 `chains[].club_id` 推断。
- 同一人兼任多角色时会出现两行相同 guuid：创建者/代理行按当前俱乐部口径，总群主行按全联盟口径；客户端按 flag 区分，**不要按 guuid 去重**。
- 总群主行的数值不等于创建者行；它是整个联盟的汇总。
- **每个节点的分组（2026-11-07）**：`chain[].groups` 按该节点**所在俱乐部**（与 `club_id` 同口径）的管理域取。分组只覆盖被加入过分组的玩家，代理链上多数节点是 `[]`；管理域未加载时先返回 `[]`，不阻塞链路查询、不主动触发加载。

### 3.3 空链路

- 单条链为空（玩家是俱乐部创建者/总群主且没有上级，独立俱乐部老板也是创建者）：该链 `count="0"`、`chain=[]`；顶层仍为成功 `0x200`。
- 零命中（联盟内不属任何俱乐部，或非联盟单俱乐部不是成员）：顶层 `count="0"`、`chains=[]`，仍为成功 `0x200`。
- 客户端展示“无上级代理/不在本俱乐部”即可，不要当错误。

### 3.4 错误

| 情况 | ret_code | result |
| --- | --- | --- |
| 非平台 boss | `0x301` | `{"error":"无权访问"}` |
| 非客户端调用（HTTP 后台） | `0x301` | `{"error":"仅客户端可用"}` |
| `club_id` 非法/俱乐部不存在 | `0x301` | `{"error":"俱乐部不存在"}` |
| 非俱乐部模式 | `0x301` | `{"error":"俱乐部功能未启用"}` |
| `user_id` 非法 | `0x301` | `{"error":"玩家ID非法"}` |
| 代理数据加载中 | `0x301` | `{"error":"代理数据加载中，请重试"}` |
| 统计查询失败 | `0x301` | `{"error":"链路统计查询失败"}` |
| 成功 | `0x200` | 先推送 `ClubMemberAgentChain`，再回 `{"context":"..."}` |

> 失败均通过 `onHallCommand(0x301, {"context":"<ctx>","result":{"error":"..."}})` 回调；上表只列 `result.error` 文案。参数/权限等同步校验失败由 `reqHallCommand` 统一包裹，格式相同。
> 零命中（联盟内不属任何俱乐部，或非联盟单俱乐部不是成员）不报错，成功返回 `count="0"`、`chains=[]`。

### 3.5 时序

1. 客户端发送 `查询_俱乐部_成员_代理链路`。
2. 服务端校验平台 boss 权限、俱乐部存在、`game_mode=club`、`user_id` 格式。
3. 服务端判断请求 `club_id` 是否已入盟：
   - 已入盟：查玩家 `sm_club_join/sm_club_join2`，枚举同联盟已加载俱乐部，只保留玩家当前所属俱乐部；
   - 未入盟：只查当前俱乐部；玩家不是成员时返回空数组。
4. 目标俱乐部代理树未加载则触发加载并回“代理数据加载中，请重试”；全部加载后再继续。
5. 逐个俱乐部查询当前成员统计/红利；如需要总群主行，本联盟汇总只查一次，复用到每条链。
6. 组装 `chains[]`，一次推送 `ClubMemberAgentChain`，随后回 `0x200`；零命中推空数组。
7. 客户端按 `chains[].club_id` / `club_name` 分块渲染；总群主行只渲染一次。

## 5. 客户端渲染建议

- 平台 boss 打开“玩家信息”详情卡时调用一次，不需要逐级点击。
- 按 `chains[]` 分块渲染，每块用 `club_name` 标注俱乐部；`chain` 数组是“直属上级→总群主”的顺序；`is_creator` / `is_union_owner` 渲染“老板/总群主”角标。
- 同一 guuid 可能出现两行（兼任多角色）：创建者/代理行看当前俱乐部，总群主行看全联盟；按 flag 区分，不要按 guuid 去重。
- 每条链末尾都有总群主行；多链时只渲染一次，不要相加。
- 展示每行今日/昨日/总输赢、今日/昨日/总贡献、今日/昨日/总红利；不展示被点玩家自己一行。
- 积分可负；贡献/红利单位分，展示时 ÷100。
- 顶层 `count="0"` 显示“无上级代理/不在本俱乐部”；单条链内 `count="0"` 显示“无上级代理”。
- 错误处理：
  - `无权访问`：入口本就不应对非平台 boss 展示；
  - `代理数据加载中，请重试`：自动重试 1~2 次或提示稍后重试。

## 6. 边界与注意事项

| # | 场景 | 说明 |
| --- | --- | --- |
| 1 | 玩家无代理行/历史成员 | 该俱乐部链路为 `[老板]`；有联盟再追加总群主 |
| 2 | 链路中间有已取消代理 | 跳过该节点，上级接上；统计/红利按成员列表兜底口径 |
| 3 | 总群主 = 俱乐部创建者 | 创建者行 + 总群主行，两行同 guuid；`is_creator` / `is_union_owner` 分别标记 |
| 4 | 总群主已在链路中 | 代理行保持代理口径 + 总群主行，两行同 guuid |
| 5 | 俱乐部有 `union_id` 但联盟数据取不到 | 不追加总群主行，不报错 |
| 6 | 同一玩家属于多个俱乐部 | 联盟内返回多条链（请求俱乐部优先，其余按 club_id 升序）；非联盟俱乐部只查该俱乐部 |
| 7 | 无分页 | 链路深度很小，一次返回全部 |
| 8 | 不提供 HTTP 后台入口 | 后台如需要，后续加 `异步_查询_俱乐部_成员_代理链路` |
| 9 | 无 DDL / 无配置 | 复用 `club_agent_info.bonus`、`club_history_info`、`club_member_score_info`；需重启 baseapp 生效 |
| 10 | 零命中（联盟内不属任何俱乐部，或非联盟单俱乐部不是成员） | 成功 `count="0"`、`chains=[]` |
| 11 | 多链时的总群主行 | 每条链各带一条，数值相同；客户端只渲染一次、不要相加 |

补充解释：

- **为什么 `total_bonus_fen` 和 `total_contrib_fen` 通常不相等**：贡献是该级整条线创造的全部抽水；红利是该线实际留下的累计分成，上级层分走的、联盟上缴的部分不在里面。总群主行例外：它的红利已加回自己的联盟上缴。
- **今日/昨日红利和总红利的关系**：`today_bonus_fen` / `yesterday_bonus_fen` 取 `usr_income_info` 当日/昨日新增；`total_bonus_fen` 取当前 `bonus` + 已提取流水。V2 前回补、跳过写账等情况下，两者不保证“日合计 = 总红利”。
- **为什么本接口的红利和红利明细可能对不上**：代理/盟主行只算当前俱乐部成员；总群主行的俱乐部代理红利也只算当前成员，但联盟上缴按历史累计。历史全量以 `查询_俱乐部_红利_明细` / `查询_联盟_红利_明细` 为准。
