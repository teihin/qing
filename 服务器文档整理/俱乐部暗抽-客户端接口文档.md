## 1. 通用说明

### 1.1 通道与响应

- 客户端→服务器：`reqHallCommand(param, context)`；
- 服务器→客户端：`onHallCommand(ret_code, result)`；
- 本组只有 1 个写命令 `设置_俱乐部_代理_暗抽`；它和 `设置_俱乐部_代理` 一样，服务端内部用 `0x500` 标记“不同步返回”（该码不下发），最终结果经 `onHallCommand` 回调送达：`0x200` 成功 / `0x301` 失败。
- 通用返回码、JSON 包裹、异常路径与 `doc/俱乐部代理与邀请码-客户端接口文档.md` §1 一致，本文不重复。

### 1.2 可见性总则

| 对象 | 能否看到暗抽 |
| --- | --- |
| 群主（俱乐部创建者）/ 联盟房间 owner | `NumberList` 可见行覆盖值；能看到**房间默认** `dark_percent`（见 `ClubPlayList`）和设置命令的返回值 |
| 被设置的直属上级 | `NumberList` 自己直属下级行的覆盖值；设置时知道本次值 |
| 被设置的代理本人 | **看不到**；`NumberList` 自身行返回 `"-1"`；`ClubAgentInfo` / `roomSetting` 均不返回 |
| 普通成员/玩家 | **看不到**；`NumberList` 返回 `"-1"` |
| 联盟总群主 | `NumberList` 成员俱乐部可见行的覆盖值（2026-11-05 起）；盟主虚拟行显示该盟主自己俱乐部的覆盖值；另能看到自己链上的 `uniondark` 收益明细/统计 |
| 独立俱乐部创建者 | 自己俱乐部 `NumberList` 可见行覆盖值 + `darkroot` 收益明细/统计 |

> **2026-11-05 新增**：`查询_俱乐部_成员` 的 `NumberList` 每行新增 `dark_percent`（字符串，仅俱乐部模式）。
> `"-1"`=未设置/无权查看，`"0"`=明确不抽，`">0"`=覆盖比例；盟主虚拟行显示盟主自己俱乐部的覆盖值（仅联盟总群主可见，取不到时 `"-1"`）。仍**没有独立查询命令**，但管理者/直属上级可从列表直接读到覆盖值。
> **客户端注意**：盟主虚拟行的 `is_agent` 恒为 `"0"`（它不是本俱乐部代理），不要用 `is_agent` 过滤该行；请按 `is_leader="1"` / `role="盟主"` 判断后展示其 `dark_percent`。
>
> V2 联盟边界：总群主通过自己俱乐部的玩法配置控制**房间默认**暗抽；2026-11-05 起联盟总群主也可对属下俱乐部整棵树设置单代理覆盖（`IsClubManager`），但仍不能修改成员俱乐部的房间玩法默认值。成员俱乐部创建者可以设置自己代理的覆盖，但看不到总群主俱乐部的房间默认值。

### 1.3 比例口径

- `dark_percent` 单位是**百分点，按玩家输赢金额计**，不是“占分账池的百分比”。
- 房间水率 `W` 来自玩法配置；房间默认 `dark_percent` 也来自玩法配置（`ClubPlayList` 可见）。
- 代理单独设置的 `dark_percent`：`NULL`=用房间默认；`0`=明确不抽；`>0`=该层暗抽比例。
- 每层实际抽取比例 = `dark_percent / W`：
  - `W=5、d=1` → 该层正常分得的 20% 被抽走，保留 80%；
  - `W=5、d=2` → 抽 40%，保留 60%（相对默认 1% 的保留额少 25%）。
- `d > W` 时服务端按 `W` 截断（该层保留 0），客户端不需要自己处理。
- `W=0`（玩法配置水率 0）：不扣水、不分账、不暗抽；此时代理覆盖无实际效果。
- 房间默认 `d=0` 时，代理覆盖非 NULL 的 2% **仍然生效**（前提 `W>0`）；客户端不要用“房间默认 0”推断该代理一定不抽。
- 暗抽只影响代理实际到账的保留额；代理的显示 `percent` 不变。

## 2. 命令：设置_俱乐部_代理_暗抽

- **命令名**：`设置_俱乐部_代理_暗抽`
- **通道**：`reqHallCommand` → 最终 `onHallCommand` 回调
- **权限**：该代理的直属上级，或该俱乐部创建者，或**该俱乐部所属联盟的盟主**；不能设置自己（盟主可以设置属下俱乐部的创建者）；目标必须是本俱乐部 `status='used'` 且持有效邀请码的代理。
  > 2026-11-05 起：联盟盟主对属下俱乐部等同创建者，**整棵代理树**都能设（含创建者本人那一层）。盟主一般不在本俱乐部的 `club_agent_info` 里，身份按 `club_union_info.owner_guuid` 判定，与代理树无关。

### 2.1 请求参数

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `header` | string | 是 | `设置_俱乐部_代理_暗抽` |
| `club_id` | string | 是 | 俱乐部 ID |
| `user_id` | string | 是 | 目标代理 guuid；建议传字符串，服务端会归一为字符串 |
| `dark_percent` | int | 是 | `0~20`；`-1` = 清空，回退到房间默认 |
| `context` | string | 否 | 原样回传 |

```json
{"header": "设置_俱乐部_代理_暗抽", "club_id": "820084",
 "user_id": "580629", "dark_percent": 2, "context": "ctx_dark_01"}
```

### 2.2 成功响应（`0x200`）

```json
{
  "context": "ctx_dark_01",
  "result": {"error": "", "user_id": "580629", "dark_percent": "2"}
}
```

- `dark_percent` 是字符串（服务端按字符串回传）；清空时回 `"-1"`。
- 成功后立即影响后续结算；已结算的牌局不追溯。
- 同一玩家在多个俱乐部当代理时，`dark_percent` 按俱乐部隔离，互不影响。

### 2.3 失败响应（`0x301`）

```json
{"context": "ctx_dark_01", "result": {"error": "只能设置自己的直属下级"}}
```

### 2.4 规则与错误

| 情况 | 错误文案 |
| --- | --- |
| `club_id` 无效/已删除 | `俱乐部不存在` |
| 服务端不是俱乐部模式 | `俱乐部功能未启用` |
| `dark_percent` 不是整数 | `暗抽比例必须是整数` |
| `dark_percent` 不在 `-1~20` | `暗抽比例必须在 0~20 之间` |
| 代理树未加载 | `代理数据加载中，请稍后重试` |
| 目标是本人或创建者 | `不能设置自己或创建者` |
| 目标不是本俱乐部 used 代理（无码/未设置/已取消） | `该成员还不是代理，请先设置代理` |
| 调用者不是目标的直属上级，也不是创建者 | `只能设置自己的直属下级` |

**创建者/盟主边界**：本命令不允许设置创建者/盟主自己的暗抽；该层按房间默认 `dark_percent` 执行。如后续业务要求“盟主层单独设暗抽”，需要另开上层配置入口。

## 3. 收益查询口径的变化

本方案**不新增收益查询命令、不新增推送路由、不新增客户端实体字段**；只改变既有红利数据中包含哪些行：

### 3.1 总群主（联盟）

- `查询_联盟_红利`（`ClubUnionBonus`）：`owner_bonus` 已包含 `uniondark` 合计。
- `查询_联盟_红利_明细`（`ClubUnionBonusList`）：返回行包含 `unionroot`（联盟上缴）和 `uniondark`（暗抽），字段结构不变；行里没有单独的层级标签，客户端展示为联盟收益即可。
- `查询_联盟_红利_统计`（`ClubUnionBonusStats`）：今日/昨日/未提取/累计提取均包含 `uniondark`。
- 总群主看不到成员俱乐部代理的 `dark_percent` 配置值，只能看到汇总收益。

### 3.2 独立俱乐部创建者

- `查询_俱乐部_红利`（`ClubBonus`）：`bonus` 已包含 `darkroot`。
- `查询_俱乐部_红利_明细`（`ClubBonusList`）：创建者能看到自己的 `darkroot` 行；`level` 可能返回 `darkroot`，客户端遇到未知 `level` 按普通收益展示即可。
- `查询_俱乐部_红利_统计`（`ClubBonusStats`）：今日/昨日/未提取/累计提取均包含 `darkroot`。
- 普通代理只能看到自己的 `keep` 行；看不到创建者的 `darkroot`。

### 3.3 联盟成员俱乐部

- 俱乐部红利明细/统计**排除** `uniondark`（联盟暗抽只给总群主看）。
- 普通代理的收益明细仍是自己的保留额；暗抽不会以单独行出现。

### 3.4 房间与玩家

- 房间 `roomSetting` 只带 `water_rate` / `play_config_id`，**不带 `dark_percent`**。
- 玩家/代理的 `ClubAgentInfo`、房间列表均不返回暗抽配置；俱乐部模式的 `NumberList` 仅在管理者/直属上级视角返回可见行覆盖值，其余情况 `"-1"`。
- 代理看到的分成金额已经是扣掉暗抽后的 `keep`；客户端不要用 `percent × 基数` 自行反推。

## 4. 典型时序

```text
群主创建玩法（water_rate=5、dark_percent=1）        → 见玩法配置接口文档
群主/直属上级设置某代理暗抽 2%：
  设置_俱乐部_代理_暗抽 {user_id, dark_percent:2}
    → 最终 onHallCommand 0x200 {dark_percent:"2"}
牌局结算：
  该层正常分得 250 分（W=5）
    → 暗抽 250 × 2/5 = 100 分给链顶
    → 该代理保留 150 分；其他层不受影响
  联盟总群主/独立创建者：查询_联盟_红利 / 查询_俱乐部_红利 看到暗抽汇总
  代理本人：查询_俱乐部_红利 / 收益明细 只看到自己的 150 分保留
```

## 5. 客户端注意事项

1. **暗抽是“暗”的**：不要把 `dark_percent` 放进 `ClubAgentInfo` / 房间信息，也不要让被设置代理本人、普通成员看到真实值；`NumberList` 只对管理者/直属上级返回可见行覆盖值。
2. **设置命令是异步回包**：不要用同步返回判断成功；以最终 `onHallCommand` 为准。
3. **清空用 `-1`**：传 0 是“明确不抽”，不是“回退默认”；两者语义不同。
4. **房间默认 0 + 代理覆盖 2% 仍生效**；不要用房间默认值推断某个代理的实际暗抽。
5. **`dark_percent` 是百分点，不是池百分比**；展示文案建议写“暗抽比例（按玩家输赢）”并注明“仅群主/设置人可见”。
6. **`W=0` 时不产生暗抽**；玩法水率为 0 的房间，代理覆盖无效果。
7. **`d > W` 会被截断**；允许设置 20，但实际按房间水率截断。
8. **创建者/盟主不能用本命令设置自己的暗抽**，按房间默认；如业务要支持，需新增入口。
9. **没有独立查询命令**：可在 `NumberList` 的 `dark_percent` 读取授权范围内的覆盖值；设置响应回传本次值。
10. 同一玩家多俱乐部：暗抽覆盖按 club 隔离；A 俱乐部的设置不影响 B。
