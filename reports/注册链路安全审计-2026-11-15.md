# 注册链路安全审计（上线前）

审计时间：2026-11-15 22:30–23:10
审计对象：客户端注册/登录链路 + XuanManager 注册接口 + 服务器 154.37.155.17 暴露面
审计方式：读源码 + 公网实测（只做连通性和无害请求）+ SSH 只读检查。**未改任何代码与配置。**

---

## 一、结论

**能上线，但现在这个状态属于"打开门做生意"。** 三件事必须在开服前处理，否则一次被打就可能直接丢号、丢钱、丢口碑：

1. **玩家密码目前是明文在网络里跑的**（注册 HTTP、登录裸 WebSocket）。同 WiFi、公共热点、运营商侧抓包即可直接拿到账号密码。
2. **后台管理员能一键看到玩家明文密码**（AES 可逆存储）。这是合规雷，也是内鬼/后台被攻破后的核弹。
3. **游戏登录（KB 20013）没有任何失败次数限制**。撞库脚本可以无限次试，成本为零。

另外服务器本身的问题比注册接口更危险：**一台机器上同时跑着 8L 和 laba2 两套游戏，一堆 node 服务以 root 身份跑在公网开放的 13000–16000 端口上**，CentOS 7 / MySQL 5.7 都已停止安全维护。任何一个老服务出洞，等于整台机器（含数据库、含后台）全部失守。

按风险排序：**明文密码 > 后台可查明文 > 登录无暴破限制 > 批量注册薅羊毛 > 服务器横向渗透**。

## 三、P0：开服前必须做（按顺序）

### 1. 注册/改密全链路换 HTTPS（半天）

- `assets/scripts/logic/ConfigManager.ts:96-98` 三个 URL 全部改 `https://154-37-155-17.nip.io/xuanmanager/api/game/...`
  - 只有 `154-37-155-17.nip.io` 有有效证书；`154-37-155-17.sslip.io` 实测 TLS 握手直接失败，手册里写的 sslip.io 是错的，别照抄。
- Caddyfile 里 `http://154.37.155.17` 站点，对 `/xuanmanager/api/game/*` 加 308 跳 https（其他静态资源可保留 http，热更走 http 是既有设计）。
- 顺手把 `nip.io` 这类临时域名换成自有域名——换域名会让旧证书和客户端配置一起失效，越晚换越贵。
- 这一步同时修好"网页版注册被混合内容拦截"的功能问题。**改完必须实测三种端：安卓原生、iOS、网页版。**

### 2. 登录链路别再传明文（1 天，需服务端配合）

- 客户端 `loginGame` 传 `md5(password)`，服务端按 md5 比对（KB 服务端 `Account` 脚本同步改）。
- 长期把 20013 也套到 `wss://`（Caddy 已有 `/ws/20013/` 反代，客户端 `IS_USE_WSS` 打开即可，但要先确认原生 WSS 稳定性）。
- 注意：只改客户端不改服务端会全员登录失败。这条要么两边一起上，要么先不做。

### 3. 关掉"后台看明文密码"（2 小时）

- `mgr_player_login_password` 表和 `attachPlayerLoginPasswords`：要么彻底不写（注册时不再 `savePlayerLoginPassword`），要么把"查看明文"收成超管 + 二次验证 + 全量审计，且默认不展示。
- 现在 `config.go:115` 在 `XUAN_CREDENTIAL_KEY` 为空时直接拿**数据库密码**当加密密钥 —— 数据库密码一泄露，明文密码全解。至少把 `XUAN_CREDENTIAL_KEY` 独立设置成随机 32 字节。
- 现实影响：玩家密码在别处复用率极高，这批明文一旦流出，等于把玩家在其他平台的账号也送出去。

### 4. 登录加失败锁定（1 天，KB 服务端脚本）

- 按 `账号 + IP` 双维度：同一账号 5 次失败锁 15 分钟，同 IP 20 次/小时限流。
- 失败计数放 Redis（本机 6379 已在跑，正好用）。
- 不做这条，前面所有加密都白搭——攻击者可以直接暴力猜。

### 5. 防火墙收口（1 小时，需 root）

```
20000:20099  → 只放 20013（登录）+ 20015/20016（BaseApp），其余 KB 内部组件一律 DROP
13000:16000  → 确认是 laba2 的 node 服务后，从公网撤掉（要么只放 Caddy 反代用的 /ws/ 路径，要么迁走）
8890         → 进程改 bind 127.0.0.1，不要只靠 iptables 拦（规则不在持久化文件里，重启即裸奔）
```
- KB 的 dbmgr / baseappmgr / cellappmgr / logger / interfaces 是**组件间无鉴权的二进制协议**，暴露公网等于把游戏服务内部总线交出去：轻则打挂，重则伪造内部消息改数据。
- `iptables` 现在实际生效的规则和 `/etc/sysconfig/iptables` 可能不一致，改完用 `iptables -S` 对一遍，并确认 `@reboot` 会恢复。

### 6. 注册加一层人机校验（半天）

- 接腾讯防水墙 / 极验 / Cloudflare Turnstile，走客户端 SDK 拿 token，服务端校验。
- 兜底方案（半天能上，效果差一档）：限流从 10 次/10 分钟降到 3 次/10 分钟 + 单日新增账号总量熔断 + 同设备 ID 24 小时内最多 1 个号。
- 不加这层，开服当天就会有工作室拿新人礼包/首充活动刷号，一个 IP 一天能刷 1440 个。

## 四、P1：开服首周补

1. **注册返回统一文案**：`LOGIN_NAME_EXISTS` / `NICKNAME_EXISTS` 改成"账号或昵称不可用"，并加 300–800ms 随机延迟，堵账号枚举。
2. **CORS 收窄**：`*` 改成固定白名单（网页版域名 + `null` 给原生 WebView）。
3. **客户端不再明文存密码**：`localStorage.pass` 换成 token，或者存"仅本机可解"的加密串；自动重连改用服务端下发的 session。
4. **弱口令黑名单**：注册时拦截 top 1000 弱密码（123456 / 111111 / 生日型），现在只校验 6–32 位。
5. **设备指纹**：现在 `deviceId` 完全由客户端生成、可任意伪造，`antiTheftEnabled` 打开也只是"自证"。至少把 deviceId 与注册 IP 段、机型做关联，后台能看到"一台设备 N 个号"。
6. **告警**：注册量 5 分钟突增 3 倍、登录失败率突增、单 IP 多账号，直接推到客服群/邮件。
7. **备份**：确认 MySQL 有异地/离线备份，并且**演练过一次恢复**。这类机器最常见的死法不是被黑，是被勒索、被误删。

## 五、P2：中长期

1. 密码存储从 MD5 升级到 `md5 + 每用户盐`（KB 兼容改法：`player_wxpwd` 存 `md5(md5(pwd)+salt)`，服务端脚本改一处），或直接换 argon2（要改 KB 的 account 鉴权）。
2. 邀请码是 6 位纯数字（100 万空间），单 IP 10 次/10 分钟枚举要 190 年，问题不大；但多 IP 分布式仍可撞，建议验证码后加权。
3. **服务器分层**：把 8L、laba2、后台、KB 拆到不同机器/不同用户。现在 root 跑一堆 node 服务，一个 node 漏洞 = 全盘失守。
4. CentOS 7 EOL 的补丁方案（换 Rocky/Alma 9，或至少上云厂商的补丁源）；MySQL 5.7 升 8.0 要评估 KB 兼容性。
5. 撤销/迁移 `xray`，这东西和业务无关，是纯暴露面。
6. 加 CDN/WAF（Cloudflare 免费版就够挡 CC），现在单机 Caddy 直接面对公网，被打就是全站不可用。
