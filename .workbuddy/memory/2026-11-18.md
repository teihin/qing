### 同一功能的第二个 bug：盟主被显示成「大盟主」（A3，2026-11-18）
- 现象：A3（A3俱乐部创建者、联盟里的**盟主**，卡片还显示「联盟池 2153 元」=他的俱乐部额度）。日志里服务端一直下发 `is_owner: 0, union_percent: 30`。
- 根因三条叠加：
  1. 服务端对**无权限的 hall 查询**回 `200 + result:{}`（日志里 `club:union:status` 就是这样），而 `{}` 是 truthy → `club:union:name` 分支把空壳交给 `OnClubMyUnion`。
  2. `OnClubMyUnion` 用请求 context 反推出联盟号后直接 `isOwner=true, ownerConfirmed=true` —— 空壳也被当成「我是总群主」。
  3. `ownerConfirmed` 在设计上压过 `is_owner`（`isOwner = ownerConfirmed ? true : ...`），所以之后 `is_owner=0` 永远纠正不回来；顺带 `RememberOwnedUnion` 也把联盟号记进内存，联盟级入口一起错开。
- 修（`panelMain.ts`）：①`OnClubMyUnion` 只认真正数据（`union_id` / `members` / `union_name` / `union_quota|union_percent` 至少一个），空壳只当 ack，冷却 60s；②`OnClubUnionQuota` 里 `is_owner` 有值就永远优先，`ownerConfirmed` 只在缺字段时兜底，`is_owner=0` 顺手清掉 confirmed（自愈）；③该俱乐部已有 `is_owner` 结论时，`查询_我的_联盟` 不再改写 isOwner、也不往 `ownedUnionIds` 里加。
- 教训：**hall 命令 0x200 + 空 result 只是 ack，不能当业务成功**；这一条对其它 `if(response.result)` 分支同样适用（同类分支还有 club:agent / club:info 等，暂未出问题）。

### 观战/观众时「芒池 + 皮池」公共行不刷新（已修，待联调）
