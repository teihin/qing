# 2026-11-20

## 安卓 App 连高防 20013 失败 → 根因是 Host 头缺端口（01:50 解决）

**现象**：正式服安卓包连 `ws://72679781.tjkdplus.com.cname.hcnamedns.com.:20013` 一直
`onerror_before_onopen error:undefined`，服务器侧几乎收不到回源连接。但同一台手机上：
浏览器连同一地址 OPEN 成功、App 连源站 IP `8.153.70.197:20013` 完全正常（KBE 协议跑通）、
App 连高防节点 IP `220.185.184.144:20013` 也正常。Mac 用完全相同的请求打高防也是 101。

**根因**：Cocos 内置 libwebsockets 发 WebSocket 握手时，**Host 头不带端口**（`Host: 域名.`）。
高防按「域名:端口」匹配站点，缺端口直接返回 **403**（`Server: Beaver`）。
TCP 三次握手成功、握手请求也发出去了（内核 `tx_queue` 堆积 289 字节），
所以表象是"连接建立但 onerror"，极易误判为网络/回源问题。

实测匹配规则（同一 IP:20013）：
- `Host: 域名.:20013` → **101**
- `Host: 域名.`（无端口）→ **403** ← lws 的默认行为
- `Host: 220.185.184.144`（IP，无端口）→ 101（IP 走另一套匹配规则，所以填 IP 能通）

**修复**（`cocos/network/WebSocket-libwebsockets.cpp`，`WebSocketImpl` 构造 connectInfo 处）：
```cpp
std::string hostHeader = hostName;
if (port != 80 && port != 443) { hostHeader += ":"; hostHeader += std::to_string(port); }
connectInfo.host = hostHeader.c_str();     // 域名.:20013
```
同时保留三项辅助改动（无害，降低不确定性）：
1. `connectInfo.address` 去尾点后**自己 getaddrinfo 解析成 IPv4 字面量**，绕开 lws 自身 DNS
2. `info.options |= LWS_SERVER_OPTION_DISABLE_IPV6`，避免 lws 把 IPv4 目标 uplevelling 成 v6-mapped
3. `printWebSocketLog` 改 LOGE（release 下原本被 `#if COCOS2D_DEBUG` 整段砍掉，看不到 lws 内部原因）

**产物**：`native/cocos-engine/websocket-trailing-dot-host.patch`（全部改动）、
`native/cocos-engine/WebSocket-libwebsockets.cpp.orig`（原始备份）、同目录 `README.md`。

**验证**：`adb logcat --pid=$(adb shell pidof com.fireball.qing)` 过滤 `ws connect:`，
确认 `host` 带 `:20013`，并出现 `onOpenLoginapp_login: successfully!`。

**踩过的弯路**（别重复）：
- 不是尾点问题：lws 能解析带尾点域名，去掉尾点也没用
- 不是 IPv6 问题：禁掉 uplevelling 后依旧失败
- 不是高防不转发：浏览器 / Mac 都能通
- 不是请求头内容问题：抓到 lws 原始请求逐字节复现，Mac 发同样内容仍 101
- 手机的 `toybox nc` 不可靠（连 28800 普通 GET 都无响应，但浏览器正常），别用它下结论
- Mac 开 Clash TUN 时出口是香港 IP，会干扰判断；用 `curl -4 https://ipv4.icanhazip.com` 看真实出口
