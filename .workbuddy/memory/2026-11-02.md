## 安卓直聊长连接建立失败（定位完成，未改代码）

- 现象：网页版长连接正常，安卓包收不到实时消息，只能手动刷新。手机 `192.168.3.109:9527`（Cocos V8 Inspector 端口是 **9527**，不是 Creator 默认 6086）。
- 根因：ChatTool `handleWebSocket` 在消费 ticket 前先做 Origin 白名单校验；**原生 Cocos WebSocket 的 Origin 由连接地址推导为 `http://154.37.155.17`**（实测：手机连电脑探针 `ws://192.168.3.111:9002` 时发的是 `Origin: http://192.168.3.111:9002`），不在默认白名单
  `http://localhost:7456,http://127.0.0.1:7456,https://154-37-155-17.nip.io` 内 → 403 → 客户端 `onerror`→`onclose`、`readyState=3`、永不 `onopen`。
- 线上对照（原始 Upgrade）：`Origin: http://154.37.155.17` → 403；`https://154-37-155-17.nip.io` → 401（过了来源校验，仅票无效）。403 由 ChatTool 返回，证明 Caddy 反代与手机到服务器的链路都通，唯一被拒的是 Origin。网页版用的正是白名单里的 nip.io 域名，所以只有原生坏。
- 修复已存在工作区（`ChatTool/server/internal/directchat/realtime.go` 的 `originAllowedForTicket`：带一次性 ticket 跳过 Origin 校验，`go test` 已绿），但线上 `bin/chattool` 是 `2026-11-01 21:53`，早于修改时间 `2026-11-02 00:56`，**未编译部署**，所以安卓仍复现。
- 排查手法留档：V8 Inspector 用 `node` 内置 WebSocket 连 `ws://<ip>:9527/<id>`（先 `Runtime.enable`，再 `Runtime.evaluate` 且 `awaitPromise:true`），可在真机里直接构造 WebSocket 观测 `readyState`；Origin 值用 Mac 上临时 TCP 探针抓请求头得到。临时脚本用完即删。
- 详见 `docs/memory/handoffs/2026-11-02-android-direct-chat-ws-origin.md`（已补第二轮复核证据）。

## 直聊「选图 / 拍照上传」双端支持现状（只排查，未改代码）

- **选图**：代码层面安卓 + iOS 都已实现。JS 走 `DirectChatManager.ImagePickSupported/PickImage`，原生分支 `PickImageNative()` 用 `jsb.reflection` 调
  Android `org.cocos2dx.javascript.DirectChatImageBridge.Pick(String)`、iOS `DirectChatImageBridge.Pick:`；桥源码在 `native/android/chat/`、`native/ios/chat/`。
  Android 侧 `AppActivity` 已 `initialize/onActivityResult/shutdown` 全接好；iOS 侧 `8L.xcodeproj` 已把 `.mm` 加进 Sources；`ios/Info.plist` 已有
  `NSPhotoLibraryUsageDescription` + `NSCameraUsageDescription`。上传链路 `NormalizeUploadData` 已兼容原生 TypedArray。
- **拍照**：**两端都没实现**。Android 只 `ACTION_OPEN_DOCUMENT`（相册/文件），iOS 只 `UIImagePickerControllerSourceTypePhotoLibrary`；TS 里
  「拍照上传」和「发送图片」共用一个分支（`panelMessageChat.ts` 1190 行两个按钮都调 `SendImage()` → `PickImage()`，无 camera 参数）。
  `AndroidManifest.xml` 也没有 `CAMERA` 权限和 `FileProvider`，真要做拍照必须补这两项。
- **关键坑**：原生类改不了热更。仓库里 `qing-debug.apk`（07-28）的 `classes.dex`、`qing-ios-voice-unsigned.ipa`（07-28）主二进制里都搜不到
  `DirectChatImageBridge`（对照 `QingVoiceBridge` 有命中，检索方法有效），说明现网分发包不含桥。真机 V8 实测：调用 `Pick` 后 1.2s 内无任何
  Activity 切换，且 `jsb.reflection` 找不到类时**不抛异常**（用 `NoSuchBridgeXYZ` 对照确认），所以不会走 catch 提示，而是 Promise 永不 resolve →
  用户看到的就是「点了没反应」。要支持必须重新打原生包。
