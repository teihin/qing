## 游戏改名 BL → BY：login_shield_exact 盾牌图

- 目标图：`assets/V7/login_shield_exact.png`（417×514 RGBA，带透明通道，四角 alpha=0）。
  图内旧名两处：中央金色大 LOGO「8L」（=BL 艺术写法）、顶部小字「BL POKER」；底部「POKER GAME」为通用词不改。
- 用户确认规则：两处都改 → 中央 `8L→BY`，顶部 `BL POKER→BY POKER`。

### 关键结论（重要）
- **单纯图生图改不了「效果不变」**：Seedream 4.5 会把整只盾牌重画——轮廓、金边层数、蓝菱格尺寸、底部黑桃变黑。
  试了 7 版提示词（含透明底输入、显式保真清单、局部重绘框架），最好的一版（gen_D）轮廓接近但仍是重绘。
- **Ark 生图 API 无 mask/inpaint 参数**，做不到真正的局部重绘。
- 因此改用**像素级合成**：原图当底，只重建文字区背景 + 贴新字形，其余像素（盾牌、金边、材质、透明通道）原样不动。
- 产物：`art_sources/rename-BY/compose/login_shield_exact_BY.png`（417×514 RGBA，可直接覆盖原文件，`.meta`/UUID 不变）。

### 踩过的坑（复用要点）
1. **4.5 的 size 下限不是 1280×720**，实测报错要求 ≥ 3,686,400 px。显式像素尺寸要按这个来（本次用 2048×2524）。
2. `np.nonzero` 按行序返回，`a[0]`/`a[-1]` **不是 min/max**，取包围盒必须用 `.min()/.max()`——曾因此把字形切片切空。
3. 旧文字周围有暗色投影，归一化卷积填背景时会从「暗环」插值导致整块发黑；改用**离掩码 ≥14px 的远场做三次多项式曲面拟合外推**才干净。
4. 大 sigma 的归一化卷积会把远处金色边框颜色拉进来，得到灰褐色，务必限制采样范围。
5. 蓝底是**不规则有机纹理**（不是规则菱格），无法平铺，用「干净区频谱 + 随机相位」合成高频纹理。

### 字形来源
- 从 gen_D（透明底输入那版）抠出金色 `BY`（1160×768）与顶部 `Y`（88×117），按 R−B 软阈值做 alpha，
  缩放到原图尺寸后合成；中央 BY 目标 234×155，中心 (203,228)；顶部 Y 19×25，中心 (170,107)。

### 用户裁定（10:46）
- **合成版被否**：`login_shield_exact_BY.png` 底下残留旧「8L」的影子。根因是文字掩码用「金色」判定（R>B+18），
  旧字的**暗部/倒角笔画**不满足该条件没被识别，dilate 4px 也盖不住。若今后还要走合成路线，掩码必须改成
  「偏离平滑蓝底模型」而非单纯金色判定。
- **采用 AI 重绘版（gen_D）**，用户认可「alt_D_transparent 这版没问题」。
- **硬约束：新图不能比原图大太多，会影响安装包体积。** 原图 417×514 = 351 KB。

### 最终产物
- `art_sources/rename-BY/compose/final/login_shield_exact.png` —— **417×514 RGBA，207 KB**（比原图小 41%）。
  做法：gen_D 抠透明底 → LANCZOS 缩到 417×514 → RGB 每通道 6bit 量化（÷4×4）+ optimize/compress_level=9。
- 量化前后在 3 倍放大下无可辨差异；深度/品红底合成检查边缘无浅色描边。
- 母版：`art_sources/rename-BY/compose/alt_D_transparent.png`（2048×2524 透明底）。
- 对比图：`final/对比_原图_vs_新图.png`。

### 踩坑补充（抠透明底）
- gen_D 背景是均匀浅灰（≈244,244,246），**不是真棋盘格**（那是预览器叠加的）。
- **`ImageDraw.floodfill` 在本机 Pillow 12 上完全没生效**（返回后一个像素都没改）。
  可靠替代：S=8 粗网格保守池化（全格为浅色才算背景）→ 从四边种子做迭代膨胀求连通域 → 上采样 → 再按浅色掩码膨胀补边。
- `np.nonzero` 首尾元素 ≠ min/max，包围盒必须用 `.min()/.max()`。

## nav_bar_exact 改名（第三张，已完成）
