## 看门狗实测 + supervise.sh 缺陷修复（23:00）

- 三层自愈都在：`@reboot start.sh`、`* * * * * start.sh`（watchdog）、`supervise.sh` 的 while 重试。
  实测 kill 业务进程后 **cron watchdog 在第 37 秒拉起**，健康恢复、pid 文件自洽。
- **缺陷：`supervise.sh` 里 `if wait "${child_pid}"; then exit 0; fi`** —— xuanmanager 捕获 SIGTERM 后
  会优雅退出（日志 `XuanManager stopped`，exit code 0），`wait` 返回 0 → 守护认为「任务完成」**自己也退出**，
  于是 3 秒能恢复的事被拖成 cron 的 60 秒。
- 已改为 `wait "${child_pid}" || true`（无条件继续循环），原文件备份 `supervise.sh.bak.<时间戳>`。
  实测 kill 业务进程后 **第 3 秒新进程起来**，supervise 全程存活，28800 入口 200。
- 停止语义不受影响：`stop.sh` 是 kill 守护进程，走 `trap stop_supervisor INT TERM` 分支，不依赖那个 wait。
- **测试服 `/www/html/.xuanmanager/supervise.sh` 是同一份脚本，同款缺陷未修**（靠 cron 兜底，最长 60 秒）。
