## 修：网页支付订单列表「查询」点了没反应

原因：`applied` 是对象 state，`query` 是 useMemo 出来的字符串，`load` 用 useCallback 依赖 `[query]`。
条件没变时 setApplied 只会换对象引用，query 字符串一模一样 → useCallback 不重建 → useEffect 不重跑，
看起来就是「点了没反应」（改过条件再点反而有效，容易误判成按钮坏了）。
修法：引入 `useQueryRefresh()` 的 `queryRevision`，load 依赖里带上它，查询/重置各抬一次。
**这是本项目查页面的通用坑**，TransactionsPage 等页面早就这么写了，新页面照抄即可。
前端 `index-Cw1WWsbA.js`，二进制未动。

## 修：/pgw 前缀下页面报「网络异常」

原因：改前缀时只改了页面算 base 的逻辑，**JS 里请求的仍是 `base + "/api/pay/public/link"`**，
而后端新前缀只注册了 `/pgw/api/link`，于是请求打到 `/pgw/api/pay/public/link`——
Go 的 `GET /pgw/` 是**子树模式**，把任何 `/pgw/xxx` 都吃掉返回页面 HTML（200），
前端 `resp.json()` 解析失败 → 只能报「网络异常」，真实原因完全看不出来。

修法：
1. 新前缀下按**老路径形状**注册：`/pgw/api/pay/public/link|orders|orders/{no}`，页面脚本无需分支；
2. `GET /pgw/` 改成 `GET /pgw/{$}`（精确匹配结尾斜杠），并加一条 `GET /pgw/` 兜底返回 404 JSON，
   避免以后写错路径又被静默吞成 200 HTML。

教训：Go 1.22 mux 里 `"/x/"` 是子树、`"/x/{$}"` 才是精确；静态兜底会把 404 变成 200。

## iOS 切后台回来无声音：音频恢复时序修正（代码已改，用户自行调试）

`QingVoiceBridge.mm`（`build-templates/.../ios/` 源 + `build/jsb-link/.../ios/` 副本，两份同步）两处：

1. `applicationDidBecomeActive` 只在 `app->onResume()` **之前**恢复一次 —— 那时引擎还没跑起来，
   补发的 `AVAudioSessionInterruptionNotification(Ended)` 被丢掉。加 `dispatch_after 1.2s`
   延迟兜底（带 applicationState 判断）。
2. `reconnectOpenALContext` 节流 1.0s → **0.35s**：JS 侧 `EVENT_SHOW` 在 800ms 后调
   `MobileManager.RestoreIOSAudio()`，而 didBecomeActive 已经占用了 t=0 那次，
   800ms < 1000ms 正好被节流吞掉 —— 两次机会全丢。

时序链：`applicationWillResignActive`（setActive:NO + 停语音）→ `didBecomeActive`（t0，无效）
→ `app->onResume()` → JS EVENT_SHOW（t≈0.1s，定时 800ms）→ JS 兜底（t=0.9s，被吞）。
调好后三路都会打 `[QingVoiceBridge] 通知引擎重连 OpenAL context`。
**若三次都打仍静音**，说明补发 Ended 对 2.4.13 的引擎不生效，下一步要重开 OpenAL device 或回前台重播音效。

### 实测确认：补发通知无效，必须重建音频引擎

真机日志显示 4 次 `[QingVoiceBridge] 通知引擎重连 OpenAL context` 之后仍静音，引擎自己只打了
`AudioEngine-inl.mm (160) UIApplicationWillResignActiveNotification` 和 `(170) UIApplicationDidBecomeActiveNotification`。

读引擎源码 `cocos2d-x/cocos/audio/apple/AudioEngine-inl.mm` 才看清：
- 三个标志位都是 `handleInterruption:` 里的 **static 变量**；
- `pauseOnResignActive` 只在收到 `AVAudioSessionInterruptionTypeBegan` **且当时 App 在前台**时才置 true；
- `resumeOnBecomingActive` 只在 `TypeEnded` **且当时 App 不在前台**时才置 true；
- 普通切后台只发 `UIApplicationWillResignActive`，两个标志都是 false → **引擎既不置空 context 也不重新
  makeCurrent，什么都不做**；但 iOS 已经把它底层的 AudioUnit 停了。结果就是 context 指针还在、play 也不
  报错，就是不出声。补发 Ended 最多走到 `alcMakeContextCurrent`，救不回已停的 AudioUnit。

改法（`QingVoiceBridge.mm`）：新增 `rebuildAudioEngine`，在回前台 1.2s 时
`cocos2d::AudioEngine::end()` + `lazyInit()` 整条重建 OpenAL device/context（`play2d` 本来就会自己
lazyInit，重建后下次播放自动接管）。`end()` 会 `stopAll()`，但回前台那一刻本来没在播，代价可接受。
同时打印 `category / mode / options / alContext` 便于继续定位。
