## Cocos Prefab / 贴图操作
- **九宫格 inset 被当两种单位**：`CCSpriteFrame._calculateSlicedUV` 按**纹理像素**切 UV，`sliced.js updateVerts` 按**节点单位**算顶点且 `xScale=min(1, nodeW/(insetL+insetR))`。⇒ 贴图 1:1 要求 `nodeSize≈textureSize`；**放大九宫格贴图必须同步放大节点**，否则装饰件被压扁。干净做法只有两条：①贴图保持原尺寸只换像素（零风险）；②贴图×N + inset×N + 节点×N + 节点 scale 1/N（先确认无子节点）。
- **SIMPLE 精灵**：`_sizeMode=1`(TRIMMED) 运行时会按贴图尺寸自动改节点 → 贴图放大 N 倍节点就大 N 倍；要放大贴图须先把 `_sizeMode` 改成 `0`(CUSTOM)。
- 已知特例：`scoreBK`(150×32, SLICED, inset 35/20) **不能放大**；`pai_1`(25×25)、`zhuang`(37×37) 是 TRIMMED。
- 九宫格换图后重设 `borderLeft/Right`，**口径 = 贴图圆角弧的水平跨度**（顶 3 行 + 底 3 行内缩量取中位）；用「行宽达最大值 99% 的位置」会偏小 → 两端变梭形/尖头。换算 `inset_1x = 圆角跨度 × 目标高 / 源高`。
- 放大贴图必须**同时改三处**：顶层 `width/height`、`subMetas.*.width/height`、`subMetas.*.rawWidth/rawHeight`（漏顶层会使资产库与磁盘不符）。
- 九宫格底框上的装饰件常有**子节点钉在上面**（`pai_1` 是 `scoreBK` 子节点，圆心落在底框 x=20）。换图前查子节点 `_trs` 对齐圆心；**底框去掉装饰件后，钉上去的子节点（含让位的数字文本）必须重新对位**。
- **读节点坐标读 `_trs` 不读 `_position`**：Cocos 2.4 序列化 `_trs=[x,y,z,qx,qy,qz,qw,sx,sy,sz]`，`_position` 为 (0,0) 时整个字段被省略 → 读 `_position` 会得 None 而误判"没坐标"。
- 查引用：`grep -rl` 反查 `.meta` 的 `uuid` **和** `subMetas.*.uuid`，再解析 prefab JSON 取节点尺寸。
- 改完 Prefab/贴图后 `library/` 需 Creator 重新导入；`assets/resources/project.manifest` 是构建产物，跑 `1生成热更新包.command` 重建，不要手改。
- **Creator 开着时覆盖 PNG，`.meta` 会被自动改写**：`subMetas.*` 的 `trimType:"auto"` 重算 trim（实测 trimX 0→3、105×116→100×110），使 `_sizeMode=0` 的元素放大约 5%。根治：按原 trim 矩形给新图四边补 `alpha=2` + 边界不透明像素中位色，让重算结果恒等于原值；验证 `alpha>0 / >=1 / >1` 三种 bbox 全等于 `(trimX,trimY,width,height)`；补边不涨体积；最后 `git checkout HEAD -- <每个 .meta>`。`trimType:null` 的素材（如 `zuotype/*.png`）天然免疫。判断是否在跑：`pgrep -fl CocosCreator`。

## AI 改图（生成 + 替换回项目）
- **硬约束**：新图体积不能明显大于原图（影响安装包），尺寸必须与原图一致。
- **换图手法**：只覆盖同名 PNG 内容，`.meta` 只改必要的数字 → UUID 不变，Creator 不用重挂引用。
- **改图脚本的输入必须先 `git show HEAD:<path> > /tmp/原图.png` 导出**，直接读工作区文件会在「已替换过一次」时二次处理，把图打爆。
- **路线总纲**：新写的内容必须 AI 生成（不许脚本画字）；**但「未改动的部分」一律保留原图原始像素**，只把 AI 生成的新内容贴回去。理由：Seedream 对密集中文（20 画字）在 ~54×50px 下无法忠实还原——实测 7 轮 28 版，结构都对但笔画一律偏粗（原图实心 0.5635，最好一版 0.60），缩小后粘连成脏斑；压粗细的措辞又会把描边压没。参考图放大、数笔画、当「不可修改素材」、单字小块喂 AI **全部无效**。只要未改动部分占多数，就走「原图打底 + AI 新字贴回」。
- **「保字形提亮」路线已否决**：`ImagesLuck/公告/1.png` 8 个标题实测技术指标全达标（alpha 逐字节不变、体积 −22.8%）仍判「效果不行」并回退。遇到「文字看不清但内容不能变」**先问用户想要什么效果**，不要自选路线。细节见技能 `art-text-swap`「路线 B（已否决）」。
- **压体积**：① `im.quantize(colors=256, method=Image.FASTOCTREE)` 完胜位深量化（105×116 按钮：4bit 12 261 B vs P256 **6 001 B**，均差 1.88；P256 能连 alpha 一起量化，透明区照留）——先试 P256，不够再降色数。② 位深 `//4*4` 按图类型选：亮色大渐变（牌背 348×480）要 **5bit**（89 KB）才达标，暗色盾牌 6bit 够。③ LANCZOS 缩回目标尺寸本身掉一大截。④ 轻高斯 0.7 只省 ~10%，别用。判据是「不大于**同组原图**」，量化台阶缩到真机尺寸后被抹平，验收必须缩到实机 px。
- **批量改图提示词的「保留清单」必须逐张看过原图再写**（凭印象复制会让 AI 凭空添加元素，如实测被补了一条不存在的导航条）；通用兜底句「原图哪里是空的，输出就必须还是空的」。
- 原图与生成图 bbox 对齐必须用**同一个 alpha 阈值**（带外发光的原图会把内容整体拉伸放大）。AI 加淡光晕时按原图覆盖率二分求阈值 `al=clip((al-t)/(1-t),0,1)` 压掉并降体积；**若拟合后覆盖率反低于原图，说明光晕是设计的一部分，别压**。光晕可能落在 bbox 外，此时改为「按 bbox 求缩放比 → 整张缩放着版」（宽度用源图宽度）。
- 原图是扁平矢量图（水平相邻像素相同率 > 0.8）时 AI 重绘会 PNG 暴涨（44→112 KB），用「生成侧高斯模糊 2.5 + BOX 下采样 + 目标尺寸中值滤波 3」压回。
- **验收四步**：① 尺寸/`.meta`/体积；② alpha 覆盖率偏差（抓光晕）；③ 分块梯度能量漂移（抓凭空添加的元素）；④ OCR 复扫旧名。别只看缩略图。
- **客观指标（小图肉眼不可靠）**：① 横切游程中位数（量笔画宽度）；② 暗占比；③ 中文区 IoU。判「有没有黑/灰」必须**同时限暗 + 限无色相**：`(max(rgb)<180) & ((max-min)<40)`；用 `rgb.sum(2)<330` 会把纯红 `#D01E28`(294) 判成暗色，得出假黑。
- **小图标糊 ≠ 贴图太小，是元素太多**：25~30px 最多容纳 **3 组**可分辨形状，且必须有**一个占直径 ≥50% 的主体**；灰白低对比、强高光/反光、辅助同心圆环都是杀手。贴图给「显示尺寸 × 2~4 倍」就够，**别为糊去改节点尺寸或加 mipmap**。生成提示词要写**否定清单**（不要内圈/不要细线/不要花纹）。验收必须**按真机 px 1:1 渲染**再挑方案。
- **AI 图生图改按钮/图标三条**：① 系列一致性只能靠「拿已定稿那张当参考图」，同一提示词各自拿原图会让每张长不一样；② AI 会给平面加球面高光带并被后续全部继承 → 写死「盘面是平的，不要白色反光条/高光带/亮斑」，并**同时给两张参考图**（原图定「平整」+ 定稿定「外框样式」）；③ `#RRGGBB` 写进提示词基本没用，改用口语色名 + 排他句（「只有红色一种色相，不要紫/品红/蓝/橙」）。
- **替换 alpha 直接复用原图 alpha 通道**（圆形/规则图标别重新解析 AI 图轮廓，白底抠图易带白边、算错 bbox）：原图 `alpha>128` 的 bbox 当剪影，AI 图按自己彩色主体 bbox 裁好缩放到同尺寸 → `putalpha(原图 alpha)` → 贴回原画布坐标。剪影逐像素一致、零白边、`.meta` trim 天然不变。
- **同尺寸换图（画布相同、本体比例不同）**：不要等比留边，要 **LANCZOS 缩放铺满旧图卡片 bbox**，使变形程度与旧图一致；画布不变则 `.meta` 不用改。交付前打印 `PNG尺寸 / PNG bbox / meta raw / meta sub`，四项必须对得上。
- **`np.nonzero` 首尾元素 ≠ min/max**，取包围盒必须用 `.min()/.max()`（否则切片切空）。
- 抠透明底：本机 Pillow 12 的 `ImageDraw.floodfill` 完全无效（零像素变化）。替代：S=8 粗网格保守池化（整格浅色才算背景）→ 从四边种子迭代膨胀求连通域 → 上采样 → 按浅色掩码膨胀补边。
- **白底图上被封闭的大块白抠不掉**（抠白只从画面四边连通开始）：补丁 `soft=clip((mn-190)/50)*clip(1-(mx-mn)/40)` → `core=soft>0.45` → `MinFilter(2k+1)` 腐蚀当种子（k=5，字母上的小块白消失、大白块存活）→ 在 core 内测地重建 → `dilate(2) & (soft>0.30)` → `al *= (1-grow)`。**k 太大会把字母掏成空心字**。
- 改按钮/图标前先查**哪些字是运行时 Label 叠上去的**：解析目标节点及子节点的所有 `cc.Label`（`_string/_fontSize/_lineHeight/_color`）与 `_trs`，先算它在贴图坐标的占位（`贴图y=(h/2−节点y)/(H/h)`，`_sizeMode=0` 按节点拉伸）再决定图上文字让位。实测 `跟` 的 num 在 y=+15.8（占贴图上半）→ 图上「跟」字须落在 y≥60；`底池1/2/3` 的 num 与 `e1/e2` 的 label 都在底部 → 那些图文字留中上部。

## 白底抠图：软 alpha 会把元素内部的高光挖成黑洞（2026-09-18 确认分牌踩到）
- 症状：金色/金属质感的按钮抠完，内盘上的白色高光带变成透出背景的**黑斑**
  （缩到实机尺寸容易忽略，4× 放大才看得见）。
- 根因：`soft = clip((252 - rgb.max(2))/10)` 是**全图**算的，按钮**内部**近白的高光 → `soft≈0` → alpha≈0。
  `dilate(inside, 2)` 只护住边界外 2px，护不住内部。
- 正解：**内部核心区强制不透明，软 alpha 只管边界几个像素**
  `core = ~dilate(~inside, 3)`（等价 `erode(inside,3)`），`al = where(core, 1.0, soft) * inside * 255`。
- 凡亮色/金属质感、内部带高光或渐变到近白的素材，一律用这一版。

## AI 改文字大小：相对描述无效，绝对占比才有效（2026-09-18）
- 实测同一张 4 字胶囊按钮：「缩小到三分之二」「缩小到 60%」AI 基本不理（甚至更大）；
  改成「只占内盘宽度的**三分之一**左右，四周留出大量干净空白」立刻收敛 ✓。
- **参考图自带文字比例会被一起抄**：拿「文字占满内盘」的按钮当参考图，提示词再强调也压不住；
  要么换参考图，要么把「绝对不要撑满内盘、绝对不要碰到外环」写进否定清单。
- 样式与文字占比**分两轮调**，比一句话全塞进去收敛快得多。
- 多字（3~4 字）按钮必须**按实机 px 1:1 验收**：放大图好看不代表实机可用，粗描边在小尺寸下会糊成一团。

## 白底抠图两类残留：一个在 alpha，一个在 RGB（2026-09-18 分两轮才修完）
1. **内部高光被挖成黑洞** → 是 **alpha** 错。软 alpha 全图算，前景内部的近白高光被当背景抠掉。
   正解：`core = ~dilate(~inside,3)`，`al = where(core, 1.0, soft) * inside * 255`。
2. **外沿一圈白色锯齿** → 是 **RGB** 错。过渡像素的 RGB 是「前景掺白」，alpha 给满也还是浅色。
   正解：从正常像素迭代扩散颜色替换 —— `good = (~white)&(al>0)&((sat>0.30)|(mn<140))`，四方向膨胀 12 轮，
   只改 `rgb[white]`，alpha 原样保留（保住抗锯齿）。
- **诊断白边的判据必须同时限「去饱和」**：`band & (mn>170) & (sat<0.15)`。
  `sat` 放宽到 0.40 会把金环高光误判成白边（圆钮全部假阳性，白改一轮）。
- 判完**先放大目视校准阈值**，再批量跑。横向胶囊（回座/确认分牌）的白边最显眼，圆钮的容易被金环高光掩盖。

## 「抠图不干净、难看」≠ 白边，多半是 alpha 的外发光雾边（2026-09-18 被明确否决一次）
- `room_ready_art` 走「扩散修 RGB」把外沿近白像素 574→0、体积降 74%、`.meta` 分毫未动，**指标全过但用户仍判难看**。
- 真因：生成图自带**外发光**，外沿 alpha 是 255→0 的十几像素平滑渐变 → 游戏里是一圈晕开的雾边。
  用户说「抠不干净」≈ **边界不锐利**，跟 RGB 是白是金关系不大。
- **判据**：贴深色底放大，边缘是「一圈渐隐的雾」而非「一条硬边」→ 修 RGB 治不了。
- **正解 = 重新生成 + 硬策略抠图**（用户说「重新生成」时别再提修补）：
  ①提示词写死「边缘极其干净锐利／绝对不要外发光、光晕、白边、半透明过渡／最外沿直接是描边本身／纯白背景、主体完整居中」；
  ②`hard = clip((255-mn)/30,0,1) > 0.55` 硬切 → `core = erode(hard,3)` → 颜色四方向扩散 **14 轮** →
  **所有非 core 的可见像素 RGB 一律取内侧色**（不是外沿 2px）→ alpha 只 `GaussianBlur(0.6)` + `keep=dilate(hard,1)`，核心强制 255。
- 参数别改小：10 轮 + 腐蚀 2px 时外沿仍剩 492 个近白像素。
- 详细流程见技能 `cocos-ui-element-reskin` 6.20（含「硬边 alpha 走 6.19 / 外发光软渐变走 6.20」决策表）。

## 「抠图乱 / 减少镂空」是设计问题，改抠图没用 —— 加实心底板（2026-09-18 第三次才做对）
- 复杂艺术字（银白字面 + 描边 + 内部渐变反光 + **两侧 1~2px 细金线**）天生带**成百上千处细缝、内腔、细线**：
  细缝在硬阈值下时断时续、闭合内腔抠成孔洞、细线缩到实机不到 1px 必然断成一串点。
  **RGB 修补（6.19）和硬切（6.20）都只修边界那一圈，救不了形状本身。**
- **解法 = 把元素改成「一个饱满实体块」**：加**实心底板**（牌匾/横幅/圆章底座），文字与装饰都画在底板上。
  机制是「字与底**都不透明** → 不产生任何镂空」。底板本身也不能有镂空花纹。**细线装饰一律删掉。**
- 硬性要求：文字实心填色（不要空心字/描边字）；提示词写「内部绝对没有任何镂空、没有透空花纹、没有细线装饰」。
- 字占比用**绝对占比**（「字高占底板二分之一左右」有效）；**写「五分之二」AI 会反向理解成放大并加黑描边**，别贪小。
- 两个抠图细节：① **在目标分辨率上抠图**（先 resize 到目标尺寸 → 再硬阈值 → 再扩散填色），
  原分辨率抠完再缩会被 LANCZOS 重新掺进白像素；② AI 牌匾常**铺满整张画布**（只四角露白）→
  bbox = 全画布，**不要裁**（会切掉圆角），整张缩放到目标尺寸再贴坐标。
- **验收看「真孔洞」**：从画布四边在 `alpha=0` 上连通膨胀，剩下的才是被包围的孔 → 必须为 0。
  配套看外沿白像素 = 0、`0<alpha<250` 过渡带只应是 1px 抗锯齿。
- 实例 `room_ready_art.png`：**真孔洞 0 / 白像素 0 / 136 566 → 30 108 B（22%）**，画布、bbox、`.meta` 全不变。
  流程见技能 `cocos-ui-element-reskin` **6.21**。

## 底板/新元素的颜色必须取自场景，且验收要把新图贴回实机截图（2026-09-18 第 4 轮才定案）
- **加了实心底板还是被说"突兀"**：底板选了跨色相的装饰色（深棕木牌 vs 深墨绿桌）→ 撞色 + 质感太重。
- 规则：① **底板色 = 场景主色的同色系深一档**（桌面 `#003E2F` → 底板 `#012B18`），对比靠金边金字；
  ② 质感跟随场景 UI 语言（本项目按钮全是「深色圆角 + 细金边 + 金字」→ 就照这个做，不要木纹/粗金框/浮雕）；
  ③ 细线装饰、徽章一律删。
- **验收必须把新图贴回用户给的实机截图**，不能在纯色底上模拟——纯色底只能验"形状干净"，**验不出撞色**。
  定位法：颜色掩码 → 按行统计找主体行段 → 行段内按列统计找列段；缩放比 = 截图 bbox 宽 / 贴图主体宽，
  paste 位置 = `(bx0 − 主体左上x×scale, by0 − 主体左上y×scale)`。校验：截图 bbox 宽高比应≈贴图主体比例。
- 详见技能 `cocos-ui-element-reskin` **6.22**。

## 同一素材连续被否 3 次就停手问方向（2026-09-18 教训）
- `room_ready_art` 被连续否定 4 轮（RGB 修补 → 重新生成硬抠 → 实心木牌 → 同色系横幅），
  最后主人回复「算了，帮我退回最开始的版本」——**四轮全部作废**。
- 根因：一开始没确认「这个元素到底要不要动」。它只是一行提示文字，主人可能本来就没打算大改。
- **规则**：同一素材被否 ≥3 次，停下问清方向（"要更轻/换色" 还是 "干脆别改"），不要自己一路迭代。
- 退回用 `git checkout HEAD -- <path>`；若 `.meta` 从未动过（`trimType:null` 类素材）就不需要一起回滚。
