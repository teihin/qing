## Cocos 换 UI 素材的尺寸约束（2026-09-18 读引擎源码确认，**改任何 UI 图前先看这条**）
- **九宫格 Sprite 的 `borderLeft/Right/Top/Bottom` 被当两种单位用**：
  `CCSpriteFrame._calculateSlicedUV` 按**纹理像素**切 UV；`sliced.js updateVerts` 按**节点单位**算顶点，
  且 `xScale = min(1, nodeW/(insetL+insetR))`。
  ⇒ 贴图 1:1 映射到节点要求 `nodeSize ≈ textureSize`。
  **放大九宫格贴图必须同步放大节点尺寸，否则 `insetL+insetR > nodeW` → `xScale<1`，装饰件被压扁。**
  干净做法只有两条：① 贴图保持原尺寸只换像素（零风险）；② 贴图×N + inset×N + 节点×N + 节点 scale 1/N（需确认无子节点）。
- **SIMPLE（非九宫格）Sprite**：`_sizeMode=1`(TRIMMED) 运行时会按贴图尺寸自动改节点 → 贴图放大 N 倍节点就大 N 倍；
  要放大贴图得先把 `_sizeMode` 改成 `0`(CUSTOM)，节点 `_contentSize` 不动。`_sizeMode=0` 的本来就能直接受益。
- 已知特例：`scoreBK`(个人金币底框) 150×32 SLICED inset 35/20 → **不能放大**；
  `pai_1` 25×25、`zhuang` 37×37 是 TRIMMED → 放大需改 `_sizeMode`。
- 查引用必须 `grep -rl` 反查 `.meta` 的 `uuid` **和** `subMetas.*.uuid`，再解析 prefab JSON 取节点尺寸。
- **小图标在真机上糊 ≠ 贴图太小，而是元素太多。** 25~30px 最多容纳 **3 组**可分辨形状，
  且要有**一个占直径 ≥50% 的主体**；灰白低对比、强高光/反光、辅助同心圆环都是杀手。
  贴图给到「显示尺寸 × 2~4 倍」就够（`_sizeMode=0` 的 SIMPLE 精灵天然享受超采样），
  **别为了糊去改节点尺寸或加 mipmap**。验收必须**按真机像素 1:1 渲染**再挑方案（放大图会骗人）。
  生成提示词要写**否定清单**（不要内圈 / 不要细线 / 不要花纹），否则模型一定加辅助圆环。
- **读节点坐标要读 `_trs` 不是 `_position`**：Cocos 2.4 把变换序列化成
  `_trs = [x,y,z,qx,qy,qz,qw,sx,sy,sz]`；`_position` 为默认 (0,0) 时**整个字段被省略**，
  只读 `_position` 会得到 None 而误判"没坐标"。
- **换贴图只覆盖同名 PNG 内容、`.meta` 只改必要的数字** → UUID 不变，Creator 里不用重挂引用。
- 九宫格底框换图后要重设 `borderLeft`/`borderRight`。
  **口径：等于贴图「最顶一行的左端内缩量」= 圆角弧的水平跨度**（取顶 3 行 + 底 3 行内缩量的中位）。
  设小了（例如用「行宽达最大值 99% 的位置」）→ 圆角弧后半段被甩进可拉伸的中间列、被水平压缩，
  **两端会变成梭形/尖头**。换算：`inset_1x = 圆角跨度 × 目标高 / 源高`。
- **放大贴图必须同时改三处尺寸**：顶层 `width/height`、`subMetas.*.width/height`、`subMetas.*.rawWidth/rawHeight`。
  漏改顶层（实测漏过一次）编辑器资产库会与磁盘不符。
- **九宫格底框上的装饰件（徽章/图标位）常常有子节点钉在上面**（如 `pai_1` 是 `scoreBK` 的子节点，
  圆心落在底框节点 x=20）。换图前先查子节点 `_trs` 确认新装饰件圆心对得上，否则图标会偏。
  **反过来：底框去掉装饰件后，钉在上面的子节点（含跟着让位的数字文本）必须重新对位。**
- 改完 Prefab/贴图后：`library/` 缓存需 Creator 重新导入；`assets/resources/project.manifest`
  是构建产物（`assets/resources/native/` 磁盘上不存在），跑 `1生成热更新包.command` 重建，不要手工改。

## 美术改图（游戏改名 BL → BY）
- **硬约束：新图体积不能明显大于原图**，会直接影响安装包大小。原图 `assets/V7/login_shield_exact.png`
  为 417×514 / 351 KB；改名后成品 207 KB。
- **换图手法：** 覆盖同名 PNG 内容、保留 `.meta` 不动 → UUID 不变，Creator 里不用重挂引用。
  覆盖前确认 `.meta` 里的 `width/height/rawWidth/rawHeight` 与新图尺寸一致（不一致要改，否则显示异常）。
- **尺寸必须与原图一致**（本图 417×514）。缩回原尺寸后再压体积。
- **压体积有效手法（按性价比排序）：**
  1. RGB 每通道降到 6bit（`//4*4`）+ `optimize=True, compress_level=9` —— 视觉无差异，本图 398KB → 252KB。
  2. LANCZOS 从生成图缩回目标尺寸（本身就会掉一大截）。
  3. 轻高斯模糊 0.7 只省 ~10%，不划算，别用。
- **量化位深要按图的类型选（2026-09-18 牌背实测）**：亮色渐变 + 白描线的 348×480 图，
  原样 244 KB / 7bit 188 KB / 6bit 136 KB / **5bit 89 KB** / 4bit 56 KB。
  6bit 在本项目的老图（暗色盾牌）够用，但**亮色大渐变图要降到 5bit** 才达标。
  判据是「**不大于同组原图**」而不是「不大于上一张图」。量化台阶在缩到真机尺寸后被抹平，
  验收时必须缩到实机 px 再看。
- **AI 图生图改文字改不了「效果不变」**：Seedream 会重画部分内容（轮廓、金边层数、纹样、甚至黑桃颜色）。
  Ark 生图 API 无 mask/inpaint 参数。**但这就是唯一该走的路。**
- **【硬规矩 · 2026-09-18 主人明确要求】一律用 AI 生成，不要走像素级合成。**
  合成出来的图质感有问题（背景纹理不对、边缘发假、旧字残影），已被否定两次。
  做法：把「必须原样保留的元素」在提示词里逐条列全，一次生成即可，实测场景/中文文字/招牌都能零漂移。
  遇到生成版不够完美也仍用生成版，不再回去做合成。
- **【硬规矩 · 2026-09-18 补充，取代上面「一律用 AI」的绝对版】改名 ≠ 整张重画。**
  **未改动的文字/图形一律保留原图原始像素，只把 AI 生成的新内容贴回去。**
  理由：Seedream 对**密集中文**（如「耀」20 画）在 ~54×50px 字号下**无法忠实还原**——实测 7 轮 28 版，
  结构都能画对，但**笔画一律比原图粗**（原图实心 0.5635 / 暗占比 0.128，最好的一版实心也 0.60），
  缩小后笔画粘连成脏斑；压粗细的措辞又会把深蓝描边一起压没。参考图放大、数笔画、
  当「不可修改素材」、把单字小块单独喂给 AI——**全都无效**。
  → 只要「未改动的部分」占多数，就走「原图打底 + AI 新字贴回」，这才是唯一能真正「干净」的路。
  「不用合成」这条只针对**新写的内容**（新内容必须 AI 生成，不许用脚本画字）。
- **抠透明底（仅在生成版本身有透明底需求时用）：** 本机 Pillow 12 的 `ImageDraw.floodfill` 完全无效
  （调用后零像素变化）。可靠替代：S=8 粗网格保守池化（整格为浅色才算背景）→ 从四边种子迭代膨胀求连通域
  → 上采样 → 再按浅色掩码膨胀补边。
- **`np.nonzero` 首尾元素 ≠ min/max**，取包围盒必须用 `.min()/.max()`（否则切片会切空）。
- **判「成品里有没有黑/灰」的口径（2026-09-18 踩坑）**：`rgb.sum(2)<330` 这种总和阈值会把
  红 `#D01E28`(198,47,49)=294 判成暗色 → 得出 32.6% 的假黑。必须**同时限暗 + 限无色相**：
  `(max(rgb)<180) & ((max-min)<40)`。纯红/纯白都不该被算进去。
- **验收小尺寸图标先渲染实机尺寸**：把成品按游戏真实显示尺寸（如 30px）LANCZOS 缩小、
  贴到游戏同色底上、再 NEAREST 放大 N 倍肉眼看 —— 这才是主人看到的画面，
  直接看 100px 原图会高估可辨识度。

## 批量改美术图（批量改名 / 换字）
- **提示词里的「保留清单」必须逐张看过原图再写**。凭印象复制别的图的描述，AI 会照单**凭空添加**元素
  （实测：把「保留底部导航条」错写进没有导航条的公告图提示词里，AI 就补了一条导航条上去）。
  → 通用兜底句：「原图哪里是空的，输出就必须还是空的」。
- **所有 bbox 对齐，原图与生成图必须用同一个 alpha 阈值**，否则带外发光的原图会把生成内容整体拉伸放大。
- **AI 会加淡光晕**：比较 `(alpha>0).mean()`，若新图明显更高，就按原图覆盖率为目标二分求阈值
  `al = clip((al-t)/(1-t),0,1)` 压掉——顺带还能降体积。**但如果拟合后覆盖率反低于原图，说明光晕是设计的一部分，别压。**
- **光晕可能落在 bbox 之外**：只贴 bbox 内的内容会把光晕裁掉。此时改为「按 bbox 求缩放比 → 整张缩放着版」
  （注意宽度用源图宽度，不是目标宽度）。
- **原图是扁平矢量图时（水平相邻像素相同率 > 0.8），AI 重绘后 PNG 会暴涨**（实测 44KB → 112KB）。
  用「生成侧高斯模糊 2.5 + BOX 下采样 + 目标尺寸中值滤波 3」压回来（→58KB）。判据先测平坦度。
- **验收四步**：① 尺寸/`.meta`/体积；② alpha 覆盖率偏差（抓光晕）；③ 分块梯度能量漂移（抓凭空添加的元素）；
  ④ OCR 复扫旧名。别只看缩略图，缩略图看不出加了导航条。
- **量笔画粗细/字形接近度的三个客观指标**（肉眼在小图上不可靠，必用）：
  ① **横切游程中位数**——逐行统计连续实心像素长度取中位，直接量笔画宽度；
  ② **暗占比** `(rgb.sum(2)<330)&(alpha>128)` —— 抓描边有无与厚薄；
  ③ **中文区 IoU**——候选与原图 `alpha>128` 二值掩码的 IoU（限定到中文列范围），挑最优版用。
- **白底图上「被封闭的大块白色」抠不掉。** 抠白只从**画面四边连通**开始（种子只取边界），
  被金框/边框封住的内部白块（如盾牌菱形内部）永远抠不到，会以 ~40% alpha 残留成奶白块 →
  在黑底 UI 上就是「中间不干净」。
  补丁：`soft = clip((mn-190)/50)*clip(1-(mx-mn)/40)` → `core = soft>0.45` →
  `MinFilter(2k+1)` 腐蚀（k=5，字母上的小块白消失、大白块存活）当种子 → 在 core 内测地重建 →
  `dilate(2) & (soft>0.30)` → `al *= (1-grow)`。
  **k 太大会把字母掏空成空心字**（实测 k 让 R2/R3 作废）。
