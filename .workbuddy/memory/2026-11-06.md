## 切换账号重启时的 `Assertion of KBEngine.app not is null`（已修）
- 现象：点设置里「切换账号」→ 重启进新场景时控制台报
  `声明失败：Assertion of KBEngine.app not is null`，栈为
  `kbengine.js:3036 ← 5460 ← GameDataManager.ts:166(initKBE) ← :86 ← :49 ← StartGameManager.ts:17`。
- 根因：`KBEngine.app` 是**模块级单例**，`cc.game.restart()` 只重跑场景、不重置 JS 模块，
  旧 `KBEngineApp` 实例会活到新场景；新场景 `initKBE()` → `KBEngine.create()` 断言失败。
  **全仓从来没调用过 `KBEngine.destroy()`**（`kbengine.js:5467` 就是为此准备的：
  清 `idInterval`、`uninstallEvents()`、`reset()`（内含 `resetSocket()` 卸 handler+关 socket）、`app=undefined`）。
  不清掉的后果不只是这条断言：旧 `update` 定时器仍在跑（会去操作**新** app 的 socket，心跳发两遍），
  旧 app 的 `login/logout` 等 Event 处理器也还在，登录包可能被发两次。
- 修法：`GameDataManager.logoutToLogin()` 在 `cc.game.restart()` **之前** `KBEngine.destroy()`（try/catch 包住）。
  `destroy()` 是干净拆卸，不会像 `app.logout()` 那样在消息表已清理时抛异常
  （后者正是 `GameDataManager.onDestroy` 注释里踩过的坑）。
- 同时给 `GameDataManager.getAccount()` 加了 `KBEngine.app == null` 判空返回 null：
  destroy 之后到新场景 create 之前有个 app 为 undefined 的窗口，场景销毁期的遗留回调会走到这里。
- **未修但同一病根**：`GameDataManager.ts:142`（后台超 30 分钟 `cc.game.restart()`）、
  `panelLogin.ts:761/768`（内外网切换，那里还先 `initKBE()` 再重启，断言必现）、
  `panelUpdate`/`UpdateManager` 的热更重启。要修就同样在 restart 前补 `KBEngine.destroy()`。
- 验证：ts.transpileModule 0 诊断；浏览器实点未复测（待验证）。
- 注：本工作区此刻有另一个任务在改 `ClubManagementView.ts` / `docs/memory/CURRENT.md`（我的红利入口），
  与本改动无关，未触碰。
