- 入口图标原来是小金币.png(24×24) 拉到 108 → 糊；重做 128×128，**底框直接复用 拍照上传.png 的像素**
  （填掉居中相机后重画铜钱+双箭头），保证与同排三图标逐像素同款。
- 聊天页底部三按钮补 Widget：photo `BOT|LEFT left=101` / img `BOT|CENTER` / gold `BOT|RIGHT right=101`，
  bottom 统一 76。原来 gold 没 Widget 留在 (220,-557)，长屏会压到「发送」上。
- 弹窗 prefab 整棵重建（约 160 对象），去掉了其他模型留下的 12 个孤儿节点（贴图字与 Label 叠字、
  两块「确定发送」、anchor(0,0.5) 从中心右排导致溢出）。素材在 `assets/ImagesLuck/上下分/`，
  由 `tools/gen_chat_gold_pad_art.py` 程序化绘制（不走 AI 生图，纯几何形状更可控）。
  标题与「上分/下分」是美术字贴图（金属渐变+描边+高光+投影）。
- 上分/下分加了二次确认：`showPanel("panelMsgView", Top, 文案, [(confirmed)=>{}])`
  —— `arrayEx[0]` 是函数就自动变成确定/取消双按钮（panelMsgView.start 里判断）。
- **坑：九宫格 + 2× 贴图会把圆角压扁**（`xScale=min(1,nodeW/(l+r))`，inset 当节点单位、UV 当纹理像素）。
  固定尺寸控件一律 SIMPLE+CUSTOM，2× 贴图等比缩到节点才对。
- **坑：`base64.b64encode(md5[:18])` 里 md5 只有 16 字节** → fileId 变成 24 字符带 `==`；
  Cocos 的 fileId 是 24 字符无填充，改用 `sha1[:18]`。
- **坑：Cocos EditBox 不排版子 Label**：textLabel/placeholderLabel 必须挂 `Widget(45)` 铺满输入框 +
  `anchor(0,1)` + `Label.verticalAlign=CENTER`，否则文字跑到框外。别自己算坐标。
- **坑：`cc.EditBox.InputFlag` 里 PASSWORD = 0、DEFAULT = 5**（顺序反直觉）。写 0 会让普通输入框变 ●●●。
- 美术字：PingFF 只有常规字重，用 **同色 stroke 顶字重**（生成时 `bold` 参数）比找字体可靠；
  中文标题不要走 imagegen（笔画会碎）。
- 工具三个：`gen_chat_gold_pad_art.py`（画图）/ `apply_chat_gold_pad_layout.py`（meta+prefab）/
  `preview_chat_gold_pad.py`（读 prefab 离线渲染设计稿，比手搓合成图可靠）。

### 系统通报消息（codex/club-ui，续）

- 上下分成功后要在聊天里留记录 → 不能只本地插（重进就没了），改走 `/api/direct` 的 `system` 消息。
- 服务端 `directchat` 原本**一律拒绝**客户端发 system（防伪造），现在放开但加两道闸：
  `CanSendSystemNotice(role)` 只放 owner/leader/agent + `systemNoticePattern` 正则绑文案格式。
  `message_type` ENUM 早就含 `system`，不用迁移。
- 客户端插消息后需要**跟随滚动**：抽 `AppendToTail()`（原 `OnPolledMessages` 的滚动逻辑），
  实时推送和系统通报共用；`IsNearBottom(12)` 判断是否跟底，不跟底就累加 `pendingNewCount`。
- 服务端只回 `createdAt`（`YYYY-MM-DD HH:MM:SS`），`DirectChatTime.Parse` 就是按本地时间解析的，
  系统条要完整时间就加 `FormatFull()`，别用 `new Date(iso)`（iOS 对带空格格式会 NaN）。

### 聊天页「赠送积分」接口修正（续）

- 原实现把赠送复用上分的 `添加_俱乐部_成员_积分` —— 那是**代理按额度发筹码**（后台侧也是直接加减目标
  积分、不扣操作者），拿它「赠送」等于白送，自己的积分不会被扣。用户指出后改正。
- 正确接口：`赠送_俱乐部_积分`（文档 §8.3，2026-11-01 新增），参数
  `club_id / user_id(接收方) / user_add_gold(元,>0) / user_pwd`，**扣自己积分、不动额度**，
  限制「双方必须在同一个授信代理下」，不能赠自己。
- 改法：`panelClubGoldPad.ts` 加 `GIFT_HEADER`，`DoSubmit` 按 action 选 header；
  `onHallCommand` 的兜底匹配也按 action 分开（`expectedHeader`），否则两条命令的回包会互相误判。
- 查接口名时教训：本地文档有新旧两版，`服务器文档整理/俱乐部积分与额度方案-客户端接口文档.md`
  是最新（§8.3），别只看 `俱乐部金币与钻石-客户端接口文档.md`（只有普通的添加/修改）。
- 游戏服务端（`python3.9 main.py`，PID 1954）跑在 154.37.155.17 上但属 root，`client_update`

### AddMemberGoldList 记录行显示修正

- 实测回包结构：`{"AddMemberGoldList":[{"number","count","guuid","name","gold","date","room_id","opter_name","type","remark"}]}`，
  `normalizeClubGiftRecordList` 已含该键，无需改解析；`guuid/name` 是被操作人、`opter_name` 是操作人、`remark` 是变动后余额。
- 原实现把 `type` 列写死成「赠送」，导致 `gold=-111` 的下分记录也显示「赠送」。
  **用户确认：`AddMemberGoldList` 里「添加」和「赠送」两类记录都有**，所以不用换查
  `查询_俱乐部_积分流水`；`type` 列改为**按服务端 `type` 原样显示**（空时才按正负兜底「赠送/扣除」），
  `count` 保留原始符号（负数=减少）。
- 没改：`opter_name`/`remark` 仍未上屏（这页是「我操作出去的」记录，变动后余额列当前用的是 gold）。

### 聊天页「赠送积分」放开到代理对象

- 现象：自己是代理但无可用额度时，只有对方是玩家（member/manager）才显示「赠送积分」，
  对下级代理不显示。
- 改 `panelMessageChat.ts` 的 `RefreshClubGoldButton`：`peerIsPlayer` → `peerCanGift`，
  白名单加 `agent`（仍排除 `owner`/`leader`）。
- 依据：服务端 `赠送_俱乐部_积分` 只校验「两人带入时扣同一个授信代理的额度」，不按对方角色拦。
  另外服务端 `memberFromAccount` 把「直接挂群主下的代理」标成 `leader`，这种人不可能是
  一个 `agent` 的下级（上级唯一），所以排除 leader 是对的，不会误伤下级代理。
- 已知限制：`DirectPeer` 没有上下级字段，对**自己的上级代理**仍会显示赠送，点了才被服务端拒。
