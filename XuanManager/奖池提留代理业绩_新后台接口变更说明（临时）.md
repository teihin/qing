## 1. 通用命令入口（摘录自 §2.2，本次不变）

```http
GET http://127.0.0.1:8890/hall/command
```

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `header` | string | 是 | 命令名，中文字符串，需要 URL encode |
| `param` | JSON string | 是 | 命令参数 JSON 字符串，需要 URL encode |

返回格式：`{"ret_code": 512, "ret_result": "..."}`（`ret_result` 是 JSON 字符串，需二次解析）。

| `ret_code` | 含义 | 处理 |
| ---: | --- | --- |
| `512` | 成功 | 正常解析 `ret_result` |
| `769` | 失败 | 给出失败提示，写审计 |
| `1280` | 已接收/异步处理 | 不能认为业务已完成，需按校验方式读结果 |

约定：`context` 每次传唯一操作号（便于排查与审计）；`param` 必须是合法 JSON；HTTP **只允许新后台后端从本机访问**，不允许公网访问。
前提（既有）：该通道以服务端 `self.boss` 作为调用者，**boss 账号未配置时整条通道不可用**。

## 2. 变更一：修改玩家属性白名单新增 `client_prop`（原 §4.4）

### 2.1 白名单变化

```text
旧：name, photo, sex, role, client_status, player_setting
新：name, photo, sex, role, client_status, player_setting, client_prop
```

> **`client_prop`（代理的"业绩比例"开通开关）**：`True` = 开通（该代理客户端出现"业绩比例"入口），空串 `""` = 关闭。属性为 `BASE_AND_CLIENT` 持久化属性，目标代理**在线时即时同步**到其客户端；离线则下次登录生效。

### 2.2 调用示例

```bash
# 开通业绩
curl --get 'http://127.0.0.1:8890/hall/command' \
  --data-urlencode 'header=异步_设置_玩家_属性' \
  --data-urlencode 'param={"guuid":"189836","name":"client_prop","value":"True","context":"admin-20260922-0001"}'

# 关闭业绩: value 传空串 ""
curl --get 'http://127.0.0.1:8890/hall/command' \
  --data-urlencode 'header=异步_设置_玩家_属性' \
  --data-urlencode 'param={"guuid":"189836","name":"client_prop","value":"","context":"admin-20260922-0002"}'
```

### 2.3 设置后校验 SQL

```sql
SELECT sm_guuid, sm_name, sm_role, sm_client_status, sm_client_prop
FROM tbl_Account
WHERE sm_guuid = ?;
```

### 2.4 注意

- 其余属性（`name`/`photo`/`sex`/`role`/`client_status`/`player_setting`）行为不变；高危属性策略不变，**默认不开放**给普通管理员。
- `client_prop` 仅用于"业绩比例"入口显示与业绩扣减口径，**服务端不加权限校验、不加值校验、不加审计**（与相邻 `client_status`/`player_setting` 一致的既有做法）；建议后台侧按业务要求限制为超管/财务可操作。
- **线上已有 1 个账号为 `True`：`189836 / 8L`**。业务已确认（2026-09-22）**保留不动**——不要清空；该账号开通后即独立显示业绩，其上级（老板级）业绩会相应扣除其份额，属正常口径。

## 3. 变更二：新增 `异步_查询_奖池业绩_结算报表`（原 §14.3，新增章节）

用途：运营每天结束后，列出**全部已开通业绩比例（`sm_client_prop='True'`）的代理**当日业绩与应返款，用于线下人工分配。

### 3.1 调用

```bash
curl --get 'http://127.0.0.1:8890/hall/command' \
  --data-urlencode 'header=异步_查询_奖池业绩_结算报表' \
  --data-urlencode 'param={"date":"2026-09-21","context":"admin-20260922-0002"}'
```

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `date` | string | 否 | 统计日 `YYYY-MM-DD`（**绝对日期**）；**缺省 = 昨天**（每天结束后结算昨日） |
| `context` | string | 否 | 操作号 |

### 3.2 返回示例

```json
{
  "ret_code": 512,
  "ret_result": "{\"JackpotSettlementReport\":{\"date\":\"2026-09-21\",\"all_performance\":4000,\"pool_performance\":2000,\"rebate_total\":300,\"platform_keep\":1700,\"check_ok\":true,\"count\":2,\"list\":[{\"guuid\":\"182605\",\"name\":\"第二\",\"agent_id\":\"648425\",\"my_performance\":400,\"granted_performance\":100,\"proxy_performance\":300,\"rebate\":150,\"granted_list\":[[\"590326\",\"8LL\",100]]}]}}"
}
```

字段说明（金额单位一律**分**，展示前 `/100` 换算为元）：

| 字段 | 说明 |
| --- | --- |
| `date` | 实际统计日 |
| `all_performance` | 当日全平台奖池提留总额 × 2（用于算占比；×2 即"平台保留一半"的口径） |
| `pool_performance` | 当日提留总额 T = `all_performance / 2` |
| `rebate_total` | Σ应返款 = Σ `list[].rebate` |
| `platform_keep` | 平台保留 = `pool_performance − rebate_total` |
| `check_ok` | `true` 表示 Σ净业绩 ≤ T（即返款总额 ≤ T/2）；`false` 时**先人工复核再打款** |
| `count` | 已开通业绩的代理数 |
| `list[]` | 按净业绩倒序；每项含 `guuid`、`name`（昵称）、`agent_id`（一级上级）、`my_performance`（我/毛）、`granted_performance`（下发）、`proxy_performance`（剩/净）、`rebate`（应返款 = 净/2）、`granted_list`（下发给谁：`[guuid, 昵称, 业绩]`，可为空数组） |

### 3.3 使用要求（重要）

- **占比展示**：某代理业绩比例 = `proxy_performance / all_performance`（与客户端界面同一口径）；业绩金额（元）= `proxy_performance / 100`；预计可返款（元）= `rebate / 100`。
- **取数时点**：建议在当日对局全部结束、服务端无异常后取数；报表的链判定依赖服务端内存中已加载的代理，极端情况下个别代理的"下发"会少算 → **以服务端方案 §6.3 的对账 SQL 为最终依据**。
- **返款登记（后台自建，建议本期做）**：建议建表记录 `date、guuid、name、my_performance、granted_performance、proxy_performance、rebate、操作人、时间、状态（待付/已付/异常）`，用于**防重复返款**与对账导出；同一 `date + guuid` 建议做唯一约束。
- **开通/关闭业绩**：见本文档 §2（写 `client_prop`）。
- 本接口**与客户端接口无关**（客户端用大厅命令通道的两个命令），后台只调用本命令。

## 4. 后台自查用只读 SQL（可选，便于页面自检/导出）

```sql
-- 当日提留总额 T（单位：元）；新记录单位是"分"，故 /100
SELECT date, SUM(activity_int)/100 AS total_yuan, SUM(activity_int)/200 AS pool_yuan
FROM usr_activity_info_sub_shuying
WHERE activity_type='奖池提留' AND date='YYYY-MM-DD' GROUP BY date;

-- 各代理当日业绩（元）；remark2 = 代理 guuid
SELECT remark2 AS proxy_guuid, SUM(activity_int)/100 AS perf_yuan, SUM(activity_int)/200 AS rebate_yuan
FROM usr_activity2_info
WHERE activity_type='奖池提留' AND date='YYYY-MM-DD' GROUP BY remark2 ORDER BY perf_yuan DESC;

-- 已开通业绩的代理名单
SELECT sm_guuid, sm_name, sm_client_prop FROM tbl_Account WHERE sm_client_prop='True';
```

> 说明：上述第 2 条是**毛业绩**（不扣减已下发），与报表的 `proxy_performance`（净）不同；正式付款依据是报表 + 服务端对账。
