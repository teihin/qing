# XuanManager 部署说明

## 安全基线

- 服务和 MySQL 部署在同一台游戏服务器，数据库地址固定为 `127.0.0.1`。
- 用户已明确要求 XuanManager 使用纯 HTTP，不配置 HTTPS。后端仍只监听 `127.0.0.1:8891`，由现有 Caddy 通过公网 HTTP 入口反向代理。
- 不直接开放 8891 端口；公网只访问 Caddy 提供的 XuanManager HTTP 页面和同源 API。
- HTTP 无法加密后台账号、密码和管理数据，链路上的网络设备或中间人可能读取或篡改内容。若保持纯 HTTP，应至少限制访问来源 IP、使用防火墙白名单或仅允许可信内网/VPN 访问。
- 运行环境文件权限设为 `0600`，不得写入 Git、Web 根目录或审计日志。
- 首个超级管理员创建后，立即从运行环境删除 `XUAN_BOOTSTRAP_ADMIN_PASSWORD`。

## 构建

```bash
cd web
npm ci
npm run lint
npm run build

cd ../server
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -ldflags="-s -w" -o bin/xuanmanager ./cmd/xuanmanager
```

部署包只需要：

```text
server/bin/xuanmanager
web/dist/
```

数据库迁移已嵌入 Go 二进制，后端启动时只执行尚未记录在 `mgr_schema_migration` 中的迁移。
迁移适配现有 `webcm_user` 权限，不依赖 MySQL `REFERENCES` 权限；角色、模块、权限和用户之间的关联完整性由后端接口校验。

## 运行环境

环境变量样例见 `.env.example`。生产环境必须至少配置数据库账号、数据库密码、Cookie 安全标记和静态页面目录：

```text
XUAN_HTTP_ADDR=127.0.0.1:8891
XUAN_DB_HOST=127.0.0.1
XUAN_DB_PORT=3306
XUAN_DB_NAME=webcm
XUAN_GAME_ADMIN_URL=http://127.0.0.1:8890
XUAN_COOKIE_SECURE=false
XUAN_STATIC_DIR=/path/to/xuanmanager/web/dist
```

数据库和超级管理员的真实账号密码不写入本文件。
`XUAN_GAME_ADMIN_URL` 只允许 `http://127.0.0.1:8890` 或等价的 `localhost` 地址，不能配置公网主机、其他端口或附加路径。

## 上线前检查

1. Caddy 的公网 HTTP 路由能访问 XuanManager，8891 仍只监听服务器本机。
2. 公网无法直接连接 MySQL、旧管理端口 8890 和 XuanManager 内部端口 8891。
3. 若有固定办公网络，已配置来源 IP 白名单；否则已明确接受公网 HTTP 明文传输风险。
4. 使用超级管理员完成登录、改密、创建角色、创建测试后台用户、分配权限和退出登录。
5. 使用受限角色确认无权限菜单不可见，同时直接请求无权限接口返回 403。
6. 在 `mgr_audit_log` 中确认创建用户、修改角色、分配权限和登录失败都有记录，且没有明文密码。
7. 使用代理查询角色确认 `game.agent.view` 菜单和接口可用，并验证无权限角色直接请求代理接口返回 403。
8. 在代理详情中抽查至少一条非 BOSS 链路能回溯到 BOSS，直属代理/玩家数量及下级获授比例与游戏数据一致。
9. 抽查代理红利：累计总红利等于已提取加剩余红利，来源流水合计与累计总红利一致；按来源玩家、房间和日期筛选正确，每笔收入均能说明来源玩家、房间、基数和比例。存在账户累计提取但缺少历史提取明细时，页面必须明确提示，不能伪造逐笔记录。
10. 使用交易查询角色确认 `game.transaction.view` 菜单和接口可用，并验证无权限角色直接请求交易接口返回 403。
11. 按玩家 ID 抽查金币流水：列表首尾余额连续、汇总净变化等于各行 `new_money - old_money` 之和，游戏/道具/消费筛选无重复记录，页面不显示钻石。
12. 使用房间战绩角色确认 `game.room_record.view` 菜单和接口可用；房间列表默认加载，按房间号、房间名、参与玩家和日期筛选及分页均正确，列表与详情不显示创建人；启用地九王时只显示“地九王”标签，未启用时留空，且与真实房间规则一致。无权限角色直接请求接口返回 403。
13. 从房间列表点击进入真实房间，抽查总战绩与逐局明细：参与玩家和局数完整、牌面花色与点数正确、操作时间线顺序正确；最终输赢优先等于结算返还减累计带入，原始战绩分数不一致时页面明确提示，并能返回原房间列表。
14. 从玩家管理点击真实玩家，核对基本资料、资金情况和房间战绩三个页签；资金汇总与交易记录一致，房间数、局数、带入、返还和输赢与总战绩一致，且可继续跳转到完整交易记录和指定房间战绩。缺少 `game.transaction.view` 或 `game.room_record.view` 时，对应页签不可越权访问。
15. 使用公告只读角色确认 `configuration.announcement.view` 可读取当前内容但不能保存；使用修改角色保存后应核对 `usr_hash_info` 的“系统公告”只有客户端兼容编码，并确认回读内容、审计前后值和操作者一致。线上表为 MyISAM，故障测试不能把 `ROLLBACK` 当作恢复手段。
16. 使用通知只读角色确认只能查看记录；有 `configuration.notification.send` 权限时，未勾选“确认发送给全部在线玩家”必须被前端和后端同时拒绝。真实全服通知只能在有明确业务内容和发送授权时测试，并核对玩家端“系统广播:”正文及 `mgr_audit_log` 记录。
17. 使用奖池只读角色确认 `configuration.reward_pool.view` 能看到9个皮池和正确总额，但输入区不可编辑；运营页面必须以“元”显示并允许两位小数，HTTP API和旧服务仍以整数“分”交互，例如页面 `999.99` 元对应接口 `99999` 分。修改角色必须具备 `configuration.reward_pool.update`，未勾选确认时前后端均拒绝。保存前记录当前全部金额，保存后核对9项分值回读、页面元值、合计和审计；生产验证不得为了测试随意改变真实奖池金额。
18. 使用封号只读角色确认 `game.ban.view` 只能查看全部当前已封游戏账号；封号和解封分别要求 `game.ban.create`、`game.ban.remove`。前后端未勾选确认时必须拒绝操作，玩家 ID 必须为6位数字；上线验证不得为了测试封禁真实玩家。业务确需操作时，应核对玩家身份、玩家端提示、`sm_client_status` 回读结果及 `mgr_audit_log` 的操作前后状态。
